# 战斗结算框架

本文描述当前 Godot 战斗运行时的实际契约。源码对照见《无名杀运行逻辑重构分析》，技能入口见《内容制作指南》。这些规则约束流程顺序，不引入新的伤害、费用或触发概率。

## 组件职责

| 组件 | 职责 | 内容脚本使用方式 |
|---|---|---|
| `EventScheduler` / `GameEvent` | 父子事件、next/after、选择所有权、终态归档与有预算推进 | 卡牌沿用正式用牌与效果接口，不自行改栈 |
| `TriggerManager` | 排序技能、保留暂停游标、执行前复核订阅身份 | 沿用 `SkillDefinition` 订阅接口 |
| `RuleStepSequence` | 保存内容游标、纯数据上下文和选择结果 | `SkillDefinition.run_steps()` |
| `RuleContinuationQueue` | 调度规则后半段与 `rule_sequence`，子流程先于父流程 | 只由控制器维护 |
| `DamageResolutionService` | 编排修改窗口、装备修正、护盾与伤害结果 | 保持 `MatchController.damage()` 公共入口 |
| `DyingResolutionService` | 编排濒死开始与获救通知，逐窗口等待子交互 | 保持原濒死与救援入口 |
| `CardUseMaterialResolutionService` | 逐张消费与回收真实/虚拟用牌材料，持有lose/cardsDiscard子事件暂停 | 沿用公开用牌接口，不直接调用内部服务 |
| `ResponseResolutionService` / `ResponseChoiceResolutionService` | 统一响应消费、费用与结果接收；选择与消费结果槽分离 | 正式响应询问、结果对象及稳定接收者 |
| `JudgmentResolutionService` / `JudgmentAreaResolutionService` | 单次判定、延时牌区域、嵌套判定和回收 | `request_judgment` 与稳定结果接收者 |
| `CardMoveResolutionService` / `CardBatchResolutionService` | 单牌与多牌的前置、原子提交、装备离区、后置及实际结果 | 公开获得/弃置/给予入口，下一步骤读取结果 |
| `EquipmentResolutionService` / `PersistentCardBindingService` | 装备替换、携粮、虚拟区域牌和物理材料绑定 | 公开装备与延时牌安装接口 |
| `RecastResolutionService` | 重铸专属时机、实际费用和补摸 | 重铸结果的count与selected_count分开使用 |
| `PlayerStateChangeResolutionService` / `ZoneChangeResolutionService` | 体力、护甲、上限、横置、翻面及区域废除的完整等待 | 公开状态与区域API的独立结果 |
| `SkillActivationResolutionService` | 发动声明、主体子内容和后置；响应声明复用同一内容 | activate_skill受理结果或begin_skill_activation完整句柄 |
| `PauseRegistry` | 按事件和通道持有暂停令牌 | 只释放自己拥有的令牌 |
| `MatchController` | 权威状态修改、选择校验、组件协调和旧规则兼容 | 内容调用稳定公开规则接口 |

`RuleStepSequence` 是内容对象，不是第二套调度器。它通过已有 `RuleContinuationQueue` 恢复。回调只留在本局内存，`context` 仅保存稳定 ID、代次、数字、字符串、数组和字典。步骤对象不进入存档、回放或网络包。

## 父子所有权与终止

- 子事件记录 `parent_id` 和 `parent_queue`，从待执行队列弹出后仍属于父事件；活动子索引不能依赖待执行队列反推。
- `cancel` / `neutralize` 停止主体及普通子树，保留父事件的 `after`；`abort` 连同 `after` 中断。终态不能被 `PAUSED` 或 `WAITING_CHILDREN` 覆盖。
- 终止祖先清理在暂停检查之前执行，避免取消后的子选择继续持有令牌。只释放该子树拥有的暂停，不影响网络或菜单等独立全局暂停。
- 完成时先出栈、回写父结果、清除 live 索引，再发布 `event_finished`。监听者观察已提交状态，诊断继续使用归档快照。
- 不存在或已经中断的父事件不能接收新工作；无法归属的子事件立即中断并归档，不能成为无人推进的 live 对象。
- 同一运行时重置后，事件、请求、暂停令牌 ID 保持单调递增。普通响应和超时均复核请求、事件、角色、候选和终态，旧局应答不能恢复新局。

## 可以暂停的步骤

控制器在回调前推进游标，并在续接栈预留父步骤位置。本步骤产生的选择、规则时机、装备触发、子判定、子规则续接和技能后续优先完成，再执行下一步骤；不会重新扣费、移动实体或发布同一窗口。

已完成自身窗口的最内层序列，先恢复自己的后半段，再让外层时机询问剩余技能。序列记录创建时已有的判定 ID：`judgeBefore` 内的技能只等待自己新建的子判定，不能反过来等待尚需该技能完成的外层判定。

1. 请求目标或牌后立即返回；下一步检查 `sequence.choice_response` 是否为空及 `confirmed`，再读 `target_ids` / `card_ids`。
2. 一个可能产生子交互的效果独占一步；后续效果放下一步。
3. 条件不成立时调用 `sequence.finish()`；它停止剩余步骤，不回滚已经成立的效果，不取消其他技能，也不代替卡牌收尾。

步骤序列接入统一选择、规则时机、伤害、摸牌、死亡、牌移动、状态和区域变化、技能发动、响应及多材料用牌。独立额外出牌、额外弃牌按实例ID等待，结果通过正式响应/效果槽读取。内容必须通过已登记公开端口产生子树；直接改牌区数组或自行启动未归属的await协程不会获得此契约。同一后续不得同时使用步骤序列和手工 `defer_settlement()`。

## 伤害流程

`damageBefore → damageBegin → damageBegin1 → 来源武器修正 → damageBegin2 → damageBegin3 → 目标防具修正 → damageBegin4 → damage_before → 候选点damagePointBefore/Begin → changeHujiaBefore（有吸收时） → 原子提交 → 结果时机 → damagePoint → 濒死开始步骤与兼容求桃入口 → 步骤式尾部`

每个修改窗口保留原始 `RuleEvent`，等待全部处理器及子选择完成后回读最终 `data`。数值、属性、扩展字段和取消不会因为提前复制字典而丢失。扣血前取消或中立化发布 `damageCancelled`，停止伤害主体。

护盾、体力、统计和结果快照在一个无触发回调的提交点写入一次。护盾吸收量最多等于最终伤害和提交时可用护盾；取消 `changeHujiaBefore` 只取消护盾扣减，伤害穿透体力。随后 `changeHujiaAfter`、`changeHp`、`damage` 依次等待，最终伤害为0时进入 `damageZero`。结果时机不得再次扣血或统计。

尾部顺序沿用 `damage_after → hp_reduced → 濒死/死亡 → damageSource → damageEnd → damageAfter → damagePointAfter → 属性连环`；整条顺序由原伤害 `RuleStepSequence` 持有，不再按目标保存独立结果恢复上下文。濒死开始、获救收尾和死亡内部均使用步骤服务；`source_id` 为最终伤害来源，`card_user_id` 为原牌使用者，不能混用。

## 卡牌与响应

整牌、逐目标及【杀】专属 Before/Begin/End/After 窗口依次完成。`useCard0/1/yingbian/2/useCard` 及目标分发窗口等到最终 `RuleEvent` 结果后更新活动上下文；异步取消、排除目标和直接命中不能在选择前被提前读取。目标主体执行前再次检查是否被排除。

目标取消只影响对应目标，整牌取消影响整牌主体。实体材料进入处理区时使用可暂停 `CardMoveResolutionService`，先完成 loseBefore/loseBegin 再提交移动，并等待 loseEnd/loseAfter；真实牌和多材料虚拟牌均由 `CardUseMaterialResolutionService` 在 lose 与 cardsDiscard 子事件中逐张等待并回收，不能在内容中通过清空队列或直接移牌“解卡”。

响应按“权威校验与接受 → 关闭旧选择并恢复所属阶段 → 技能声明与费用（适用时） → respondBefore/Begin → 实际材料消费 → 响应End/After及其子交互 → 交付原响应结果”执行。先关闭旧选择，After里的新选择才能独立存在；原响应结果通过局部上下文保留，嵌套选择不能覆盖它，也不能重复消费响应牌。

## 触发快照与帧预算

时机保留稳定排序快照，但每次执行前检查注册 ID。等待期间卸载技能后，旧快照不再运行它；即使同一对象重新订阅，也要等下一事件收集新快照。

达到预算时通过真实 `SceneTree.process_frame` 继续，给输入、网络和渲染让出主循环。`call_deferred` 可能在同一空闲轮继续排空，不能作为跨帧证据。控制器和事件调度器各自只持有一条帧唤醒连接，直接接管、重置和离树时主动断开，代次校验用于额外拒绝旧回调。

沿用原技术预算：事件每批256、单步自旋2048、规则每批256、触发批次64、同步嵌套32层、同语义续接16次、变化上下文因果链512步。这些是防错预算，不是技能次数或游戏时间。正常结算不能依赖看门狗清空队列才能完成。

## 兼容边界与验证

当前主链已覆盖伤害、濒死/救援/死亡、回复/摸牌、六阶段生命周期、回合开始、用牌材料/回收、响应、无懈预演、单次及外层判定和批量弃置/获得；均通过步骤内容等待子结算。技能可用request_step_response读取完成结果。单牌获得/弃置/给予、装备及附属牌、游戏外实体/铸造入手、秘密置牌的结果读取者均已迁移；旧同步移牌包装、全局获得/弃置批次栈与独立伤害恢复表已移除。秘密置牌保留不公开lose/gain的隐私语义，无玩家区域生命周期的void新实体创建及公共堆洗回保持明确原子边界。正常执行预算、错误诊断、网络超时与断线接管继续保留。

- `battle_lifecycle_test`：终止子树、after、独立暂停、结果发布、旧应答/超时、孤儿事件和真实跨帧预算。
- `damage_sequence_test`：7个修改窗口、取消、护盾/结果时机、嵌套顺序、选择结果、换将、外层判定和步骤预算。
- `card_timing_sequence_test`：15个前置窗口、12个生命周期窗口、响应After选择、订阅卸载重装及正式【加护】子流程。

回归通过正式请求提交和规则入口推进，检查队列排空、效果只应用一次。20点体力和低预算等均是测试夹具值，不改变正式数值。完整验证记录见《战斗框架回归说明》。

## 逐点伤害与阶段步骤契约

PhaseLifecycleService负责六阶段的Before/Begin、End/After和明确后继；TurnStartService负责轮开始、回合前置、翻面跳过与准备阶段；DamageResolutionService负责整次伤害、逐点筛选及伤害尾部。三者均复用RuleStepSequence与已有续接管线。阶段实例按starting/body/ending推进：Begin窗口排空后才进入body，只有body状态受理结束请求，取消或跳过直接清除实例。因此阶段Begin询问内确认跳过阶段必须调用统一跳过入口，不能请求结束阶段。

- 整次修改窗口结束后，每个候选1点依次执行damagePointBefore、damagePointBegin。取消、中立化或amount<=0只阻止这一点；Before已阻止时不发该点Begin。增加总伤害应修改整次Begin窗口，不通过单点amount放大。
- damage_point_index从1开始；前置damage_total_amount为候选总数，结果窗口为最终成立总数。候选索引与结果索引不表示同一实体ID。
- 汇总后只提交一次护盾、体力和整次统计。护盾吸收仍计点，全部阻止则damageZero。damagePoint在damage后报告逐点事实，damagePointAfter保持在整次damageAfter之后；2点伤害不会拆成两次伤害统计或两次濒死。
- 六阶段前置取消不开主体、不伪造End/After；正常收尾依次等待End、After再调用后继。准备阶段补齐phaseZhunbei主体和phaseZhunbeiAfter，判定阶段补齐phaseJudgeAfter。
- 摸牌Before、Begin、Begin1、Begin2全部结束后回读draw_count并只摸一次；基础仍为2张。End/After只报告已完成事实。
- 独立出牌与额外弃牌使用单调phase_id；父序列等新建子阶段，阶段内序列不等待创建时已有的外层阶段。额外弃牌使用独立生命周期键；前置取消不发放以完成阶段为条件的收益。
- 恢复触发队列后仍检查技能“然后”步骤，避免父阶段抢跑。已删除damage_finalization、turn_start、phase_after_completion旧续接分支及待结束回合标记和补偿函数；安全预算、诊断及仍服务旧路径的看门狗保留。

新增逐点Before/Begin/主体名称是本项目扩展。参考无名杀的是独立步骤等待和整次提交，不表示完整复刻其执行器。

## 濒死开始与获救收尾

濒死开始顺序为 `dyingBefore → dyingBegin → 登记dying_queue与dying事实 → dying → dying_begin → 原单轮求桃入口`。各窗口独占步骤，并持有原RuleEvent直到触发、选择和技能“然后”结束；下一窗口才读取最终data，避免提前复制而丢失异步修改。

开始时记录目标character_generation，每步按ID重读角色。Before或Begin期间已恢复正体力且尚未登记濒死时，结束开始内容并恢复原伤害；dying或dying_begin期间已回复且登记过濒死时，必须经过获救收尾，不能只返回而遗留dying标记。窗口cancel/neutralize本身不替代实际回复或死亡，沿用原规则。

获救时先移出队列并清除本次dying状态，再依次等待 `dyingAfter → dying_end → 原伤害尾部`。获救数据保留完成时快照，重复调用完成入口不会重复派发通知；子通知期间不能再次清除角色可能新建的濒死状态。旧角色完成入口按代次复核，避免取走新武将的伤害尾部。伤害尾部由每条 `DamageResolutionService` 序列独立持有，不再使用全局待结束表。

删除独立濒死开始数组、阶段恢复中的濒死弹栈分支、“没有选牌就提前完成伤害”的补偿分支，以及按目标保存的伤害尾部恢复状态。失效目标通过明确入口收尾。死亡模式奖励中的多张摸牌/弃牌、同步无懈预演与通用技能询问结果槽仍需调用方逐项迁移；这些兼容边界不能作为标准步骤已完成的证明。

## AI 响应伤害快照

统一响应请求继续由权威规则层生成合法候选。带有效 `parent_card_uid` 的响应上下文提供 `direct_response_count` 和 `direct_response_count_excluding_source`：后者为排除预计伤害来源本人后的直接响应数量，决斗来源取当前 `opponent_id`，其他响应依次读取 `actor_id/source_id`。两者只统计直接响应父牌的实际打出，不递归统计反响应。该字段供 AI 判断【制动】等“其他角色响应”增伤，不改变真实响应记账、规则伤害或卡牌生命周期。

普通决斗的基础伤害始终为 `1`；仅当当前对手拥有【制动】时，AI 才按 `1 + direct_response_count_excluding_source` 估算其增伤，再应用防具和护盾。旧请求缺失排除来源计数时，兼容回退已有总计数。卖血模型和既有制动停止响应判断使用同一计数，避免普通决斗被无条件估成越来越高的伤害。

## 使用牌材料与判定内容（2026-11-08）

`CardUseMaterialResolutionService` 统一真实牌和多材料虚拟牌的 lose 与 orderingDiscard/cardsDiscard 内容。每张材料经 `CardMoveResolutionService` 完成全部 Before/Begin、提交、End/After 后，才处理下一张。消费前检查整份UID清单；材料失效或前置取消使父牌上下文取消，已提交的材料仍按正常after回收，不回滚已成立事实。逻辑代理在最终回收完成后返回void，不进入弃牌堆。源/目标武将代次及装备、判定区域约束在移牌提交前再次校验。

`JudgmentResolutionService` 使用一条 `RuleStepSequence` 执行 `judgeBefore → judgeBegin → 处理区移牌 → judge → 展示 → judgeFixing → judgeResult记录 → 判定牌回收 → judgeEnd → judgeAfter → 完成接收`。每个窗口及回收时机均可等待。前置取消不取牌；已亮出的牌即使角色换将仍完成回收，但旧结果返回null；被技能移动出处理区的牌不被再次强制弃置。

`request_judgment` 保持同步兼容：只有所有步骤在调用栈内完成才返回实体，发生等待时返回null，最终由稳定接收者 `continue_judgment` 接收一次结果。同步返回与异步回调互斥。活动判定已按request_id注册；嵌套判定、无懈预演与技能步骤响应结果槽见2026-11-09节，剩余单牌兼容端口仍需迁移。

## 统一响应消费与接收（2026-11-08）

普通实体牌、单材料技能转化、无材料技能与装备材料共用`ResponseResolutionService`。顺序为方案校验、respondBefore、respondBegin、逐张材料失去/展示/处理区回收、唯一响应历史、动作主体（useCard或respond）、技能/装备消费通知、respondEnd及respondAfter（使用型为useCardAfter）、结果完成。每个窗口和子效果均独立等待；求桃回复、无懈奇偶翻转与父牌响应结果必须在最终完成之后应用。

`ResponseChoiceResolutionService`负责把已接受选择接入消费结果并通知原技能、父牌或装备。`result=null`且`completed=false`表示尚未完成，不能解释为放弃；取消或失效完成后才返回明确空结果。装备判定将结果写回所属响应序列，重试维持排除集合与原父上下文。原有5类手工响应恢复项、旧自动响应消费和使用/打出同步回收包装已移除。

同时无懈先关闭同轮竞争请求，再执行获胜者的完整响应内容；其使用After尚未完成时不翻转奇偶、不恢复锦囊，也不提前创建下一轮。规则管线在外层序列返回后交回原EventScheduler，令牌所有权继续决定父事件能否推进。普通出牌窗口仅在父卡牌、规则内容和可恢复任务全部排空后重建，移除响应分支内的提前补开。

仍须审计无match_id的同步无懈预演、通用技能响应询问的步骤结果槽、嵌套判定注册与批量移牌。标准生产响应已步骤化，不代表任意旧同步端口都能表达异步结果。

## 嵌套判定、批次与濒死所有权（2026-11-09）

活动判定以request_id注册，RuleStepSequence记录创建时已有的全部外层判定ID，只等待之后创建的子判定，避免内层内容反向等待祖先。结果句柄与稳定continuation互斥交付；阶段中断后旧请求完成为空且不通知旧接收者。JudgmentAreaResolutionService取代延时牌外层await/while与手工结果停留标志，依次持有每张延时牌的时机、移牌、无懈与子判定，经过原GameFlowPacer间隔后才进入下一张。

CardBatchResolutionService负责有限UID批量弃置与获得；每张完整CardMoveResolutionService内容结束后再前进，整批After后交付实际数量。结果对象与Callable只存运行期，批次上下文继续是纯数据。源区域不预先pop；嵌套批次独立记账。源/目标代次、目标存活/离场状态、弃牌保护在提交前再次复核。装备离区副作用在前置通过后作为可等待内容执行。

修复移牌服务在目录没有某个生命周期窗口时未前进索引的问题。比如addJudge没有Begin，必须跳过不存在的窗口；不得给目录伪造时机或通过看门狗打断同步死循环。闪电传递与回到本人用例覆盖此边界。

ResponseChoice结果可直接写入sequence.response_card；无交互预演无懈也持有ResponseResolutionService结果，After完成后才翻转奇偶。移除录事、追歼、邀她、濯世已经无调用者的费用后手工续接，以及机缘弃牌后等量摸牌的独立恢复槽。

濒死唯一所有权来自活动dying_start/rescue序列及原武将代次，不另建全局恢复表。已有内容时子伤害不重新启动求桃，原内容等待子伤害后再应用已消费的桃并重读体力。伤害事实和尾部仍由每次DamageResolutionService独立持有；同目标嵌套的来源、量、事件ID、逐点After分别保留。

本节的已迁移端口不代表所有历史单牌移动接口都已步骤化；最终剩余项及全量证据以交接清单和回归说明为准。正常执行预算、错误诊断、断线托管和可应答性恢复仍保留。

### 原生用牌嵌套的所有权边界（2026-11-09）

CardUseEvent 优先挂到当前原生内容事件，没有活动事件时才回退长期根。RuleStepSequence 和 RuleEvent 运行期保存本步产生的原生子 ID；等待条件使用调度器活动索引，只有子事件完整 after 与归档结束后才清除。TriggerManager 在首次与恢复处理器两条路径都登记窗口归属，终止窗口不等于结束已产生的子内容。

内部 card_content、材料和生命周期令牌使用内容级暂停，调度器只放行不受任何选择/全局/祖先子树令牌阻塞的首个 next，不释放父令牌。目标前置组与目标主体分开声明，防止预排主体被误当成可放行子内容。

连续虚拟牌基类使用同一规则序列等待完整事件；移除 useCardAfter/useCardCancelled 的手工下一张续接和延后一帧恢复出牌窗口。阶段恢复中扫描活动目标并补齐 End/After 的旧补偿已删除；明确的牌效/响应完成入口继续承担收尾。模式换将边界的独立补齐逻辑尚需随剩余入口继续审计。


### 独立单牌请求与规则子内容（2026-11-09）

CardMoveResolutionService.resolve持有独立完成结果，begin继续供批量/判定/材料序列内嵌。resolve复用同一逐窗口游标，不复制同步lose/gain循环；成功批次与完成接收均属于本对象。装备离区副作用在真实移牌提交后产生，前置取消不得卸载实例或产生回复。

RuleEvent运行期记录pending_rule_sequence_ids；TriggerManager的内容等待条件同时检查原生子树与规则子序列，解决仅预算让帧、尚未出现选择时外层处理器抢跑的问题。RuleStepSequence.effect_result是运行期结果槽，不进入稳定上下文或回放。

机缘逐张获得、交换手牌以及区域弃置/获得/弃后摸牌改用步骤完成边界，移除_pending_transfer_entries、_process_pending_transfers及对应选择屏障续接；装备交换同样已改为有限原UID步骤，旧两组恢复数组已经删除。


### 规则子序列的直接归属

RuleStepSequence.pending_rule_sequence_ids记录当前步骤创建的直接子内容，RuleEvent记录触发处理器创建的规则子内容。二者只按活动身份索引检查完成，不依据当前是否有选择推测结算结束。父序列最后一步执行完或主动finish后，仍保留父身份与续接，直至该步创建的原生/规则子内容归档。每次恢复只剔除已结束身份，不扫描角色或强制修复队列。

单张弃置与重铸已采用独立结果。CardMoveResolutionService.count在完整完成前为0，完成后按实际提交为0或1；RecastResolutionService按去重UID逐张执行非弃置移牌，统一补摸后才completed。旧_discard_batch_stack、_gain_batch_stack及未使用的_discard_playable_card已删除。摸牌同样嵌入统一单牌游标，成功UID与批次ID只归原摸牌序列持有；drawAfter之后关闭已完成物理摸牌的表现收集，再等待cardsGainedBatchAfter及技能子内容，最后结束原摸牌规则。动画登记与规则完成是两个独立边界。


### 装备复合提交与公共展示

EquipmentResolutionService复用CardMoveResolutionService的逐窗口游标；它持有成员服务，不维护第二套时机调度器。所有成员Before/Begin通过后才等待旧装备离区，再在无规则派发的原子块内提交装备与粮，安装持续实例，逐张等待End/After。普通换装前置取消不会提前卸载旧实例或触发回复；转移不执行源木牛清粮。

五谷由一条规则内容处理无懈结果槽、选择结果槽、获得结果槽与剩余回收。延时牌安装、装备处理区交换、木牛存粮及牌堆用牌已迁移；原_move_card_with_timings同步包装已经删除。开局手气卡、新虚拟代理登记和公共牌堆亮出是有明确无战斗lose/gain生命周期的原子边界；秘密置牌和铸造相关战斗入口仍须逐项核对。

过关入场持有独立规则根，原演出过渡期间仍阻止旧回合重建交互，但已创建的入场根及子内容允许跨帧恢复。敌人依次换将、装备、补摸，全部结束后玩家复活与机缘选择，不能再在同步for中并发发起所有入场效果。


火攻现在由同一目标规则内容依次等待huogongBegin、展示选择、费用选择、实际弃牌、伤害与目标收尾。选择结果直接路由原sequence.choice_response；原展示/费用continue_choice分支已删除，不再按“暂无选择”手工完成目标。费用被取消时不伤害；父用牌After只在全部子内容结束后执行。


## 持久虚拟牌与材料守恒

`PersistentCardBindingService`只负责虚拟装备/延时牌的原材料绑定，不创建额外调度器。安装复用同一可暂停移动游标，在所有前置结束后原子绑定材料、安装第一份实体并清除临时代理，再发布只读移动通知。`CardMovementService`负责持久效果结束后的整组恢复；判定处理区保持逻辑身份，普通获得/弃置恢复每张原实体。

原生CardUseEvent及其材料子事件使用展开后的真实`card_uids`，响应消费同样逐一回收结果中的所有物理成员。不能只更新context里的材料数组而遗漏父GameEvent.card_uids，也不能只回收选中的主材料。移牌服务在提交前比对成员清单和双方代次，嵌套改变成员使旧请求明确失败。装备离区逻辑定义在恢复实体牌面前锁定，离区回复等子效果结束后才发布获得After。

批量结果区分物理数量`count`和费用选择数量`selected_count`。例如选中两条费用，其中第一条为双材料装备、第二条被取消，则count=2、selected_count=1，不能支付要求两条选择的费用。批次After中换将后，绑定旧SkillDefinition的完成接收者不再执行；已成立的移动事实保留。


重铸专属窗口按recastingLose、recastingLost、recast、recastingGain、recastingGained依次完整等待。失牌前取消不付材料，补摸前取消只阻止补摸；事实后置不回滚。成功N张默认补摸N张，仍不计使用或主动弃置；标准时机目录增加5项至242项。


游戏外实体/铸造入手现复用CardMoveResolutionService.resolve_new：待入手牌仅由服务私有持有，前置完成后才调用唯一新实体入区端口，之后等待gain后置和获得批次。create_card_in_player_hand、mint_card_for_player和按铸造来源检索统一返回完成句柄。造牌提交再次验证名字唯一性和角色代次；以太以真实规则内容ID阻止进行中重放，最终成功才消耗额度。没有另建异步恢复队列。


三区域秘密置牌现返回独立移牌完成句柄：置牌本体仍不公开lose/gain、牌名及位次，装备持续实例正常卸载，装备自身回复和附属粮清理作为子内容完整等待。游丝成功后才登记原UID和回合私有事实。位置仍只允许第1或第2，复合材料主实体保持指定位置，其他成员依序在其下；全部原材料隐藏旧知识，无材料逻辑效果不入牌堆。白银狮子离区回复仍为1点、木牛原粮全部逐张清理，未修改原技能文字和数值。


角色标量状态变化已接入独立PlayerStateChangeResolutionService：护盾、失去体力、体力上限、横置、翻面的前置、提交及后置逐步完整等待。结果amount保留方向，count在完整结束后为绝对量，success区分真实变更与取消/幂等，completed查询原规则内容寿命。护甲最低0且无上限，上限最低1，倾力费用仍为1点体力；未改变技能描述或数值。倾力响应费用在原选择关闭后进入响应父链；机缘翻面/横置逐名等待，旧翻面恢复队列已移除。区域废除和模式边界仍待后续迁移/验证，不能据此宣称整个交接已完成。


### 出牌请求的内容归属边界

原生用牌上下文保存enclosing_play_phase_id，RuleStepSequence保留其既有同名阶段身份。_has_current_play_phase_content按当前独立出牌阶段ID检查未完成原生牌与规则内容；标准阶段ID为-1。普通动作/选择出口不能在父牌尚未结束时重建chooseToUse，即使当前规则序列已经暂时为空。独立子阶段忽略归属外层的父内容，避免父内容等待子阶段、子阶段又等待父内容的互锁。正式phaseUse主体入口显式标注phase_entry，允许建立本阶段第一个输入请求；后续重建都受完整内容边界约束。

星火的横置→领航确认→重铸→原杀响应链即使用该边界：不得在领航重铸结束时另开普通出牌窗口，也不得通过清空父目标、放行无关令牌或延时重试补齐流程。父牌实际完成后才恢复出牌操作。


区域废除/恢复已接入独立ZoneChangeResolutionService结果。每个区域先完整等待区域Before与全部牌移动前置，统一复核原武将代次和原成员集合，再提交标志和整组移牌，随后等待装备自身离区效果、每张牌End/After及区域After。取消前置不改原状态或移牌，不强制清空；装备最多5栏、判定区计1个区域，恢复不返还旧牌。轮回/永劫由明确代次内容持有自身换形后继，自身换形更新预期代次，其他换将使旧链失效。阈值12枚火种、返生至2点、额外回合1个均不变。


### 技能发动与原生用牌单一执行链

主动发动由SkillActivationResolutionService逐步等待logSkillBegin/logSkill/useSkillBegin/useSkill、主体及useSkillAfter/skillAfter/skill_used。前置取消和原武将代次失效阻止主体；主体的全部子内容结束后才发布After。响应先关闭原选择，再执行同一技能声明与费用；材料按钮预览不支付或发动。activate_skill的bool仅表示受理，完整结果使用begin_skill_activation的独立句柄。

用牌目标仅由原生CardUseEvent创建内容子树；移除runtime_managed双轨、栈外目标推进及模式强制目标收尾。换层登记在当前结算栈之后，等待父伤害、牌目标尾部与子选择自然排空；保留正常预算和诊断。区域废除与上述标量状态变化也采用相同的子内容等待协议，具体API见内容制作指南。


### 模式交接与原生父分支

`defer_after_settlement`保存`after_native_event_id`和`enclosing_play_phase_id`，RuleContinuationQueue只持有可序列化的原身份；原生分支包括全部contentAfter、orderingDiscard和After归档后才执行模式后继。当前阶段还有此类后继时不能重建chooseToUse，外层阶段后继不阻塞其独立子阶段。清层待换将时以已登记的换层后继识别合法暂态，父牌最终回收不得提前判红方获胜。

旧换层全局原生暂停令牌、对应孤儿补偿与机缘/阿哈时刻续接白名单已删除。进入转场时旧父内容已经完成，新入场与机缘内部规则、原生子牌均可用统一调度跨帧结算。转场标志仍约束外部操作和回合交接，演出计时仍由GameFlowPacer管理；不暂停场景树或弃牌动画。

### 已有出牌窗口的AI续接

`resume_play_phase_choice()` 同时恢复输入窗口与其AI驱动，两者不能以“窗口存在”相互替代。它先检查临时交互及 `_has_current_play_phase_content()`；当前阶段的原生牌、规则子内容或模式后继尚未结束时不得补调度。完整排空后，已有窗口保持原请求ID且不重复广播，缺失窗口才重建；两种情况都经唯一的 `_ensure_ai_progress_after_resolution()` 检查AI任务。驱动仍由原令牌防重，不增加轮询、计时器种类或强制修复路径。【奇袭】的延后重置完成后同样遵循这一空闲出口。
