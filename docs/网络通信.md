# 网络通信

## 当前范围

项目已实现可直接游玩的局域网直连：一名玩家创建 ENet 房间，其他玩家输入房主的局域网 IPv4 地址与端口加入；房主在大厅确认成员与游戏总人数后创建标准身份局。当前不实现公网房间发现、账号、匹配、密码房、NAT 穿透、断线重连、主机迁移、旁观、回放下载或反作弊服务端。

局域网使用 Godot `ENetMultiplayerPeer` 的可靠 RPC 通道。ENet 基于 UDP，系统防火墙必须允许游戏程序使用所选端口；默认端口为 `7000`，界面允许输入 `1024` 至 `65535`。房主最多接受 `9` 名远端客户端，加上房主最多 `10` 名真人。

## 玩家流程与人数规则

1. 主菜单点击“局域网联机”。
2. 房主填写本局显示名与端口并点击“创建房间”；大厅展示本机可分享的 IPv4 地址。
3. 客户端填写显示名、房主 IPv4 与相同端口并点击“加入房间”。同机双实例测试可使用 `127.0.0.1`。
4. 大厅至少登记 `2` 名真人后，房主才可开始对局。
5. 游戏总人数范围为 `2` 至 `10`，且不得少于当前真人数；真人未占用的座位由内置 AI 补齐。
6. 玩家显示名最长 `20` 个 Unicode 字符，空名称回退为“玩家”。名称只用于当前大厅、玩家牌面与对局日志，不建立账号。

当前没有自动房间发现。不同设备必须处于可互访的局域网，客户端需手工输入房主地址；访客 Wi-Fi 隔离、不同 VLAN 或防火墙阻断 UDP 时无法直连。

## 权威同步模型

局域网采用权威房主模式：

- 房主独占 `GameState`、牌堆顺序、身份、随机种子、事件运行时、技能实例和胜负结算。
- 客户端的 `MatchController.state` 始终为空，只保存最近一份观察者裁剪快照，不在本地运行第二套规则或随机数。
- 客户端只上传 `PlayerAction`；房主按阶段、玩家、实体 UID、目标、次数、距离、请求 ID 和候选集合再次校验。
- 房主为每名远端玩家分别调用 `GameState.to_dict(viewer_id, false)`，禁止把同一私有快照广播给全部客户端。
- 联网快照不发送 `random_seed`。客户端只能看到自己的身份、手牌、“粮”和私有选择候选；他人的隐藏身份与手牌牌面保持裁剪。
- 房主额外向当前行动玩家发送 `local_legal_actions`，客户端据此完成卡牌、目标与装备的无状态预览；该列表只控制界面，不能替代房主最终校验。
- 选将期间，快照额外携带仅属于观察者的 `character_selection`：领袖武将立即公开，非领袖候选和已选武将只对本人可见，全部完成后统一公开。

真人成员在开局前随机绑定到不重复的稳定玩家 ID，空余玩家 ID 注册基础 AI。物理座次仍在身份确定后以领袖为一号位旋转，稳定玩家 ID 不随座次变化。

## 通信模式

`NetworkGateway.Mode` 包含：

- `OFFLINE`：本地回环，发送动作后立即触发接收信号。
- `LAN`：内置 ENet 局域网会话，支持建房、加入、大厅、定向快照和表现事件。
- `REMOTE`：保留给未来公网传输适配器，继续通过 `packet_ready_for_transport` 交付封包，不自动连接服务器。

`NetworkGateway.LanRole` 包含 `NONE`、`HOST` 和 `CLIENT`。房主固定使用 ENet peer ID `1`；客户端无权发送快照、开局通知或权威表现事件。

局内日志展开和武将详情打开的暂停只适用于 `OFFLINE`。LAN 与 REMOTE 打开日志或详情时继续运行，客户端不得通过本地界面暂停权威对局。

## 封包结构

```json
{
  "protocol_version": 2,
  "message_type": "command | snapshot | choice_request | choice_response | game_event | lobby_join | lobby_state | match_start",
  "transport_mode": "offline | lan | remote",
  "sequence": 1,
  "payload": {}
}
```

- `protocol_version` 当前固定为 `2`，身份值使用 `leader`，选将字段使用 `leader_player_id` 与 `leader_character_id`；版本1的 `lord` 字段不接受。
- `sequence` 由每个发送端单调递增。接收端按真实 peer ID 记录最近序号，小于或等于已接收值的重复包直接丢弃。
- `command` 负载为 `PlayerAction.to_dict()`。房主先验证封包真实发送 peer 绑定的玩家 ID 与 `payload.actor_id` 完全一致，再交给规则控制器。
- `snapshot` 负载为面向单一观察者裁剪的 `GameState` 字典，并可附加 `local_legal_actions` 与私有 `character_selection`。
- `choice_request` 在 LAN 中使用现有 UI 兼容选择字典，并只定向发送给实际选择者；`choice_response` 保留通用 `ChoiceResponse` 协议，当前桌面也可通过 `command/choose_cards` 上行相同结果。
- `game_event` 只承载日志、公开牌面表现、按观察者裁剪的移牌动画、摸牌批次、技能/装备提示、公共选牌展示、动作拒绝与终局提示，不修改客户端规则状态。
- `lobby_join`、`lobby_state` 与 `match_start` 只用于局域网会话控制，不进入 `MatchController` 规则协议。

所有 payload 只允许字符串、数字、布尔、数组和字典，禁止节点引用、资源运行时实例与 `Callable`。

## 选择请求与公共展示

响应、弃牌、区域选牌、技能选目标和文字选项继续使用 `ChoiceRequest/ChoiceResponse` 的稳定 ID、事件 ID、玩家 ID、数量范围与候选校验。LAN 房主在界面请求真正发布时才把完整候选定向发送给对应远端玩家；响应提示延迟仍遵循游戏速度设置。

非响应者的 `GameState.to_dict()` 会清空卡牌、目标、按钮、控制项、已选结果和活动上下文。五谷丰登的 `public_card_choice_display` 与无懈可击的 `simultaneous_response_display` 仍属于全体观察者可见公共快照，但不包含其他玩家私有候选、是否持有响应牌或候选数量。

卡牌移牌表现按观察者裁剪：摸牌和无关玩家之间的私有手牌转移只发送实体 UID 与牌背语义；牌进入弃牌堆、来自公共区域，或观察者是转移当事人时才发送完整牌面。使用、展示和判定牌属于公开表现，但发送前移除 `known_to` 与 `private_owner_id` 等内部知识元数据。

## 掉线与会话结束

- 客户端在对局中掉线：房主保留该稳定玩家状态，立即注册基础 AI 托管，并从当前选将、普通选择、同时无懈或出牌阶段继续流程。
- 客户端在大厅离开：房主移除成员并广播最新成员表。
- 房主断开或关闭房间：所有客户端返回主菜单；当前版本不进行主机迁移。
- 对局开始后拒绝新连接；当前版本没有中途加入与断线重连。
- 同一局域网房间内重新开始时保持真人玩家映射和游戏总人数，不允许在重开时改变总人数。

## 组件边界

- `NetworkGateway`：ENet 生命周期、公共大厅、peer 与玩家映射、序号去重、actor 防伪和定向传输。
- `MatchController`：权威状态、动作校验、每观察者快照、选择请求、掉线 AI 托管和表现事件裁剪。
- `LanLobbyPanel`：连接表单与公共成员列表，只发出建房、加入、开始和离开意图。
- `MatchTable`：协调主菜单、大厅、网关和控制器，不直接修改 `GameState`。

## 自动验证

- `res://tests/lan_network_test.tscn`：启动两个 Godot 进程，验证真实 ENet 大厅、随机玩家绑定、定向私有快照、重复/伪造 actor 拒绝与合法命令上行。
- `res://tests/lan_match_flow_test.tscn`：房主运行完整权威控制器，客户端完成私有选将、接收起始手牌，并验证他人手牌与随机种子未泄漏。
- `res://tests/lan_lobby_ui_test.tscn`：验证主菜单联机入口、大厅模态焦点、单人房主状态、客户端成员快照绑定、地址/端口提示与安全离开。
