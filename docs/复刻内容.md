## 二、三张示例卡牌的对应逻辑

### 【杀】

无名杀逻辑：出牌阶段基础限用1次，选择攻击范围内1名其他角色；目标进入【闪】响应，未响应时受到1点伤害。

项目实现：

- `sha.gd` 配置 `play_limit=1`、`min_targets=1`、`max_targets=1`、`distance_limit=attack_range`。
- 使用牌先完成 `chooseToUse` 的选牌与选目标，再进入真实 `CardUseEvent`。
- 单个目标由 `SlashCardEffect` 创建【闪】响应请求；响应未成功时造成基础1点伤害。
- 火【杀】和雷【杀】复用同一牌族组件，只改变伤害属性。

### 【桃】

无名杀逻辑：正常出牌只能对受伤的自己使用并回复1点体力；濒死救援时可由其他角色对濒死角色使用。

项目实现：

- `tao.gd` 使用 `target_mode=self_wounded`，正常出牌只允许选择受伤的自己。
- 正常牌效固定回复1点体力。
- 濒死请求通过 `get_dying_response_pattern()` 单独开放【桃】，不篡改正常出牌目标规则。
- 每张救援【桃】仍固定回复1点体力，直到目标达到1点体力或救援流程结束。

### 【过河拆桥】

无名杀逻辑：先选择1名其他角色，再从其手牌区、装备区或判定区选择并弃置1张可弃置牌；其他角色的手牌默认只显示牌背。

项目实现：

- `guohechaiqiao.gd` 使用 `target_mode=single_other_with_cards`，目标必须是区域内有牌的其他存活角色。
- 目标进入自己的逐目标 `content` 后，控制器创建1选1的区域选牌请求。
- 候选顺序固定为手牌区、装备区、判定区；不可见手牌只传输 UID、区域和牌背语义。
- 选择确认后按实体 UID 再次定位真实区域并弃置，不使用数组下标。

## 三、本轮实际重构内容

### 1. 统一牌与目标组合选择

`ChoiceRequest` 新增 `card_target` 类型，并增加四个独立数量字段：

- `min_card_count` / `max_card_count`
- `min_target_count` / `max_target_count`

权威端会分别校验卡牌和目标数量、候选归属、重复项，以及可选的 `target_ids_by_card_id` 牌目标组合映射。合法牌和合法目标单独存在，不代表二者组合必然合法。

### 2. 主动技能选择接口

`SkillDefinition` 新增三种可复用接口：

- `request_card_selection()`：只选牌。
- `request_target_selection()`：只选目标。
- `request_card_target_selection()`：同时选牌与目标。

接口会自动写入 `skill_id` 与 `skill_owner_id`。技能只读取牌时可继续覆盖 `continue_choice()`；需要目标时覆盖 `continue_selection(context, response)`，从 `response.card_ids` 和 `response.target_ids` 取得结果。

### 3. `chooseToUse` 与技能衔接

可发动主动技能现在会进入当前 `chooseToUse` 请求的 `button_ids`。玩家提交 `use_skill` 后，控制器先完成当前出牌选择，再执行技能 `activate()`；技能随后创建的选牌或选目标请求会进入同一事件链，不会遗留一个仍在等待的旧出牌请求。

### 4. UI、AI 与网络统一

- 本地只选目标时直接复用武将牌合法目标与已选目标描边。
- 本地牌目标组合选择同时复用手牌临时选择、武将目标选择和中央确认/取消按钮。
- 选择某张牌后，若存在牌目标映射，合法目标会立即刷新；已不合法的旧目标会被清除。
- 基础 AI 从权威端生成的目标或牌目标组合动作中选择，不直接修改状态。
- 网络 `ChoiceResponse` 不再丢弃本轮已接入选择使用的 `target_ids`；`button_ids` 与 `control_id` 继续保留在通用结构中供后续按钮和控制项界面接入。

## 四、兼容性与数值影响

本轮没有修改现有卡牌和技能数值：

- 【杀】基础次数仍为每出牌阶段1次、基础目标1名、基础伤害1点、基础需要1张【闪】。
- 【桃】每张仍回复1点体力，正常出牌仍只能对受伤的自己使用。
- 【过河拆桥】仍选择1名其他角色并弃置其区域内1张牌。
- 没有新增伤害、回复、摸牌、冷却、触发概率、资源消耗或持续时间。

旧的普通选牌、响应、弃牌、无懈可击、五谷丰登、装备材料和濒死救援继续使用兼容字段，不需要修改现有卡牌脚本。

## 五、验证结果

已通过以下无头验证：

- `tests/event_runtime_test.tscn`：事件父子阻塞、暂停、组合选择映射、backup/restore 和序列化恢复。
- `tests/skill_choice_test.tscn`：技能只选目标与1张牌+1名目标的组合选择。
- `tests/skill_target_ui_test.tscn`：技能纯目标与牌目标组合的本地高亮、临时选择和确认按钮状态。
- `tests/inline_hand_choice_test.tscn`：原有响应、弃牌、装备费用、公共选牌与内联确认流程兼容。
- `tests/smoke_test.tscn`：现有身份局烟雾流程。
- `tests/gameplay_regression_test.tscn`：无懈、群体锦囊、濒死、桃园、朱雀、银月、丈八和判定回归。
- `tests/response_choice_test.tscn`：响应选择与出牌阶段恢复。
- `tests/rule_timing_test.tscn`：规则时机、主动入口和使用牌目标生命周期。

当前工程仍属于“事件化迁移中、规则部分等价”。本轮没有宣称已经完整复刻无名杀的全部技能 backup 界面、同优先级技能选择、实际联网房间、重连超时托管或独立回放执行器。
