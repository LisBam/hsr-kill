# 内容制作指南

本文档是项目卡牌、技能与武将内容制作的标准入口。所有内容均使用独立 GDScript 文件保存，`GameDatabase` 会自动扫描目录并建立索引，不需要修改集中注册表。

## 通用制作规范

| 内容 | 存放目录 | 基类 |
|---|---|---|
| 卡牌 | `game_data/cards` | `CardDefinition` |
| 技能 | `game_data/skills` | `SkillDefinition` |
| 武将 | `game_data/characters` | `CharacterDefinition` |
| 势力 | `game_data/factions.json` | JSON 展示数据 |
| 实体牌堆 | `data/decks.json` | JSON 实体牌数据 |

三个源码定义基类分别位于 `game_data/card_definition.gd`、`game_data/skill_definition.gd` 和 `game_data/character_definition.gd`。具体内容文件只继承对应 `class_name`，不得复制基类或引用同目录下另一具体内容文件形成强耦合。

所有卡牌、技能和武将文件必须遵守以下约定：

1. 文件名使用小写拼音，可加入数字和下划线；允许字符为 `a` 至 `z`、`0` 至 `9` 和 `_`，不允许空格、横线、中文或大写字母。例如【顺手牵羊】可使用 `shunshouqianyang.gd`，火【杀】也可使用 `sha_fire_2.gd`。
2. 文件内部的稳定 `id` 必须非空且全项目唯一。推荐只使用小写英文字母、数字和下划线，例如 `sha_fire`、`march_7th`。
3. 文件名用于开发者定位源码，稳定 `id` 用于规则、牌堆、网络、回放与存档。重命名文件时不得随意修改已经投入使用的稳定 ID。
4. 所有变量必须拥有独占注释，说明用途、取值范围、默认值原因与修改影响。
5. 卡牌效果必须直接写在对应卡牌文件中；`CardEffectResolver` 只负责按父牌 UID 调度同步入口和异步恢复，不提供任何具体牌效函数。内容代码只能通过 `resolver.host`、事件总线和统一选择请求修改规则状态，不得读取或修改 UI 节点。
6. 新增或调整玩法后必须同步《卡牌系统》和《游戏机制与玩法内容》，记录伤害、回复、摸牌、次数、距离、概率、资源消耗、冷却和持续时间等全部具体数值。

目录扫描会检查继承类型、空 ID、重复 ID、武将技能引用、势力引用和牌堆卡牌引用。任一错误都会写入 `GameDatabase.validation_errors` 并阻止开局。

### GameDatabase 完整源码索引

`GameDatabase` 是自动加载的静态内容仓库。查询函数返回深拷贝或静态定义；持续装备和运行时技能必须使用创建函数获得独立实例，禁止把数据库定义对象当作对局状态容器。

| 常量 | 值 | 用途 |
|---|---|---|
| `CARDS_DIRECTORY` | `res://game_data/cards` | 卡牌源码扫描目录。 |
| `CHARACTERS_DIRECTORY` | `res://game_data/characters` | 武将源码扫描目录。 |
| `SKILLS_DIRECTORY` | `res://game_data/skills` | 技能源码扫描目录。 |
| `DECKS_PATH` | `res://data/decks.json` | 牌堆配置路径。 |
| `FACTIONS_PATH` | `res://game_data/factions.json` | 势力展示配置路径。 |

| 变量 | 类型 | 索引内容与修改权限 |
|---|---|---|
| `cards` | `Dictionary` | 卡牌 ID 到静态元数据；内容代码使用 `get_card()`，不得直接修改。 |
| `card_definitions` | `Dictionary` | 卡牌 ID 到数据库静态 `CardDefinition`。 |
| `card_scripts` | `Dictionary` | 卡牌 ID 到脚本资源，用于创建持续运行时实例。 |
| `decks` | `Dictionary` | 牌堆 ID 到配置。 |
| `characters` / `character_definitions` | `Dictionary` | 武将 ID 到元数据和静态源码定义。 |
| `factions` | `Dictionary` | 势力 ID 到展示元数据。 |
| `skills` / `skill_scripts` | `Dictionary` | 技能 ID 到元数据和脚本资源。 |
| `validation_errors` | `Array[String]` | 最近一次载入错误；非空时 `start_match()` 拒绝开局。 |

| 函数 | 可见性 | 返回值与行为 |
|---|---|---|
| `_ready()` | 生命周期函数 | `void`；节点进入场景树时调用 `reload_all()`。 |
| `reload_all()` | 公共函数 | `bool`；清空全部索引，按技能、卡牌、武将、牌堆、势力顺序重载并校验。开发工具可调用，运行中内容效果不得调用。 |
| `get_card(card_id)` | 公共查询 | `Dictionary` 深拷贝；未知 ID 返回空字典。 |
| `get_card_definition(card_id)` | 公共查询 | 数据库静态 `CardDefinition` 或 `null`；只用于调用无状态钩子，不能绑定运行时。 |
| `create_card_runtime(card_id)` | 公共工厂 | 新 `CardDefinition` 或 `null`；尚未绑定 host、玩家和实体 UID。 |
| `get_character(character_id)` | 公共查询 | 武将元数据深拷贝，未知 ID 为空字典。 |
| `resolve_character_name(character_id)` | 公共查询 | 优先返回非空 `display_name`；空 ID 返回“未选武将”，未知非空 ID 返回“未知武将”。 |
| `get_faction(faction_id)` | 公共查询 | 势力元数据深拷贝。 |
| `get_skill(skill_id)` | 公共查询 | 技能元数据深拷贝。 |
| `create_skill(skill_id)` | 公共工厂 | 新 `SkillDefinition` 或 `null`；尚未 `bind()`、`install()`。 |
| `get_deck_cards(deck_id)` | 公共查询 | `[花色, 点数, 卡牌ID]` 条目数组深拷贝。 |
| `_load_cards()` | 私有载入 | 按文件名排序载入；检查脚本可载入、继承 `CardDefinition`、ID非空且不重复，并建立三类卡牌索引。 |
| `_load_skills()` | 私有载入 | 先于武将载入；检查继承、空 ID 和重复 ID并建立元数据、脚本索引。 |
| `_load_characters()` | 私有载入 | 检查继承、空 ID、重复 ID，并要求技能脚本直接位于技能目录。 |
| `_load_decks()` / `_load_factions()` | 私有载入 | 从 JSON 建立牌堆与势力索引；势力同时检查空 ID 和重复 ID。 |
| `_list_gd_scripts(directory_path)` | 私有查询 | 返回按文件名排序的 `.gd` 路径；目录缺失或文件名非法会记录错误，非法命名文件仍继续载入以一次报告更多问题。 |
| `_is_lowercase_pinyin_filename(base_name)` | 私有查询 | 只接受 ASCII 小写字母、数字和下划线；空名称返回 `false`。 |
| `_load_json_object(path)` | 私有查询 | 读取 JSON 对象；文件缺失、无法读取、语法错误或根节点非对象时记录错误并返回空字典。 |
| `_validate_decks()` | 私有校验 | 每个条目必须正好3项，且卡牌 ID 已登记。当前函数不额外验证花色或点数范围，内容作者仍必须遵守牌堆表约定。 |
| `_validate_factions()` | 私有校验 | 要求非空 `display_name`、`short_name` 和不带 `#` 的六位十六进制 `color`。 |
| `_validate_characters()` | 私有校验 | 同时校验卡牌七个必填文本字段，以及武将显示名、势力和技能 ID 引用。 |

数据库源码当前真正强制的卡牌必填字段为 `original_name`、`custom_name`、`type`、`subtype`、`effect_id`、`target_mode`、`description`。本指南参数表中标记为必填的其他字段属于规则完整性制作规范；遗漏时部分核心会使用默认值，但不应依赖这种容错创建正式内容。

## 卡牌制作

### 卡牌文件的工作流程

一张实体牌的完整使用流程为：

```text
data/decks.json 创建实体牌
  ↓
CardRuleService 校验阶段、目标、距离与次数
  ↓
实体牌从 hand / wooden_ox 进入 processing
  ↓
卡牌文件的 resolve() 或 resolve_target()
  ↓
响应、选牌、伤害、回复、装备或判定
  ↓
continue_choice() / continue_response() / continue_negation() 恢复异步步骤
  ↓
实体牌进入 discard_pile / equipment / judgment
```

新增普通卡牌只需要创建一个卡牌文件，并在需要生成实体牌时修改 `data/decks.json`。新增文件不需要修改 `GameDatabase`、效果 ID 白名单或卡牌注册数组。

### MatchController 私有使用牌事件流程

下表是控制器内部的完整牌效调度骨架。具体卡牌不得调用这些函数，但覆盖钩子和返回区域必须符合这一顺序。

| 私有函数 | 行为与制作影响 |
|---|---|
| `_uses_active_target_resolution(definition, target_ids)` | `resolution_mode=per_target` 且存在目标时使用活动逐目标上下文；整牌模式或无目标走一次内容。 |
| `_begin_active_card_resolution(card, actor_id, target_ids, card_use_event_id=-1)` | 创建共享结算上下文，调用 `configure_resolution_context()` 和 `on_resolution_started()`；准备钩子等待时暂停首目标。 |
| `_continue_active_card_resolution(parent_card_uid)` | 从共享 `target_index` 继续逐目标结算；死亡、排除目标或结算停止时跳过或暂停。 |
| `_complete_active_card_target(parent_card_uid)` | 标记当前目标完成、递增游标并继续下一目标；全部完成后收尾父牌。 |
| `_resume_active_card_target(parent_card_uid)` | 无懈恢复后重新执行当前目标内容，不递增目标索引。 |
| `_execute_card_use(actor_id, card, target_ids, material_card_uids=[], virtual_proxy=false)` | 建立 `VirtualCard`、材料 UID和完整 `CardUseEvent`；真实牌默认把自身 UID 加入材料。 |
| `_card_use_step_declare(event, scheduler)` | 重新校验使用者、实体、定义和目标，登记使用历史、声明钩子和 `card_used` 事件。 |
| `_execute_use_card_lose_event(event, scheduler)` | 创建使用牌失去事件，把真实材料从手牌或木牛牌源移动到处理区；虚拟材料按传入 UID处理。 |
| `_card_use_step_enqueue_use_timings(event, scheduler)` | 入队 `USE_TIMING_NAMES` 五个整牌触发时机。 |
| `_card_use_step_enqueue_target_timings(event, scheduler)` | 按四种目标时机分组遍历当前动态目标数组。 |
| `_card_use_step_enqueue_content_before(event, scheduler)` | 创建唯一 `contentBefore` 子事件。 |
| `_execute_card_use_timing_event(event, scheduler)` | 构造 `RuleEvent`，依次派发普通和有序触发器，并把目标、排除、直击、`custom_args` 写回使用牌上下文。 |
| `_execute_card_content_before_event(event, scheduler)` | 只把最终目标、排除目标、直击目标和 `custom_args` 深复制到 `contentBefore` 结果；活动上下文和准备钩子在后续内容步骤建立。 |
| `_card_use_step_resolve_content(event, scheduler)` | 按 `resolution_mode` 入队整牌内容或每个目标的 `content` 子事件。 |
| `_execute_card_content_event(event, scheduler)` | 调用卡牌 `resolve()` 或 `resolve_target()`；处理 `pending`、最终区域和目标完成状态。 |
| `_card_use_step_enqueue_content_after(event, scheduler)` | 内容全部完成后创建唯一 `contentAfter` 子事件。 |
| `_execute_card_content_after_event(event, scheduler)` | 把上下文中的最终区域和卡牌 UID写入该 `contentAfter` 子事件结果；区域已经在前一内容步骤写入共享上下文。 |
| `_card_use_step_prepare_after(event, scheduler)` | 创建 `orderingDiscard` 后置事件，确保收尾移动晚于全部内容和响应。 |
| `_execute_ordering_discard_event(event, scheduler)` | 对仍需弃置的处理区材料创建 `cardsDiscard` 子事件。 |
| `_execute_cards_discard_event(event, scheduler)` | 把指定仍在处理区的实体逐张移动至弃牌堆。 |
| `_complete_card_use_context(card_uid, destination)` | 事件树路径只写入 `destination/content_complete` 并保留上下文给父事件收尾；兼容路径记录 `contentAfter` 后移除使用牌上下文。 |
| `_finalize_processing_card(card_uid)` | 把当前兼容牌效按 `discard` 收尾；事件树路径只标记完成，由后置事件移动，兼容路径清理活动上下文并移动仍在处理区的实体。 |
| `_execute_recast(actor_id, card_uid)` | 仅允许普通手牌且定义 `recast=true`；弃置该牌并摸1张，不允许木牛“粮”重铸。 |
| `_append_if_legal(result, player_id, card, requested_targets)` | 规范化目标并调用 `validate_use()`，合法时追加标准 AI 动作。 |

卡牌内容返回 `pending` 只表示当前调用存在等待请求，不是新的最终区域。异步恢复完成后必须通过对应恢复钩子和 `complete_card_target()` / `finish_processing_card()` 结束内容；事件树路径最终仍由 `orderingDiscard` 决定材料移动。

### 卡牌完整模板

下面的示例牌只能对自己使用，效果为摸1张牌：

```gdscript
extends CardDefinition

## 【示例牌】卡牌源码。静态信息、目标规则与效果入口均在本文件维护。


## 写入卡牌完整静态信息；所有字段会由 GameDatabase 自动建立只读索引。
func _init() -> void:
	super({
		"id": "shilipa",
		"original_name": "示例牌",
		"custom_name": "示例牌",
		"type": "trick",
		"subtype": "normal",
		"effect_id": "example_draw_one",
		"nature": "normal",
		"target_mode": "self",
		"min_targets": 1,
		"max_targets": 1,
		"distance_limit": "none",
		"play_limit": 0,
		"response_pattern": "wuxie",
		"recast": false,
		"delayed": false,
		"description": "出牌阶段对自己使用，摸1张牌。",
		"resolution_mode": "per_target",
		"final_zone": "discard",
		"provided_response_pattern": "",
	})


## 目标未被【无懈可击】抵消时摸1张牌；选择等待期间返回 pending 保持当前内容事件暂停。
func resolve(resolver: Object, card: CardInstance, actor_id: int, target_ids: Array[int]) -> String:
	for target_id: int in target_ids:
		if resolver.should_skip_trick_target(card, actor_id, target_id):
			continue
		resolver.host.draw(target_id, 1)
	return resolver.default_destination()
```

### 卡牌静态参数总表

| 参数 | 必填 | 类型 | 可填范围 | 作用与注意事项 |
|---|---:|---|---|---|
| `id` | 是 | `String` | 任意非空唯一字符串；推荐 `[a-z0-9_]+` | 永久逻辑 ID。牌堆、网络、回放、AI 和存档都使用它。 |
| `original_name` | 是 | `String` | 任意非空文本 | 原版名称；原版名称模式下显示。 |
| `custom_name` | 是 | `String` | 任意非空文本 | 《崩铁杀》名称；自定义名称模式下显示。 |
| `type` | 是 | `String` | `basic`、`trick`、`equipment` | 卡牌主类别，影响牌面类别文本与颜色。其他字符串没有完整 UI 与规则保证。 |
| `subtype` | 是 | `String` | 见“卡牌子类型”表 | 进一步描述攻击、回复、锦囊或装备槽类别。 |
| `effect_id` | 是 | `String` | 任意非空稳定字符串；可复用当前牌族标签 | 只用于规则语义、事件和扩展查询，不会按值自动执行具体牌效。自定义效果必须在本文件实现。 |
| `nature` | 条件 | `String` | `normal`、`fire`、`thunder` | 伤害属性。非伤害牌通常填写 `normal`。其他字符串只会作为自定义属性文本传递，不具备完整连环和装备规则。 |
| `target_mode` | 是 | `String` | 见“目标模式”表 | 决定哪些玩家可以成为候选目标。 |
| `min_targets` | 是 | `int` | `0` 以上，且不得大于 `max_targets` | 手动目标的最少数量。响应牌通常为0，普通单目标牌为1。 |
| `max_targets` | 是 | `int` | `min_targets` 以上；当前全体牌使用99 | 基础最大目标数。实际人数最多10，最终目标仍受存活人数和规则修正限制。 |
| `distance_limit` | 是 | `String` | `none`、`one`、`attack_range`、`special` | 目标距离约束。`special` 表示由专用逻辑处理，通用规则不会自动校验。 |
| `play_limit` | 是 | `int` | `0` 以上 | 出牌阶段基础使用次数；`0` 表示无限制。限制由通用历史统计执行，不再按具体牌名判断。 |
| `play_limit_group` | 否 | `String` | 空字符串或稳定 `[a-z0-9_]+` 分组 | 多个卡牌定义共享次数时填写同一值，例如三种【杀】均填写 `slash`。缺省时只统计自身 `id`。 |
| `play_limit_message` | 否 | `String` | 任意非空玩家可见文本 | 达到 `play_limit` 后的拒绝原因；缺省为“本阶段使用次数已用尽。”。 |
| `response_pattern` | 是 | `String` | `""`、`sha`、`shan`、`tao`、`jiu`、`wuxie` | 该牌效关联的响应语义。普通可被无懈的锦囊填写 `wuxie`。 |
| `recast` | 是 | `bool` | `true`、`false` | 是否允许从普通手牌重铸。`true` 时无目标确认可提交重铸；木牛“粮”不能重铸。 |
| `delayed` | 是 | `bool` | `true`、`false` | 是否为延时锦囊。`true` 会启用同名判定区限制，并要求实现判定阶段效果。 |
| `description` | 是 | `String` | 任意非空文本 | 玩家可见规则说明，必须写明目标、数值、次数、费用和条件。 |
| `resolution_mode` | 是 | `String` | `per_target`、`whole` | `per_target` 为每名目标创建独立内容事件；`whole` 一次取得完整目标数组。 |
| `final_zone` | 是 | `String` | `discard`、`equipment`、`judgment` | 正常使用后的目标区域语义，也用于中央牌面判断是否接管弃牌动画。 |
| `provided_response_pattern` | 是 | `String` | `""`、`sha`、`shan`、`tao`、`jiu`、`wuxie` | 该实体牌自身能作为哪种响应打出。普通锦囊通常为空。 |
| `art_path` | 否 | `String` | 空字符串或有效 `res://` 图片路径 | 推荐 `res://assets/art/cards/<卡牌ID>.webp`。无效路径显示占位图，不影响规则。 |
| `slot` | 装备牌 | `String` | `weapon`、`armor`、`offensive_mount`、`defensive_mount`、`treasure` | 装备进入的唯一槽位。非装备牌不填写。 |
| `attack_range` | 武器 | `int` | `1` 以上；当前标准武器为1至5 | 武器攻击范围。小于1会被规则层修正为1。 |
| `distance_modifier` | 坐骑 | `int` | 进攻坐骑填写 `-1`，防御坐骑填写 `1` | 当前距离规则按装备槽固定应用1点修正；字段必须与槽位规则保持一致。 |
| `ai_use_value` | 否 | `float` | 任意有限浮点数；缺省 `3.0` | 基础 AI 使用该牌的静态价值；大于0更愿意使用，小于等于0通常结束出牌。 |
| `ai_target_attitude` | 否 | `String` | `neutral`、`hostile`、`friendly`、`self_boost` | AI 的目标收益方向；依次表示不修正、偏向敌方、偏向友方、优先自己。 |
| `ai_beneficial` | 否 | `bool` | `true`、`false`；缺省 `false` | 无懈可击 AI 判断该锦囊通常对目标有利还是有害。 |
| `response_material_count` | 响应装备 | `int` | `0` 以上 | 选择装备作为响应入口后，还需要选择的普通手牌材料数。 |
| `play_phase_interaction` | 主动装备 | `String` | 空字符串、`virtual_card_materials`、`store_attachment` 或扩展稳定标签 | UI 使用的通用交互类别；空字符串表示没有出牌阶段主动入口。 |
| `play_phase_action_type` | 主动装备 | `String` | 任意非空唯一动作名，推荐 `[a-z0-9_]+` | `PlayerAction.action_type`；必须同时由装备文件的动作钩子声明和处理。 |
| `play_phase_material_count` | 主动装备 | `int` | `0` 以上 | 出牌阶段主动效果需要选择的普通手牌材料数。 |
| `play_phase_action_card_source` | 主动装备 | `String` | `equipment`、`material` | 动作中的 `card_uid` 取装备实体还是第一张材料实体。 |
| `shows_attachment_count` | 附属牌装备 | `bool` | `true`、`false` | 是否在装备区域显示当前附属牌数量。 |

当前桌面 UI 对装备元数据的实际处理：

- `play_phase_interaction` 只要非空就会进入装备交互状态；界面不会按具体字符串分派牌效，因此扩展稳定标签可以复用同一材料/目标流程。
- 普通主动装备严格要求已选材料数量等于 `play_phase_material_count`；装备响应严格等于 `response_material_count`。
- 材料选择只提交普通手牌 UID。响应动作选择装备 UID并把材料写入 `payload.material_card_uids`。
- 出牌阶段动作名取 `play_phase_action_type`；为空时界面拒绝提交。
- `play_phase_action_card_source=material` 时动作 `card_uid` 使用第一张材料，否则缺省使用装备实体 UID。
- 无论界面预览为何，核心仍会调用装备源码的权威校验；UI字段不能代替 `validate_play_phase_action()` 或响应材料校验。

### 目标模式

| `target_mode` | 合法目标 | 常用目标数 |
|---|---|---|
| `response_only` | 不能在普通出牌阶段使用，只能进入响应候选 | `0..0` |
| `self` | 只能选择使用者自己 | `1..1` |
| `self_wounded` | 只能选择已受伤的使用者自己 | `1..1` |
| `single_other` | 一名其他存活角色 | `1..1` |
| `single_other_with_cards` | 一名区域内至少有1张手牌、装备牌或判定牌的其他角色 | `1..1` |
| `single_with_hand` | 一名至少有1张普通手牌的角色，可以包含自己 | `1..1` |
| `weapon_holder` | 装备武器的其他角色；当前配合【借刀杀人】双目标语义 | `2..2` |
| `one_or_two` | 任意一至两名存活角色 | `1..2` |
| `all_others` | 所有其他存活角色，按使用者下家开始的行动顺序自动展开 | `1..99` |
| `all_players` | 所有存活角色，先处理使用者本人，再按行动顺序展开 | `1..99` |

规则层还识别 `wounded`，表示任意已受伤目标，但当前内置卡牌没有使用该模式。填写自定义目标模式字符串时，通用规则只会执行存活、目标数和距离检查，复杂条件必须在卡牌代码或扩展规则查询中实现。

### 距离限制

| `distance_limit` | 规则 |
|---|---|
| `none` | 不检查距离。 |
| `one` | 使用者与目标最终距离必须不大于1。 |
| `attack_range` | 目标必须位于使用者当前攻击范围内。 |
| `special` | 通用规则不处理，由卡牌专用逻辑负责，例如【借刀杀人】。 |

### `effect_id` 与效果代码

`effect_id` 只是稳定规则语义标签，用于事件记录和扩展查询，不会自动执行任何效果，也不存在集中牌效白名单。次数由 `play_limit/play_limit_group` 决定，响应能力由 `provided_response_pattern` 决定，目标组合由元数据和卡牌钩子决定。新增卡牌必须在自身文件覆盖 `resolve()`；逐目标共享状态使用 `resolve_target()`；选牌、响应或专用无懈链分别使用 `continue_choice()`、`continue_response()` 和 `continue_negation()` 恢复。

普通【杀】、火【杀】和雷【杀】属于同一规则牌族，为避免复制数百行武器与响应流程，三个卡牌文件显式调用 `SlashCardEffect` 共享组件。该组件只服务【杀】牌族，不按 `effect_id` 分发其他牌；【决斗】、【借刀杀人】、【火攻】、【五谷丰登】、【水淹七军】和群体锦囊的完整控制流程均位于各自卡牌文件。

### CardDefinition 运行时变量

| 变量 | 类型 | 取值范围 | 说明 |
|---|---|---|---|
| `_metadata` | `Dictionary` | 构造时写入，之后只读 | 当前卡牌全部静态信息。具体卡牌不应在运行时修改它。 |
| `runtime_host` | `Object` | 静态定义为 `null`；持续实例为当前 `MatchController` | 仅装备等持续区域实例使用。 |
| `runtime_owner_player_id` | `int` | 未绑定为 `-1`；正式玩家为 `0..9` | 持续效果所属玩家的稳定 ID。 |
| `runtime_card_uid` | `int` | 未绑定为 `-1`；正式实体牌为 `1` 以上 | 持续效果对应的实体牌 UID。 |

自定义卡牌可以增加自己的运行时变量，但每个变量必须独立注释。一次性普通牌不要把对局状态保存在数据库静态定义中；需要跨响应保存的数据应写入 `resolution_context` 或选择请求 `context`。

### CardInstance 完整成员索引

`CardInstance` 表示一张实际存在于牌堆或区域中的牌，和只读的 `CardDefinition` 配置对象不同。内容代码可以读取实体字段和调用查询函数，但移动、公开、弃置和改变归属必须通过 `MatchController` 的公开端口完成。

| 成员或函数 | 类型或返回值 | 范围与行为 |
|---|---|---|
| `_next_uid` | 静态私有 `int` | 从1开始递增，为本地新实体分配唯一 UID；内容代码不得读取、修改或复用。 |
| `uid` | `int` | 构造后为1以上的唯一实体 ID；网络、回放和选择必须使用它而非数组下标。 |
| `definition_id` | `String` | 对应 `CardDefinition.id`；用于查询牌效和显示配置。 |
| `suit` | `String` | `spade`、`heart`、`club`、`diamond`；无花色虚拟实体使用 `none`。 |
| `rank` | `int` | 实体牌为1至13；无点数虚拟实体为0。 |
| `zone` | `String` | 默认 `draw_pile`；由统一移牌服务维护当前区域。 |
| `owner_id` | `int` | 玩家区域为所属玩家 ID；公共区域为 `-1`。 |
| `known_to` | `Array[int]` | 已知完整牌面的玩家 ID 集合，由移牌和公开规则维护。 |
| `shown` | `bool` | 是否曾公开展示；公开后不会因再次移动自动变回未知。 |
| `private_owner_id` | `int` | 仅某名玩家私密可见时保存其 ID；公共牌为 `-1`。 |
| `_init(card_definition_id="", card_suit="spade", card_rank=1)` | `void` | 分配新 UID 并保存定义、花色和点数。内容制作通常不直接构造实体，虚拟牌应使用控制器入口。 |
| `get_color()` | `String` | 红桃、方块返回 `red`；黑桃、梅花返回 `black`；其他花色返回 `none`。 |
| `to_dict()` | `Dictionary` | 返回包含上述公开字段和计算后 `color` 的网络安全字典。 |

#### 卡牌名称与表现事件

`GameSettings.resolve_card_name(card_definition)`（函数名 `resolve_card_name()`）是卡牌玩家可见名称的唯一解析入口：`ORIGINAL` 模式优先 `original_name`，缺失时回退 `id` 或“未知牌”；`CUSTOM` 模式优先 `custom_name`，再回退 `original_name` 或“未知牌”。内容日志若需要显示完整实体牌，应优先调用 `host.describe_card(card)`，不要自行拼接名称模式。

全局名称模式变量为 `card_name_mode`，枚举 `NameMode` 包含 `CUSTOM` 与 `ORIGINAL`；`set_card_name_mode(mode)` 设置并在变化时发出 `card_name_mode_changed(mode)`，`toggle_card_name_mode()` 在两种模式间切换。AI等待配置 `ai_response_delay_seconds` 默认0.30秒，由 `set_ai_response_delay_seconds()` 按 `MIN_AI_RESPONSE_DELAY_SECONDS`（0.05秒）、`MAX_AI_RESPONSE_DELAY_SECONDS`（1.0秒）、`AI_RESPONSE_DELAY_STEP_SECONDS`（0.05秒）限制并发出 `ai_response_delay_changed(delay_seconds)`。这些配置只影响显示与等待，不改变卡牌或技能规则。

`CardPresentationEvent` 只描述表现，不执行牌效或移牌：

| 成员或函数 | 类型或返回值 | 语义 |
|---|---|---|
| `presentation_id` / `event_id` | `int` | 每局表现序号与关联规则事件 ID；无关联为 `-1`。 |
| `event_name` | `String` | 当前稳定值包括 `useCard`、`showCards`、`judge`。 |
| `card_data` | `Dictionary` | 实体牌只读快照。 |
| `actor_id` / `target_ids` | 玩家 ID或数组 | 表现来源和相关目标。 |
| `source_zone` | `String` | 创建时从 `card_data.zone` 读取的来源区域。 |
| `owns_discard_transfer` | `bool` | 是否由本次表现接管随后弃牌动画；纯展示必须为 `false`。 |
| `_init(presentation_sequence=-1, related_event_id=-1, related_event_name="", serialized_card={}, source_actor_id=-1, related_target_ids=[], discard_transfer_owned=false)` | `void` | 深复制牌快照和目标，并记录来源区域。 |
| `to_dict()` | `Dictionary` | 返回全部表现字段深拷贝。 |

卡牌和技能不得创建表现事件来代替规则操作。控制器在真实使用、展示和判定时自动生成；UI 动画是否播放不影响权威结算。

### 实体牌移动规则与记录

`CardMovementService` 是项目唯一底层移牌入口。卡牌和技能不能直接调用它或修改区域数组，而应使用 `MatchController` 的语义端口；下表用于明确区域、知识状态和移动失败语义。

标准区域只有：`draw_pile`、`hand`、`equipment`、`judgment`、`processing`、`wooden_ox`、`discard_pile`、`void`。其中 `void` 只作为移出对局的回放区域，不加入任何当前状态数组。

| CardMovementService 成员或函数 | 可见性 | 行为 |
|---|---|---|
| `card_moved(move_data, card_data)` | 信号 | 权威移动完成后发出只读字典；订阅者不得反向修改状态。 |
| `state` | 公共变量 | 当前对局状态引用。 |
| `_next_move_id` | 私有变量 | 从1递增的移牌事件 ID。 |
| `_init(game_state)` | 生命周期函数 | 绑定当前状态。 |
| `move_card(card, to_zone, target_player_id=-1, reason="move", event_id=-1, target_slot="", visible_to=[])` | 公共底层函数 | 返回 `CardMoveEvent` 或 `null`。牌不存在、目标区域非法、玩家区域缺少有效目标玩家或找不到实际来源时失败。移动成功后更新区域、归属、知识、历史并发信号。仅控制器调用。 |
| `move_cards(cards, ...)` | 公共底层函数 | 按输入顺序逐张调用 `move_card()`；第一张失败时停止，返回此前已完成记录，不自动回滚。 |
| `reveal_card(card, viewer_ids=[])` | 公共底层函数 | 空观察者数组表示向全部当前存活玩家公开；否则只追加指定知情者。成功时设置 `shown=true`、`private_owner_id=-1`。 |
| `_find_actual_zone(card)` | 私有函数 | 优先扫描权威区域数组；都找不到时才接受合法的 `card.zone`。 |
| `_remove_from_zone(card, zone, owner_id)` | 私有函数 | 从对应数组或装备槽移除；未知玩家区域不会误删其他牌。 |
| `_add_to_zone(card, zone, owner_id, target_slot)` | 私有函数 | 添加到目标数组；装备未给槽位时底层回退 `treasure`，但正式内容必须显式使用定义槽位。 |
| `_update_knowledge(card, zone, target_player_id, visible_to)` | 私有函数 | 公共弃牌、处理、判定和装备区域会全场公开；手牌和木牛区域把持有者设为私密所有者并加入知情者。 |
| `_is_valid_zone(zone)` | 私有函数 | 只接受上列八种稳定区域名。 |

`CardMoveEvent` 的完整数据结构：

| 成员或函数 | 类型或返回值 | 语义 |
|---|---|---|
| `move_id` / `event_id` / `parent_move_id` | `int` | 移动 ID、关联规则事件 ID和父移动 ID；无关联为 `-1`。 |
| `card_ids` | `Array[int]` | 本次移动实体 UID，顺序稳定。当前服务每条记录通常只有1张。 |
| `from_zone` / `to_zone` | `String` | 移动前后标准区域。 |
| `source_player_id` / `target_player_id` | `int` | 前后持有者；公共区域为 `-1`。 |
| `visible_to` | `Array[int]` | 显式可见玩家；空数组由实体知识字段推断。 |
| `reason` | `String` | 稳定移动原因，例如 `use/respond/gain/discard/equip/judge/wash`。 |
| `target_slot` | `String` | 目标装备槽，非装备移动为空。 |
| `_init(card_uid_list=[], old_zone="", new_zone="", old_owner=-1, new_owner=-1, move_reason="")` | `void` | 复制基础记录字段，不执行区域修改。 |
| `to_dict()` | `Dictionary` | 返回全部字段的可序列化深拷贝。 |

#### MatchController 私有区域选择与持续装备流程

| 私有函数 | 行为与制作影响 |
|---|---|
| `_build_player_zone_candidates(viewer_id, target_id, include_hand=true, include_equipment=true, include_judgment=true)` | 固定按手牌、五种标准装备槽、判定区顺序生成候选；查看他人手牌时隐藏牌面。 |
| `_serialize_choice_candidate(card, owner_id, zone, visible, slot="")` | 候选固定包含 `uid/owner_id/zone/slot/visible/card_data`；隐藏牌只暴露 UID、区域和归属，定义为空、花色 `none`、点数0。 |
| `_discard_selected_player_card(target_id, card_uid)` | 按 UID 搜索手牌、装备、判定区；装备弃置会触发运行时卸载与离区效果。 |
| `_take_selected_player_card(source_id, target_id, card_uid)` | 按 UID 从目标手牌、装备、判定区取得并移动到来源手牌；取得装备会先触发离区效果。 |
| `_continue_target_card_choice(context, selected_uids, is_steal)` | 恢复过河拆桥或顺手牵羊；执行精确 UID 移动后完成父牌当前目标。 |
| `_discard_playable_card(player_id, card_uid)` | 从普通手牌或木牛“粮”移除并弃置；与只允许普通手牌的 `discard_card_from_hand()` 不同。 |
| `_find_processing_card(card_uid)` | 只在公共处理区按 UID 查询。 |
| `_discard_equipment_slot(player_id, slot, trigger_loss_effects)` | 先从装备字典移除，再卸载运行时并调用离区钩子，最后把装备实体移入弃牌堆。 |
| `_on_equipment_lost(player, card, trigger_loss_effects)` | 卸载该实体运行时，再调用数据库静态定义的 `on_leave_equipment()`；不移动装备本身。 |
| `_install_card_runtime(card, owner_player_id)` | 先卸载同 UID 旧实例，再通过 `create_card_runtime()` 新建、绑定、索引并调用 `install_runtime()`。 |
| `_uninstall_card_runtime(card_uid)` | 调用对应实例 `uninstall_runtime()` 后移除索引；不存在时安全返回。 |
| `_uninstall_all_card_runtimes()` | 重开局前卸载全部实例并清空索引，必须先于替换状态和事件服务。 |
| `_get_equipment_card_by_definition(player_id, definition_id)` | 在玩家装备区按定义 ID 返回实体；装备发动请求据此保存准确 UID。 |

区域候选的 `visible=false` 只隐藏提交给选择者的牌面，不改变实体 `shown` 或 `known_to`。异步恢复必须继续按 UID 查询权威区域，不能信任候选中的旧区域和牌面字段。

### 卡牌函数参数与返回值

#### `resolve(resolver, card, actor_id, target_ids)`

| 参数 | 类型 | 范围与含义 |
|---|---|---|
| `resolver` | `Object` | 当前 `CardEffectResolver`，只提供 `host/state`、停止判断、默认结束区域和父牌恢复调度，不包含具体牌效。 |
| `card` | `CardInstance` | 当前位于 `processing` 的实体牌；包含 `uid`、`definition_id`、`suit`、`rank`、`zone` 和 `owner_id`。 |
| `actor_id` | `int` | 使用者稳定 ID，正式对局为 `0..9`。 |
| `target_ids` | `Array[int]` | 规范化后的目标 ID；长度为 `0..10`，普通逐目标调用通常只含1项。 |

返回值只能使用以下区域语义：

| 返回值 | 含义 |
|---|---|
| `discard` | 效果完成后进入弃牌堆。 |
| `equipment` | 已进入装备区。 |
| `judgment` | 已进入判定区。 |
| `pending` | 已创建响应或选择请求，当前内容事件必须等待。 |
| `consumed` | 卡牌被其他规则接管、对局结束或不再执行默认移动。 |

#### `resolve_target(resolver, card, actor_id, target_id, resolution_context)`

仅 `resolution_mode=per_target` 时使用。基类默认把当前目标包装为单元素数组后调用 `resolve()`。多目标【杀】或拥有共享状态的牌需要覆盖本函数。

`resolution_context` 常见字段如下：

| 字段 | 类型 | 含义 |
|---|---|---|
| `parent_card_uid` | `int` | 原卡牌实体 UID。 |
| `card_use_event_id` | `int` | 当前使用牌事件 ID，未登记时为 `-1`。 |
| `actor_id` | `int` | 使用者 ID。 |
| `card_definition_id` | `String` | 卡牌稳定 ID。 |
| `target_ids` | `Array[int]` | 整张牌的逐目标顺序。 |
| `target_index` | `int` | 下一名尚未开始的目标下标，范围 `0..target_ids.size()`。 |
| `current_target_id` | `int` | 当前正在等待响应的目标；无目标时为 `-1`。 |
| `slash_damage_amount` | `int` | 【杀】共享基础伤害，默认1。 |
| `slash_nature` | `String` | 【杀】共享属性：`normal`、`fire`、`thunder`。 |
| `slash_ignore_armor` | `bool` | 当前【杀】是否无视防具。 |
| `effect_target_ids` | `Array[int]` | 【借刀杀人】等需要保留完整语义顺序的目标数组。 |

#### `resolve_delayed_judgment(match_host, player_id, card, negated)`

延时锦囊必须覆盖该函数：

- `match_host`：当前 `MatchController`。
- `player_id`：判定角色 ID，正式范围 `0..9`。
- `card`：已经进入 `processing` 的延时锦囊实体。
- `negated`：`true` 表示生效前被【无懈可击】抵消。

可调用 `perform_judgment()` 获取1张判定牌，调用 `mark_player_phase_skipped()` 标记跳过阶段，调用 `discard_delayed_card()` 进入弃牌堆。所有分支都必须明确处理原延时锦囊的最终区域。

#### 异步恢复函数

- `continue_choice(resolver, context, selected_uids) -> bool`：恢复卡牌创建的普通选牌。识别 `context.kind` 后执行后续效果并返回 `true`；不属于本牌时返回 `false`。
- `continue_response(resolver, context, response_card) -> bool`：恢复响应牌选择。`response_card=null` 表示放弃，非空实体已经完成合法性校验和消费。
- `continue_negation(resolver, context, final_negated) -> bool`：只用于五谷等拥有专用无懈后续队列的整牌流程。
- 所有异步 `context` 必须包含 `parent_card_uid`。调度器用该 UID 查找仍在处理区的父牌，再回到对应卡牌源码；禁止让控制器按卡牌名或选择 kind 调用具体牌效。

#### WuxieChainState 完整成员索引

普通卡牌不直接创建或修改无懈链，只调用 `resolve_trick_negation()`。该内部结构解释了为何同步返回值只在没有等待时代表最终结果。

| 成员或函数 | 类型或返回值 | 语义 |
|---|---|---|
| `root_event_id` | `int` | 原锦囊根事件 ID，未绑定为 `-1`。 |
| `source_event_id` | `int` | 当前被响应事件；没有嵌套时等于根事件。 |
| `state` | `int` | 初始1；每张成功【无懈可击】乘以 `-1`，负数表示原效果被中立化。 |
| `responded_by` | `Array[int]` | 按实际顺序保存响应者，同一玩家可重复出现。 |
| `response_results` | `Array[Dictionary]` | 每次响应的可序列化牌或选择结果深拷贝。 |

| `to_dict()` | `Dictionary` | 返回全部字段的深拷贝。 |

| 函数 | 返回值 | 调用时机与覆盖要求 |
|---|---|---|

| `bind_runtime(match_host, owner_player_id, card_uid)` | `void` | 系统为装备等持续区域实例绑定控制器、持有者与实体 UID；不要手动调用或覆盖。 |

| `uninstall_runtime()` | `void` | 装备离区或重开局时调用。覆盖时先清理自定义修正，再调用 `super.uninstall_runtime()`。 |

| `configure_resolution_context(match_host, card, actor_id, resolution_context)` | `void` | 整牌上下文登记前调用。只能写入可序列化字段，不能创建选择。 |
| `on_resolution_started(match_host, card, actor_id, resolution_context)` | `bool` | 上下文登记后、进入首个目标前调用。创建等待请求时返回 `true`。 |
| `on_card_declared(match_host, actor, card)` | `void` | 实体牌完成使用声明时调用；用于卡牌自己拥有的兼容统计或声明触发。 |

| `append_play_phase_card_actions(match_host, actor_id, card, result)` | `bool` | 复杂目标卡牌向 AI 动作列表追加组合；返回 `true` 表示完全接管默认枚举。 |
| `get_dying_response_pattern(responder_id, dying_player_id)` | `String` | 声明本牌能否参与当前濒死关系；返回空字符串或自身响应模式。必须是纯查询。 |

| `validate_play_phase_action(match_host, action)` | `String` | 权威无副作用校验；空字符串合法。 |
| `execute_play_phase_action(match_host, action)` | `bool` | 执行已校验动作；成功或进入异步流程返回 `true`。 |
| `get_play_phase_action_preview(match_host, owner_id, equipment_uid, payload, selected_target_ids)` | `Dictionary` | 返回 UI 只读预览，不得修改状态。 |

无父牌装备请求的恢复分支会先检查 `equipment_definition_id`，再用 `context.kind.contains("response")` 判断调用 `continue_equipment_response()` 还是 `continue_equipment_choice()`。因此自定义装备响应的 `kind` 必须包含小写字符串 `response`；普通装备选择的 `kind` 不得误含该片段。响应上下文还必须包含 `responder_id`，请求端口会补入 `response_patterns`。

#### PlayerAction 完整成员索引

装备主动动作和技能动作最终都通过 `PlayerAction` 提交。内容文件在 `validate_play_phase_action()` 与 `execute_play_phase_action()` 中接收权威动作对象，不得信任客户端预览结果，必须重新校验所有字段。

| 成员或函数 | 类型或返回值 | 规则 |
|---|---|---|
| `action_type` | `String` | 标准动作名；主动技能使用 `use_skill`，装备使用自身 `get_play_phase_action_types()` 声明的名称。 |
| `actor_id` | `int` | 发起玩家 ID；系统动作可为 `-1`。装备必须复核它等于当前持有者。 |
| `card_uid` | `int` | 动作主实体 UID；无卡牌动作使用 `-1`。来源由 `play_phase_action_card_source` 决定。 |
| `target_ids` | `Array[int]` | 请求目标；借刀保留角色顺序，其他多目标可能由规则层规范化。 |
| `payload` | `Dictionary` | 可扩展参数，只允许可序列化值。技能动作至少包含 `skill_id`；装备动作应复核材料 UID、装备 UID和自定义参数。 |
| `client_sequence` | `int` | 客户端动作序号；单机可为0，内容规则不依赖该值。 |
| `_init(type="", player_id=-1, entity_uid=-1, targets=[])` | `void` | 保存字段并复制目标数组。 |
| `to_dict()` | `Dictionary` | 深复制目标和 `payload`，用于网络与回放。 |
| `from_dict(data)` | 静态 `PlayerAction` | 从不可信字典恢复动作，并逐项把目标转换为整数；缺失字段使用无效默认值，仍需规则层校验。 |

#### `install_runtime()` 与 `uninstall_runtime()`

装备等持续区域卡牌可以覆盖 `install_runtime()` 订阅事件。系统在装备、转移、替换、弃置、死亡清区和重新开局时，按实体 UID 创建或卸载独立实例。

覆盖 `uninstall_runtime()` 时必须先清理自定义修正，再调用：

```gdscript
super.uninstall_runtime()
```

#### CardRuleService 完整源码索引

`scripts/core/card_rule_service.gd` 是卡牌目标、距离、次数和虚拟牌合法性的只读权威服务。具体卡牌通过 `validate_target_selection(rule_service, ...)` 接收同一实例，装备主动动作可通过 `match_host.card_rules` 读取它。内容代码不得通过此服务移动牌或修改状态。

#### ChoiceRequest 与 ChoiceResponse 运行时协议

卡牌和技能通常只调用 `request_card_choice()` 或响应请求入口，由控制器创建以下对象。内容文件不得自行提交 `ChoiceResponse`、修改调度器请求或依赖请求 ID；理解这些字段用于保证 `context`、取消和同步返回语义与运行时一致。

`ChoiceRequest.Status` 包含 `PENDING`、`RESOLVED`、`CANCELLED`、`TIMED_OUT`、`ABORTED`。

| ChoiceRequest 变量 | 类型 | 行为 |
|---|---|---|
| `request_id` / `event_id` | `int` | 请求稳定 ID 与所属事件 ID；未登记为 `-1`，响应必须同时匹配。 |
| `actor_id` | `int` | 唯一合法响应玩家。 |
| `choice_type` | `String` | `use/respond/card/target/button/control/bool/discard` 等稳定类型。 |
| `prompt` | `String` | 玩家可见提示。 |
| `card_ids` / `target_ids` | `Array[int]` | 合法实体牌 UID 或目标玩家 ID。 |
| `button_ids` / `control_ids` | `Array[String]` | 合法按钮或控制项 ID。 |
| `min_count` / `max_count` | `int` | 对当前 `choice_type` 主选择数组生效的数量范围。 |
| `forced` / `can_cancel` | `bool` | 强制请求即使 `can_cancel=true` 也不能用未确认响应取消。 |
| `deadline_msec` / `deadline` | `int` | 毫秒截止时间及兼容别名；0表示不自动超时。 |
| `selected_card_ids` / `selected_target_ids` / `selected_button_ids` | 数组 | 用于界面重建的当前临时选择，目标顺序不会在请求层重排。 |
| `base_context` / `active_context` | `Dictionary` | 基础和当前技能替换后的可序列化选择上下文。 |
| `excluded_candidates` | `Dictionary` | 当前请求被排除候选 ID 到稳定原因的映射。 |
| `status` / `result` | `Status` / `Dictionary` | 当前状态与最终响应快照。 |
| `pause_token_id` | `int` | 所属事件暂停令牌；未暂停为 `-1`。 |
| `revision` | `int` | backup、restore、redo 和排除候选时递增的界面修订号。 |

| ChoiceRequest 函数 | 返回值 | 行为 |
|---|---|---|
| `_init(owner_event_id=-1, chooser_id=-1, type="card", message="")` | `void` | 创建最小请求。 |

### 把卡牌加入牌堆

只有创建卡牌文件不会自动在牌堆中生成实体牌。需要在 `data/decks.json` 加入：

```json
["heart", 7, "shilipa"]
```

三个值依次是：

| 位置 | 参数 | 可填范围 |
|---:|---|---|
| 0 | 花色 | `spade`、`heart`、`club`、`diamond` |
| 1 | 点数 | `1..13`；1显示A，11显示J，12显示Q，13显示K |
| 2 | 卡牌 ID | 已登记的稳定 `id` |

同一卡牌 ID 可以配置多张不同花色与点数的实体牌。

## 技能制作

### 技能的运行方式

武将文件直接引用技能脚本。选将完成后，系统为每名持有者创建独立 `SkillDefinition` 实例并自动调用：

```text
_init()
  ↓
bind(match_host, owner_player_id)
  ↓
install()
  ↓
对局运行：事件触发或玩家提交 use_skill
  ↓
uninstall()
```

不同玩家即使拥有同一个技能，也不会共享次数、标记或临时状态。

#### MatchController 私有技能、回合与判定调度

| 私有函数 | 行为与制作影响 |
|---|---|
| `_create_players(player_count)` | 创建稳定玩家 ID并随机分配身份；武将、体力和技能状态在选将完成后初始化。 |
| `_apply_character(player, character_id, reveal_character)` | 写入武将 ID和公开状态；基础体力至少1，五人及以上身份局主公额外增加1点体力上限和当前体力。 |
| `_install_all_character_skills()` | 为每名玩家按武将 `skills` 顺序调用 `GameDatabase.create_skill()`、`bind()`、`install()`，同技能不同持有者实例独立。 |
| `_uninstall_all_character_skills()` | 逐实例调用 `uninstall()` 后清空索引；重开局时先于创建新技能执行。 |
| `_finish_character_selection()` | 完成亮将、应用武将、安装技能、每人摸4张起始手牌，并由主公开启首回合。 |
| `_reorder_players_from_lord()` | 把主公旋转到座次数组首位，保持每名玩家稳定 `player_id` 不变。 |
| `_start_turn(player_id)` | 建立回合事件、重置当前回合统计，通知所有卡牌定义 `on_turn_started()`，并派发阶段流程。 |
| `_continue_turn_after_judgment(player_id)` | 判定区处理完成后进入摸牌、出牌等后续阶段；跳过标记由判定牌预先写入。 |
| `_resume_interrupted_turn_flow()` | 所有响应、装备队列和异步选择结束后恢复被暂停的判定、濒死或回合流程。 |
| `_process_judgment_area(player_id)` | 启动当前玩家判定区序列，使用流程令牌防止旧异步结果恢复新回合。 |
| `_run_judgment_area_sequence(player_id, flow_token)` | 按判定区顺序处理延时锦囊；每张先进入处理区并建立无懈链，再执行自身判定钩子。 |

| `_end_play_phase(player_id)` | 结束出牌阶段并进入弃牌阶段选择。 |
| `_continue_discard_phase_choice(context, selected_uids)` | 恢复阶段弃牌，按提交 UID 弃置并完成回合。 |
| `_finish_turn(player_id)` | 通知全部卡牌定义 `on_turn_ended(..., false)`、派发阶段结束并启动下一名存活角色。 |
| `_advance_after_current_player_death(dead_player_id)` | 当前回合角色死亡时通知 `on_turn_ended(..., true)`，取消旧出牌请求并转交下一名存活玩家。 |
| `_notify_card_definitions_turn_started(player_id)` | 遍历全部数据库静态卡牌定义调用 `on_turn_started()`；该钩子不得保存玩家共享状态。 |
| `_notify_card_definitions_turn_ended(player_id, interrupted)` | 遍历全部静态定义调用 `on_turn_ended()`，`interrupted=true` 表示死亡中断。 |

卡牌的回合通知调用的是数据库静态定义而非装备运行时实例，因此只适合维护定义拥有的全局兼容统计。每玩家、每实体状态必须放在 `PlayerState`、活动结算上下文或已绑定的运行时实例中。

### 技能静态参数总表

| 参数 | 必填 | 类型 | 可填范围 | 作用 |
|---|---:|---|---|---|
| `id` | 是 | `String` | 任意非空唯一字符串；推荐 `[a-z0-9_]+` | 技能永久逻辑 ID，也是主动技能动作和回放记录使用的 ID。 |

| `trigger` | 是 | `String` | `sample_only` 或任意非空稳定标签 | `sample_only` 是保留值，表示只有元数据、规则尚未接入；其他值表示正式技能。推荐填写 `active`、`passive` 或主要事件名。该字段本身不会自动订阅事件。 |

### 基础 AI 对内容字段的真实解释

`BasicAIPolicy` 只从核心已经生成的合法动作中选择，不会令非法卡牌或技能变为合法。它的业务变量 `player_id` 是当前受控玩家稳定 ID，构造函数 `_init(controlled_player_id)` 只绑定该玩家。

| 函数 | 返回值与决策行为 |
|---|---|
| `choose_action(authoritative_snapshot, legal_actions)` | 对每项调用 `_score_action()`，选择严格最高分的首项；最高分小于等于0或没有动作时返回 `end_play`。 |
| `choose_card_choice(snapshot, choice_request, legal_actions)` | 上下文字段 `ai_prefer_select` 缺省为 `true`，此时返回首个非空选择；为 `false` 时优先保留放弃动作。强制选择没有放弃时回退首个合法动作。 |
| `_score_action(snapshot, action)` | `ai_use_value` 缺省3.0；无目标直接返回基础分。只读取第一个目标。`hostile` 加 `-attitude*5`，`friendly` 加 `attitude*6`，`self_boost` 对自己加6，否则加 `attitude*2`。未知模式不修正。 |
| `_get_attitude(snapshot, target_id)` | 同非内奸身份为1；主忠互为1；反贼对主忠、主忠对反贼或内奸为-1；内奸对所有目标为-0.4；其他关系为-0.7。 |

这意味着多目标动作目前只按第一目标评分；`ai_beneficial` 不参与普通出牌评分，只用于无懈可击自动决策；未写 `ai_use_value` 的牌默认获得3分，若没有目标态度修正通常仍可能被使用。

`AICoordinator` 的私有 `_policies` 字典按玩家 ID 保存策略实例：

| 函数 | 行为 |
|---|---|
| `register_basic_ai(player_id)` | 覆盖安装新的 `BasicAIPolicy`。 |
| `unregister_ai(player_id)` | 移除控制权。 |
| `is_ai_controlled(player_id)` | 查询是否存在策略。 |
| `request_action(player_id, snapshot, legal_actions)` | 无策略时返回 `end_play`，否则调用策略动作选择。 |
| `request_card_choice(player_id, snapshot, choice_request, legal_actions)` | 无策略返回空字典，否则调用策略选牌。 |
| `request_choice(player_id, snapshot, request, presentation_request, legal_actions)` | 把策略动作转换为 `ChoiceResponse`；选择非空或请求最少数大于0时 `confirmed=true`，来源固定 `ai`。 |

主动技能若希望基础 AI 使用，`append_play_phase_actions()` 必须追加完整动作；若动作没有 `card_definition_id`，基础评分会使用空定义的默认3分。技能可以在动作中提供一个已登记卡牌 ID 复用其 AI 元数据，但该字段只影响决策评分，不能替代 `payload.skill_id` 或权威技能校验。

### 技能生命周期函数

| 函数 | 是否需要覆盖 | 作用 |
|---|---:|---|
| `_init()` | 是 | 调用 `super({...})` 写入技能元数据。 |
| `bind(match_host, player_id)` | 否 | 系统自动绑定 `host` 和 `owner_player_id`。通常不得覆盖。 |
| `install()` | 被动技能需要 | 订阅事件、触发器或查询修正。 |
| `uninstall()` | 有自定义注册时需要 | 清理修正管线，然后调用 `super.uninstall()` 清理事件订阅。 |
| `can_activate(context)` | 主动技能需要 | 无副作用检查当前是否可发动，返回 `bool`。 |
| `activate(context)` | 主动技能需要 | 执行效果；成功返回空字符串，失败返回玩家可见错误文本。 |
| `continue_choice(context, selected_uids)` | 技能创建普通选牌时需要 | 恢复技能选牌；识别后返回 `true`。 |
| `continue_response(context, response_card)` | 技能创建响应请求时需要 | 恢复技能响应；`null` 表示放弃。 |
| `append_play_phase_actions(result)` | 需要基础 AI 主动发动时覆盖 | 追加 `action_type=use_skill` 的合法动作字典。 |
| `get_activation_preview(context)` | 需要目标、费用或确认预览时覆盖 | 返回只读 `Dictionary`，不得产生副作用。 |

当前桌面技能按钮只提交 `action_type=use_skill` 和 `payload.skill_id`，不会主动调用 `get_activation_preview()` 构建技能目标或材料界面。需要选牌、选目标或响应的主动技能，应在 `activate()` 中创建统一选择请求并通过 `continue_choice()` / `continue_response()` 恢复；`get_activation_preview()` 目前主要供外部界面、AI或后续扩展查询，不能假设现有按钮会自动消费其字段。

`context` 必须只包含可序列化数据，例如数字、字符串、布尔值、数组和字典。不得放入节点、`PlayerState`、`CardInstance` 或 Callable。技能创建异步请求时必须写入：

```gdscript
context["skill_id"] = get_id()
context["skill_owner_id"] = owner_player_id
```

创建响应牌请求时还要写入 `responder_id`。`request_response_card()` 会自动补充 `response_patterns`，选择提交后控制器会消费合法实体并调用当前技能实例的 `continue_response()`。技能等待期间若被移除，旧选择会安全失效。

#### MatchController 私有濒死、死亡与胜负流程

| 私有函数 | 行为与制作影响 |
|---|---|
| `_resolve_dying(target_id, killer_id, rescue_start_override=-1, already_asked_rescuer_ids=[])` | 体力不大于0时建立救援顺序并派发 `dying_begin`；同一轮记录已询问救援者，允许异步逐人响应。 |
| `_continue_dying_choice(context, selected_uids)` | 恢复【桃】或【酒】救援选择，消费并应用合法救援牌；仍濒死则继续下一救援者。 |
| `_get_dying_response_options(responder_id, dying_player_id)` | 遍历可出牌来源，调用每张定义的 `get_dying_response_pattern()`，只返回当前关系允许的牌候选。 |
| `_apply_dying_response_card(responder_id, dying_player_id, card)` | 调用所选牌定义的 `resolve_dying_response()`；卡牌文件必须再次复核自己救援关系。 |
| `_finish_dying_rescue(target_id)` | 救援成功时清除濒死状态并派发 `dying_end`；当前实现事件数据为 `hp` 和 `rescued=true`。 |
| `_get_alive_players_in_action_order(start_player_id)` | 返回从指定玩家开始的存活且未离场角色环形顺序；找不到起点时从数组首位开始。 |
| `_resolve_death(victim_id, killer_id)` | 确认死亡、公开身份、卸载装备和技能相关状态、执行身份奖惩并检查胜负。 |
| `_check_game_over()` | 使用 `IdentityRules.evaluate_winner()` 检查阵营胜负并结束对局。 |
| `_end_match_as_draw(reason)` | 以平局结束，记录稳定原因并中断事件运行时。 |

救援牌不是仅凭 `provided_response_pattern` 自动生效：候选生成与实际应用分别调用 `get_dying_response_pattern()` 和 `resolve_dying_response()`。新救援牌必须同时实现两者，且响应实体会在应用前由控制器完成合法消费。

真实使用牌还会按固定顺序派发以下 `RuleEvent` 时机：整牌时机 `useCard0`、`useCard1`、`yingbian`、`useCard2`、`useCard`，随后对每名目标依次派发 `useCardToPlayer`、`useCardToTarget`、`useCardToPlayered`、`useCardToTargeted`。这些事件的 `source_id` 为使用者，逐目标时机的 `target_id` 为当前目标，整牌时机为 `-1`；`event.data` 均包含：

| 字段 | 类型 | 修改影响 |
|---|---|---|
| `card_uid` | `int` | 当前实体牌 UID，只读。 |
| `card_id` | `String` | 当前卡牌定义 ID，只读。 |
| `target_ids` | `Array` | 整张牌当前目标；回调修改后会写回后续时机。 |
| `excluded_target_ids` | `Array` | 被排除的目标；内容阶段跳过这些目标。 |
| `direct_hit_target_ids` | `Array` | 不允许响应的目标；【杀】会跳过【闪】请求。 |
| `custom_args` | `Dictionary` | 技能与卡牌跨时机共享的自定义可序列化参数。 |

对整牌时机调用 `event.cancel()` 或 `event.neutralize()` 会取消整张牌内容；对逐目标时机调用则把当前目标加入 `excluded_target_ids`。回调修改数组时必须保留整数玩家 ID，修改 `custom_args` 时只能写入可序列化值。

`CardUseEventService` 定义上述事件树拓扑。它是控制器内部构建组件，不是内容调用端口，但其全部源码元素决定卡牌和技能能观察到的顺序：

| 常量或函数 | 可见性 | 行为 |
|---|---|---|
| `USE_TIMING_NAMES` | 公共常量 | 五个整牌时机，严格按数组顺序入队。 |
| `TARGET_TIMING_NAMES` | 公共常量 | 四个逐目标时机；每组遍历全部当前目标后才进入下一组。 |
| `create_use_event(scheduler, parent_id, event_context, content_steps)` | 公共函数 | 创建 `CardUseEvent`，复制使用者、目标、`virtual_card` 和材料 UID；调度器为空返回 `null`。只由控制器调用。 |
| `enqueue_use_timings(scheduler, use_event, timing_step)` | 公共函数 | 把五个整牌触发子事件加入 `next` 队列。 |
| `enqueue_target_timing(scheduler, use_event, timing_name, target_id, timing_step)` | 公共函数 | 只接受四个标准逐目标时机，创建目标触发子事件；参数无效返回 `null`。 |
| `enqueue_content_before(scheduler, use_event, content_step)` | 公共函数 | 创建唯一 `contentBefore` 子事件。 |
| `enqueue_target_content(scheduler, use_event, target_id, content_step)` | 公共函数 | 创建 `content` 子事件；`target_id<0` 表示整牌一次读取完整目标数组。 |
| `enqueue_content_after(scheduler, use_event, content_step, destination)` | 公共函数 | 在全部内容完成后创建 `contentAfter`，上下文携带最终区域语义。 |
| `enqueue_ordering_discard(scheduler, use_event, ordering_step)` | 公共函数 | 把 `orderingDiscard` 加入父事件 `after` 队列，之后才创建弃牌移动事件。 |
| `_base_child_context(use_event)` | 私有函数 | 复制 `card_use_event_id`、`actor_id`、`target_ids`、`card_uid`、`virtual_card`、`material_card_uids` 和 `virtual_proxy`。 |

因此卡牌实体进入处理区后不会在 `resolve()` 返回时立即弃置；只有 `contentAfter` 确认最终区域且 `orderingDiscard` 执行后，仍应弃置的材料才离开处理区。异步内容必须完成父目标或父牌，不能自行提前移动父牌。

### GameEvent 完整成员索引

`GameEvent` 是可暂停、嵌套的事件树节点。卡牌和技能通过规则事件和选择端口间接参与，不应直接修改调度器事件；以下索引用于理解父牌为何必须等待选择恢复。

`GameEvent.Status` 包含 `CREATED`、`RUNNING`、`WAITING_CHILDREN`、`PAUSED`、`FINISHED`、`CANCELLED`、`NEUTRALIZED`、`ABORTED`。

| 变量 | 类型 | 语义 |
|---|---|---|
| `event_id` / `parent_id` | `int` | 当前事件和父事件稳定 ID；未登记或根事件父 ID 为 `-1`。 |
| `name` / `event_type` | `String` | 稳定事件名与调试分类。 |
| `step` / `status` | `int` / `Status` | 当前内容步骤游标和生命周期状态。 |
| `result` / `context` | `Dictionary` | 子事件结果与事件创建时深复制的可序列化上下文。 |
| `next_event_ids` / `after_event_ids` | `Array[int]` | 主体期间子事件和主体终止后的收尾事件队列。 |
| `content_steps` | `Array[Callable]` | 内部步骤，每项接收当前事件与调度器；不会出现在序列化快照。 |
| `player_id` / `source_id` / `target_id` / `target_ids` | 玩家 ID或数组 | 主要行动者、来源、当前目标和完整目标顺序。 |
| `card` / `card_uids` | `Dictionary` / `Array[int]` | `VirtualCard` 字典和实体材料 UID。 |
| `termination_reason` | `String` | 正常、取消、中立化或中断原因。 |
| `allow_out_of_game` | `bool` | 是否允许死亡或离场角色继续；默认 `false`。 |
| `body_finished` / `finalized` / `held_open` | `bool` | 主体结束、历史已最终写入和长期根事件保持开放状态。 |
| `_next_step_override` / `_redo_requested` | 私有变量 | `goto()` 与 `redo()` 保存的下一次游标控制。 |

| 函数 | 返回值 | 行为 |
|---|---|---|
| `_init(event_name="", steps=[], event_context={})` | `void` | 复制步骤数组和上下文字典，尚不登记 ID。 |
| `finish(reason="")` | `void` | 正常结束主体并保留 `after` 队列；已经终止时无操作。 |
| `cancel(reason="cancelled")` | `void` | 进入取消终态、清空未开始的 `next`，保留 `after`。 |
| `neutralize(reason="neutralized")` | `void` | 进入中立化终态、清空 `next`，保留事件事实和 `after`。 |
| `unneutralize()` | `bool` | 仅尚未最终写入历史的中立化事件可恢复为运行状态。 |
| `abort(reason="aborted")` | `void` | 清空 `next` 和 `after`；用于对局结束、重置或不可恢复错误。 |
| `goto(next_step)` | `void` | 设置下一次执行步骤，负数限制为0。 |
| `redo()` | `void` | 下一次重新执行当前步骤，不立即递归。 |
| `insert(child_event_id)` / `insert_after(after_event_id)` | `void` | 把非负事件 ID 加入主体或收尾队列。 |
| `trigger(scheduler, event_name, event_type="trigger", steps=[], event_context={})` | `GameEvent` 或 `null` | 在当前已登记事件下创建子事件；内容脚本不得绕过公开规则端口调用。 |
| `is_terminal()` / `is_paused()` | `bool` | 查询是否为四种终态或是否处于暂停状态。 |
| `consume_step_transition(executed_step)` | `void` | 私有调度用途：优先处理 redo，其次 goto，否则游标加1。 |
| `to_dict()` | `Dictionary` | 返回不含 Callable 的事件快照，状态为小写字符串。 |

### EventScheduler 与暂停令牌源码索引

这些对象属于控制器内部运行时。内容代码只能通过 `request_card_choice()`、响应入口、`complete_card_target()` 和 `finish_processing_card()` 间接使用，禁止直接创建、暂停、恢复或排空事件。

`EventScheduler` 信号：`event_started(event_data)`、`event_step_executed(event_data)`、`event_finished(event_data)`、`choice_requested(request_data)`、`choice_resolved(request_data, response_data)`、`scheduler_idle()`、`scheduler_aborted(reason)`。所有参数均为快照，不提供可变事件引用。

| EventScheduler 变量 | 可见性 | 语义 |
|---|---|---|
| `_next_event_id` / `_next_request_id` | 私有 | 分别从1递增的事件与请求 ID。 |

| 参数 | 类型 | 可填范围 |
|---|---|---|
| `event_name` | `String` | 上表稳定事件名或自定义已派发事件名 |
| `owner` | `Object` | 技能中固定传 `self`，用于卸载时批量清理 |
| `callback` | `Callable` | 参数签名通常为 `(event: RuleEvent) -> void` |

`RuleEventBus` 的完整制作相关接口如下：

| 成员或函数 | 返回值或类型 | 使用规则 |
|---|---|---|
| `_handlers` | `Dictionary` | 私有普通订阅表，按事件名保存回调；内容代码不得访问。 |
| `_ordered_triggers` | `TriggerManager` | 私有有序订阅表，与公开的 `host.trigger_manager` 不是同一实例。 |

```gdscript

	event_name,
	self,
	callback,
	priority,
	owner_player_id,
	role,
	first_do,
	last_do,
	condition
)
```

| 参数 | 可填范围 |
|---|---|
| `priority` | 任意整数，越大越早 |
| `owner_player_id` | 全局触发为 `-1`，玩家触发为 `0..9` |
| `role` | `player`、`source`、`target`、`global` |
| `first_do` | `true/false`；`true` 进入最先执行组 |
| `last_do` | `true/false`；`true` 进入最后执行组；不要同时开启二者 |

`TriggerManager` 的公共与私有成员行为：

| 成员或函数 | 可见性 | 返回值与规则 |
|---|---|---|
| `_next_registration_id` | 私有变量 | 从1递增的稳定注册序号，同优先级和同座次时用于保持注册顺序。 |

| `arrange(event_name, start_player_id, seat_order, event=null)` | 公共查询 | 返回排序后的记录快照：`first_do` 组在前、普通组居中、`last_do` 组最后；组内先按优先级降序，再按起点环形座次，最后按注册序号。通常由核心调用。 |
| `dispatch(event, start_player_id, seat_order)` | 公共派发 | 逐项执行排序结果；每次执行前重新检查 `condition`，事件进入终态后停止。内容技能通常不主动派发。 |
| `_seat_distance(start_player_id, player_id, seat_order)` | 私有函数 | 计算环形座次距离；全局或未知玩家排在全部有效角色之后。 |

### 纯查询修正管线

技能若要改变“能否使用、能否响应、目标是否合法或是否在范围内”，应注册 `host.modifier_pipeline`，不要在事件回调中直接伪造 UI 状态。当前稳定修正名如下：

| 修正名 | 初始值 | `context` 自动字段 |
|---|---|---|
| `card_enabled` | `bool`：实体位于可出牌来源，持有者存活且处于自己的出牌阶段 | `actor_id`、`card_uid`、`card_id` |
| `card_respondable` | `bool`：牌的 `provided_response_pattern` 与请求模式一致 | `actor_id`、`card_uid`、`card_id`、`response_pattern` |
| `card_usable` | `bool`：`card_enabled` 且规范化目标通过 `validate_use()` | `actor_id`、`card_uid`、`target_ids` |
| `target_enabled` | `bool`：目标存活且位于 `list_legal_targets()` | `actor_id`、`target_id`、`card_uid`、`card_id` |
| `target_in_range` | `bool`：按 `distance_limit`、最终距离和攻击范围计算 | `actor_id`、`target_id`、`card_uid`、`distance`、`limit`；无限距离的 `limit=-1` |

修正回调签名为 `(current_value: Variant, context: Dictionary) -> Variant`。管线按优先级从高到低传递前一项结果；返回 `null` 表示保留前值。`context` 每次都会深复制，修改它不会写回查询或传给下一修正器。修正器必须是无副作用纯查询。

| RuleModifierPipeline 成员或函数 | 可见性 | 行为 |
|---|---|---|
| `_modifiers` | 私有变量 | 按修正名保存回调数组。 |
| `_next_registration_id` | 私有变量 | 从1递增；同优先级时保证注册顺序。 |
| `register(modifier_name, owner, callback, priority=0)` | 公共函数 | 返回注册 ID；空名称或无效回调返回 `-1`。 |
| `unregister_owner(owner)` | 公共函数 | 移除指定或已失效所有者的全部修正器。覆盖技能 `uninstall()` 时必须在 `super.uninstall()` 前调用。 |
| `apply(modifier_name, value, context={})` | 公共函数 | 链式应用修正并返回最终值；通常由 `RuleQuery` 调用，技能不应主动重复应用。 |

`host.rule_query` 是修正后的只读查询门面，拥有公共变量 `state`、`card_rules`、`modifiers`，以及以下函数：

| 函数 | 返回值 | 行为 |
|---|---|---|
| `_init(game_state, rule_service, modifier_pipeline=null)` | `void` | 绑定状态、卡牌规则和修正管线；缺省时创建独立管线。由核心调用。 |
| `card_enabled(actor_id, card, context={})` | `bool` | 检查实体来源、存活、阶段，再应用 `card_enabled`。 |
| `card_respondable(actor_id, card, response_pattern, context={})` | `bool` | 检查响应模式，再应用 `card_respondable`。 |
| `card_usable(actor_id, card, target_ids, context={})` | `bool` | 先执行 `card_enabled()`，规范化目标并调用 `validate_use()`，再应用 `card_usable`。 |
| `target_enabled(actor_id, card, target_id, context={})` | `bool` | 检查基础单目标候选，再应用 `target_enabled`。 |
| `target_in_range(actor_id, card, target_id, context={})` | `bool` | 计算无限、距离1或攻击范围限制，再应用 `target_in_range`。 |

技能安装与卸载示例：

```gdscript
func install() -> void:
	host.modifier_pipeline.register("card_enabled", self, _modify_card_enabled)


func uninstall() -> void:
	host.modifier_pipeline.unregister_owner(self)
	super.uninstall()


func _modify_card_enabled(current_value: Variant, context: Dictionary) -> Variant:
	return bool(current_value)
```

### 主动技能示例

该技能在自己的出牌阶段每回合限一次，主动摸1张牌：

```gdscript
extends SkillDefinition

## 【补给】技能源码。出牌阶段限一次，主动摸1张牌。

## 每回合最大主动发动次数；固定为1，修改后会改变资源产出频率。
const MAX_USES_PER_TURN: int = 1

## 当前回合已经发动的次数；范围0至1，在持有者回合开始时重置。
var uses_this_turn: int = 0


## 写入主动技能元数据；ui_enabled=true 允许技能栏提交 use_skill 动作。
func _init() -> void:
	super({
		"id": "buji",
		"name": "补给",
		"trigger": "active",
		"ui_enabled": true,
		"description": "出牌阶段限一次，你可以摸1张牌。",
	})


## 订阅回合开始事件，用于重置本回合发动次数。
func install() -> void:
	host.event_bus.subscribe("phase_start", self, _on_phase_start)


## 只有持有者存活、处于自己的出牌阶段且尚未达到1次上限时允许发动。
func can_activate(_context: Dictionary = {}) -> bool:
	# 当前技能持有者状态；不存在或死亡时不能主动发动技能。
	var owner: PlayerState = host.state.get_player(owner_player_id)
	return owner != null and owner.alive and host.state.current_player_id == owner_player_id and host.state.current_phase == "play" and uses_this_turn < MAX_USES_PER_TURN


## 消耗本回合1次发动次数并摸1张牌；成功必须返回空字符串。
func activate(_context: Dictionary = {}) -> String:
	if not can_activate():
		return "【补给】当前不能发动。"
	uses_this_turn += 1
	host.draw(owner_player_id, 1)
	return ""


## 持有者新回合开始时把发动次数恢复为0；其他角色回合不修改本技能状态。
func _on_phase_start(event: RuleEvent) -> void:
	if event.target_id == owner_player_id:
		uses_this_turn = 0
```

主动技能需要选牌时，应在 `activate()` 中创建统一选择请求，并由同一技能文件的 `continue_choice()` 恢复，不能同步假设玩家已经完成选择：

```gdscript
func activate(_context: Dictionary = {}) -> String:
	# 本人手牌候选；技能只保存序列化选择上下文。
	var candidates: Array[Dictionary] = host.get_hand_candidates(owner_player_id, owner_player_id)
	var choice_context: Dictionary = {
		"kind":"example_skill_cost",
		"skill_id":get_id(),
		"skill_owner_id":owner_player_id,
	}
	host.request_card_choice(owner_player_id, "技能选牌", "请选择一张手牌", candidates, 1, 1, false, choice_context)
	return ""


func continue_choice(context: Dictionary, selected_uids: Array[int]) -> bool:
	if str(context.get("kind", "")) != "example_skill_cost":
		return false
	if selected_uids.size() == 1 and host.discard_card_from_hand(owner_player_id, selected_uids[0]):
		host.draw(owner_player_id, 1)
	return true
```

## 武将制作

### 武将文件的作用

武将文件只负责：

1. 声明稳定 ID、中文名称、性别、势力、基础体力、说明和插画。
2. 直接 `preload` 所需技能脚本。
3. 按展示顺序把技能脚本传给 `CharacterDefinition`。

武将文件不负责创建玩家、发牌、增加主公体力或直接安装技能。选将完成后 `MatchController` 会统一处理这些流程。

### 武将静态参数总表

| 参数 | 必填 | 类型 | 可填范围 | 作用与注意事项 |
|---|---:|---|---|---|
| `id` | 是 | `String` | 任意非空唯一字符串；推荐 `[a-z0-9_]+` | 选将、网络、回放和玩家状态使用的永久 ID。 |
| `display_name` | 是 | `String` | 任意非空中文文本 | 所有玩家可见的武将名。不得把英文 ID 直接当显示名称。 |
| `gender` | 是 | `String` | `male`、`female`、`unknown` | `male/female` 会参与雌雄双股剑异性判断；`unknown` 不参与异性触发。 |
| `faction` | 是 | `String` | `game_data/factions.json` 中已登记的势力 ID | 只影响武将牌名称、简称和颜色，不替代身份阵营。 |
| `max_hp` | 是 | `int` | `1` 以上；建议 `1..99`，当前样例为3或4 | 武将基础体力上限。小于1会被修正为1；1至5显示体力点，高于5显示数字。 |
| `description` | 是 | `String` | 任意非空文本 | 武将定位与使用说明，不应重复写无法追踪的隐藏数值。 |
| `art_path` | 否 | `String` | 空字符串或有效 `res://` 图片路径 | 推荐 `res://assets/art/characters/<武将ID>.webp`。无效时显示占位图。 |

### CharacterDefinition 内部变量

| 变量 | 类型 | 取值范围 | 内容作者是否直接修改 |
|---|---|---|---|
| `_metadata` | `Dictionary` | 构造时写入武将静态信息，之后只读 | 否，通过 `super({...})` 传入 |
| `_skill_scripts` | `Array[Script]` | `0` 个以上、全部来自技能目录 | 否，通过 `super(metadata, skills)` 第二个参数传入 |

`CharacterDefinition.get_metadata()` 会自动实例化技能脚本读取稳定技能 ID，并生成供 UI、网络和玩家快照使用的 `skills` 字符串数组。武将文件不得再手工维护一份重复技能 ID 数组。

### CharacterDefinition 完整函数索引

| 函数 | 参数与返回值 | 内容作者使用方式 |
|---|---|---|
| `_init(metadata={}, skill_scripts=[])` | `metadata: Dictionary`，`skill_scripts: Array[Script]` | 具体武将覆盖无参 `_init()`，调用 `super(metadata, skills)`；不要在运行时再次调用。 |
| `get_metadata()` | 返回 `Dictionary` 深拷贝 | 系统、UI、网络读取；自动补充 `skills: Array[String]`。通常不覆盖。 |
| `get_id()` | 返回稳定 `String` | 读取武将 ID；通常不覆盖。 |
| `get_skill_scripts()` | 返回 `Array[Script]` 副本 | 数据库校验技能路径和创建运行时实例；武将文件通常不直接调用。 |

武将本身不直接持有对局效果函数。所有会触发、修改数值、创建选择或保存运行时状态的能力必须写入 `game_data/skills` 中的技能文件，再由武将 `preload` 引用；这样多个武将可以复用同一技能而不复制代码。

### 体力与选将规则

- `max_hp` 是基础上限，当前体力在选将确认时初始化为相同数值。
- 对局人数不少于5人时，主公在武将基础上限上增加1点；2至4人局不增加。
- 所有登记武将会自动进入 `CharacterSelectionService` 候选池。
- 每名玩家默认展示5张候选，实际数量不超过武将库总数。
- 主公先选并立即公开，其他玩家完成前保持私密，全部完成后统一亮将。
- 武将技能在全员选将完成后创建独立实例并安装。

#### CharacterSelectionService 完整源码索引

| 成员或函数 | 类型或返回值 | 行为 |
|---|---|---|
| `PHASE_LORD` / `PHASE_OTHERS` / `PHASE_COMPLETE` | 常量 | `lord_selecting`、`others_selecting`、`complete`。 |
| `phase` | `String` | 当前阶段；空字符串表示未开始。 |
| `lord_player_id` | `int` | 主公稳定 ID；未解析为 `-1`。 |
| `candidate_count` | `int` | 默认5，开始时限制到1至武将库数量。 |
| `_player_ids` / `_character_ids` | 私有数组 | 参与玩家座次顺序和可用武将 ID副本。 |
| `_candidates_by_player` / `_selections_by_player` | 私有字典 | 每名玩家候选和已确认选择。 |
| `_rng` | 私有随机源 | 由控制器注入，与对局种子一致。 |
| `begin(players, character_ids, requested_candidate_count, rng)` | `String` | 清空旧流程、查找主公并只生成主公候选；无武将或无主公返回错误。 |
| `select_character(player_id, character_id)` | `String` | 复核阶段、玩家、重复提交和候选归属；主公完成后为其他玩家生成候选，全员完成进入完成阶段。 |
| `get_candidates(player_id)` | `Array[String]` | 返回候选强类型副本。 |
| `get_selection(player_id)` | `String` | 未确认返回空字符串。 |
| `get_pending_player_ids()` | `Array[int]` | 主公阶段只返回主公，其他阶段返回未确认的非主公，保持座次顺序。 |
| `to_dict(viewer_id)` | `Dictionary` | 只向当前可选择且未确认的观察者公开本人的候选；其他非主公具体选择在完成前隐藏。 |
| `can_player_select(player_id)` | `bool` | 根据阶段、身份和是否已确认判断。 |
| `_make_candidates(excluded_character_id)` | 私有 `Array[String]` | 洗牌后取不重复候选；候选池数量大于配置数时排除主公武将，否则回退完整池。 |
| `_shuffle(values)` | 私有 `void` | 使用对局随机源执行 Fisher–Yates 洗牌。 |

#### IdentityRules 与内容相关规则

`DISTRIBUTIONS` 保存2至10人标准身份数组。`get_distribution(player_count)` 返回强类型副本，范围外返回空数组。

`evaluate_winner(state)` 的源码规则：主公死亡时，若唯一存活者为内奸则内奸胜，否则反贼胜；主公存活且反贼、内奸均为0时主公与忠臣胜；其他情况继续。

| 函数 | 返回值与行为 |
|---|---|
| `get_death_reward(killer, victim)` | 击杀反贼返回 `draw_three`；主公击杀忠臣返回 `lord_penalty`；无效角色或其他关系返回空字符串。 |
| `_find_identity(state, identity)` | 私有查询，返回数组中首名该身份玩家或 `null`。 |

死亡奖惩由控制器执行实际摸牌或弃置，武将和技能文件不得直接修改 `DISTRIBUTIONS` 或绕过统一死亡流程。

## 内容制作检查清单

### 卡牌检查

- 文件是否位于 `game_data/cards`，并且只使用小写字母、数字和下划线命名。
- `id` 是否唯一，双名称、类别、目标、说明是否完整。
- `min_targets` 是否不大于 `max_targets`。
- `response_pattern` 与 `provided_response_pattern` 是否没有混淆。
- 有次数限制时是否填写正确的 `play_limit_group` 与拒绝文本。
- 基础 AI 是否需要配置 `ai_use_value`、`ai_target_attitude` 或 `ai_beneficial`。
- `resolution_mode` 是否与效果需要的目标数组一致。
- 所有异步响应和选择是否在等待时返回 `pending`。
- 异步卡牌上下文是否包含 `parent_card_uid`；异步装备是否同时包含定义 ID 与实体 UID。
- 延时锦囊是否在所有分支处理最终区域。
- 持续装备是否正确安装与卸载运行时订阅。
- 主动装备是否完整实现动作声明、可用性、校验、执行和预览五类钩子。
- 是否确认控制器、AI 和 UI 中没有新增本卡牌 ID 分支。
- 需要实体牌时是否已加入 `data/decks.json`。

### 技能检查

- 文件是否位于 `game_data/skills`，ID 是否唯一。
- `sample_only` 是否只用于尚未实现的占位技能。
- 主动技能是否设置 `ui_enabled=true` 并完整实现两个主动函数。
- 被动技能是否在 `install()` 订阅事件，并能在卸载时清理。
- 次数、冷却、目标和实体 UID 是否使用独立运行时变量保存。
- 选择上下文是否完全可序列化并包含 `skill_id` 与 `skill_owner_id`。
- 技能需要异步选择或响应时是否实现 `continue_choice()` 或 `continue_response()`。
- 技能需要基础 AI 主动发动时是否实现 `append_play_phase_actions()`。
- 是否确认控制器和 UI 中没有新增技能 ID 分支。

### 武将检查

- 文件是否位于 `game_data/characters`，显示名称是否为中文。
- `gender`、`faction` 和 `max_hp` 是否位于允许范围。
- 技能是否直接 `preload` 对应技能文件。
- 技能数组顺序是否符合技能栏展示需求。
- 插画路径不存在时是否接受占位图表现。
