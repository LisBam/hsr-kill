# 数据扩展指南

## 新增卡牌

1. 在 `data/cards.json` 新增唯一 `id` 和双名称。
2. 可选填写 `art_path`，推荐使用 `res://assets/art/cards/<卡牌ID>.webp`；未填写时自动显示占位图。
3. 选择已有 `effect_id` 复用通用逻辑；只有规则行为不同才新增效果执行器。
4. 配置目标模式、最少/最多目标、距离、响应、延时和重铸标记。
5. 若需要进入某套牌堆，在 `data/decks.json` 添加 `[花色, 点数, 卡牌ID]`。
6. 运行烟雾测试，确保引用、双名称和效果映射完整。
7. 同步更新《卡牌系统》和《游戏机制与玩法内容》。

牌堆可以新增任意 ID，不需要修改 `GameState` 或 `MatchController`。启动前把 `MatchController.default_deck_id` 指向新牌堆即可。

## 新增武将

1. 在 `data/characters.json` 的 `characters` 数组新增武将。
2. 必填字段为 `id`、`display_name`、`gender`、`faction`、`max_hp`、`skills`。
3. 可选填写 `art_path`，推荐使用 `res://assets/art/characters/<武将ID>.webp`；未填写时自动显示占位图。
4. 在 `skills` 数组登记每个技能的元数据。
5. 为实际技能创建独立组件，通过技能 ID 绑定，并订阅 `RuleEventBus`。
6. 若技能需要玩家主动点击，在技能元数据中补充 `ui_enabled: true`，并实现独立技能交互控制器；技能按钮只负责展示和发出技能 ID，不直接执行效果。
7. 不在控制器中编写 `if character_id == ...` 逻辑。

样例武将只用于证明数据接口，目前包含开拓者、三月七、丹恒、姬子、瓦尔特、布洛妮娅、景元和卡芙卡。项目允许武将数量少于玩家人数，演示开局会循环使用样例数据；正式选将系统应保证候选与禁用规则。

## 新增 AI

实现 `choose_action(snapshot, legal_actions)` 并在 `AICoordinator` 中登记。AI 可以读取权威快照，但只能返回 `PlayerAction` 字典。不要让策略引用 UI 节点、网络连接或直接调用核心结算函数。

## 新增传输适配器

监听 `packet_ready_for_transport`，把字典编码后发送；收到数据后调用 `receive_transport_packet(packet)`。传输适配器负责连接、重试、加密和可靠性，`NetworkGateway` 负责协议与游戏消息分流。

## 注释与文档要求

所有新增变量必须有独占注释，说明用途、数据含义、范围、默认值原因和修改影响。新增或调整机制必须同步模块文档与《游戏机制与玩法内容》，记录所有具体数值。已有变量名和注释不得擅自删除或改写。
