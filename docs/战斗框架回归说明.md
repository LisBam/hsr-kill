- 父事件取消后，普通子树与其选择/暂停回收，after执行一次；独立全局暂停保留，abort_all不留活动对象。
- 完成信号发布前父结果与事件栈已经提交；旧局应答、终态超时及不存在父事件的子任务不能复活流程。
- 7个伤害前窗口在等待时不扣血，恢复后读取最终修改；取消、护盾、结果窗口、换将和外层判定顺序正确，效果只写入一次。
- 15个用牌前置窗口支持异步取消，12个生命周期窗口严格按序；响应After可以创建新选择，处理区材料正常收尾。
- 等待期间卸载再安装同一技能对象不能复活旧订阅；正式【加护】的横置子选择结束后才授予1点护盾。
- 有限任务在真实进程帧间让步；同帧反复显式接管只留下1条合法连接，reset后连接数为0；不用看门狗代替正常推进。

## 回归过程中处理的诊断

- 旧延迟回调只修改代次而未断开帧信号，导致同帧接管后出现重复连接。控制器与事件调度器均显式保存和释放唯一连接，并用连接数断言覆盖。
- event_runtime 原有退出时12个ObjectDB实例/3个资源占用，定位为测试匿名回调捕获自身 TriggerManager 的引用环。测试在断言后通过正式 unsubscribe_owner 解除订阅，最终复跑不再出现告警，不关闭引擎泄漏检查。
- 广域首轮斗地主有一次退出时2个ObjectDB实例/1个资源占用；后续连续3次复跑未复现。该偶发退出观测不作为稳定修复结论，后续若复现应继续保留 verbose 对象明细。最后一次斗地主回归无错误或警告。
- skill_settlement_runtime 的 faults=1 是故意注入无法识别技能续接的负例断言，验证局部保护生效；不是正常新流程依赖熔断才能结束。

本轮修复与验证结论：

- 核心修复：`SkillDefinition._can_receive_timing_event()` 的统一“局内获得技能额度”检查原本对**所有**技能调用控制器端口，而该端口对死亡角色一律返回 `false`，使“覆盖 `can_trigger_while_owner_inactive` 以在死亡后完成持续效果清理”的分支对固有技能永远不可达（例如【酩酊】的持有者死亡清理）。现在该检查只在技能确实位于 `player.acquired_skills` 时执行，活着的角色行为完全不变。
- `conquest_coop` 的“各自选择”流程原本盲目提交 `get_candidates(0)[0]`；玩家2为内置AI并会先于真人确认武将，武将池增加真珠后恰好占用了真人候选首项，导致真人提交被服务拒绝（“该武将已经被其他玩家选择”）。测试改为挑选首个未被其他玩家占用的候选；这与既有 `control_all_characters_test` 记录的“固定种子随武将池变化换人”属同一类问题。
- `gameplay_regression` 的延时锦囊表现场景原本固定等待0.12秒（四段0.02秒节拍加余量）；在顺序跑完数十个场景后单帧调度变慢，曾出现“四次表现完全正确、但阶段仍为 judgment”的假失败。现改为按条件等待（表现收齐且阶段进入 `play`），保留2秒兜底，真正卡住时仍以实际观测值失败。
- `doudizhu_mode`、`gameplay_pause` 退出时的资源告警为 `AudioStreamMP3`（`res://game_data/BGM/battle.mp3`）播放泄漏，用 `--verbose` 可定位到具体实例，与本轮改动无关；本轮36项复跑未复现，与既有“偶发观测、不作为稳定修复结论”的记录一致。
- `smoke` 本轮的标记为 `SMOKE_PASS running phase=play turn=22 actions=188`：该测试对“跑到胜局”和“帧预算用尽仍在进行”两种结果都判定通过，武将池变化会改变固定种子对局的长度，因此标记文本可能在这两种合法结果之间变化。

本轮未覆盖：换将（`swap_player_character_cards`）在补缀记录未到期时替换真珠的后续表现、B 为装备牌时其他装备类型（武器/坐骑/宝物）的逐槽验证、以及真实联机下 `roundEnd` 选择与轮末流程的同步；这些边界沿用“技能实例卸载即失去实例内记录”的既有结论。

## 主演与支离回归（2026-09-30）

新增 `zhuyan_zhili_test` 专项用例，并复跑全量 71 项（不含需要派生第二进程、占用本机 UDP 回环的联机用例）：

- 主演：角标条目 `zhuyan`（文本“主演”、排序值 `50`）在四名角色间始终保持全场唯一，新主演顶替旧主演时旧条目被摘除，重复设为同一人为幂等，对不存在/已死亡/已离场角色设置无效且无副作用；`get_starring_player_id()` 在无人主演时返回 `-1`。
- 座次相邻：四人局一号位返回 `[2, 0]`、零点位返回 `[1, 3]`；跳过已离场角色并顺延；仅剩一名存活角色时返回空集合。查询为纯函数，不写状态、不派发时机。
- 四条技能的 `name`/`description` 与设计原文逐字一致（含全角标点、【】、`X`、全角引号 `“主演”`），锁定技标签分别为【悬壶】`lock=true`、【支离】`lock=true`，【生息】与【万死】为非锁定。
- 【悬壶】：手牌上限豁免只作用于弃牌阶段溢出张数的扣减（`get_hand_limit()` 本身仍为 `3`）；死亡后从句牌堆取得第一张【桃】，牌堆中没有【桃】时不产生任何效果。
- 【生息】：二选一窗口、`X` 初值 `1` 且只增不减、累加在**使用基本牌时所在回合**结束的 `phaseAfter` 兑现（订阅 `role="global"` 并按回合角色分桶，因此他人回合打出的【闪】在那个回合结束时兑现，持有者自己的回合结束不会误兑现他人回合的登记）、每回合额度按全局回合号惰性刷新。
- 【万死】：体力恰为 `1` 时确认后于本回合结束依次成为主演并执行一个额外回合；体力经护盾吸收伤害而未变化时不触发。受伤通常发生在**对手回合**，因此时机订阅 `role="global"` 并按“登记的回合角色 + 登记的回合号”双重匹配：该登记在对手回合结束兑现，与登记无关的第三个角色回合结束不兑现。
- 【支离】：自己是自己使用【杀】的合法目标且距离限制被一并放开；使用时唯一目标被整体改写为座次相邻角色并与只读预览一致；结算完毕后无条件失去 `1` 点体力（含改写后命中持有者本人、无合法相邻角色仍照付两种边界）；任意主演使用【杀】造成正数伤害时该主演回复 `1` 点体力。
- 回归类断言：`GameDatabase.validation_errors` 为空（新增内容通过双向校验）；四项技能都不提供出牌阶段主动按钮，因此结构上不存在“发动→取消”空转路径；两个可取消窗口的最优选项分数严格高于取消的 `0` 分——【生息】在 `X` 大于与不大于手牌数两种局面下分别让摸牌项与累加项严格为正、另一项为 `0`，【万死】在体力恰为 `1` 时确认分为正、体力已变化时为负。`zhuyan_zhili_test` 专项用例现已覆盖设计文档验证设计的全部 23 条断言。

本轮修复与验证结论：

- 武将库规模由 45 增至 47 后，固定种子选将与过关斩将换将结果再次换人，暴露三处**测试侧**脆弱性（核心规则无缺陷，均已用 `git stash` 回退基线确认是本次内容增长引入）：`conquest_mode_test` 假设敌方一定是可被【杀】指定的在场目标，但换到的**貊泽**是离场技武将（【幽锋】每轮开始时强制离场）；`conquest_coop_test` 假设强制窗口只需提交目标，但貊泽【幽锋】创建的是**不可取消的选牌窗口**；`conquest_save_test` 假设强制窗口回退总有候选牌，但换到的玩家武将是**海瑟音**，其【泛音】黑色效果创建的是**纯目标窗口**，原实现在候选牌为空时直接放弃提交，导致等待存档的循环空转。现三处统一为“取消优先 → 按权威窗口下发的首个候选做牌+目标+文字选项三者一并确认”，并按窗口声明的 `min_select` 一次提交足够张数；`conquest_mode_test` 另在建立候选前对离场敌人调用 `restore_player_to_game()`。
