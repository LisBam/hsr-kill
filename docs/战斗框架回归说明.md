替换为本机 Godot 控制台程序路径，项目根目录执行：

```powershell

New-Item -ItemType Directory -Force .godot_test_logs | Out-Null

& '你的Godot控制台程序.exe' --headless --path . --scene res://tests/damage_sequence_test.tscn *> .godot_test_logs/damage_sequence.log
```

其余场景同样替换 tests 下的测试文件名。各 Godot 进程顺序执行，避免共享用户设置导致交叉污染。技能选择、丰收等夹具显式固定开局模式并关闭自定义选将、AI选将调整及手气卡干扰；机缘悬停测试使用独立正式面板实例，避免活跃对局刷新释放被测控件。

判定以**进程退出码与输出**为准，日志文件只是留痕：`.godot_test_logs/` 每次运行都会被同名文件覆盖，因此目录已被 `.gitignore` 忽略，回归结论统一记录在本文件，不要把日志本身当作交付物入库。

## 核心断言

- 父事件取消后，普通子树与其选择/暂停回收，after执行一次；独立全局暂停保留，abort_all不留活动对象。
- 完成信号发布前父结果与事件栈已经提交；旧局应答、终态超时及不存在父事件的子任务不能复活流程。
- 7个伤害前窗口在等待时不扣血，恢复后读取最终修改；取消、护盾、结果窗口、换将和外层判定顺序正确，效果只写入一次。
- 15个用牌前置窗口支持异步取消，12个生命周期窗口严格按序；响应After可以创建新选择，处理区材料正常收尾。
- 等待期间卸载再安装同一技能对象不能复活旧订阅；正式【加护】的横置子选择结束后才授予1点护盾。
- 有限任务在真实进程帧间让步；同帧反复显式接管只留下1条合法连接，reset后连接数为0；不用看门狗代替正常推进。
- 翻面跳过一整个回合：被跳过的回合没有回合开始与回合结束，**全部回合开始时机**（回合分隔日志、`phase_start`、`phaseBefore`、`phaseBeforeStart/End`、`phaseBeginStart/Begin`）与 `phaseJieshu`、`phaseAfter` 一律不派发，因此全局“回合开始时”技能（如【巡礼】）不会在跳过回合被询问；`_complete_finish_turn` 的回合结束收尾（手牌临时牌名到期、卡牌定义 `on_turn_ended`）不在跳过回合执行，效果顺延到该角色下一个真正结束的回合；跳过回合仍推进回合轮转与轮末/额外回合队列。轮级步骤（限时离场恢复、临时技能到期与 `roundStart`）仍排在翻面检查之前。

## 回归过程中处理的诊断

- 旧延迟回调只修改代次而未断开帧信号，导致同帧接管后出现重复连接。控制器与事件调度器均显式保存和释放唯一连接，并用连接数断言覆盖。
- event_runtime 原有退出时12个ObjectDB实例/3个资源占用，定位为测试匿名回调捕获自身 TriggerManager 的引用环。测试在断言后通过正式 unsubscribe_owner 解除订阅，最终复跑不再出现告警，不关闭引擎泄漏检查。
- 广域首轮斗地主有一次退出时2个ObjectDB实例/1个资源占用；后续连续3次复跑未复现。该偶发退出观测不作为稳定修复结论，后续若复现应继续保留 verbose 对象明细。最后一次斗地主回归无错误或警告。
- skill_settlement_runtime 的 faults=1 是故意注入无法识别技能续接的负例断言，验证局部保护生效；不是正常新流程依赖熔断才能结束。

## 额外出牌阶段死锁与轮回节阶段额度回归（2026-10-04）

## 翻面跳过回合仍派发回合开始时机（2026-10-05）

- **触发条件**：任意角色背面朝上、轮到他的回合开始。**用户可见现象**：本不该存在的回合仍然给出了【巡礼】（`phaseBefore`，`role = "global"`）的发动询问，并在日志里写出“某某的回合开始。”。
- **根因**：`TurnStartService.resolve()` 的稳定游标把 `_check_face_down` 排在 `_log_begin` 与 `_emit_turn_window("phaseBefore")` **之后**（原顺序 `roundStart → 日志/phase_start → phaseBefore → 翻面检查 → phaseBeforeStart → …`）。于是被跳过的回合照常派发了两项回合开始时机：`phase_start`（旧兼容时机，与回合分隔日志同属 `_log_begin`）与 `phaseBefore`。这与既有文档「翻面跳过一整个回合：被跳过的回合没有回合开始」直接矛盾——此前只把“没有回合开始”理解为“不派发 `phaseBegin/phaseJieshu/phaseAfter`”，而 `phaseBefore` 被当作翻面判定前的“维护窗口”保留，导致所有全局“回合开始时”技能（【巡礼】【振旗】【摄伏】【暗刻】以及【幻影】的兜底返场）都会在一个不存在的回合里触发。
- **实测证据（修复前）**：`yinzhi_xunli_lijie_test` 输出 `YINZHI_FAIL face_down_turn_offered_choice={ "kind": "xunli_activate", "turn_player_id": 0, … }`，同一次运行的日志为 `["…锁定技保持背面向上。", "…锁定技无法翻至正面。", "————————", "银枝（一号位）的回合开始。"]`——跳过回合确实写出了“回合开始”并建立了技能窗口。
- **修复（单点顺序调整，不新增端口或队列）**：`TurnStartService.resolve()` 把 `_check_face_down` 提到 `_log_begin` 与 `phaseBefore` **之前**，新顺序为 `roundStart → 翻面检查 → 日志/phase_start → phaseBefore → phaseBeforeStart → phaseBeforeEnd → phaseBeginStart → phaseBegin → phaseZhunbei`。轮级步骤（`_restore_round_players`、`_emit_round_start`：限时离场恢复、临时技能到期与 `roundStart`）**保持在检查之前**，它们属于“轮”而不属于被跳过的那个回合；若一并后移，新轮恰好落在跳过回合时整轮效果会永久丢失。翻面判定本身仍先执行 `enforce_face_down_lock()`，因此「武将牌始终背面向上」的兜底纠正与普通背面角色走同一条跳过分支。
- **可预期结果（内容层必须知道）**：①被跳过的回合不再有任何回合开始窗口，持有者自己的 `phaseBefore` 技能（【鸿运】【遥塔】【红云】【升变】【破风】【谍影】【追箭】等）在该回合不触发——这正是“没有回合开始”的直接推论；②以“你的下个回合开始”为到期点的效果在跳过回合**不到期**，顺延到下一个真正开始的回合（与【酩酊】既有口径一致：它本来就用 `phaseBegin` 表达“下一个实际回合”）；③【幻影】的返场不依赖 `phaseBefore`：跳过分支照常派发 `phaseOver`（带 `turn_number`），其主路径即 `phaseAfter`/`phaseOver`，`phaseBefore` 只是兜底。
- **回归覆盖**：①`yinzhi_xunli_lijie_test._test_face_down_lock()` 改为断言“跳过回合**没有**巡礼窗口、日志不含该角色的回合开始、随后仍推进到下家真实回合（下家真实回合的巡礼窗口照常出现并取消）”；②`phase_progression_test._test_face_down_turn_progression()` 新增 `phase_start / phaseBefore / phaseBeforeStart / phaseBegin` 四项计数断言（各恰好 `1` 次，即只来自下家的真实回合）。
- **反向验证**：把 `_check_face_down` 临时移回 `phaseBefore` 之后复跑，`phase_progression_test` 稳定失败在 `PHASE_PROGRESSION_FAIL face_down_turn_start_timings={ "phase_start": 2, "phaseBefore": 2, "phaseBeforeStart": 1, "phaseBegin": 1 }`——精确指出泄漏的只有 `phase_start` 与 `phaseBefore` 两项，且证明新断言具有区分力；恢复修复后退出码 `0`（`YINZHI_PASS` 与 `PHASE_PROGRESSION_PASS`）。
- **本轮未覆盖**：跳过回合恰好落在**新轮第一回合**时的 `roundStart` 组合（轮级步骤刻意保持在检查之前，未单独构造对照用例）；以及回放/局域网下“跳过回合没有回合开始日志”的跨端表现一致性（仅验证规则层日志与快照字段）。
