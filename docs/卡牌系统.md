# 卡牌系统

## 生命周期结算契约

详细顺序见[战斗结算框架](战斗结算框架.md)。卡牌继续从正式用牌接口进入 `CardUseEvent`，定义脚本不直接操作事件栈、暂停令牌和处理区收尾。

- 整牌、逐目标及【杀】的 Before/Begin/End/After 逐个等待技能和子选择；目标主体执行前再次确认没有被排除。
- `useCard0/1/yingbian/2/useCard` 和目标分发窗口完成后读取原 `RuleEvent` 最终数据。异步取消、直接命中、排除目标都必须生效。
- 目标取消与整牌取消作用域不同；处理区材料仍走原收尾，不能通过清空全局队列恢复游戏。
- 响应接受后先清除旧询问，再发布响应After；After的新交互完成后应用保存的原响应结果，不能重复消费响应牌。
- `run_steps()` 可用于顺序规则效果，但不能假定所有虚拟用牌调用都已支持自动等待；专用选择、判定、响应仍使用正式恢复契约。

这些约束不改变卡牌文本、伤害、次数、目标数或费用。

## 数据来源与牌堆

默认牌堆 ID 为 `standard_162`，严格对齐项目内置《三国杀官方规则集 3.0》的身份局牌表，共 162 张。牌堆包含 1 张方块 Q【银月枪】与 1 张方块 5【木牛流马】，不包含国战专属牌。

`game_data/cards` 保存46个独立卡牌源码文件。每个文件同时包含稳定 ID、双名称、类型、目标、距离、配置化次数、响应、AI 价值、说明、最终区域、同步效果和异步恢复函数；`GameDatabase` 扫描目录后自动建立索引，不再读取集中卡牌 JSON。`CardEffectResolver` 只定位卡牌定义并按父牌 UID恢复选择、响应和无懈流程，不保存任何具体牌效。目标顺序与组合校验、濒死救援、回合专属状态、延时传递和装备动作均通过卡牌钩子回到对应文件；控制器和基础 AI 不维护具体卡牌 ID 白名单。普通【杀】、火【杀】和雷【杀】分别使用 `sha.gd`、`huosha.gd` 和 `leisha.gd`，实体牌直接携带伤害属性，三个文件显式复用专属 `SlashCardEffect` 牌族组件。三者规则牌名均为【杀】；“火【杀】”“雷【杀】”只区分属性，卡牌显示仍固定为两个字“火杀”“雷杀”。所有需要比较牌名字数的游戏规则固定优先读取非空 `rule_name`，未声明规则名时才读取 `custom_name`（《崩铁杀》牌名），不受界面当前名称模式影响；因此火【杀】与雷【杀】均按规则名“杀”的一个汉字计算，其余牌仍按《崩铁杀》牌名计算。

卡牌文件使用小写拼音命名，并允许加入数字和下划线，例如【顺手牵羊】为 `game_data/cards/shunshouqianyang.gd`，扩展版本也可使用 `shunshouqianyang_2.gd`。文件名只负责源码定位；牌堆、网络、回放、存档和规则判断始终使用文件内声明的稳定 `id`，因此调整文件组织时不得同时擅自改变逻辑 ID。

### 专属锦囊牌的数据流差异

专属锦囊牌（元数据 `"exclusive": true`，读取入口 `CardDefinition.is_exclusive() -> bool`）在数据流上与本表其余卡牌有三处差异：

1. **不进入 `data/decks.json`**。专属牌的定义由 `GameDatabase` 正常扫描登记，但**没有任何牌堆引用它**，因此开局洗牌、摸牌、重排都不会产生它。这不是错误：`GameDatabase._validate_decks()` 只做「牌堆 → 卡牌」单向校验，没有「每张牌必须入堆」的反向检查；同类先例为未进入默认牌堆的【水淹七军】。
2. **运行期由技能或其他效果加入游戏**。加入统一走端口 `MatchController.create_and_insert_card_into_draw_pile(definition_id, suit = "", rank = 0, position = 1) -> int`：端口先校验对局未终局、定义存在、位次合法，再用 `CardInstance.new(definition_id, suit, rank)` 造出**全新实体牌**，经唯一移牌边界 `CardMovementService.insert_new_card_into_draw_pile()` 按位次落入 `draw_pile`，产生恰好 1 条 `card_moved` 增量与 1 条移牌历史。缺省或非法牌面时改用本局权威随机源并写入 `state.random_history`（`kind = "exclusive_card_insert"`），因此存档恢复与回放重演得到同一组牌面。`position` 除 `1`（牌堆顶第一张）与 `2`（第二张）外还接受 `0`（`DRAW_PILE_POSITION_RANDOM`）：由权威随机源在 `1..当前牌堆张数+1` 内均匀选位，并把抽到的位次写进随机历史，这是「随机加入」的唯一实现方式（不新增第二个随机源）。**全新实体牌不能使用 `move_card()`**：该方法要求牌已在某区域内，新牌默认 `zone = "draw_pile"`，会被「来源区域等于目标区域」的重复判据拒绝。
3. **牌面可以自带**。普通牌的牌面来自牌堆条目，专属牌没有牌堆条目，因此**必须**由卡牌文件自己声明 `suit`/`rank`；端口在调用方未给出显式牌面、且定义声明了牌面时优先使用定义声明的值（当前唯一实现为【言灵】的**梅花K**：`suit = "club"`、`rank = 13`），只有定义也没有声明时才回落到随机花色点数。

图鉴侧不受影响：`all_cards_panel` 直接枚举 `GameDatabase.cards`，因此专属牌自动收录，不因未入牌堆而消失（只缺代表花色点数）；类型文本会前置「专属」标识并进入搜索文本。牌面底部标签同样前置「专属 · 」。

## 主菜单卡牌图鉴

- 主菜单“所有卡牌”中的“所有游戏牌”直接枚举 `GameDatabase.cards`，每个稳定定义 ID 对应1张 `CardView`，不从162张牌堆实体重复生成同名牌。新增独立卡牌源码后，数据库自动发现与图鉴再次打开共用同一索引，不需要维护图鉴白名单。
- 图鉴游戏牌使用固定类型顺序：基本牌、锦囊牌、装备牌。基本牌按杀、闪、桃、酒分组，普通/火/雷【杀】通过共同 `rule_name="杀"` 归入同组；锦囊牌按普通锦囊、延时锦囊分组，除 `subtype="delayed"` 外的锦囊均属于普通组；装备牌按武器、防具、进攻坐骑、防御坐骑、宝物分组。每个同组内部再按当前玩家可见名称与稳定ID排序，未知扩展类型或子类型排在对应正式分组之后。
- 图鉴牌面仍使用正式111×148像素 `card_view.tscn`，默认在网格中缩放为0.90倍。代表花色点数按已登记牌堆稳定ID顺序扫描，并取对应定义首次出现的实体配置；未进入任何牌堆的扩展定义仍可显示牌名、类别、插画与说明，只把花色点数留作空回退。代表牌只服务静态浏览，不创建 `CardInstance`、实体UID生命周期、手牌分区或用牌动作。
- 游戏牌搜索同时索引稳定ID、`original_name`、`custom_name`、`rule_name`、`type`、`subtype` 与 `description`。玩家可以使用三国杀名或崩铁杀名搜索，不受当前显示模式限制；点击牌面后资料标题与正文继续通过 `GameSettings.resolve_card_display_name()` 和 `GameDatabase.resolve_card_names_in_text()` 解析，因此名称切换与正式手牌、技能说明保持一致。
- “所有武将牌”和“所有机缘牌”子分页分别读取 `GameDatabase.characters` 与 `OpportunityCatalog.get_all_cards()`；武将牌按星穹列车、银河学者、贝洛伯格、仙舟联盟、匹诺康尼分组，未列出的扩展势力随后按势力名稳定排列。武将详情左侧复用正式武将牌，右侧用黄色技能名显示固有技能。选将面板的“所有武将”入口复用同一势力顺序，保证开局前图鉴浏览与开局选将看到一致的武将排列。三个子分页与游戏牌图鉴只共享分类、搜索和资料模态，不把武将、游戏牌、机缘合并为同一种规则对象。

## 卡牌 AI 数据

46个卡牌文件均在自身元数据中声明 `ai` 字典，对齐无名杀 `card/standard.js` 与 `card/extra.js` 的 `ai.basic/order/result/tag/equipValue/expose` 结构。基础 AI 只读取这些内容数据，不在中央策略维护卡牌 ID 分支。

通用字段包括出牌顺序 `order`、手牌保留价值 `value`、装备价值 `equip_value`、使用者结果 `player_result`、目标结果 `target_result`、伤害与属性标签、响应【杀】/【闪】标签、回复、救援、摸牌、失去牌、获得牌、跳阶段、多目标、通常正面效果与身份暴露度。当同一张牌的保留价值需要随场面变化时，在卡牌文件覆盖 `modify_ai_hand_value()` 动态重算（基类默认原样返回静态 `value`），由 `NonameAIEvaluator.get_card_value_by_id()` 在静态取值与既有特例之后调用；返回值同时用于弃牌排序、用牌机会成本与濒死救援成本，因此“救命牌值多少分”有唯一入口，不需要在基础 AI 里维护牌名白名单。

牌效估值使用身份态度组合目标结果。伤害牌对1点体力目标的效果倍率为2.5，对2点体力目标为1.8；目标0张手牌时通常为1.5，需要响应【杀】或【闪】时为1.7；1张手牌为1.3，2张为1.1，3张及以上为0.5。目标已知拥有所需【闪】或【杀】时预期倍率再乘0.35，没有已知【闪】但装备【八卦阵】时再乘0.65，1点体力且已知拥有【桃】或自救【酒】时再乘0.7。火焰和雷电伤害会继续估算横置角色的连环传播：使用者自身横置时自伤损失乘1.5，任一传导受击者为1血时乘2.5，自己1血时再减12.0分；伤害类群体锦囊也会逐名检查1血友方。预计击杀已确认反贼加3.0分，击杀已确认队友减8.0分，主公击杀忠臣额外减 `12.0 + 2.0×(手牌数+装备数)` 分；未知身份不会读取真实阵营。回复牌对满体力目标收益为0；这些倍率只影响 AI 选择，不改变卡牌实际结算。出牌阶段的【桃】还会额外比较“现在回复自己”与“把这张桃留给队友后续救援”，并让这张桃的**保留价值随队友危险度浮动**（对应无名杀 `ai.basic.useful`）。留桃判定按顺序排除“桃数超过手牌上限 / 手牌溢出超过2张珍贵牌 / 多张桃时已溢出 / 自己是受伤或缺牌的领袖 / 没有队友”后，取保留分初值（无溢出 `2.0`，有溢出 `0.0`），存在残血友方领袖时固定为 `3.0` 并直接留桃，否则溢出正好 `2` 张或自己体力不超过 `1` 时吃桃；随后手上【桃】不超过体力的一半（`2 × 桃数 ≤ 体力`）时降级为 `1.0`，并**只在保留分为正时**才按队友体力差累加危险度（保留分为 `0` 时跳过累加并吃桃，与无名杀 `if (keep && …)` 一致），严格大于 `2.0` 即留桃（动作分扣 `8.0` 后压到 `-0.01`），AI 因此主动结束出牌阶段而不消耗这张【桃】。珍贵牌门槛为 `8.1 − 4.5 × 体力 ÷ 体力上限`，【桃】本身无条件计入珍贵牌。识别队友使用**真实阵营关系**而非暴露度衰减态度，因为留牌不可观察且身份局开局暴露度恒为 `0`；动态价值为：有濒死与受伤待救者时 `5×濒死 + 3×受伤`（至少 `8.0`）、只有一类且超过一份时 `8.0`、自己体力比例低于 `0.7` 时 `7.0 + |比例 − 0.5|`、只有濒死 `7.0`、只有受伤 `max(3.0, 7.8 − 同名牌序号)`、无人待救 `max(1.0, 7.2 − 同名牌序号)`，夹到 `1.0` 至 `10.0` 分。完整口径与全部阈值见《AI 模块》与《游戏机制与玩法内容》。公开身份观察同样从卡牌源码调用 `get_identity_observation_ai_profile()` 取得逐目标牌效：回复牌对满体力目标固定为0，【铁索连环】对未横置目标使用-0.5、对已横置目标使用+0.5，避免把无实际回复或解除连环误判为相反阵营行为。

复杂牌仍在自身文件提供专属 AI：铁索连环枚举包括自己在内的全部单目标与不重复双目标组合，并根据每名目标当前横置状态同时反转行动评分和身份观察方向；三人及以上局面中，若任一使用动作没有正收益目标，或总使用收益未比同一实体牌重铸摸1张的收益高出 `0.15` 分，AI 选择重铸而非消耗该牌；恰好2名存活在场角色的1v1局面则固定重铸并摸1张，不评估目标收益。借刀杀人在使用动作中直接枚举“持刀者、被【杀】者”的完整合法双目标组合；闪电根据身份局势决定是否使用；木牛流马依据手牌溢出与材料价值存粮；丈八蛇矛枚举两张普通手牌组合并扣除材料价值。技能或装备转化出的虚拟牌通过 `build_ai_virtual_card_action()` 进入与实体牌相同的卡牌专属和持有者被动技能评分链，基础目标牌效只计算一次。AI 会把未被无视防具的仁王盾对黑色【杀】、藤甲对普通【杀】、【南蛮入侵】和【万箭齐发】的确定免疫按 `ARMOR_VOID_TARGET_PENALTY = -0.5`（半张牌资源价值）的**明确负收益**处理，不再按0处理；把白银狮子对单次大于1点伤害的预期承伤封顶为1，并把火焰伤害目标收益乘2.0。若所有实际目标均被防具拦截，策略只在移除 `order` 排序分后仍有严格正向的卡牌或技能联动收益时使用该牌；否则跳过。因此单纯攻击不会消耗实体牌（被无效目标自身已是负收益），而【星火】等独立技能收益幅度足以覆盖 `-0.5` 时仍可保留无效【杀】。【全垒】会用转化前后相同目标的收益差抵扣普通【杀】材料成本，因此藤甲使普通【杀】无效但不拦截雷【杀】时会优先转化。【酒】先比较合法【杀】的完整直接评分与“酒后该【杀】评分 + 实际增伤 - 0.5分机会成本”；只有后者严格更高且仍为正收益时主动使用，因此无论合法动作枚举顺序如何都会先酒后杀。次数耗尽、无合法后续【杀】、无合法敌方目标或白银狮子令增伤无收益时不喝酒。【火攻】若对某目标未造成正数伤害，会在当前使用者本回合内避开该目标。卡牌效果、AI 配置、身份观察与专属 AI 钩子必须同步维护，不能只更新其中一侧。

## 是否为伤害牌

每个卡牌定义可选择声明顶层字段 `is_damage`（布尔，缺省 `false`），语义是**规则事实口径**：使用或结算这张牌时其自身效果会对目标造成伤害。读取入口是 `CardDefinition.is_damage_card()`，内容层禁止为此另建牌名白名单；【弃和】这类“成为伤害牌目标时”的技能一律读取该字段。

| `id` | 文件 | 伤害来源 |
|---|---|---|
| `sha` | `sha.gd` | 【杀】 |
| `sha_fire` | `huosha.gd` | 火【杀】 |
| `sha_thunder` | `leisha.gd` | 雷【杀】 |
| `juedou` | `juedou.gd` | 【决斗】 |
| `nanman` | `nanmanruqin.gd` | 【南蛮入侵】 |
| `wanjian` | `wanjianqifa.gd` | 【万箭齐发】 |
| `huogong` | `huogong.gd` | 【火攻】 |
| `shuiyanqijun` | `shuiyanqijun.gd` | 【水淹七军】 |
| `shandian` | `shandian.gd` | 【闪电】（延时，判定结算时造成 3 点雷电伤害） |

当前共 **9** 张牌标记为伤害牌。装备牌一律保持 `false`：即便【古锭刀】【寒冰剑】【麒麟弓】【银月枪】等装备会条件性地造成或改写伤害，那也是装备效果的产物而不是“这张牌本身结算伤害”，同理【白银狮子】【藤甲】这类改写承伤的防具也不标记；其余基本牌、锦囊牌与装备牌同样都是 `false`。

`is_damage` 与 `ai.damage` 是**两个独立口径**：前者是规则事实，后者是 AI 估值标签。两者当前对这 9 张牌完全一致，但既有 AI 读取点继续读 `ai.damage`，新增伤害牌判定必须读 `is_damage`；`tests/qingque_mechanics_test.gd` 会断言两个集合完全相等，防止日后只改一侧。

## 双名称配置

每个卡牌定义同时包含：

- `rule_name`：可选规则称呼；火【杀】与雷【杀】填写“杀”，不参与牌面显示。
- `original_name`：原版三国杀名称。
- `custom_name`：《崩铁杀》自定义名称。
- `id`：永不随显示名称变化的逻辑 ID。

`GameSettings.card_name_mode` 新启动时默认为 `CUSTOM`，因此主菜单与局内菜单首先显示《崩铁杀》自定义牌名；玩家可在任一设置入口切换为 `ORIGINAL` 显示原版三国杀牌名。该设置只改变前端文本，卡牌合法性、效果、AI、网络消息和存档始终使用 `id`，因此切换名称不会创建第二套逻辑。

武将技能源码只保存一份需求钦定原文，不维护第二套技能描述。原文中的完整 `【牌名】` 可以写已登记卡牌的原版名或崩铁杀名；展示时 `GameDatabase.resolve_card_names_in_text()` 按完整括号逐段精确匹配 `original_name/custom_name`，再统一映射为当前名称模式，避免先后替换造成级联误改。名称模式变化后，技能按钮、已经打开的统一悬停信息和武将详情都会原位刷新，因此技能说明与手牌、装备和判定牌同步切换；普通叙述文字、规则数值、标点和技能稳定 ID 不参与替换。

## 卡牌插画字段

卡牌定义可选填写 `art_path`，例如 `res://assets/art/cards/sha.webp`。该字段只由 `CardView` 通过 `ArtworkLoader` 读取，不参与牌堆构建、规则合法性、效果执行、AI、网络动作、回放或存档判断。

未填写或资源无效时，牌面中部显示统一占位区。后续补充插画只需导入资源并填写路径，不需要修改 `CardInstance`、`GameState` 或卡牌效果代码。

牌面底部类别由 `CardView` 统一解析。`basic` 显示“基本牌”，`trick` 显示“锦囊牌”；`equipment` 不再统一显示父类型，而是按 `subtype` 把 `weapon/armor/offensive_mount/defensive_mount/treasure` 分别显示为“武器牌”“防具牌”“进攻坐骑牌”“防御坐骑牌”“宝物牌”。未知装备子类型回退“装备牌”，未知主类型回退“卡牌”；该文本只帮助识别，不改变装备槽、牌效或规则类型。

### 使用牌目标合法性（含强制用牌）

「使用牌不可被指定为目标」只有一条权威链路：`SkillDefinition.validate_incoming_card_target_selection(actor_id, card_definition, card_color)` → `MatchController.validate_incoming_skill_card_target_selection()` → `CardRuleService._validate_target()`。`validate_use()`、`validate_virtual_use()`、`list_legal_targets()`、`list_legal_virtual_targets()` 四条正常用牌链路都走它，核心层不维护任何牌名或技能白名单。

强制用牌（【借刀杀人】要求持刀者使用的【杀】）不新增机制，而是接入同一份判定：`CardRuleService.list_legal_targets_for_definition()` 与 `validate_target_only()` 是与出牌阶段、当前行动者、持牌区域和使用次数无关的**单目标资格查询**，供“执行者不是当前行动者”的场景枚举与声明目标（调用方仍应显式传入 `{"ignore_phase_limit":true, "ignore_play_count_limit":true}` 等既有纯数据覆写）；`validate_entity_card_target(actor_id, card, target_id)` 用实体牌真实颜色（含转化牌聚合颜色与手牌标记覆写）复核，专供执行者交出真实牌之后调用。三个入口都是纯查询：不消费次数、不移动牌、不创建选择，也不咨询用牌禁令钩子。

`_validate_target()` 有一个必须记住的边界：当牌源码 `preserves_requested_target_order()` 返回 `true`（例如【借刀杀人】）且传入的目标数组长度大于 1 时，它会直接判定通过。因此**任何目标复核都必须传单元素目标数组**，否则被指定的角色会绕过全部来牌限制。

### 装备牌

武器、防具、进攻坐骑、防御坐骑和宝物分别占用唯一装备槽。界面固定按武器、防具、防御坐骑、进攻坐骑、宝物从上到下显示（防御坐骑在进攻坐骑上方，槽位ID与规则数值不随显示顺序改变）；进攻与防御坐骑图标分别为 `-` 与 `+`。第一视角本地装备栏常态显示全部五槽，外层固定150×148像素并与手牌牌面等高，五槽各占29.6像素且相邻间距为0。空宝物槽与其他空槽统一使用深色底框与类型图标，不显示“无”且不触发自动补位。本地玩家装备只在左侧装备栏显示，不在右下武将牌重复绘制；其他玩家仍在武将牌中显示公开装备。替换装备时，旧装备进入弃牌堆并执行离开装备区效果。所有武器的前端显示名在当前名称后追加攻击范围，例如“银河球棒 3”；该后缀不改变逻辑 ID、距离或数值。

装备 `subtype` 与装备槽使用 `EquipmentSubtype` 的唯一映射：`weapon -> weapon`、`armor -> armor`、`offensive_mount -> offensive_mount`、`defensive_mount -> defensive_mount`、`treasure -> treasure`。新增装备必须填写其中一个稳定子类别和同名 `slot`；未知值不能默认落入宝物槽。按子类别随机装备时，同一轮最多选择每个子类别1张。

- 武器：诸葛连弩、青釭剑、雌雄双股剑、贯石斧、青龙偃月刀、丈八蛇矛、方天画戟、麒麟弓、寒冰剑、古锭刀、朱雀羽扇、银月枪。
- 防具：八卦阵、仁王盾、白银狮子（崩铁杀名【光能盾牌】）、藤甲。
- 防御坐骑：绝影、的卢、爪黄飞电、骅骝，其他角色计算距离 +1。
- 进攻坐骑：赤兔（崩铁杀名【斯科特】）、大宛（崩铁杀名【泡泡】）、紫骍，装备者计算距离 -1。
- 宝物：木牛流马。

已实现的装备结算包括【杀】次数、攻击范围、无视防具、异性触发、弃两牌强命中、追杀、两牌转【杀】、最后手牌额外目标、选择弃置坐骑、银月枪回合外黑色手牌触发、八卦判定、黑色【杀】无效、无手牌目标增伤、选择普通【杀】转火【杀】、伤害封顶、失去回复、锦囊/普通【杀】免疫、火伤增加、坐骑距离以及木牛存粮/转移/粮牌使用与响应。装备入槽、伤害修正、目标数、次数、防具无效和离区效果均通过对应装备源码钩子提供；锁定技按条件直接应用。青釭剑会在异步武器选择恢复后重新读取当前武器并令整次【杀】无视防具，该结论同时覆盖防具的无效判定、防具伤害修正与其防具槽提供的响应入口（目标装备的【八卦阵】在本次【杀】中不会收到发动询问）；麒麟弓在【杀】专属 `shaDamage` 前置时机选择弃置目标坐骑，选择结束后才进入通用伤害并扣减护盾与体力；【还阳】订阅通用 `damageBegin4` 来源前置时机，在本段伤害扣减前先回复1点体力。二者都严格遵循“先结算造成伤害时效果，再造成伤害”，不再等待濒死救援后的 `damageSource`。仁王盾会令黑色实体【杀】无效，基础 AI 在出牌评分阶段会读取公开防具和自身实体颜色：被拦截的目标收益按 `ARMOR_VOID_TARGET_PENALTY = -0.5` 计为负值，若全部所选目标都被该规则拦截则进一步移除 `order` 排序分，因此不使用该【杀】；青釭剑等声明无视防具的武器不受此预判限制。雌雄双股剑、青龙偃月刀、寒冰剑、麒麟弓、朱雀羽扇、银月枪等非锁定装备必须建立可取消选择请求，装备实体会由界面自动选中，玩家点击确定才发动、点击取消则放弃。贯石斧使用独立的两张费用选择：本体只用于锁定发动武器且不进入候选、不自动选中，玩家必须另选正好2张手牌或装备。贯石斧弃置正好2张费用牌或雌雄双股剑令目标弃置1张牌时，如果费用移动触发新的技能选择，【杀】共享组件先保存武器后的稳定恢复阶段，完成子选择后再进入防具、【闪】或伤害，不重复弃牌。出牌或响应时可以主动发动的丈八蛇矛、木牛流马直接把装备实体加入当前选择候选，不创建专用技能按钮。装备候选横条用0.25秒向右移动10像素，选中后再用0.25秒右移10像素，取消候选或选中时也用0.25秒复原。需要使用或打出【闪】时，八卦阵先以只包含防具实体的独立窗口立即询问“是否发动【八卦阵】？”；玩家取消或黑色判定失败后，本响应时机排除该八卦阵并立即恢复普通手牌、木牛“粮”、转化技能和其他装备候选，防止重复判定或阻断手牌【闪】。八卦阵判定若被【戏法】等 `judgeBefore` 技能暂停，原响应上下文保持不变，排序结束并得到最终判定牌后才生成虚拟【闪】或重开其余候选；等待期间不得把暂时的 `null` 结果当成黑色失败。银月枪攻击范围为3，持有者于回合外使用或打出黑色手牌完成原响应子事件后，再决定是否发动并令范围内目标响应【闪】，否则造成1点普通伤害；木牛“粮”不属于手牌，不会触发该效果。

防具实际阻挡【杀】、阻挡伤害类群体锦囊、修正受到的伤害、八卦阵判定或白银狮子离区回复时，控制器向桌面发出一次防具发动通知，并在持有者武将牌中心以与技能发动相同的短暂样式显示当前防具名。该提示只反馈已经成立的防具效果，不改变伤害、回复、判定或响应数值。

丈八蛇矛只有在当前可以使用或打出【杀】且持有者至少有2张普通手牌时进入装备候选。点击后必须选择正好2张不同的普通手牌作为实体材料；木牛“粮”和装备牌都不能作为丈八材料。生成的虚拟【杀】没有点数，花色与颜色按两张材料聚合：两张同花色视为该花色，两张同色不同花色视为该颜色无花色牌，一黑一红视为无色牌。因此两张黑色手牌（无论黑桃、梅花如何组合）转化的【杀】会被仁王盾阻挡、也不能指定拥有【琥珀】的角色，而两张红色材料与红黑混合材料仍可按原规则指定；材料在整张虚拟【杀】结束后统一进入弃牌堆，丈八蛇矛仍留在武器槽。方天画戟只在实际使用的【杀】位于手牌区且是最后1张手牌时增加目标数，丈八虚拟【杀】和木牛“粮”不会借助手牌数量误触发。

## 装备栏、装备区与判定区废除

装备区固定由 `weapon`、`armor`、`offensive_mount`、`defensive_mount`、`treasure` 五个基础栏位组成，每个栏位容量固定为1。`PlayerState.abolished_equipment_slots` 是单栏废除的权威公开字典；只有五栏全部废除时，兼容字段 `equipment_area_abolished` 才为 `true`。因此“废除武器栏”只禁止武器进入，不影响防具、两种坐骑或宝物；“废除装备区”严格等价于同时废除五个栏位。旧存档只有 `equipment_area_abolished=true` 且没有新字典时，载入会迁移为五栏全部废除。

废除装备栏使用 `PlayerZoneAbolitionService` 统一结算。输入栏位先过滤未知值、去重并按上述固定顺序排列；没有实际变化时幂等返回。废除前派发可取消的 `disableEquipBefore`，上下文包含 `slots/abolished/reason/source_player_id/card_uids`；取消或无效化后不改状态、不弃牌。时机通过后先写入废除状态，再把对应栏位内现有装备按标准失去牌与弃牌流程置入弃牌堆，正常卸载装备持续效果，并执行白银狮子、木牛流马等离开装备区效果，最后派发 `disableEquipAfter`。恢复栏位只重新允许卡牌进入，不找回废除时离区的装备，并派发 `enableEquipAfter`。

判定区使用独立公开布尔值 `judgment_area_abolished`。废除前派发可取消的 `disableJudgeBefore`；通过后写入废除状态，把当前全部延时锦囊按判定区顺序置入弃牌堆，再派发 `disableJudgeAfter`。恢复判定区不返还旧延时锦囊，只派发 `enableJudgeAfter`。已废除判定区不能成为延时锦囊的最终进入区域；【闪电】传递时会继续寻找下一个判定区可用且没有同名牌的合法角色。

区域限制拥有两层权威防线：`CardRuleService` 在用牌预览和提交校验阶段拒绝对应装备牌或延时锦囊；`MatchController._move_card_with_timings()` 在实际区域移动前再次读取最新状态，防止异步选择、技能连续结算或旧调用绕过。最终装备移动同时拒绝五种标准ID之外的未知栏位。装备移动未显式传入栏位时，沿底层兼容约定解析为宝物栏，并以同一解析结果完成废除校验、时机数据和移动历史。装备或延时锦囊最终移动失败时，不安装装备运行时，也不记录虚假的入区日志。

客户端只渲染房主快照，不自行推演废除状态。本地五槽装备区在对应位置显示不可交互的主题色“已废除”横条；其他角色武将牌在固定槽位显示红色废除条。废除判定区即使没有实体延时锦囊，也显示独立的红色“废”菱形。上述占位均不是 `CardInstance`，不进入候选、区域牌数量、弃置、获得、网络实体或回放移动历史。

## 区域移动

实体牌区域使用稳定字符串：`draw_pile`、`hand`、`processing`、`equipment`、`judgment`、`wooden_ox`、`discard_pile`。任何使用牌先从所有者牌源进入处理区，效果结束后再进入弃牌堆、装备区或判定区。移动使用实体 UID，不能使用数组下标作为网络或回放标识；同一实体在同一区域且持有者未改变时视为无效重复移动，不写入历史也不发出 `card_moved`。`CardMovementService.card_moved` 是移动完成后的唯一增量来源；控制器据此生成 `card_transfer_requested`，为摸牌、获得、响应弃牌、展示牌获得和普通弃牌携带来源玩家、来源区域、目标玩家和目标区域，规则函数不得手工重复发出同一次移动。

每条移动历史同时保存发生时的 `turn_number`、`turn_player_id` 与 `phase` 快照。`CardMovementService` 按“全局回合号+行动角色”增量索引其中 `phase=play` 且进入 `discard_pile` 的 UID 顺序；从既有状态恢复服务时只进行一次历史重建。需要检索“指定角色在指定回合出牌阶段进入弃牌堆”的牌时，以该索引和实体当前仍处于 `discard_pile` 为共同条件，查询成本只随目标回合桶与当前弃牌堆大小变化，不能重新扫描整局历史，也不能在回合已经推进后读取当前阶段猜测。`get_turn_play_discard_candidates()` 负责生成公开候选，`gain_turn_play_discard_card()` 在最终移动前再次复核回合、行动角色、`phase=play`、花色与区域；同一 UID 多次进入弃牌堆只展示1次。

控制器在唯一移动端口前后派发标准区域时机。进入手牌使用 `gainBefore/Begin/End/After`，离开玩家手牌、装备、判定区或木牛附属区使用 `loseBefore/Begin/End/After`，进入弃牌堆使用 `discardBefore/Begin/End/After` 与 `cardsDiscardEnd/After`，原持有者牌进入弃牌堆后追加 `loseToDiscardpileAfter`，一次批量弃置动作的全部实体移动完成后再派发一次 `cardsDiscardedBatchAfter`；进入装备区使用 `equipBefore/End/After`，进入判定区使用 `addJudgeBefore/End/After`。取消前置时机时本次实体移动不会发生，也不会写入移动历史。

与弃置批次对称，进入玩家手牌的完整后置时机结束后再派发一次 `cardsGainedBatchAfter`，把“一次获得动作”的整批牌聚合为一个事件：非摸牌获得走唯一移动端口登记，摸牌由 `DrawResolutionService` 直接调用移牌服务、绕过该端口，因此摸牌路径单独显式登记同一批次的成员。批量获得入口（一次获得某角色全部手牌、一次按分组取多张、一次取指定数量同字数牌）在循环外层开关批次，使整次动作只产生一个事件；单张获得同样自成一批（`batch_size` 为1），空批次不派发。**开局前分发起始手牌期间不建立也不登记任何获得批次**：控制器在该窗口内置位 `_before_match_start_deal_active`，统一移牌管线的 `counts_as_gain_action` 与 `DrawResolutionService` 的批次开启/成员登记都受它约束，因此起始手牌不触发任何“获得牌”类技能；窗口在 `gameStart` 时机之前关闭，技能在 `gameStart` 的摸牌照常成批。手气卡换牌重发本来就绕过统一移牌管线（直接调用移牌服务的 `mulligan_return`/`mulligan_deal`），同样不派发批次。

技能按指定牌名或牌名字数从牌堆、弃牌堆取得实体时，获得过程仍属于隐藏信息：实体进入手牌前重置为仅获得者知晓，其他角色只看到牌背，公共记录只写“获得了一张牌”，不得显示牌名。技能文本中已经写明搜索条件不构成公开该次实际实体的理由。其他获得牌效果在移动完成后检查实体 `known_to`：若当前全部存活角色都已知该实体牌面，日志必须写出花色、点数与牌名；只要仍有一名存活角色未知，就只能写“一张牌”或“一张手牌”。

控制器按实体 UID 查询权威位置的实现必须同时覆盖牌堆、弃牌堆、处理区与每名角色的 `hand`、`wooden_ox`、`judgment`、`equipment`，并为 `wooden_ox` 返回稳定区域名 `wooden_ox`。木牛“粮”与普通手牌同属可使用或打出的牌源，遗漏该分支会让区域移动在准备阶段找不到来源区域而静默失败：牌不会进入处理区、不会离开木牛分区、也不会触发装备替换，界面只表现为点击“确定”后无事发生。因此任何新增区域或牌源都必须同步登记到该查询与 `CardMovementService` 的区域读写。

## 界面选择与拖放

`CardSelectionPanel` 中所有不属于当前 `candidates` 的展示牌必须完整暗置且不可点击，例如【星祈】观看到的非锦囊牌与【过河拆桥】面对【机巧】保护的防具、宝物；已被其他角色领取的公共牌位改用领取者复制虚影，不与普通禁用暗置混用。主动转化牌若材料对应的虚拟牌只有唯一自身目标，可在同一个 `card_target` 请求中用 `auto_target_ids_by_card_id` 预填自身；【传冲】方块材料视为【无中生有】时因此不需要再点击自己，最终仍以 `target_combinations_by_card_id` 做权威校验。

手牌选中后向上移动18像素，取消选中后回到布局基线；上移与下移动画时长均为0.025秒。该动画只改变客户端临时视觉偏移，不改变实体牌区域、选择 UID 或提交时机。

手牌与木牛“粮”统一由以 `Node2D` 为根的 `CardView` 按实体 UID 渲染。`card_view.tscn` 是唯一牌面结构，直接保存111×148像素纸张、类别条、插画槽、花色点数、原例牌名、类别、默认隐藏的“牌背”覆盖层、默认隐藏的视为名称横条和透明输入区域，编辑器默认预览黑桃7【杀】基本牌；手牌、选择窗口、摸牌动画、获得动画和出牌动画全部实例化该场景，禁止再创建第二套卡牌 UI。实体手牌临时视为另一张牌，或以恰好1张实体材料主动转化使用另一张牌时，牌面继续以原定义绘制插画、类别和底部名称，牌面中心以22像素高的细条显示本次实际逻辑牌名，横条文字默认16像素；前者由 `original_definition_id` 描述手牌内持续视为，后者由使用表现快照的 `presentation_original_definition_id/view_as_definition_id` 描述本次转化。机缘“所有手牌视为【无中生有】”只批量设置结算时已有普通手牌，之后新获得的牌不受影响；【永劫】属于持续锁定视为，安装时批量处理已有非伤害手牌，并在每次 `gainAfter` 后处理新获得的非伤害手牌。每张实体离开当前持有者手牌区时独立恢复原定义。底板使用与实体牌一致的纸张白色并默认完全不透明，边框使用逻辑牌的属性或类别色，文字按实体花色沿用牌名红黑配色。悬停信息框标题保留原牌名，并在副标题标注“视为【当前牌名】”，规则说明读取当前逻辑牌效。该表现不改动实体 UID、花色点数、区域移动或既定逻辑定义；多材料与无材料虚拟牌没有唯一原牌面，不强行生成材料标签。木牛“粮”始终排在普通手牌左侧，但仍属于 `wooden_ox` 区域，不计入普通手牌数与弃牌阶段手牌上限。牌面本身不是按钮；透明 `CardInputArea` 把点击、悬停和同分区手牌排序拖拽转换为稳定 UID 信号。开始拖动后，桌面直接移动并显示同一张 `CardView` 实体，绝不创建预览牌、副本或新的实体 UID；释放时才按落点决定同分区顺序，拖拽不包含角色目标选择语义。可见本地手牌悬停时由 `CardView.information_requested(information, anchor_rect)` 把当前名称、花色点数、细分类别与静态规则说明交给牌桌唯一 `InformationBoxLayer`；不可使用状态禁止点击但仍允许同分区排序拖拽，不禁止查看说明。牌背不发送信息请求，目标来源离开或节点释放时必须发送 `information_dismissed`，全部卡牌视图保持空 `tooltip_text`。

手牌还可通过 `CardInstance.hand_mark_tags` 保存不改变牌名的技能标记。每个来源条目只保存可序列化的 `label/order/rule_overrides`；`label` 负责牌面标签，`order` 决定多个标记的稳定顺序，`rule_overrides` 只允许规则层显式支持的覆盖项。`CardView` 把视为牌名与全部非空文字手牌标记放入同一居中标签行：标签使用相同的22像素高纸张样式，文字16像素，相邻间距4像素；同时存在时视为牌名在前，手牌标记按顺序在后。驭空【鸣弦】写入标签“【鸣弦】”与 `ignore_distance_limit=true`，因此被标记的普通、火或雷【杀】离开当前持有者手牌区前无距离限制，但牌名、伤害属性、每阶段【杀】次数和目标数量均不改变。【永劫】以空 `label` 的专属隐藏标签为已经视为火【杀】的手牌提供同一距离覆写，牌面只显示“火【杀】”视为横条，不重复显示文字。统一移牌边界只在移动确认成立后清除标记；被时机取消的移动仍保留标签和规则，成功离开手牌区后立即清除，处理区与弃牌堆不保留该持续标记。

普通出牌的点击只改变 UI 临时选择，不改变卡牌区域；拖拽只改变本地同分区手牌顺序。只有玩家点击“确定”或按 `Enter`，并通过 `MatchController.submit_action()` 校验后，卡牌才会从 `hand` 或 `wooden_ox` 移入 `processing`。出牌阶段逐张读取当前 `chooseToUse.card_ids`：普通手牌与木牛“粮”只有存在合法 `use_card` 或普通手牌 `recast_card` 动作时才进入该集合；主动装备本体通过独立装备 UID 入口加入。木牛存粮、【传冲】及其他技能/装备动作的手牌材料即使已存在合法动作，也不能把材料 UID 提前加入普通候选，必须保持暗置，待玩家点击对应装备或技能按钮进入专用材料选择后才点亮。响应专用牌、次数用尽的杀/酒、没有合法目标的牌和其他当前不可用牌即使轮到本人也必须禁用灰显，但仍可在手牌所属分区内排序。重铸动作只枚举普通 `hand` 中配置允许重铸的实体牌，`wooden_ox` 中的同名“粮”只能使用或打出，不能重铸；选中【铁索连环】后没有选择目标时，“确定”直接提交重铸，不显示独立重铸按钮。响应、弃牌、火攻和装备费用等请求的候选若全部属于选择者本人的 `hand/wooden_ox/equipment`，直接复用当前手牌区与装备区：非候选手牌使用相同禁用灰显样式且不接收点击，可选装备先右移10像素、选中后总计右移20像素，位移与复原时长均为0.25秒；上下文通过 `valid_card_combinations` 限制固定组合时，每选1张牌都会立即暗置所有不可能再补成合法组合的候选，取消选择后恢复；`CardSelectionPanel` 使用同一前缀兼容规则。请求的 `display_candidates` 可完整展示观看牌、他人公开牌或受保护装备，但只有 `candidates` 内的 UID 可选；其余展示牌必须以相同禁用深灰状态显示，例如【星祈】的非锦囊牌和【过河拆桥】面对【机巧】防具/宝物。上下文绑定具体装备实体的触发询问自动选中该装备，选中数量满足约束后才启用“确定”，规则允许放弃时才启用“取消”。点击丈八蛇矛后，普通手牌临时切换为2张材料候选；点击木牛流马后，普通手牌临时切换为1张存粮候选。响应转换技能的材料默认保持暗置，只有技能按钮被点击并写入准确 `response_skill_id` 后才可选择；控制器从本次响应候选反向汇总 `response_conversion_skill_ids` 并与通常 `active_skill_ids` 合并，因此任何合法转化牌都能在对应 `chooseToRespond` 窗口点亮入口，【借刀杀人】要求打出【杀】时的【罡风】也遵循此规则。黑色牌不会自动视为【杀】。主动转化牌可改用单个 `card_target` 请求：`target_combinations_by_card_id` 把“材料 UID → 完整有序目标数组”写入权威上下文，界面选中材料后只亮起能补全该数组的下一名目标，AI、`ChoiceRequest` 和控制器提交都会精确复核同一数组；多材料请求可使用 `target_combinations_by_card_combination`，其键为规范化材料UID集合，值为该组合的完整目标数组。素裳【山倾】通过该字段在同一窗口完成两张材料与一名目标的选择。该协议支持同一次请求中同时出现1目标【无中生有】与2目标【借刀杀人】。包含公共展示牌、他人牌、判定牌或公开弃牌堆牌的请求继续使用 `CardSelectionPanel`，公开弃牌堆候选显示独立“弃牌堆”分区。所有选择界面的禁用确定、取消及同类按钮固定使用深灰样式，禁用期间不显示悬停变化。

木牛流马的1张存粮材料可以是任意仍在持有者普通手牌区的实体，包括当前出牌阶段不能直接使用的【闪】、【无懈可击】、次数耗尽牌或没有合法目标的牌。确认木牛动作时，`chooseToUse` 消费的是已经点亮的木牛装备 UID，材料 UID 只交给木牛定义复核并移入 `wooden_ox`；不得用材料 UID 代替装备入口提交。未点击木牛期间仍只按普通 `chooseToUse.card_ids` 决定手牌可选状态，所以这些不可用材料继续灰显且不可点击。

本地 `EquipmentStackView` 的五个槽位和其他玩家 `PlayerTargetView` 牌面上的公开装备横条共用相同信息内容契约：已装备实体悬停时显示槽位、花色点数、当前名称模式和 `description`，空槽不显示卡牌说明。其他玩家牌面的装备横条位于最上层武将输入区域下方，因此由 `PlayerTargetInputArea.pointer_moved(local_position)` 转发局部坐标并在 `PlayerTargetView` 内完成横条命中；UI 只能读取公开装备快照，不能显示其他玩家手牌或木牛内部牌面。

普通独立请求继续使用正式主场景820×460像素 `CardSelectionPanel` 与当前 UI 风格的统一 `shade` 背景滤镜；崩铁风格透明度约0.82，暖木家园约0.84，高级黑金约0.85。【过河拆桥】与【顺手牵羊】共用该固定窗口，候选按手牌区、装备区、判定区、处理区和公开弃牌堆的稳定顺序纵向排列，内容超高时使用纵向滚动；弃牌堆候选明确显示“弃牌堆”分区，不再因未知区域键而被漏绘。`context.kind="discard_target"` 与 `context.kind="steal_target"` 只负责把选择结果恢复为弃置或获得，不允许创建卡牌专用布局。窗口内全部明置 `CardView` 都向牌桌唯一 `InformationBoxLayer` 转发悬停说明，包括可选牌、只读五谷公共牌、禁用公开牌和已领取复制虚影；牌背仍不泄露信息，关闭或重建窗口时统一撤销旧说明。互斥文字选项在牌桌手牌上方操作区直接提交稳定 `selected_control_id`，不进入独立窗口。五谷丰登公共展示改用紧凑动态窗口：牌阵固定4列，每张111×148像素，水平与垂直间距均为8像素，4列牌阵宽468像素，窗口只额外保留36像素横向总边距且不显示“展示区”标题；最多10名玩家时形成3行。窗口通过中心锚点和对称四边偏移保持居中，动态尺寸不会把窗口移到左上角屏幕外。`GameState.public_card_choice_display` 保存最初固定牌位、当前选择者和领取者：窗口从亮牌后立即出现，AI 或其他玩家选择时保持只读可见；本地进入与五谷选牌不同类型的【无懈可击】响应时暂时隐藏公共窗口并开放手牌内联输入，响应结束后从同一公共快照恢复。被领取的牌不从牌列删除，而是以 `(0.72, 0.72, 0.72, 0.48)` 调制色保留复制虚影，并在牌底103×26像素标签中显示领取者武将名。私有选择请求仍只开放当前未领取的合法 UID 或控制项 ID，公共展示不能替代 `choose_cards` 权威校验。

`CardSelectionPanel` 的单选请求在已经选中1张时仍让其余合法候选保持可点击；再次点击另一候选会先清空旧UID再记录新UID，确认只提交最后的1张。该通用单选规则覆盖【五谷丰登】展示牌，不会开放已领取、旁观只读或不属于当前权威请求的实体。牌堆顶/底排序使用同一 `CardInputArea` 的直接拖动；拖拽完成信号可以同步重建两行牌位，旧输入节点消费事件时必须容忍已脱离视口，不能再调用空视口。通用模态选择层级固定为150，高于手牌悬停100与拖拽101，五谷公共牌位不会再被底部手牌遮挡。

五谷公共牌阵按牌位 UID、牌面快照、名称模式与 UI 风格生成结构签名。同一结构的重复公共快照或本地请求刷新只更新交互权限、复制虚影和领取者标签，持续复用已有 `CardView`；仅结构签名变化或公共窗口因其他模态请求真正关闭后才重建节点，避免一次五谷流程内反复加载牌面资源和排版。

【无懈可击】对每个锦囊目标建立独立响应链。每轮公开高亮全部存活玩家，但候选牌只进入各玩家私有请求；没有合法候选的玩家不创建阻塞窗口，仍保持与持牌玩家相同的公共高亮。多个有效请求同时等待，权威端接受最先提交且通过当前区域、响应模式和实体 UID 复核的一张【无懈可击】，随后关闭同轮其余请求并翻转一次抵消状态；下一轮重新按相同规则开放，完整一轮无人响应后结束。AI面对正态度队友对自己使用且动态结果为负的锦囊时，首轮不使用【无懈可击】，相信队友具有战术意图；反无懈等后续奇偶轮仍按统一效用判断。卡牌询问中的玩家目标名称优先使用已公开武将名，不显示“玩家X”或“[AI]玩家X”。【无懈可击】属于锦囊牌，但在响应链中派发 `respond` 而非普通出牌的 `useCard`；监听“使用锦囊牌”的技能必须同时覆盖这两个时机并按卡牌 `type="trick"` 统一筛选，因此【智识】可在每张成功打出的【无懈可击】后询问并摸1张牌。

`CardView.disabled_darkening` 默认值为 `0.38`，用于把禁用纸张和类别条压暗38%；`disabled_content_modulate` 默认值为 `(0.45, 0.45, 0.45, 1.0)`，用于把禁用插画与文字保留为45%亮度的深灰表现。两个参数只影响客户端可读性，不改变卡牌合法性、目标、伤害、回复、次数、距离、资源消耗或持续时间。

界面通过 `get_card_use_preview()` 获取目标模式、规则修正后的最大目标数、合法候选与当前组合是否可提交。【桃】【酒】【无中生有】【闪电】和 `target_mode=self` 装备仅在使用者本人是唯一合法目标时自动选择并锁定本人；其他普通目标和主动装备目标即使当前恰好只有1名合法候选，也必须由玩家点击该角色后才写入临时目标数组。手动选择目标期间，非法且未选中的武将牌使用 `(0.42, 0.42, 0.42, 1.0)` 整体调制色变暗，合法目标、已选目标、普通浏览和规则自动展开目标保持原亮度。最大目标数为1且存在多个合法候选时，点击新目标会直接替换旧目标，无需先取消；方天画戟满足条件时查询返回3，不会被误判为单目标。全体目标牌由规则层从使用者开始按环形行动顺序自动展开：包含使用者的牌先检查使用者，排除使用者的牌先检查其下一名存活角色；每名角色继续经过卡牌条件、来牌限制与使用者技能目标限制，非法角色从本次目标数组中移除，剩余角色保持行动顺序。自动展开后只要仍达到卡牌配置的最少目标数即可使用，因此【破风】仅允许1名其他角色时，【五谷丰登】与【桃园结义】仍可正常使用且目标数固定为1；若合法目标数降为0，而卡牌最少目标数为1，则拒绝使用。手动多目标先按点击顺序编辑，提交后由规则层按当前回合角色起算的行动顺序规范化。技能在整牌 `useCard` 时机改写目标后同样必须给出**按同一行动顺序**排列的目标数组：`replace_card_use_targets()` 刻意保持调用方给出的顺序与重复项（控制器不额外排序或归一化，因为部分牌的目标顺序带角色语义），因此排序责任在技能侧——例如【支离】把目标改为原目标的相邻角色时，必须先按“从持有者开始的行动顺序”重排邻居集合，否则会出现“先结算队友、再结算自己”这类与座次不符的顺序。【借刀杀人】使用时必须按持刀者、被【杀】者声明2名角色；卡牌结算前由 `get_resolution_target_ids()` 收敛为唯一持刀者，第二名角色由 `configure_requested_target_context()` 写入结算上下文，不触发本牌目标时机且不创建二次目标选择。常规选牌提示仅显示 `description` 中的卡牌效果，不再拼接当前牌名、目标名称、分隔符或空占位；牌名由实体牌面表达，目标由合法高亮与选中状态表达。该接口始终显式返回 `Array[int]`：没有目标时返回空的强类型数组，有首名目标时只返回该角色，避免动态数组返回值破坏脚本类型契约。涉及实体牌或目标选择的效果通过 `card_choice_requested` 询问，提交 `choose_cards` 后才继续结算；过河拆桥、顺手牵羊的候选顺序固定为手牌区、装备区、判定区，不可见手牌只渲染牌背。出牌、响应和效果选牌统一由 `EventScheduler` 分配全局唯一请求 ID，运行时登记成功后才允许启用对应的本地区域内联交互或独立选择窗口，并在响应确认接收后才清理待选上下文。任一目标结算使对局满足胜负条件时，效果执行器立即停止后续目标、响应与卡牌区域移动。预览结果不是权威状态，不能用于跳过 `validate_use()`。

卡牌与技能共用同一临时选择模型：卡牌、目标和按钮都只写入 `ChoiceResponse`，确认前不移动实体牌、不消耗次数。普通【杀】与【桃】仍在 `chooseToUse` 中先选牌再选目标；【过河拆桥】先通过卡牌目标规则选择一名其他角色，进入该目标 `content` 后再创建选牌请求，从其手牌、装备区或判定区中选择1张弃置。【借刀杀人】在 `chooseToUse` 内一次性声明持刀者与被【杀】者，结算直接读取共享上下文并要求持刀者响应【杀】。技能需要“选择一张牌并选择一名角色”时使用 `choice_type=card_target`，牌数与目标数分别校验，可选的牌到目标映射不会改变任何现有卡牌伤害、回复、距离或次数数值。

主动技能创建的可取消内联选择会保留原技能按钮的选中与可点击状态；再次点击同一按钮提交 `confirmed=false`，不执行材料消费、目标效果或次数记录。响应转化技能的第二次点击只清除当前 `response_skill_id` 筛选和临时材料选择，不取消整个响应窗口。

摸牌和获得牌的动画由 `card_transfer_requested` 统一驱动，实体牌 UID 始终作为移动标识。一次 `draw()` 产生独立表现批次：同批每张牌都从同一牌堆锚点同时起飞；本机批次的每张牌直接以正面飞向该牌自己的最终手牌槽位（进入本机手牌区的牌一律不使用牌背，避免落地瞬间翻面），其他观察者不可见私有手牌、其批次继续显示同款牌背并按42像素横向间距围绕目标锚点整体居中；飞行0.24秒、停留0.10秒、淡出0.18秒，同批不使用逐张延时。带摸牌堆叠键而未进入批次接口的兼容转移使用相同三段时长，并以正面从中央牌堆锚点直飞该牌槽位；每个批次在收到完整移牌后立即开始，多个玩家或连续多次 `draw()` 的批次允许同时飞行、停留和淡出，不互相等待。本地玩家进入手牌区的牌最终都落在同一个长期存活的正式 `CardView` 上：桌面先登记实体 UID，收到包含该牌的本地快照后按 UID 创建或复用手牌容器中的唯一正式节点，快照刷新期间实例保持不变，动画结束后同一节点继续承担选择、拖放和后续出牌。正式节点不再从手牌区右侧滑入：桌面在区域移动时只登记“飞行起点 + 门闸”，等包含该牌的本地快照完成布局、算出它自己的最终槽位之后，才让飞行牌面从该牌真实来源位置直接飞向那个槽位；门闸期间正式节点被按在飞行起点（该点位于手牌滚动区之外因而被裁剪不可见），落地回调解除门闸的那一帧它就直接出现在自己的槽位上，全程只有一段连续飞行，因此不会出现“牌已躺进手牌区又被重新飞入”或落地后的第二段滑动。获得牌若此刻正显示在中央展示队列中（例如获得其他角色刚打出的【杀】），本次获得拆成**两段连续飞行**：第一段是这张牌原有的出牌动画，它先把牌飞进中央弃牌展示队列并落位（规则上即“已进入弃牌堆”）；桌面只登记一次落位等待（`request_active_card_landing`），落位之前绝不取牌，落位通知到达后才接管**同一张牌面实例**从中央区飞向获得者，队列剩余成员在0.18秒内重新以弃牌中心为轴居中，因此既不会出现“牌飞进手里、原牌还留在中央”的复制观感，也不会出现“牌还没进弃牌堆就被抢走”的错序；本机视角的第二段终点是该牌自己的手牌槽位，其他视角的终点是获得者武将牌锚点，两个视角共用同一条落位等待与同一个取走接口。等待落位期间正式节点与普通门闸一样被按在飞行起点；等待登记必须与门闸同批撤销（`cancel_active_card_landing`），否则迟到的落位通知会取走一张已经无主的牌面。飞行起点的来源解析优先级固定为“本机手牌或木牛正式槽位 → 本机装备槽矩形 → 其他角色武将牌锚点 → 公共弃牌区中心”，无法解析时只跳过飞行、不伪造坐标；本机区域之间的移动没有可见来源，同样只保留落位。门闸正常只由落地回调解除，并在清场路径导致飞行牌面提前释放时按“飞行牌面失效”自动补齐解闸；牌离开手牌区或重新开局时，未起飞的飞行牌面与待起飞批次一并释放，不会留下停在屏幕上的孤立牌面。撤销未起飞门闸还要求快照确实晚于门闸登记（门闸记录登记时的快照代次）：区域移动信号先于权威快照到达，而询问界面等入口会在同一帧用旧快照重新对账手牌，只有快照代次更大时才把“快照里没有这张牌”判为已经离手，否则【风口】这类“一次性获得至少两张牌后立刻询问”的技能会让整批摸牌飞行被误取消，表现为摸牌跳过动画直接进手牌。牌离开手牌区或装备区时表现不再先让牌面消失：弃置或被他人取走的牌直接接管手牌容器中的正式节点（装备区取该装备槽矩形），从原位置连续飞向弃牌堆或目标玩家，接管前先收尾该牌未播完的入场与整理偏移；被接管节点同时从手牌 UID 映射移除。手牌区有牌离场或插入后，缺口右侧的存活手牌用0.18秒从原槽位滑向新槽位补齐空缺，而悬停补偿不进入槽位，因此悬停不会触发整理过渡。直接拖拽排序在松手后走同一条槽位过渡：松手帧被拖牌仍停在鼠标松开的位置，再用 `drag_settle_seconds = 0.18` 秒滑向重排后的稳定槽位；释放点未命中同分区手牌时沿同一条过渡回到自己的原槽位，两种情况都不跳位，落位释放点数量也参与布局签名以保证松手帧必然重新布局。纯展示的 `showCards` 副本同样从本机该牌真实位置起飞，实体仍留在手牌区。卡牌与武将组件保存最近配置签名，未变化快照不会重复加载插画或重建样式、体力、装备和判定子节点；对手座位按玩家 ID 持久复用。隐藏候选仍使用同一牌背覆盖层，不通过伪造空白牌面实现信息隐藏。重新开局清空表现时，转移牌、正式手牌补间、飞行牌面与并行批次补间分别停止并清除，同时清空待入场登记、待起飞摸牌批次与飞行门闸（清场会终止飞行补间，落地回调不会再触发），并让仍在容器中的手牌重新布局回自己的槽位；旧局异步任务不得写入新局节点。

卡牌通过校验进入处理区时，规则层生成可序列化 `CardPresentationEvent(event_name=useCard)`，表现层直接接管手牌中的同一 `CardView` 节点，并从实际使用者区域移动到中央弃牌展示落点，保持111×148像素的3:4正式牌面、插画、花色、点数、名称和类别不变。火攻展示使用 `event_name=showCards` 的独立表现实例，实体仍留在原手牌区；判定阶段先用 `event_name=delayedJudge` 展示当前延时锦囊，再用 `event_name=judge` 把牌堆顶1张判定牌直接从中央弃牌展示锚点公开，不从判定角色位置打出。四类表现共用中央队列；真实使用牌、延时锦囊和判定牌可按最终区域声明 `owns_discard_transfer=true`，纯展示牌不会吞掉该实体未来真正进入弃牌堆的移动。玩家来源或目标缺少真实座位锚点时跳过本次短时动画，不能回退中央锚点伪造位置；新建 `CardView` 在写入父级、起点和外观前保持隐藏。动画牌的悬停结束与样式刷新只修改缩放、颜色和层级，默认不再写入非手牌 `position.y`，因此响应等待期间不会从中央队列跳到窗口顶部。`GameState.to_dict()` 同时公开不含牌面的 `processing_card_uids`，中央动画层据此核对认领牌：权威实体已离开处理区而最终移动通知缺失时，仍会启动正常收尾。目标线用0.24秒动态延伸，完成后立即独立用0.36秒淡出。同一帧进入弃牌堆的多张牌按移动信号顺序以66像素中心间距从左到右完整铺开并保持0度旋转。纯展示与普通弃牌完成0.42秒飞行和0.48秒停留后使用0.36秒淡出；接管最终区域移动的真实牌会在响应、选牌或判定完成前持续留在中央，最终移牌到达后再完整停留0.48秒并淡出。每张牌只保留一个收尾生命周期 Tween，不再创建两个 SceneTreeTimer 等待协程。普通弃牌首次观察到某个实体 UID 时登记其中央表现生命周期，重复增量、同区域重复移动和纯展示牌的迟到弃牌都不会在牌桌上方或中央重建第二张牌；未被 `useCard`、`delayedJudge` 或 `judge` 明确认领的处理区弃牌收尾也不会合成无来源牌面。

## 独立源码字段与效果入口

新增牌必须在 `game_data/cards` 创建继承 `CardDefinition` 的拼音文件，并至少声明 `id`、双名称、`type`、`subtype`、`effect_id`、目标模式、目标数、距离限制、次数限制、响应模式、是否延时、是否可重铸、说明、`resolution_mode`、`final_zone` 与 `provided_response_pattern`；`rule_name`、`art_path`、`play_limit_group`、`play_limit_scope`、`allow_self_target`、`requires_actor_choice`、AI 字段和装备交互字段按需要填写。文件必须覆盖 `resolve()`，特殊逐目标牌可覆盖 `resolve_target()`。

`resolution_mode=per_target` 表示每名有效目标分别进入内容事件，`resolution_mode=whole` 表示一次取得完整目标数组；装备、延时锦囊和五谷公共牌池使用 `whole`。`final_zone` 当前使用 `discard`、`equipment` 或 `judgment`，用于表现层判断是否接管处理区到弃牌堆的移动，权威终点仍由卡牌函数返回值决定。

`response_pattern` 对普通锦囊表示该牌效可被【无懈可击】响应，不代表该实体自身能当【无懈可击】打出；实体实际能提供的响应由 `provided_response_pattern` 明确声明。当前【杀】提供 `sha`、【闪】提供 `shan`、【桃】提供 `tao`、【酒】提供 `jiu`、【无懈可击】提供 `wuxie`，其他牌为空字符串。新增自定义效果不需要加入集中效果 ID 白名单，只要对应卡牌文件提供合法函数并通过数据校验与回归测试即可。

`play_limit` 与 `play_limit_group` 决定同组使用次数，`play_limit_scope` 决定从当前回合历史还是当前出牌阶段历史统计。普通【杀】、火【杀】与雷【杀】通过同一 `slash` 分组和 `phase` 作用域共享每个出牌阶段1次基础限制，进入额外出牌阶段会清空阶段历史并重新获得1次额度；诸葛连弩通过装备钩子解除该配置限制，武将技能可通过 `SkillDefinition.ignores_play_count_limit()` 参与同一纯查询，例如【王牌】只解除 `slash` 分组，不清空或伪造历史。【酒】使用 `turn` 作用域，额外出牌阶段仍与原阶段共享每回合1次限制。`ai_use_value`、`ai_target_attitude` 和 `ai_beneficial` 分别决定基础 AI 静态牌值、目标友敌方向和无懈收益方向，新增卡牌无需修改 `BasicAIPolicy`。

次数规则保留两类不可混用的语义。`ignores_play_count_limit()` 表示“使用无次数限制”：已经达到上限仍可通过使用前校验，成功后照常增加完整回合/阶段历史。`does_not_count_toward_play_limit()` 表示“本次不计入次数限制”：使用前不能绕过已经达到的上限，成功声明后仍写入完整历史，同时写入独立豁免历史，后续限制计数才扣除该次。`CardRuleService.get_grouped_play_count()` 返回扣除豁免后实际占用上限的同组数量；`get_grouped_actual_play_count()` 返回未扣除豁免的真实使用序号，供“前X张【杀】”等规则使用。两类查询都按 `play_limit_scope` 选择回合或当前出牌阶段历史。

需要自行枚举多目标组合的卡牌覆盖 `append_play_phase_card_actions()`，并通过 `append_card_action_if_legal()` 复用统一合法性校验与动作结构。传入该端口的目标列表必须先声明为 `Array[int]`；卡牌源码以 `Object` 访问控制器时，未定型数组字面量不会自动转换为方法要求的强类型数组。【铁索连环】枚举全部合法单目标和不重复双目标组合，合法目标包含使用者自己。【借刀杀人】只枚举单元素持刀者数组，被【杀】者不属于该牌目标。

濒死救援不再由控制器判断桃或酒的定义 ID。卡牌通过 `get_dying_response_pattern()` 声明当前响应者与濒死者关系下能否进入救援窗口，再由 `resolve_dying_response()` 自行执行回复和日志；桃允许任意存活角色救援，酒只允许濒死者本人自救，数值仍均为回复1点。

存活角色体力不大于0时必须继续濒死流程。`dyingBefore` 或 `dyingBegin` 的取消、中立化标志只有在处理器已把目标恢复到1点或以上或确认死亡时才能终止入口；仅取消事件而不修正角色状态不会绕过求桃与死亡确认。离场角色进入濒死后仍派发标准濒死时机，但不建立【桃】或【酒】救援窗口，而是立即进入死亡流程；死亡入口先调用统一返场流程清除离场状态并派发 `enterGame`，随后才派发 `dieBefore/dieBegin/die`，因此死亡快照中的角色必定已经在场。

延时锦囊在自身文件覆盖 `resolve_delayed_judgment()`；当前【闪电】的黑桃2至9与3点雷电伤害、【乐不思蜀】的非红桃跳过出牌阶段、【兵粮寸断】的非梅花跳过摸牌阶段均已从控制器分支迁入对应卡牌文件。三者通过可暂停 `request_judgment()` 建立稳定卡牌 continuation，并在 `continue_judgment()` 中按原延时牌 UID 恢复；【戏法】排序期间原延时牌继续留在处理区，不能提前传递、弃置或写入跳过阶段。装备等持续区域卡牌可覆盖 `install_runtime/uninstall_runtime`，系统按实体 UID 创建独立实例并在离区时卸载，新增被动装备可直接订阅规则事件而无需登记集中装备表。

### 使用者阵亡后的牌效分支

牌的使用事实在声明使用时已经成立，使用者在结算完成前阵亡不再撤销整张牌：

- **默认分支**：牌效继续完成目标的响应窗口、防具判定、无懈可击与逐目标伤害。所有以使用者为来源的伤害降级为无来源：`source_id` 与 `source_character_generation` 为 `-1`，`card_user_id` 保留原使用者 ID；阵亡角色的累计造成伤害与击杀统计不增加。卡牌源码在需要按来源做规则判断或派发以来源为前提的时机时，必须通过 `resolver.effective_source_id(actor_id)` 取有效来源；直接调用 `damage()` 时把使用者 ID 传入即可，核心层会自动降级。
- **失效分支**：声明 `requires_actor_choice=true` 的牌在使用者阵亡后整张失效（不创建选择、不移动牌、不造成伤害，实体正常进弃牌堆）。当前为【过河拆桥】【顺手牵羊】【火攻】【借刀杀人】，其失效判定由 `CardEffectResolver.resolve()/resolve_target()` 统一执行。装备主动效果无需声明，因为装备随使用者阵亡一同卸载。

`request_card_choice()` 只拒绝“请求创建时已阵亡”的选择者，因此恢复路径必须自行复核来源有效性：控制器在 `_apply_target_card_choice()` 中拦截过河拆桥与顺手牵羊，【火攻】在 `continue_choice()` 的展示与弃牌两段复核，【借刀杀人】在 `continue_response()` 中复核，防止把目标区域的牌或武器交给已经阵亡的角色。完整规则、端口与数值清单见[内容制作指南](内容制作指南.md)的“牌效来源阵亡规则”。

## 事件化卡牌生命周期

`CardMovementService` 是规则层的统一移动边界，写入 `CardMoveEvent` 并保存 `from_zone/to_zone/source_player_id/target_player_id/event_id/reason/visible_to`。`processing` 是使用牌、响应牌和判定牌的 ordering 区域；完成主体前不得把牌直接放入弃牌堆。实体 `CardInstance` 额外保存 `known_to`、`shown` 和 `private_owner_id`，公开展示会更新知识集合，弃牌堆洗回牌堆时清理临时知识。

`EventScheduler` 只为长期根事件与尚未完成的当前事件树保留完整 `GameEvent`。卡牌、响应、伤害和同步规则记录结束后，调度器立即释放其中的 `Callable`、步骤队列与可变上下文，只让历史和按ID查询索引共享一份最终可序列化摘要；这不改变父子事件ID、终态、结果、触发顺序或卡牌区域生命周期。

使用牌生命周期由真实 `CardUseEvent` 驱动：实体材料在 `lose` 子事件进入 `processing`，随后依次派发 `useCardBefore`、`useCardBegin` 和五组 `useCard0/useCard1/yingbian/useCard2/useCard`。四组目标时机 `useCardToPlayer/useCardToTarget/useCardToPlayered/useCardToTargeted` 按阶段优先顺序逐项进入调度栈；每组先遍历全部当前目标。每次目标时机结束都会重新读取目标数组，并按当前行动座次生成本轮遍历副本；动态新增目标能够补齐当前与后续阶段，同一目标重复出现时按出现次数分别触发。

每个实际目标由 `useCardToBefore/Begin/End/After` 包裹，死亡或离场目标派发 `useCardToOmitted`，规则排除目标派发 `useCardToExcluded`，前置窗口取消则派发 `useCardToCancelled` 并只跳过该目标。`directHit` 目标跳过对应【闪】与【无懈可击】响应，`customArgs` 由全部子事件共享。【杀】在目标生命周期内部依次派发 `shaBefore/Begin`、命中或闪避的 `shaHit/shaMiss`、造成伤害前的 `shaDamage`，最后先派发 `shaEnd/shaAfter`，再退出到 `useCardToEnd/useCardToAfter`。

`shaDamage` 中的可选技能可能创建选牌和判定。共享【杀】组件在这些子流程完成前只保存“共享基础伤害”和“已读取目标加值”，不会提前扣减体力；恢复时重新读取当前目标最新 `damage_bonus`，以“共享基础伤害 + 最新目标加值”计算最终伤害。因此【剑势】红色判定的 `+1` 能在异步【戏法】排序后生效，多目标【杀】仍按目标分别保存加值，不会重复累加到其他目标。

实际目标各自拥有可暂停 `content`，响应与效果选择作为其子事件；五谷丰登等整牌异步效果在恢复回调写入 `content_complete` 后，原 `content` 事件只读取最终区域并结束，禁止再次执行亮牌或重复创建选择请求。全部内容完成后派发 `useCardEnd/useCardAfter`；整牌前置被取消时改派 `useCardCancelled`。父事件随后只创建1次 `contentAfter`，并通过 `after` 队列执行 `orderingDiscard -> cardsDiscard`。实体牌、装备牌和延时锦囊的最终区域仍由规则效果决定，事件树不会改变区域规则。

响应牌在实际消费前后依次派发 `respondBefore → respondBegin → respond → respondEnd → respondAfter`；被抵消的牌或事件使用 `eventNeutralized`。判定流程依次派发 `judgeBefore → judgeBegin → judge → judgeFixing → judgeEnd → judgeAfter`，判定牌仍只从牌堆顶取得1张。`judgeBefore/judgeBegin` 可创建选择并暂停唯一活动判定；统一管线只恢复最内层触发续列，先完成该判定及其稳定 `continue_judgment()`，再返回外层伤害、响应或回合时机。判定请求可携带 `favorable_condition/unfavorable_condition/favorable_result_player_values/preferred_suit_values`，供改判定 AI 判断结果方向，不改变真实判定规则。观看牌堆顶需要的数量超过当前剩余牌数时，弃牌堆先洗入原牌堆下方，原有顶牌及其相对顺序保持不变；不能用新洗入数组覆盖仍未离开摸牌堆的实体。五谷丰登仍有未领取展示牌时，在这些牌离开处理区进入弃牌堆之前派发 `wuguRemained`，便于技能使用剩余实体 UID。

响应牌、无懈、濒死救援、重铸和目标区域牌移动均遵循可恢复结算边界：实体牌先完成一次权威移动；若该移动产生技能或装备选择，控制器把已消费逻辑牌快照与父规则上下文压入 `RuleContinuationQueue`，完成最内层选择后只读取一次结果并继续父流程。典型顺序为“最后一张【桃】进入弃牌堆 → 触发并完成【冥谶】目标选择、获得1张【无中生有】及可能的1点雷属性自伤 → 原【桃】回复濒死目标1点 → 目标达到1点后退出濒死”，不得因【冥谶】占用选择窗口而丢失桃或濒死流程。重铸仍严格为弃置1张、随后摸1张；最后手牌触发插入事件时只延后摸牌，不改变数量。通用恢复优先级为同一时机剩余触发、装备延后触发、最内层规则后半段、技能登记后续、阶段或父牌游标。

`VirtualCard` 只描述逻辑牌名、花色、点数、属性、颜色和扩展存储，实体材料牌通过 UID 数组单独保存。丈八蛇矛、技能视为牌和无懈可击响应不能把多张实体材料压扁成一张新的普通实体牌；回放必须同时记录逻辑牌和材料 UID。单张材料形成的虚拟牌继承该实体花色、点数与颜色语义；多张材料形成的虚拟牌按全部材料聚合花色与颜色：全部同花色视为该花色，花色不同但颜色一致视为该颜色无花色牌，颜色不一致或含无花色材料视为无色牌；无材料虚拟牌保持无花色、无点数并按无色处理。聚合颜色通过 `CardInstance.color_override` 写入代理实体，并由 `get_color()` 统一提供给距离、次数、目标限制与防具判定，因此转化牌与普通使用牌走完全相同的目标过滤链。多材料技能可在 `VirtualCard.storage` 保存来源技能与去重花色等基础数据，控制器把它传入使用牌、目标、【杀】与伤害来源时机；`get_card_virtual_storage()` 只返回当前使用牌存储的深拷贝。技能主动转化可向 `validate_virtual_use()` 与 `list_legal_virtual_targets()` 传入本次规则覆写：`ignore_distance_limit=true` 只忽略该虚拟牌的距离，`maximum_target_count_bonus=1` 只把基础目标上限增加1；单材料查询必须额外写入该实体的真实 `card_color`，多材料查询必须使用 `card_rules.build_material_rule_overrides()` 生成的聚合颜色，未覆写的次数、目标模式、重复目标、存活状态和技能目标限制仍按统一规则复核。持续手牌视为牌通过普通 `use_card` 动作进入同一单材料虚拟牌协议：控制器把实体手牌标记中受支持的距离覆写传给代理，代理展示使用 `hand_view_as_original_definition_id` 保留真正原牌名，不能把当前逻辑牌名误当原牌名。【安打】因此仍为1名目标但无距离限制，【全垒】仍受攻击范围限制但最多指定2名不同目标。【山倾】把两张材料的花色按红桃、方块、黑桃、梅花固定顺序去重写入 storage，同花色只触发1次。

无材料虚拟牌的 `VirtualCard.storage` 同样可由 `execute_cardless_virtual_card_use(..., virtual_storage)` 写入，用于区分同一技能的连续用牌与结算令牌。同一技能依次视为使用多张【火攻】或火【杀】时，必须等待前一张的 `useCardAfter/useCardCancelled` 再发起下一张；不得在同一栈帧内并发创建多个用牌事件，否则无懈、响应与选择上下文会互相覆盖。**存储也可以携带“本次视为用牌的联动收益”供被使用牌读取**：被使用的牌在自己的效果与 AI 评分中用 `get_card_virtual_storage(card_uid)` 取回该字段，从而在“使用者对自己使用这张牌”这类统一评分无法正确估值的场景下按真实联动收益决策。例如【飞焰】视为使用【火攻】时写入 `hit_reward_value`（本次命中能换回的摸牌与阶段转换收益），【火攻】随即用该值判断自己成为目标时是否值得支付同花色手牌。存储键名必须由“写入方技能”与“读取方牌”各自声明常量并保持一致，只允许传递可序列化数值，且实体牌读不到存储时必须退回原有行为。

## 装备区与判定区废除

- `PlayerState.equipment_area_abolished` 与 `judgment_area_abolished` 是两个独立的公开布尔状态。废除区域时，该区域内所有实体牌经标准移牌时机进入弃牌堆；装备运行时实例与离区效果正常处理。
- 向已废除装备区使用或转移装备，以及向已废除判定区使用、转移或传递延时锦囊，均会在预览与最终移牌入口双重拒绝。延时锦囊寻找下家时会跳过判定区已废除的角色；没有合法接收者时进入弃牌堆。
- 恢复区域只把可用性设回正常，不恢复或重新生成废除时已经弃置的实体牌。内容脚本只调用 `MatchController.set_player_zones_abolished()`，不直接改写布尔字段或牌区数组。

主动转化技能使用 `target_ids_by_card_id` 保存“材料 UID → 该材料对应合法目标”的映射：材料尚未选择时显示所有材料合法目标的并集，选中材料后立即缩小为该材料自己的候选。玩家预览、AI 动作枚举和技能提交都必须使用同一映射与完整虚拟牌校验；`MatchController.execute_virtual_card_use(..., rule_overrides={})` 在移动材料和创建处理区代理前还会按真实材料强制覆盖 `card_color`（单材料读实体颜色，多材料读聚合颜色）并再次调用 `validate_virtual_use()`。因此黑色材料转化的【罡风】【安打】【全垒】以及两张黑色牌转化的【山倾】【丈八蛇矛】【杀】均不能指定拥有【琥珀】的角色，红色材料与红黑混合材料仍按聚合结果决定，调用方不能通过省略或伪造颜色绕过最终入口。

响应候选除实体自身的 `provided_response_pattern` 和装备响应入口外，还会查询持有者技能的 `can_convert_response_card()` 与 `get_converted_response_definition_id()`。例如【罡风】可把当前拥有的1张黑色手牌、木牛“粮”或装备牌当雷【杀】打出；提交时控制器再次复核技能、颜色、区域和响应模式，把材料移入处理区，创建继承其花色与点数的虚拟雷【杀】，完成响应后再将材料送入弃牌堆。装备材料成功离区时必须卸载对应运行时并正常执行装备离区效果。该转换不改变牌面原定义，也不额外生成可进入牌堆的实体牌。当发起本次响应的卡牌在上下文中宣布 `ignore_armor=true` 时（青釭剑无视防具的【杀】），请求端口会把该结论固化为响应上下文 `ignored_response_equipment_slots`（当前固定为 `["armor"]`，依据装备所在槽位而非具体防具 ID）：该槽位装备既不进入独立即时询问，也不进入统一候选窗口，恢复重试与提交消费阶段同样拒绝，因此【八卦阵】不能在这次【杀】中发动，而手牌、木牛“粮”与技能转化入口完全不受影响。

出牌阶段本身由 `chooseToUse` `ChoiceRequest` 表示；一次合法 `use_card`、`use_zhangba`、`recast_card`、木牛操作或主动技能选择完成后会创建下一次请求，`end_play` 以取消当前请求推进弃牌阶段。主动技能 ID 进入该请求的 `button_ids`，提交 `use_skill` 时先完成当前 `chooseToUse`，再在同一事件链内执行技能及其后续选牌/选目标。旧 UI 仍提交 `PlayerAction`，控制器先转换成 `ChoiceResponse` 再执行权威校验。`chooseToUse` 与五谷、火攻、弃牌、响应等后续请求不能维护各自独立的自增 ID；所有请求必须使用事件调度器的同一全局序号，避免交错窗口引用到其他仍活动的请求。

延时锦囊在判定阶段按判定区数组的**「后来居上」**顺序逐张处理（数组只按置入先后追加，结算从数组末位取起，因此最后进入判定区的牌最先判定）：当前牌进入处理区后先发送 `delayedJudge` 中央展示，默认等待1.00秒，再进入【无懈可击】与实际判定；该牌完成或选择恢复后默认再等待1.00秒，才展示下一张延时锦囊。`delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds` 均可在检查器设为0.00至3.00秒，正式对局默认均为1.00秒；无 `match_id` 的纯规则预演跳过表现等待。若【无懈可击】或判定伤害触发濒死救援需要等待本地玩家，则判定阶段保持暂停，不能提前创建摸牌或出牌请求。选择完成后先结算同一张延时锦囊并保留结果，再继续剩余判定牌；全部判定结束后才依次进入摸牌、出牌、弃牌和结束阶段。

## 视为牌离手展示与群体回复

手牌视为牌离开手牌时，`clear_hand_view_as()` 立即恢复实体 `definition_id`，但保存 `presentation_original_definition_id` 与 `view_as_definition_id`。处理区和弃牌堆快照必须携带这两个字段；`CardView` 显示原实体牌面、花色和原牌名，并以横条显示视为牌名。例如【闪】视为【桃】后弃置，仍显示【闪】且标明视为【桃】。实体进入牌堆、手牌、装备、判定或木牛区域，以及弃牌堆洗回牌堆时，必须清理一次性展示来源；限时视为若在持有者回合结束时仍留在手牌区而恢复原牌名，也必须立即清理展示来源，不能继续显示已经到期的逻辑牌横条。该协议不改变实体 UID、花色、点数、结算或区域。

手牌标记与视为牌的恢复语义相互独立：视为牌可以保留离手展示快照，手牌标记则只在牌仍处于当前持有者手牌区时生效，成功离手后不进入处理区展示。两类标签可同时存在，任一类的清理都不得覆盖另一类仍有效的数据。

持续锁定视为在技能卸载时必须只清除 `hand_view_as_source_skill_id` 属于该技能的视为状态，并通过 `remove_hand_mark_tag(source_id)` 删除自己的隐藏规则标签；不得清空其他技能写入的独立手牌标记。【永劫】因此会在换回白厄前恢复仍留在手中的原牌名。

【桃园结义】目标下限为 `0`，目标集合为**全部存活角色**：满体力角色同样是本牌合法目标，照常保留在 `normalize_targets()` 的展开结果与逐目标 `content`/目标时机中，但**不为它创建【无懈可击】询问**——无懈只服务于确实会改变结果的回复，满血目标被询问无懈没有规则意义。卡牌源码因此不得再用 `validate_target_selection()` 过滤满体力角色（它会连带取消满血角色的目标身份），而是在 `resolve()` 循环里先用 `_needs_recovery()` 判定：满体力、已死亡与已离场角色直接跳过无懈链与回复；每名真正受伤的目标固定回复 `1` 点体力，同一张牌在多目标入口下也只会为受伤目标各询问一次无懈。全员满体力时本牌不创建任何无懈窗口，逐目标时机照常走完后结束牌生命周期。

## 无材料虚拟牌与目标修正

除单材料和多材料视为牌外，卡牌系统支持没有实体材料的逻辑代理。`MatchController.execute_cardless_virtual_card_use()` 生成无花色、无点数的 `CardInstance` 进入 `processing`，随后创建标准 `CardUseEvent`；代理的材料 UID 数组必须为空。它仍完整派发使用牌、逐目标、响应、【杀】伤害和弃置相关时机，但代理自身最终回到 `void`，不会污染牌堆或弃牌堆。该协议用于【倾力】等“支付非牌资源并视为使用”的效果。

多张无材料虚拟牌组成一个连续技能时，`SequentialVirtualSkillDefinition` 在每张牌的 `useCardAfter/useCardCancelled` 后登记下一步并自动延后恢复统一结算管线。只要后续队列尚未排空，`has_pending_play_interaction()` 就把它视为当前主动技能的一部分，禁止提前重建普通 `chooseToUse`；最后一张牌完整结束并执行技能完成钩子后才恢复出牌窗口。【天裁】与【弑魂】共用该协议。

**独立额外出牌阶段内的同一协议必须由子阶段自己排空。** 该阶段的归属由外层规则续接持有（外层回合开始或阶段序列正在等待它结束），统一结算管线在“栈顶父序列等待子阶段”的屏障处提前返回以免越过外层时机，因此仅靠管线末尾的待办复查重登记只会再次撞上同一屏障（条目恒非空、`has_pending_play_interaction()` 恒真、出牌窗口永不重建 = 卡死）。这类延后条目在登记时记录**登记瞬间活动的独立阶段实例号**，管线在屏障早退前只排空归属为当前独立阶段的条目，父序列遗留条目一律不动；排空后复用既有的空闲窗口重建入口恢复出牌窗口。“然后”步骤被延后恢复的技能（【奇袭】【摄伏】【逐虚】【星落】等）在独立额外出牌阶段内与普通出牌阶段内因此行为一致，卡牌侧不需要、也不得为“自己处于额外阶段”添加任何分支。**同一判定还有对称的一半**：屏障生效期间，`-1` 的父序列遗留条目**不得**被当作“当前出牌阶段仍有未完成交互”（`MatchController._has_blocking_deferred_skill_settlement()`），否则子阶段的出牌窗口虽已建立、AI 动作却会被永久拒绝，而子阶段不结束父条目也永远排空不了——同样是零进展死锁。管线在屏障早退分支排空后统一补齐子阶段自己的窗口与 AI 驱动（`_ensure_ai_progress_after_resolution()`），真实触发组合是【风口】在 `gameStart` 登记的条目与【巡礼】插入的额外阶段同时存在，回归由 `pre_game_deal_gain_test` 固定覆盖。

逐目标伤害修正写入卡牌使用上下文的 `custom_args[target_id].damage_bonus`。`add_card_target_damage_bonus(card_uid, target_id, amount, reason)` 只接受当前最终目标，`SlashCardEffect` 在每个目标结算时读取该值；因此多目标【杀】的增伤互不污染。【强攻】以红色费用写 `direct_hit_target_ids`，以黑色费用写每目标 `damage_bonus=1`，武器费用同时写入两者。同步目标时机中通过 `exclude_card_target()` 或 `add_card_direct_hit_target()` 追加的集合会与 `RuleEvent.data` 输出稳定去重合并，不能被派发前复制出的旧数组覆盖。`add_card_target_damage_bonus()` 在写入共享上下文的同时，还会把同一加值同步写入仍在等待可选技能应答的 `RuleEvent.data.custom_args`，因此无论技能是同步改写事件数据，还是像【强攻】那样在异步费用选牌恢复后才登记，加值都不会被 CardUseEvent 的结果提交用派发前快照覆盖；技能侧不需要、也不得再自行改写该字段，否则同一加值会被重复累加。【弑神】在目标指定时登记 `1` 点加值，随后失去 `1` 点体力并允许濒死流程插入，濒死结束后才继续本牌后续结算。

卡牌目标、响应与效果开始前都会排除 `out_of_game=true` 的角色。已进入逐目标事件链的角色若在等待响应或选择期间离场，当前目标以省略或停止处理收口，不影响其他仍在场目标继续结算。
