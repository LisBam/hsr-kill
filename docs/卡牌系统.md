# 卡牌系统

## 数据来源与牌堆

默认牌堆 ID 为 `standard_162`，严格对齐项目内置《三国杀官方规则集 3.0》的身份局牌表，共 162 张。牌堆包含 1 张方块 Q【银月枪】与 1 张方块 5【木牛流马】，不包含国战专属牌。

`game_data/cards` 保存46个独立卡牌源码文件。每个文件同时包含稳定 ID、双名称、类型、目标、距离、配置化次数、响应、AI 价值、说明、最终区域、同步效果和异步恢复函数；`GameDatabase` 扫描目录后自动建立索引，不再读取集中卡牌 JSON。`CardEffectResolver` 只定位卡牌定义并按父牌 UID恢复选择、响应和无懈流程，不保存任何具体牌效。目标顺序与组合校验、濒死救援、回合专属状态、延时传递和装备动作均通过卡牌钩子回到对应文件；控制器和基础 AI 不维护具体卡牌 ID 白名单。普通【杀】、火【杀】和雷【杀】分别使用 `sha.gd`、`huosha.gd` 和 `leisha.gd`，实体牌直接携带伤害属性，三个文件显式复用专属 `SlashCardEffect` 牌族组件。三者规则牌名均为【杀】；“火【杀】”“雷【杀】”只区分属性，卡牌显示仍固定为两个字“火杀”“雷杀”。

卡牌文件使用小写拼音命名，并允许加入数字和下划线，例如【顺手牵羊】为 `game_data/cards/shunshouqianyang.gd`，扩展版本也可使用 `shunshouqianyang_2.gd`。文件名只负责源码定位；牌堆、网络、回放、存档和规则判断始终使用文件内声明的稳定 `id`，因此调整文件组织时不得同时擅自改变逻辑 ID。

## 卡牌 AI 数据

46个卡牌文件均在自身元数据中声明 `ai` 字典，对齐无名杀 `card/standard.js` 与 `card/extra.js` 的 `ai.basic/order/result/tag/equipValue/expose` 结构。基础 AI 只读取这些内容数据，不在中央策略维护卡牌 ID 分支。

通用字段包括出牌顺序 `order`、手牌保留价值 `value`、装备价值 `equip_value`、使用者结果 `player_result`、目标结果 `target_result`、伤害与属性标签、响应【杀】/【闪】标签、回复、救援、摸牌、失去牌、获得牌、跳阶段、多目标、通常正面效果与身份暴露度。

牌效估值使用身份态度组合目标结果。伤害牌对1点体力目标的效果倍率为2.5，对2点体力目标为1.8；目标0张手牌时通常为1.5，需要响应【杀】或【闪】时为1.7；1张手牌为1.3，2张为1.1，3张及以上为0.5。目标已知拥有所需【闪】或【杀】时预期倍率再乘0.35，没有已知【闪】但装备【八卦阵】时再乘0.65，1点体力且已知拥有【桃】或自救【酒】时再乘0.7。火焰和雷电伤害会继续估算横置角色的连环传播，回复牌对满体力目标收益为0；这些倍率只影响 AI 选择，不改变卡牌实际结算。公开身份观察同样从卡牌源码调用 `get_identity_observation_ai_profile()` 取得逐目标牌效：回复牌对满体力目标固定为0，【铁索连环】对未横置目标使用-0.5、对已横置目标使用+0.5，避免把无实际回复或解除连环误判为相反阵营行为。

复杂牌仍在自身文件提供专属 AI：铁索连环枚举包括自己在内的全部单目标与不重复双目标组合，并根据每名目标当前横置状态同时反转行动评分和身份观察方向；借刀杀人在使用动作中直接枚举“持刀者、被【杀】者”的完整合法双目标组合；闪电根据身份局势决定是否使用；木牛流马依据手牌溢出与材料价值存粮；丈八蛇矛枚举两张普通手牌组合并扣除材料价值。卡牌效果、AI 配置、身份观察与专属 AI 钩子必须同步维护，不能只更新其中一侧。

## 双名称配置

每个卡牌定义同时包含：

- `rule_name`：可选规则称呼；火【杀】与雷【杀】填写“杀”，不参与牌面显示。
- `original_name`：原版三国杀名称。
- `custom_name`：《崩铁杀》自定义名称。
- `id`：永不随显示名称变化的逻辑 ID。

`GameSettings.card_name_mode` 新启动时默认为 `CUSTOM`，因此主菜单与局内菜单首先显示《崩铁杀》自定义牌名；玩家可在任一设置入口切换为 `ORIGINAL` 显示原版三国杀牌名。该设置只改变前端文本，卡牌合法性、效果、AI、网络消息和存档始终使用 `id`，因此切换名称不会创建第二套逻辑。

武将技能源码中的卡牌引用统一使用 `【原版牌名】` 保存，不维护第二套技能原文。技能按钮展示时调用 `GameDatabase.resolve_card_names_in_text()`，只把完整书名号中的已登记牌名解析为当前模式名称；名称模式变化后桌面重新配置技能按钮，因此统一悬停信息会与手牌、装备和判定牌同步切换。普通叙述文字、规则数值、标点和技能稳定 ID 不参与替换。

## 卡牌插画字段

卡牌定义可选填写 `art_path`，例如 `res://assets/art/cards/sha.webp`。该字段只由 `CardView` 通过 `ArtworkLoader` 读取，不参与牌堆构建、规则合法性、效果执行、AI、网络动作、回放或存档判断。

未填写或资源无效时，牌面中部显示统一占位区。后续补充插画只需导入资源并填写路径，不需要修改 `CardInstance`、`GameState` 或卡牌效果代码。

牌面底部类别由 `CardView` 统一解析。`basic` 显示“基本牌”，`trick` 显示“锦囊牌”；`equipment` 不再统一显示父类型，而是按 `subtype` 把 `weapon/armor/offensive_mount/defensive_mount/treasure` 分别显示为“武器牌”“防具牌”“进攻坐骑牌”“防御坐骑牌”“宝物牌”。未知装备子类型回退“装备牌”，未知主类型回退“卡牌”；该文本只帮助识别，不改变装备槽、牌效或规则类型。

### 装备牌

武器、防具、进攻坐骑、防御坐骑和宝物分别占用唯一装备槽。界面固定按武器、防具、进攻坐骑、防御坐骑、宝物从上到下显示；进攻与防御坐骑图标分别为 `+` 与 `-`。第一视角本地装备栏常态显示全部五槽，外层固定150×148像素并与手牌牌面等高，五槽各占29.6像素且相邻间距为0。空宝物槽与其他空槽统一使用深色底框与类型图标，不显示“无”且不触发自动补位。本地玩家装备只在左侧装备栏显示，不在右下武将牌重复绘制；其他玩家仍在武将牌中显示公开装备。替换装备时，旧装备进入弃牌堆并执行离开装备区效果。所有武器的前端显示名在当前名称后追加攻击范围，例如“银河球棒 3”；该后缀不改变逻辑 ID、距离或数值。

- 武器：诸葛连弩、青釭剑、雌雄双股剑、贯石斧、青龙偃月刀、丈八蛇矛、方天画戟、麒麟弓、寒冰剑、古锭刀、朱雀羽扇、银月枪。
- 防具：八卦阵、仁王盾、白银狮子、藤甲。
- 防御坐骑：绝影、的卢、爪黄飞电、骅骝，其他角色计算距离 +1。
- 进攻坐骑：赤兔、大宛、紫骍，装备者计算距离 -1。
- 宝物：木牛流马。

已实现的装备结算包括【杀】次数、攻击范围、无视防具、异性触发、弃两牌强命中、追杀、两牌转【杀】、最后手牌额外目标、选择弃置坐骑、银月枪回合外黑色手牌触发、八卦判定、黑色【杀】无效、无手牌目标增伤、选择普通【杀】转火【杀】、伤害封顶、失去回复、锦囊/普通【杀】免疫、火伤增加、坐骑距离以及木牛存粮/转移/粮牌使用与响应。装备入槽、伤害修正、目标数、次数、防具无效和离区效果均通过对应装备源码钩子提供；锁定技按条件直接应用。仁王盾会令黑色实体【杀】无效，基础 AI 在出牌评分阶段会读取公开防具和自身实体颜色：若全部所选目标都被该规则拦截，则不使用该【杀】；青釭剑等声明无视防具的武器不受此预判限制。雌雄双股剑、贯石斧、青龙偃月刀、寒冰剑、麒麟弓、朱雀羽扇、银月枪等非锁定装备必须建立可取消选择请求，装备实体会由界面自动选中，玩家点击确定才发动、点击取消则放弃。出牌或响应时可以主动发动的丈八蛇矛、木牛流马直接把装备实体加入当前选择候选，不创建专用技能按钮。装备候选横条用0.25秒向右移动10像素，选中后再用0.25秒右移10像素，取消候选或选中时也用0.25秒复原。八卦阵黑色判定只结束本次装备响应，统一响应窗口会排除该八卦阵并继续提供手牌或木牛“粮”中的【闪】；银月枪攻击范围为3，持有者于回合外使用或打出黑色手牌完成原响应子事件后，再决定是否发动并令范围内目标响应【闪】，否则造成1点普通伤害；木牛“粮”不属于手牌，不会触发该效果。

丈八蛇矛只有在当前可以使用或打出【杀】且持有者至少有2张普通手牌时进入装备候选。点击后必须选择正好2张不同的普通手牌作为实体材料；木牛“粮”和装备牌都不能作为丈八材料。生成的虚拟【杀】没有花色、点数和颜色，不会因任一材料牌为黑色而错误触发仁王盾；材料在整张虚拟【杀】结束后统一进入弃牌堆，丈八蛇矛仍留在武器槽。方天画戟只在实际使用的【杀】位于手牌区且是最后1张手牌时增加目标数，丈八虚拟【杀】和木牛“粮”不会借助手牌数量误触发。

## 区域移动

实体牌区域使用稳定字符串：`draw_pile`、`hand`、`processing`、`equipment`、`judgment`、`wooden_ox`、`discard_pile`。任何使用牌先从所有者牌源进入处理区，效果结束后再进入弃牌堆、装备区或判定区。移动使用实体 UID，不能使用数组下标作为网络或回放标识；同一实体在同一区域且持有者未改变时视为无效重复移动，不写入历史也不发出 `card_moved`。`CardMovementService.card_moved` 是移动完成后的唯一增量来源；控制器据此生成 `card_transfer_requested`，为摸牌、获得、响应弃牌、展示牌获得和普通弃牌携带来源玩家、来源区域、目标玩家和目标区域，规则函数不得手工重复发出同一次移动。

控制器在唯一移动端口前后派发标准区域时机。进入手牌使用 `gainBefore/Begin/End/After`，离开玩家手牌、装备、判定区或木牛附属区使用 `loseBefore/Begin/End/After`，进入弃牌堆使用 `discardBefore/Begin/End/After` 与 `cardsDiscardEnd/After`，原持有者牌进入弃牌堆后追加 `loseToDiscardpileAfter`；进入装备区使用 `equipBefore/End/After`，进入判定区使用 `addJudgeBefore/End/After`。取消前置时机时本次实体移动不会发生，也不会写入移动历史。

## 界面选择与拖放

手牌选中后向上移动18像素，取消选中后回到布局基线；上移与下移动画时长均为0.025秒。该动画只改变客户端临时视觉偏移，不改变实体牌区域、选择 UID 或提交时机。

手牌与木牛“粮”统一由以 `Node2D` 为根的 `CardView` 按实体 UID 渲染。`card_view.tscn` 是唯一牌面结构，直接保存111×148像素纸张、类别条、插画槽、花色点数、牌名、类别、默认隐藏的“牌背”覆盖层和透明输入区域，编辑器默认预览黑桃7【杀】基本牌；手牌、选择窗口、摸牌动画、获得动画和出牌动画全部实例化该场景，禁止再创建第二套卡牌 UI。木牛“粮”始终排在普通手牌左侧，但仍属于 `wooden_ox` 区域，不计入普通手牌数与弃牌阶段手牌上限。牌面本身不是按钮；透明 `CardInputArea` 只把点击、悬停和拖拽转换为稳定 UID 信号。可见本地手牌悬停时由 `CardView.information_requested(information, anchor_rect)` 把当前名称、花色点数、细分类别与静态规则说明交给牌桌唯一 `InformationBoxLayer`；不可使用状态只禁止点击和拖拽，不禁止查看说明。牌背不发送信息请求，目标来源离开或节点释放时必须发送 `information_dismissed`，全部卡牌视图保持空 `tooltip_text`。

普通出牌的点击与拖放只改变 UI 临时选择，不改变卡牌区域；只有玩家点击“确定”或按 `Enter`，并通过 `MatchController.submit_action()` 校验后，卡牌才会从 `hand` 或 `wooden_ox` 移入 `processing`。出牌阶段逐张读取当前 `chooseToUse.card_ids`：只有至少存在一种合法使用、重铸或木牛存粮动作的手牌、木牛“粮”或主动装备实体允许交互；响应专用牌、次数用尽的杀/酒、没有合法目标的牌和其他当前不可用牌即使轮到本人也必须禁用灰显。重铸动作只枚举普通 `hand` 中配置允许重铸的实体牌，`wooden_ox` 中的同名“粮”只能使用或打出，不能重铸；选中【铁索连环】后没有选择目标时，“确定”直接提交重铸，不显示独立重铸按钮。响应、弃牌、火攻和装备费用等请求的候选若全部属于选择者本人的 `hand/wooden_ox/equipment`，直接复用当前手牌区与装备区：非候选手牌使用相同禁用灰显样式且不接收输入，可选装备先右移10像素、选中后总计右移20像素，位移与复原时长均为0.25秒；上下文绑定具体装备实体的触发询问自动选中该装备，选中数量满足约束后才启用“确定”，规则允许放弃时才启用“取消”。点击丈八蛇矛后，普通手牌临时切换为2张材料候选；点击木牛流马后，普通手牌临时切换为1张存粮候选。包含公共展示牌、他人牌或判定牌的请求继续使用 `CardSelectionPanel`。所有选择界面的禁用确定、取消及同类按钮固定使用深灰样式，禁用期间不显示悬停变化。

本地 `EquipmentStackView` 的五个槽位和其他玩家 `PlayerTargetView` 牌面上的公开装备横条共用相同信息内容契约：已装备实体悬停时显示槽位、花色点数、当前名称模式和 `description`，空槽不显示卡牌说明。其他玩家牌面的装备横条位于最上层武将输入区域下方，因此由 `PlayerTargetInputArea.pointer_moved(local_position)` 转发局部坐标并在 `PlayerTargetView` 内完成横条命中；UI 只能读取公开装备快照，不能显示其他玩家手牌或木牛内部牌面。

普通独立请求继续使用正式主场景820×460像素 `CardSelectionPanel` 与当前 UI 风格的统一 `shade` 背景滤镜；崩铁风格透明度约0.82，暖木家园约0.84。互斥文字选项同样复用该组件，但不创建卡牌位：每个 `control_options` 成员生成一个280×44像素按钮，点击直接提交稳定 `selected_control_id`，允许放弃时显示“不选择”且隐藏通用确定。五谷丰登公共展示改用紧凑动态窗口：牌阵固定4列，每张111×148像素，水平与垂直间距均为8像素，4列牌阵宽468像素，窗口只额外保留36像素横向总边距且不显示“展示区”标题；最多10名玩家时形成3行。窗口通过中心锚点和对称四边偏移保持居中，动态尺寸不会把窗口移到左上角屏幕外。`GameState.public_card_choice_display` 保存最初固定牌位、当前选择者和领取者：窗口从亮牌后立即出现，AI 或其他玩家选择时保持只读可见；本地进入与五谷选牌不同类型的【无懈可击】响应时暂时隐藏公共窗口并开放手牌内联输入，响应结束后从同一公共快照恢复。被领取的牌不从牌列删除，而是以 `(0.72, 0.72, 0.72, 0.48)` 调制色保留复制虚影，并在牌底103×26像素标签中显示领取者武将名。私有选择请求仍只开放当前未领取的合法 UID 或控制项 ID，公共展示不能替代 `choose_cards` 权威校验。

【无懈可击】对每个锦囊目标建立独立响应链。每轮公开高亮全部存活玩家，但候选牌只进入各玩家私有请求；没有合法候选的玩家不创建阻塞窗口，仍保持与持牌玩家相同的公共高亮。多个有效请求同时等待，权威端接受最先提交且通过当前区域、响应模式和实体 UID 复核的一张【无懈可击】，随后关闭同轮其余请求并翻转一次抵消状态；下一轮重新按相同规则开放，完整一轮无人响应后结束。卡牌询问中的玩家目标名称优先使用已公开武将名，不显示“玩家X”或“[AI]玩家X”。

`CardView.disabled_darkening` 默认值为 `0.38`，用于把禁用纸张和类别条压暗38%；`disabled_content_modulate` 默认值为 `(0.45, 0.45, 0.45, 1.0)`，用于把禁用插画与文字保留为45%亮度的深灰表现。两个参数只影响客户端可读性，不改变卡牌合法性、目标、伤害、回复、次数、距离、资源消耗或持续时间。

界面通过 `get_card_use_preview()` 获取目标模式、规则修正后的最大目标数、合法候选与当前组合是否可提交。自身目标牌由界面自动选择并锁定本人；普通目标牌若当前恰好只有1名合法候选，也会自动锁定该目标，但仍必须点击“确定”或按`Enter`才会提交。最大目标数为1且存在多个合法候选时，点击新目标会直接替换旧目标，无需先取消；方天画戟满足条件时查询返回3，不会被误判为单目标。全体目标牌由规则层从使用者开始按环形行动顺序自动展开：包含使用者的牌先结算使用者，排除使用者的牌先结算其下一名存活角色。手动多目标先按点击顺序编辑，提交后由规则层按当前回合角色起算的行动顺序规范化。【借刀杀人】使用时必须按持刀者、被【杀】者声明2名角色；卡牌结算前由 `get_resolution_target_ids()` 收敛为唯一持刀者，第二名角色由 `configure_requested_target_context()` 写入结算上下文，不触发本牌目标时机且不创建二次目标选择。该接口始终显式返回 `Array[int]`：没有目标时返回空的强类型数组，有首名目标时只返回该角色，避免动态数组返回值破坏脚本类型契约。涉及实体牌或目标选择的效果通过 `card_choice_requested` 询问，提交 `choose_cards` 后才继续结算；过河拆桥、顺手牵羊的候选顺序固定为手牌区、装备区、判定区，不可见手牌只渲染牌背。出牌、响应和效果选牌统一由 `EventScheduler` 分配全局唯一请求 ID，运行时登记成功后才允许启用对应的本地区域内联交互或独立选择窗口，并在响应确认接收后才清理待选上下文。任一目标结算使对局满足胜负条件时，效果执行器立即停止后续目标、响应与卡牌区域移动。预览结果不是权威状态，不能用于跳过 `validate_use()`。

卡牌与技能共用同一临时选择模型：卡牌、目标和按钮都只写入 `ChoiceResponse`，确认前不移动实体牌、不消耗次数。普通【杀】与【桃】仍在 `chooseToUse` 中先选牌再选目标；【过河拆桥】先通过卡牌目标规则选择一名其他角色，进入该目标 `content` 后再创建选牌请求，从其手牌、装备区或判定区中选择1张弃置。【借刀杀人】在 `chooseToUse` 内一次性声明持刀者与被【杀】者，结算直接读取共享上下文并要求持刀者响应【杀】。技能需要“选择一张牌并选择一名角色”时使用 `choice_type=card_target`，牌数与目标数分别校验，可选的牌到目标映射不会改变任何现有卡牌伤害、回复、距离或次数数值。

摸牌和获得牌的动画由 `card_transfer_requested` 统一驱动，实体牌 UID 始终作为移动标识。一次 `draw()` 产生独立表现批次：同批每张牌均显示正式 `CardView` 的“牌背”覆盖层，从同一牌堆锚点同时起飞，并按42像素横向间距围绕目标锚点整体居中；飞行0.24秒、停留0.10秒、淡出0.18秒，同批不使用逐张延时。带摸牌堆叠键而未进入批次接口的兼容转移使用相同三段时长；每个批次在收到完整移牌后立即开始，多个玩家或连续多次 `draw()` 的批次允许同时飞行、停留和淡出，不互相等待。本地玩家所有进入手牌区的牌（包括摸牌和从其他区域获得）不创建会在动画结束后销毁的替代转移牌：桌面先登记实体 UID，收到包含该牌的本地快照后按 UID 创建或复用手牌容器中的唯一正式 `CardView`，再让这个节点从手牌可视区右侧24像素外用0.24秒移动到自身布局位置；快照刷新期间实例保持不变，动画结束后同一节点继续承担选择、拖放和后续出牌。卡牌与武将组件保存最近配置签名，未变化快照不会重复加载插画或重建样式、体力、装备和判定子节点；对手座位按玩家 ID 持久复用。隐藏候选仍使用同一牌背覆盖层，不通过伪造空白牌面实现信息隐藏。重新开局清空表现时，转移牌、正式手牌入场补间与并行批次补间分别停止并清除，旧局异步任务不得写入新局节点。

卡牌通过校验进入处理区时，规则层生成可序列化 `CardPresentationEvent(event_name=useCard)`，表现层直接接管手牌中的同一 `CardView` 节点，并从实际使用者区域移动到中央弃牌展示落点，保持111×148像素的3:4正式牌面、插画、花色、点数、名称和类别不变。火攻展示使用 `event_name=showCards` 的独立表现实例，实体仍留在原手牌区；判定阶段先用 `event_name=delayedJudge` 展示当前延时锦囊，再用 `event_name=judge` 把牌堆顶1张判定牌直接从中央弃牌展示锚点公开，不从判定角色位置打出。四类表现共用中央队列；真实使用牌、延时锦囊和判定牌可按最终区域声明 `owns_discard_transfer=true`，纯展示牌不会吞掉该实体未来真正进入弃牌堆的移动。玩家来源或目标缺少真实座位锚点时跳过本次短时动画，不能回退中央锚点伪造位置；新建 `CardView` 在写入父级、起点和外观前保持隐藏。动画牌的悬停结束与样式刷新只修改缩放、颜色和层级，默认不再写入非手牌 `position.y`，因此响应等待期间不会从中央队列跳到窗口顶部。`GameState.to_dict()` 同时公开不含牌面的 `processing_card_uids`，中央动画层据此核对认领牌：权威实体已离开处理区而最终移动通知缺失时，仍会启动正常收尾。目标线用0.24秒动态延伸，完成后立即独立用0.36秒淡出。同一帧进入弃牌堆的多张牌按移动信号顺序以66像素中心间距从左到右完整铺开并保持0度旋转。纯展示与普通弃牌完成0.42秒飞行和0.48秒停留后使用0.36秒淡出；接管最终区域移动的真实牌会在响应、选牌或判定完成前持续留在中央，最终移牌到达后再完整停留0.48秒并淡出。每张牌只保留一个收尾生命周期 Tween，不再创建两个 SceneTreeTimer 等待协程。普通弃牌首次观察到某个实体 UID 时登记其中央表现生命周期，重复增量、同区域重复移动和纯展示牌的迟到弃牌都不会在牌桌上方或中央重建第二张牌；未被 `useCard`、`delayedJudge` 或 `judge` 明确认领的处理区弃牌收尾也不会合成无来源牌面。

## 独立源码字段与效果入口

新增牌必须在 `game_data/cards` 创建继承 `CardDefinition` 的拼音文件，并至少声明 `id`、双名称、`type`、`subtype`、`effect_id`、目标模式、目标数、距离限制、次数限制、响应模式、是否延时、是否可重铸、说明、`resolution_mode`、`final_zone` 与 `provided_response_pattern`；`rule_name`、`art_path`、`play_limit_group`、`play_limit_scope`、`allow_self_target`、AI 字段和装备交互字段按需要填写。文件必须覆盖 `resolve()`，特殊逐目标牌可覆盖 `resolve_target()`。

`resolution_mode=per_target` 表示每名有效目标分别进入内容事件，`resolution_mode=whole` 表示一次取得完整目标数组；装备、延时锦囊和五谷公共牌池使用 `whole`。`final_zone` 当前使用 `discard`、`equipment` 或 `judgment`，用于表现层判断是否接管处理区到弃牌堆的移动，权威终点仍由卡牌函数返回值决定。

`response_pattern` 对普通锦囊表示该牌效可被【无懈可击】响应，不代表该实体自身能当【无懈可击】打出；实体实际能提供的响应由 `provided_response_pattern` 明确声明。当前【杀】提供 `sha`、【闪】提供 `shan`、【桃】提供 `tao`、【酒】提供 `jiu`、【无懈可击】提供 `wuxie`，其他牌为空字符串。新增自定义效果不需要加入集中效果 ID 白名单，只要对应卡牌文件提供合法函数并通过数据校验与回归测试即可。

`play_limit` 与 `play_limit_group` 决定同组使用次数，`play_limit_scope` 决定从当前回合历史还是当前出牌阶段历史统计。普通【杀】、火【杀】与雷【杀】通过同一 `slash` 分组和 `phase` 作用域共享每个出牌阶段1次基础限制，进入额外出牌阶段会清空阶段历史并重新获得1次额度；诸葛连弩只通过装备钩子解除该配置限制。【酒】使用 `turn` 作用域，额外出牌阶段仍与原阶段共享每回合1次限制。`ai_use_value`、`ai_target_attitude` 和 `ai_beneficial` 分别决定基础 AI 静态牌值、目标友敌方向和无懈收益方向，新增卡牌无需修改 `BasicAIPolicy`。

需要自行枚举多目标组合的卡牌覆盖 `append_play_phase_card_actions()`，并通过 `append_card_action_if_legal()` 复用统一合法性校验与动作结构。传入该端口的目标列表必须先声明为 `Array[int]`；卡牌源码以 `Object` 访问控制器时，未定型数组字面量不会自动转换为方法要求的强类型数组。【铁索连环】枚举全部合法单目标和不重复双目标组合，合法目标包含使用者自己。【借刀杀人】只枚举单元素持刀者数组，被【杀】者不属于该牌目标。

濒死救援不再由控制器判断桃或酒的定义 ID。卡牌通过 `get_dying_response_pattern()` 声明当前响应者与濒死者关系下能否进入救援窗口，再由 `resolve_dying_response()` 自行执行回复和日志；桃允许任意存活角色救援，酒只允许濒死者本人自救，数值仍均为回复1点。

存活角色体力不大于0时必须继续濒死流程。`dyingBefore` 或 `dyingBegin` 的取消、中立化标志只有在处理器已把目标恢复到1点或以上、确认死亡或令其离场时才能终止入口；仅取消事件而不修正角色状态不会绕过求桃与死亡确认。

延时锦囊在自身文件覆盖 `resolve_delayed_judgment()`；当前【闪电】的黑桃2至9与3点雷电伤害、【乐不思蜀】的非红桃跳过出牌阶段、【兵粮寸断】的非梅花跳过摸牌阶段均已从控制器分支迁入对应卡牌文件。装备等持续区域卡牌可覆盖 `install_runtime/uninstall_runtime`，系统按实体 UID 创建独立实例并在离区时卸载，新增被动装备可直接订阅规则事件而无需登记集中装备表。

## 事件化卡牌生命周期

`CardMovementService` 是规则层的统一移动边界，写入 `CardMoveEvent` 并保存 `from_zone/to_zone/source_player_id/target_player_id/event_id/reason/visible_to`。`processing` 是使用牌、响应牌和判定牌的 ordering 区域；完成主体前不得把牌直接放入弃牌堆。实体 `CardInstance` 额外保存 `known_to`、`shown` 和 `private_owner_id`，公开展示会更新知识集合，弃牌堆洗回牌堆时清理临时知识。

使用牌生命周期由真实 `CardUseEvent` 驱动：实体材料在 `lose` 子事件进入 `processing`，随后依次派发 `useCardBefore`、`useCardBegin` 和五组 `useCard0/useCard1/yingbian/useCard2/useCard`。四组目标时机 `useCardToPlayer/useCardToTarget/useCardToPlayered/useCardToTargeted` 按阶段优先顺序逐项进入调度栈；每组先遍历全部当前目标。每次目标时机结束都会重新读取目标数组，并按当前行动座次生成本轮遍历副本；动态新增目标能够补齐当前与后续阶段，同一目标重复出现时按出现次数分别触发。

每个实际目标由 `useCardToBefore/Begin/End/After` 包裹，死亡或离场目标派发 `useCardToOmitted`，规则排除目标派发 `useCardToExcluded`，前置窗口取消则派发 `useCardToCancelled` 并只跳过该目标。`directHit` 目标跳过对应【闪】与【无懈可击】响应，`customArgs` 由全部子事件共享。【杀】在目标生命周期内部依次派发 `shaBefore/Begin`、命中或闪避的 `shaHit/shaMiss`、造成伤害前的 `shaDamage`，最后先派发 `shaEnd/shaAfter`，再退出到 `useCardToEnd/useCardToAfter`。

实际目标各自拥有可暂停 `content`，响应与效果选择作为其子事件；五谷丰登等整牌异步效果在恢复回调写入 `content_complete` 后，原 `content` 事件只读取最终区域并结束，禁止再次执行亮牌或重复创建选择请求。全部内容完成后派发 `useCardEnd/useCardAfter`；整牌前置被取消时改派 `useCardCancelled`。父事件随后只创建1次 `contentAfter`，并通过 `after` 队列执行 `orderingDiscard -> cardsDiscard`。实体牌、装备牌和延时锦囊的最终区域仍由规则效果决定，事件树不会改变区域规则。

响应牌在实际消费前后依次派发 `respondBefore → respondBegin → respond → respondEnd → respondAfter`；被抵消的牌或事件使用 `eventNeutralized`。判定流程依次派发 `judgeBefore → judgeBegin → judge → judgeFixing → judgeEnd → judgeAfter`，判定牌仍只从牌堆顶取得1张。五谷丰登仍有未领取展示牌时，在这些牌离开处理区进入弃牌堆之前派发 `wuguRemained`，便于技能使用剩余实体 UID。

`VirtualCard` 只描述逻辑牌名、花色、点数、属性和扩展存储，实体材料牌通过 UID 数组单独保存。丈八蛇矛、技能视为牌和无懈可击响应不能把多张实体材料压扁成一张新的普通实体牌；回放必须同时记录逻辑牌和材料 UID。单张材料形成的虚拟牌继承该实体花色与点数，多材料或无材料虚拟牌保持无花色、无点数。

响应候选除实体自身的 `provided_response_pattern` 和装备响应入口外，还会查询持有者技能的 `can_convert_response_card()` 与 `get_converted_response_definition_id()`。例如【罡风】可把当前拥有的1张黑色手牌、木牛“粮”或装备牌当雷【杀】打出；提交时控制器再次复核技能、颜色、区域和响应模式，把材料移入处理区，创建继承其花色与点数的虚拟雷【杀】，完成响应后再将材料送入弃牌堆。装备材料成功离区时必须卸载对应运行时并正常执行装备离区效果。该转换不改变牌面原定义，也不额外生成可进入牌堆的实体牌。

出牌阶段本身由 `chooseToUse` `ChoiceRequest` 表示；一次合法 `use_card`、`use_zhangba`、`recast_card`、木牛操作或主动技能选择完成后会创建下一次请求，`end_play` 以取消当前请求推进弃牌阶段。主动技能 ID 进入该请求的 `button_ids`，提交 `use_skill` 时先完成当前 `chooseToUse`，再在同一事件链内执行技能及其后续选牌/选目标。旧 UI 仍提交 `PlayerAction`，控制器先转换成 `ChoiceResponse` 再执行权威校验。`chooseToUse` 与五谷、火攻、弃牌、响应等后续请求不能维护各自独立的自增 ID；所有请求必须使用事件调度器的同一全局序号，避免交错窗口引用到其他仍活动的请求。

延时锦囊在判定阶段严格按判定区数组顺序逐张处理：当前牌进入处理区后先发送 `delayedJudge` 中央展示，默认等待1.00秒，再进入【无懈可击】与实际判定；该牌完成或选择恢复后默认再等待1.00秒，才展示下一张延时锦囊。`delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds` 均可在检查器设为0.00至3.00秒，正式对局默认均为1.00秒；无 `match_id` 的纯规则预演跳过表现等待。若【无懈可击】或判定伤害触发濒死救援需要等待本地玩家，则判定阶段保持暂停，不能提前创建摸牌或出牌请求。选择完成后先结算同一张延时锦囊并保留结果，再继续剩余判定牌；全部判定结束后才依次进入摸牌、出牌、弃牌和结束阶段。
