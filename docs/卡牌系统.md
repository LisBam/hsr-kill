# 卡牌系统

## 数据来源与牌堆

默认牌堆 ID 为 `standard_162`，严格对齐项目内置《三国杀官方规则集 3.0》的身份局牌表，共 162 张。牌堆包含 1 张方块 Q【银月枪】与 1 张方块 5【木牛流马】，不包含国战专属牌。

`data/cards.json` 保存 46 个卡牌配置 ID。普通【杀】、火【杀】和雷【杀】分别登记，以便实体牌直接携带伤害属性；三者共享 `slash` 效果逻辑。

## 双名称配置

每个卡牌定义同时包含：

- `original_name`：原版三国杀名称。
- `custom_name`：《崩铁杀》自定义名称。
- `id`：永不随显示名称变化的逻辑 ID。

`GameSettings.card_name_mode` 只改变前端文本。卡牌合法性、效果、AI、网络消息和存档始终使用 `id`，因此切换名称不会创建第二套逻辑。

## 卡牌插画字段

卡牌定义可选填写 `art_path`，例如 `res://assets/art/cards/sha.webp`。该字段只由 `CardView` 通过 `ArtworkLoader` 读取，不参与牌堆构建、规则合法性、效果执行、AI、网络动作、回放或存档判断。

未填写或资源无效时，牌面中部显示统一占位区。后续补充插画只需导入资源并填写路径，不需要修改 `CardInstance`、`GameState` 或卡牌效果代码。

### 装备牌

武器、护甲、进攻坐骑、防御坐骑和宝物分别占用唯一装备槽。替换装备时，旧装备进入弃牌堆并执行离开装备区效果。

- 武器：诸葛连弩、青釭剑、雌雄双股剑、贯石斧、青龙偃月刀、丈八蛇矛、方天画戟、麒麟弓、寒冰剑、古锭刀、朱雀羽扇、银月枪。
- 防具：八卦阵、仁王盾、白银狮子、藤甲。
- 防御坐骑：绝影、的卢、爪黄飞电、骅骝，其他角色计算距离 +1。
- 进攻坐骑：赤兔、大宛、紫骍，装备者计算距离 -1。
- 宝物：木牛流马。

已实现的装备结算包括杀次数、攻击范围、无视防具、异性触发、弃两牌强命中、追杀、两牌转杀、最后手牌额外目标、弃坐骑、银月枪回合外黑色手牌触发、八卦判定、黑杀无效、无手牌目标增伤、普通杀转火杀、伤害封顶、失去回复、锦囊/普通杀免疫、火伤增加、坐骑距离以及木牛存粮/转移/粮牌使用与响应。银月枪攻击范围为3；持有者于回合外使用或打出黑色手牌时，基础自动策略优先指定范围内敌方，目标打出1张【闪】则抵消，否则受到1点普通伤害；木牛“粮”不属于手牌，不会触发该效果。

丈八蛇矛生成的虚拟【杀】没有花色、点数和颜色，不会因第一张材料牌为黑色而错误触发仁王盾。方天画戟只在实际使用的【杀】位于手牌区且是最后 1 张手牌时增加目标数，使用木牛“粮”不会借助手牌数量误触发。

## 区域移动

实体牌区域使用稳定字符串：`draw_pile`、`hand`、`processing`、`equipment`、`judgment`、`wooden_ox`、`discard_pile`。任何使用牌先从所有者牌源进入处理区，效果结束后再进入弃牌堆、装备区或判定区。移动使用实体 UID，不能使用数组下标作为网络或回放标识。控制器的 `card_transfer_requested` 会为摸牌、获得、响应弃牌、展示牌获得和普通弃牌提供统一表现事件，事件携带来源玩家、来源区域、目标玩家和目标区域。

## 界面选择与拖放

手牌与木牛“粮”统一由以 `Node2D` 为根的 `CardView` 按实体 UID 渲染。牌面本身不是按钮；透明 `CardInputArea` 只把点击、悬停和拖拽转换为稳定 UID 信号。点击与拖放只改变 UI 临时选择，不改变卡牌区域；只有玩家点击“确定”或按 `Enter`，并通过 `MatchController.submit_action()` 校验后，卡牌才会从 `hand` 或 `wooden_ox` 移入 `processing`。

界面通过 `get_card_use_preview()` 获取目标模式、合法候选与当前组合是否可提交。自身目标牌由界面自动选择本人，全体目标牌由规则层从使用者开始按环形行动顺序自动展开：包含使用者的牌先结算使用者，排除使用者的牌先结算其下一名存活角色。手动多目标先按点击顺序编辑，提交后由规则层按当前回合角色起算的行动顺序规范化；【借刀杀人】例外保留“持刀者、被杀者”顺序。涉及实体牌选择的效果通过 `card_choice_requested` 询问，提交 `choose_cards` 后才继续结算；过河拆桥、顺手牵羊的候选顺序固定为手牌区、装备区、判定区，不可见手牌只渲染牌背。出牌、响应和效果选牌统一由 `EventScheduler` 分配全局唯一请求 ID，运行时登记成功后才允许显示窗口，并在响应确认接收后才清理待选上下文。任一目标结算使对局满足胜负条件时，效果执行器立即停止后续目标、响应与卡牌区域移动。预览结果不是权威状态，不能用于跳过 `validate_use()`。

摸牌和获得牌的动画由 `card_transfer_requested` 统一驱动，实体牌 UID 始终作为移动标识。

卡牌通过校验进入处理区时，表现层直接接管手牌中的同一 `CardView` 节点，并从实际使用者区域移动到中央弃牌展示落点，保持111×148像素的3:4正式牌面、插画、花色、点数、名称和类别不变。其他玩家的手牌内容对本地不可见时，动画也只能实例化同一个 `card_view.tscn` 正式模型，不得创建细长标签或简化面板替代牌。本地玩家的来源与目标锚点统一为手牌区顶边上方8像素的水平中心，其他玩家统一为武将牌中心；目标线用0.24秒动态延伸，完成后立即独立用0.36秒淡出。多名玩家连续使用卡牌时，牌面按66像素中心间距水平铺开，保持0度旋转，并按进入队列的顺序逐张使用0.36秒淡出消失。

## 扩展字段

新增牌至少需要声明 `id`、双名称、`type`、`subtype`、`effect_id`、目标模式、目标数、距离限制、响应模式、是否延时和是否可重铸；`art_path` 为可选表现字段。新效果 ID 必须在独立执行组件中实现，并加入烟雾测试支持列表；共享规则的属性变体应复用同一 `effect_id`。

## 事件化卡牌生命周期

`CardMovementService` 是规则层的统一移动边界，写入 `CardMoveEvent` 并保存 `from_zone/to_zone/source_player_id/target_player_id/event_id/reason/visible_to`。`processing` 是使用牌、响应牌和判定牌的 ordering 区域；完成主体前不得把牌直接放入弃牌堆。实体 `CardInstance` 额外保存 `known_to`、`shown` 和 `private_owner_id`，公开展示会更新知识集合，弃牌堆洗回牌堆时清理临时知识。

`VirtualCard` 只描述逻辑牌名、花色、点数、属性和扩展存储，实体材料牌通过 UID 数组单独保存。丈八蛇矛、技能视为牌和无懈可击响应不能把多张实体材料压扁成一张新的普通实体牌；回放必须同时记录逻辑牌和材料 UID。

出牌阶段本身由 `chooseToUse` `ChoiceRequest` 表示；一次合法 `use_card`、`recast_card` 或木牛操作完成后会创建下一次请求，`end_play` 以取消当前请求推进弃牌阶段。旧 UI 仍提交 `PlayerAction`，控制器先转换成 `ChoiceResponse` 再执行权威校验。`chooseToUse` 与五谷、火攻、弃牌、响应等后续请求不能维护各自独立的自增 ID；所有请求必须使用事件调度器的同一全局序号，避免交错窗口引用到其他仍活动的请求。
