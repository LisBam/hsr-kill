# 卡牌系统

## 数据来源与牌堆

默认牌堆 ID 为 `standard_161`，由无名杀参考配置中的标准与 EX 牌 108 张、完整军争配置 53 张组成，共 161 张。完整军争配置包含 1 张【木牛流马】，因此比常见的 160 张组合多 1 张。牌堆不包含国战专属牌。

`data/cards.json` 保存 45 个卡牌配置 ID。普通【杀】、火【杀】和雷【杀】分别登记，以便实体牌直接携带伤害属性；三者共享 `slash` 效果逻辑。

## 双名称配置

每个卡牌定义同时包含：

- `original_name`：原版三国杀名称。
- `custom_name`：《崩铁杀》自定义名称。
- `id`：永不随显示名称变化的逻辑 ID。

`GameSettings.card_name_mode` 只改变前端文本。卡牌合法性、效果、AI、网络消息和存档始终使用 `id`，因此切换名称不会创建第二套逻辑。

## 卡牌插画字段

卡牌定义可选填写 `art_path`，例如 `res://assets/art/cards/sha.webp`。该字段只由 `CardView` 通过 `ArtworkLoader` 读取，不参与牌堆构建、规则合法性、效果执行、AI、网络动作、回放或存档判断。

未填写或资源无效时，牌面中部显示统一占位区。后续补充插画只需导入资源并填写路径，不需要修改 `CardInstance`、`GameState` 或卡牌效果代码。

### 装备牌

武器、护甲、进攻坐骑、防御坐骑和宝物分别占用唯一装备槽。替换装备时，旧装备进入弃牌堆并执行离开装备区效果。

- 武器：诸葛连弩、青釭剑、雌雄双股剑、贯石斧、青龙偃月刀、丈八蛇矛、方天画戟、麒麟弓、寒冰剑、古锭刀、朱雀羽扇。
- 防具：八卦阵、仁王盾、白银狮子、藤甲。
- 防御坐骑：绝影、的卢、爪黄飞电、骅骝，其他角色计算距离 +1。
- 进攻坐骑：赤兔、大宛、紫骍，装备者计算距离 -1。
- 宝物：木牛流马。

已实现的装备结算包括杀次数、攻击范围、无视防具、异性触发、弃两牌强命中、追杀、两牌转杀、最后手牌额外目标、弃坐骑、八卦判定、黑杀无效、空城增伤、普通杀转火杀、伤害封顶、失去回复、锦囊/普通杀免疫、火伤增加、坐骑距离以及木牛存粮/转移/粮牌使用与响应。

丈八蛇矛生成的虚拟【杀】没有花色、点数和颜色，不会因第一张材料牌为黑色而错误触发仁王盾。方天画戟只在实际使用的【杀】位于手牌区且是最后 1 张手牌时增加目标数，使用木牛“粮”不会借助手牌数量误触发。

## 区域移动

实体牌区域使用稳定字符串：`draw_pile`、`hand`、`processing`、`equipment`、`judgment`、`wooden_ox`、`discard_pile`。任何使用牌先从所有者牌源进入处理区，效果结束后再进入弃牌堆、装备区或判定区。移动使用实体 UID，不能使用数组下标作为网络或回放标识。

## 界面选择与拖放

手牌与木牛“粮”统一由以 `Node2D` 为根的 `CardView` 按实体 UID 渲染。牌面本身不是按钮；透明 `CardInputArea` 只把点击、悬停和拖拽转换为稳定 UID 信号。点击与拖放只改变 UI 临时选择，不改变卡牌区域；只有玩家点击“确定”或按 `Enter`，并通过 `MatchController.submit_action()` 校验后，卡牌才会从 `hand` 或 `wooden_ox` 移入 `processing`。

界面通过 `get_card_use_preview()` 获取目标模式、合法候选与当前组合是否可提交。自身目标牌由界面自动选择本人，全体目标牌由规则层从使用者开始按环形行动顺序自动展开：包含使用者的牌先结算使用者，排除使用者的牌先结算其下一名存活角色。单目标和手动多目标牌按玩家选择顺序提交。预览结果不是权威状态，不能用于跳过 `validate_use()`。

卡牌通过校验进入处理区时，表现层直接接管手牌中的同一 `CardView` 节点，并从实际使用者区域移动到中央弃牌展示落点，保持111×148像素的3:4正式牌面、插画、花色、点数、名称和类别不变。其他玩家的手牌内容对本地不可见时，动画也只能实例化同一个 `card_view.tscn` 正式模型，不得创建细长标签或简化面板替代牌。本地玩家的来源与目标锚点统一为手牌区顶边上方8像素的水平中心，其他玩家统一为武将牌中心；目标线用0.24秒动态延伸，并用0.36秒淡出。多名玩家连续使用卡牌时，牌面按66像素中心间距水平铺开，保持0度旋转，并按进入队列的顺序逐张使用0.36秒淡出消失。

## 扩展字段

新增牌至少需要声明 `id`、双名称、`type`、`subtype`、`effect_id`、目标模式、目标数、距离限制、响应模式、是否延时和是否可重铸；`art_path` 为可选表现字段。新效果 ID 必须在独立执行组件中实现，并加入烟雾测试支持列表；共享规则的属性变体应复用同一 `effect_id`。
