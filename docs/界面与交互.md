# 界面与交互

## 游戏结算界面

- `GameSettlementPanel` 是牌桌动态创建的全屏模态组件，显示在普通选牌与机缘选择之上。面板只读取终局快照，不访问或修改 `MatchController.state`。任何返回主菜单的路径（终局操作、局内菜单或局域网会话结束）都会在主菜单取得输入前关闭该模态并清空本局自动展示标记；主菜单可见性切换也执行同一兜底，不能让结算遮罩残留覆盖主菜单。
- 终局首次到达时自动打开；面板右上角保留1个“关闭”按钮，点击后只隐藏自身，不清除数据，也不会因同一局的后续状态广播再次自动弹出。
- 统计列表下方居中提供146×38像素“保存回放”按钮：点击弹出480像素宽的命名弹窗，玩家可输入最多60个Unicode字符的回放名后保存，留空确认则按默认名（保存时刻 `replay_年月日_时分秒`）保存；名称非法字符由存储层过滤，与已有回放重名时自动追加序号不覆盖。确认后把本局录制落盘为 `.lisbam_replay` 回放文件并以顶部横幅提示文件名；同一局重复保存复用首次文件，不生成重复回放。弹窗“取消”与 Esc 只关闭弹窗不保存，Esc 不会穿透触发终局返回主菜单快捷键。按钮与弹窗只发出保存意图信号，录制数据与文件写入由牌桌的回放录制器负责；离线、局域网房主与客户端保存的都是本机视角回放。
- 终局操作区固定顺序为“重新开始 → 结算界面 → 返回主菜单”。“结算界面”只在 `game_over=true` 时可见，本地角色阵亡而整局仍继续时不显示。
- 选将遮罩与结算模态受同一条返回边界约束：任何返回主菜单的路径都必须在主菜单取得输入前调用 `CharacterSelectionPanel.close()`。该清理同时做两件事——隐藏遮罩并释放全部动态候选武将牌。车轮战抓将候选牌带有“我方选择”“对方选择”中央标记文本，若只隐藏遮罩而不释放候选，这些文本会继续留在主菜单之上；`_sync_match_menu_visibility()` 在主菜单可见时执行同一兜底，防止将来新增返回入口时再次遗漏。选将面板对车轮战抓将阶段额外常驻：每次快照刷新不再关闭它，否则整个候选池会被反复销毁重建，界面闪烁且悬停状态每次刷新都被重置。
- 面板使用可滚动列表展示所有角色，固定六列为“角色、造成伤害、受到伤害、回复体力、摸牌、击杀”。角色列在同一行显示已公开武将名与玩家名，格式固定为“武将名（玩家名）”，例如“丹恒（[AI]玩家1）”；缺少武将资料的旧快照只显示玩家名。每个数值列最小宽度 `96` 像素，角色列最小宽度 `230` 像素，数据行最小高度 `38` 像素。

## 局内聊天

- 右上“菜单”按钮正下方固定提供86×34像素“聊天”按钮（`%MatchChatButton`，与菜单按钮同宽、间隔8像素）。按钮对离线玩家、局域网房主与客户端始终可见，不属于房主权威控件组；局内菜单面板展开时该区域被面板覆盖属预期。点击按钮切换聊天窗口显隐，窗口关闭按钮、牌桌空白左键与安卓返回键（优先级高于开关局内菜单）都可收起窗口。
- 聊天窗口 `MatchChatPanel` 由牌桌在运行时创建：宽340、高400像素，锚定客户区右上（距右18像素、距顶100像素），绘制层级45（高于“记录”面板35与头顶气泡38，低于主菜单60与局内菜单500）。窗口含标题行（“聊天”+“关闭”）、纯文本历史正文（禁用BBCode防注入，格式“玩家名：正文”，不显示时间）、单行输入框与“发送”按钮；输入上限200个Unicode字符，回车与按钮共用提交入口，发送后在焦点结算完成的下一帧恢复输入框焦点支持连续输入。
- 发送消息后，发言者武将牌上方出现 `ChatBubbleView` 聊天气泡：正文最大宽度176像素自动换行、12像素字号、头顶水平居中并与牌上边缘保持6像素间距，边缘座位自动钳制在客户区内。气泡尺寸严格贴合正文：组件用与标签同款断行标志（`BREAK_MANDATORY|BREAK_WORD_BOUND|BREAK_ADAPTIVE`）预排版正文并取最宽一行的实际宽度，短消息与折行消息都不残留横向空白；内容边距收紧为左右7像素、上下4像素（`horizontal_padding`/`vertical_padding` 可在检查器调整）。气泡停留4秒后以0.25秒淡出；同一玩家的新消息复用同一气泡节点并重启计时。本地玩家气泡锚定右下第一视角武将牌，其他玩家锚定其座位武将牌；发言者不在当前视图时只更新窗口历史，不创建气泡。
- 消息流转由 `NetworkGateway` 统一负责：离线模式本地回环；局域网客户端以 `match_chat` 封包可靠上行，房主按连接绑定的稳定玩家 ID 反查署名（不采信封包自报身份）后逐客户端中继并本地登记。历史上限100条；局域网在大厅“开始游戏”创建新局与会话结束时清空，断线重连与同房间局内重开保留；离线在每次新开局时清空。主菜单覆盖牌桌时聊天窗口与全部气泡同步收起。聊天只是表现层通信，不修改任何规则状态、不进入 `MatchController` 规则协议。

## 对局回放

- 主菜单顶部第四个对等内容页“对局回放”位于“所有卡牌”右侧（同宽192像素、互斥选中态与底部指示线）。内容页复用主菜单客户区安全边距（左右54、顶部104、底部38），左侧286像素侧栏依次为标题、“导入回放”按钮、数量提示与可滚动回放列表，右侧为所选回放详情与“播放 / 重命名 / 顶置回放 / 导出回放 / 删除回放”操作行。列表条目显示回放名（文件基础名，超宽裁切省略号），顶置条目附加“★ ”前缀并固定排在列表最前（顶置组内与普通组内均按保存时间倒序）；详情逐行显示保存时间、模式、人数、回放视角、对局状态、时长、步骤统计、文件大小、顶置状态与参战角色（已公开武将附注武将名）。
- 回放在对局进行期间由牌桌自动录制：每份本机观察者裁剪快照、每条对局日志与每次桌面表现事件（技能/防具发动提示、卡牌使用/展示/判定表现、区域移牌、摸牌批次边界与所有权释放，只录稳定玩家 ID、名称与牌面快照，不录坐标）按相对毫秒时间戳流式写入临时文件，不常驻内存；录制上限30000步，超出后停止追加并在回放头标记截断。结算界面经命名弹窗把回放头与步骤流转存为 GZIP 压缩的 `.lisbam_replay` 文件（格式版本1，含魔数校验），保存目录固定为 `user://replays/`。返回主菜单或新开一局会丢弃未保存的录制；已保存文件不受影响。顶置状态保存在回放目录内的 `replay_pins.cfg` 元数据文件中，不写入回放文件本体，导出不携带。
- 点击“播放”不再进入内容页内置播放器，而是像进入一场新对局一样切换到正式牌桌整局重演：主菜单与局内菜单隐藏，牌桌按录制端第一视角把快照、日志与表现步骤按录制时间差依次重新送入与正式对局完全相同的渲染与表现处理器，直接复刻原表现流程：座位、手牌、装备、判定、标记、翻面、横置、金边与“记录”面板使用对局同款组件呈现；卡牌进入牌桌中心的使用/展示/判定飞牌、区域移牌、同批居中并行的摸牌动画、本机视角手牌入场逐步重放；技能与防具发动重现武将牌中央名称提示，卡牌使用与技能发动的目标指示线（含借刀杀人等多段线）按重演时的座位布局以对局同款线条动画重放。重演期间玩家不可操作：全屏透明输入屏障吞掉全部桌面鼠标输入，牌桌快捷键（Esc/回车/空格/右键取消）整体失效，终局也不弹出结算模态；悬浮控制条只提供“≡”拖动手柄、“回放重演：名称”标题、1×/2×/4×加速下拉（只允许加速，无暂停、步进或时间轴）与“退出回放”按钮；控制条默认顶部居中（距顶10像素），可按住条体空白区域（手柄、标题或内边距，子按钮除外）自由拖动到任意位置以避免遮挡想观察的牌桌区域，拖动始终钳制在画面内（安全边距4像素），窗口缩放或标题加长时越界部分自动钳回；拖动过的位置在同一次游戏运行内保留，未拖动则每次打开回到默认顶部居中。相邻步骤间隔超过2000毫秒按上限截断以跳过长思考停顿；全部步骤播放完毕后控制条标题追加“（已播放完毕）”，终局画面停留在牌桌等待退出。Esc 与安卓返回键等同“退出回放”，退出后恢复重演前第一视角并直接回到主菜单“对局回放”页；局域网会话中不能播放回放。回放呈现严格等于录制端当时所见：录制端不可见的手牌、身份与私有候选不会出现在回放中，重演期间不产生新的回放录制。
- “导出回放”“导入回放”与“重命名”共用560像素宽的输入模态：导出预填桌面目录下的同名建议路径并自动补齐 `.lisbam_replay` 后缀；导入校验魔数与格式版本，非法文件拒绝，文件名冲突时自动追加“_2”等序号而不覆盖既有回放；重命名预填当前基础名（上限60字符），非法字符过滤、重名自动追加序号，顶置标记随文件迁移，确认后列表与详情跟随新名保持选中。“顶置回放 / 取消顶置”按选中条目状态切换文字并即时重排列表。“删除回放”直接删除所选文件并同步清理顶置标记。Esc 关闭链依次为：输入模态 → 关闭内容页回到模式选择。

## 机缘牌文字布局

- 机缘卡保持 `180×240` 像素与原有 `16/18/16/18` 像素内边距。普通机缘的完整描述统一使用 `AUTOWRAP_WORD_SMART`：存在稳定词边界时优先按词换行，导出环境无法识别无空格中文时按字符边界兜底，保证编辑器运行与导出运行的牌面宽度和换行一致。
- 带 `skill_id` 且正文含“技能名”中文引号片段的机缘会拆为“技能名前原文 / 技能名专用行 / 技能名后原文”。前后原文与普通正文使用相同的 `AUTOWRAP_WORD_SMART` 兜底策略；技能名行保留原始中文引号、字号 `24`、最小高度 `30` 像素，禁止自动换行，超过可用宽度时用 `...` 省略。静态机缘描述本身不被改写。
- 普通机缘正文默认使用 `21` 像素字号，并允许静态定义通过 `description_font_size` 为单张长文本牌覆盖字号；红色“刷新机缘”使用 `19` 像素。复用牌面切换到其他机缘时会恢复该卡自己的最终字号，不继承上张牌的覆盖值。
- 机缘选择横排中的每张牌先放入固定 `180×240` 像素牌位容器，悬停时只将容器内部的 `OpportunityCardView` 以中心点放大至 `1.06` 倍；选择弹窗内的卡面关闭自身最小尺寸上报，`HBoxContainer` 始终只计算固定牌位尺寸，因此任意牌进入或离开悬停状态、边框加粗都不会推动其他机缘牌、改变整排坐标或改变弹窗尺寸。卡面普通与悬停样式均固定4像素内容区内缩，故带技能名机缘的前缀、技能名专用行与后缀也不会在悬停时重排。

## 受限技能次数展示

- 局内获得且带总共、每回合或每轮限制的技能，技能按钮始终只显示技能名前两个字并固定使用14像素字号；按钮正文不显示次数缩写、第二行数字或其他状态文字。
- `MatchTable` 仅从权威快照中的 `acquired_skills` 计算展示副本字段 `acquired_skill_remaining_uses`，不在UI层扣减或重置次数。总次数使用“还可发动N次”，每回合次数使用“每回合可发动N次”，每轮次数使用“每轮可发动N次”，三项按总共、每回合、每轮顺序以分号连接；N为对应限制在当前回合、当前轮或全局累计下的剩余可发动次数。
- 技能按钮悬停信息与武将牌悬停信息、右键武将详情共用该展示字段，并把完整次数文案附在对应技能名后，例如“【还阳】（还可发动3次；每回合可发动2次；每轮可发动1次）”。技能描述始终保持技能定义原文，不插入次数文本。
- 轮回技在悬停标题中额外标注当前轮回数，格式为“【技能名】（轮回X）”；该片段固定排在次数文案之前，因此同时带次数限制时显示为“【技能名】（轮回X；每回合可发动N次）”。非轮回技不追加该片段，标题格式与普通技能完全一致。轮回数取自公开快照 `reincarnation_skills` 的 `round_count`，局外或状态缺失时按初始值1显示。该标注只出现在与技能名同一行的标题中，技能描述正文始终保持技能定义原文逐字不变，不插入轮回数文本。

## 离线控制所有角色

- 关闭开关时，旧AI计时令牌立即失效；临时接管角色恢复基础AI后，控制器通过统一续接入口重新安排当前选择或出牌动作，避免接管期间取消的任务令对局停滞。
- 主菜单设置与局内菜单提供“控制所有角色”复选框，默认关闭并在离线对局中即时生效。进入局域网连接、房间或对局后，主菜单与局内菜单均隐藏该选项；隐藏不会清除玩家为之后离线对局保存的偏好。
- 开启后牌桌始终只保留一个第一视角。当另一名角色进入正式回合、出牌、响应、技能询问、濒死救援或其他规则操作窗口时，桌面使用该角色的观察者快照重建本地武将牌、手牌、装备、判定区和技能栏；所有提交动作的 `actor_id` 同步切换为当前第一视角玩家ID。初次选将、车轮战抓将/阵容确认与手气卡不切换视角，仍由最初真人处理本人部分、基础AI自动处理其他角色。
- 关闭开关时立即恢复本局最初真人的第一视角，临时接管的非主角色重新注册基础AI并继续当前流程；无需重新开局，也不更改已经完成的操作。
- 同时无懈场景在该模式下保持权威端多请求登记，但本地界面按待响应角色依次切换与询问；前一名明确放弃后才显示下一名，任一角色成功响应后仍按原规则立即关闭同轮其他请求。

## 第一视角判定区与八卦阵默认选择

- 第一视角判定区仍位于手牌区上方，但其内容起点相对手牌左边界向右偏移120像素，剩余宽度同步缩短，从而避开左侧“托管”按钮。该偏移由 `local_judgment_zone_left_offset` 暴露，默认120，窗口缩放与技能栏变化后仍重新计算。
- “是否发动【八卦阵】？”独立响应询问会依据上下文中的 `immediate_response_equipment_uid` 自动选中八卦阵。玩家仍需点击“确定”发动，点击“取消”则放弃本次八卦阵并进入后续普通【闪】响应流程。

## 1v1车轮战入口与选将界面

- 被取得的候选槽保留原位与原始明暗状态：明置武将继续显示正面，暗置武将继续显示牌背；两者只关闭交互并显示带描边的“我方选择”或“对方选择”。

- 武将牌左上角 `CharacterCornerTextBadge` 使用深棕色背景、白色文字与黑色描边，使短文本与武将框配色保持协调。
- 主菜单模式列表在身份模式、斗地主、2v2之后提供“1v1车轮战”，人数固定为2。主菜单和局内菜单都显示两项专属 `SpinBox`：候选明置武将3至20名、默认6；候选暗置武将3至20名、默认4。任一项降低导致合计不足10时，界面自动抬高另一项到合法值。两套菜单的标签与数字输入框统一使用 `ThemeDB.fallback_font`；标签颜色取主题 `text_secondary`，数值取 `text_primary`，光标取 `accent`，选择区取0.42倍透明度的 `accent`。设置面板按当前模式隐藏不适用的普通选将项，局内菜单读取当前对局模式而非隐藏主菜单的待选模式。
- 抓将阶段复用正式武将牌组件，并且**双方共享同一个选将面板**：面板在整个抓将阶段常驻可见，不因尚未轮到本地而消失，未轮到的一方以只读方式观察对方抓将。明置候选显示完整牌面与悬停资料；暗置候选只显示牌背，不创建可推断武将资料的信息框。被选择的候选不删除、不补位，槽位保持原始明暗状态（明置牌继续显示正面、暗置牌继续显示牌背）并显示带黑色描边的深绿色“我方选择”或深红色“对方选择”，且不再接受点击。轮到本地时仍空置的公共槽才接受点击，单选一个稳定候选槽后确认，本批次剩余选择数显示在标题中；未轮到时标题显示“请等待对方选择候选武将”且确认按钮隐藏。
- 阵容阶段只显示本人取得的5名武将。每次点击按顺序加入或移出待确认阵容，最多3名；确认按钮以“武将A → 武将B → 武将C”显示最终出场顺序。提交后面板关闭并等待对方，不展示对方阵容。
- 对战阶段只使用普通牌桌武将牌显示当前出场武将。换将后通过权威状态刷新同一座位牌面，不新增座位或把三名武将同时铺在桌面上；累计阵亡数量可由只读快照用于后续进度表现。

## 自动化测试设置隔离

- 任何会操作AI响应速度、游戏速度、模式、人数或其他持久化设置的测试，都必须在首次写入前保存原内存值与正式设置路径，并把 `GameSettings._settings_file_path` 切换到该测试独占的 `user://*_test_settings.cfg`。
- 测试成功与失败出口必须共用恢复函数：先恢复测试前的精确值，再调用 `flush_pending_settings()` 把待保存变化写入临时文件；只有待保存队列清空后才能恢复正式设置路径，最后删除临时文件。
- 禁止测试固定恢复为默认值，例如无条件写回AI速度0.30秒。玩家可能使用合法的自定义值，测试只能恢复进入测试前实际读取到的值。
- `ui_layout_test` 与 `performance_and_pacing_test` 已采用上述隔离流程，因此真实鼠标拖动速度滑条、边界钳制和失败退出都不会修改玩家的 `user://game_settings.cfg`。

## 视觉布局

主场景采用参考无名杀的 1280×720 环桌卡牌布局；布局、尺寸与交互语义保持稳定，配色由设置中的 UI 风格独立决定。默认使用“崩铁风格”，并保留“暖木家园”与依据 `参考图/高级黑金UI风格参考图.png` 提炼的“高级黑金”供玩家即时切换：

- 逻辑视口的标准基准分辨率为 1280×720；默认启动窗口为 1152×648，为系统标题栏、窗口边框和任务栏保留空间。界面使用 `canvas_items` 与 `keep` 宽高比策略完整显示逻辑视口；底部与右侧关键区域同时使用边缘锚点，因此编辑器嵌入运行未应用画布拉伸时也不会超出客户区。
- Android 设备使用固定横屏方向，不跟随旋转传感器反复切换正反横屏，避免系统连续重建渲染表面；1280×720 逻辑画布按 `keep` 策略等比缩放到实际屏幕，16:9、18:9、19.5:9 与 20:9 等比例通过居中留边吸收多余区域，不拉伸牌面、不裁切按钮，也不让刘海、挖孔或圆角侵入逻辑画布。应用使用沉浸式全屏但关闭 edge-to-edge，系统安全区域由 Android 窗口边界负责；HiDPI 保持开启，逻辑像素与物理像素由 Godot 统一换算。
- Android 使用 Vulkan 驱动与 Godot Mobile 渲染方法，桌面端继续保留原有 Compatibility 渲染路径。移动端全局VSync开启，`AndroidDisplayStability`在Android窗口创建完成及应用从后台恢复时把最大帧率设置为60 FPS；组件不进行每帧轮询。该组合用于稳定一加Ace 5等120Hz高刷屏与高通Adreno交换链节奏，避免刷新率切换、旋转表面重建或前后台恢复造成整屏闪烁。

- 左上角：显示当前第几轮、摸牌堆剩余牌数和对局时长，不再显示当前行动角色、回合总序号或阶段名称；第一行使用居中的 `HBoxContainer`，过关斩将额外将“第X关”置于“第X轮”左侧，最终顺序固定为“第X关 第X轮”。两者间距6像素并共享一份运行时 `LabelSettings`；关卡、轮次、牌堆剩余数和对局时长四项统一使用 `ThemeDB.fallback_font`、**16像素**字号与当前主题 `BattleUIStyle.text_secondary` 颜色。关卡不得覆盖、替换或纵向挤走轮次。信息框位于 `(18, 18)`，实际尺寸为156×91像素；日志展开区从 `y=109` 开始贴合信息框下边。时长从本局创建时开始按单调时钟累计，格式为“分:秒”，终局后冻结。右上角只在已开始且主菜单未覆盖牌桌时保留“菜单”入口，供对局调整设置或重新开局；主菜单可见时 `MatchMenu` 整体隐藏并关闭已展开面板，不能在主菜单右上角显示局内菜单按钮。局内菜单集中提供卡牌名称切换、UI 风格切换、自动身份标记复选框、AI 响应速度、游戏速度、按设置重新开局及当前模式适用的下一局规则；风格、身份标记、速度与“控制所有角色”即时生效，其余开局参数在重新开局时生效。菜单根层级固定为 `z_index=500`，高于选将遮罩及候选武将牌；全屏座次容器仍忽略鼠标，只由武将牌的透明输入子组件接收点击，因此动态武将牌和选将遮罩都不能遮断菜单。
- 主菜单与局内菜单中的“卡牌名称”均使用与“UI风格”相同的“左侧标签 + 右侧下拉框”格式，选项固定为“崩铁杀”和“三国杀”，元数据使用 `GameSettings.NameMode` 枚举；切换只重绘前端文本。局内两个下拉按钮和内部弹出列表都必须覆盖常态、悬停、按下、焦点、禁用、面板和条目悬停主题，鼠标移入时不得回退 Godot 默认皮肤。局内菜单另提供“返回主菜单”按钮，退出时释放当前对局运行时、保留显示设置和下一局人数，并恢复主菜单焦点。
- 主菜单模式预览左上角提供“详情”按钮，但当前只在“斗地主”“机缘大乱斗”“过关斩将”三种模式显示；身份模式、2v2与1v1车轮战暂时隐藏且不保留空白占位。按钮位于预览内容层，但低于设置遮罩，打开设置后不得覆盖设置项或截获输入。点击后打开居中模态面板，完整说明对应模式的人数、阵营、触发、胜负或关卡规则；过关斩将正文逐项列出难度一至难度五的开局效果，具体数值以《游戏机制与玩法内容》难度表为准。遮罩阻断底层模式卡、设置与开局按钮，点击空白、点击“关闭”或按 Esc 均退出并把焦点归还入口。说明文字只属于界面文档快照，模式判断仍使用稳定模式ID。
- 主菜单与局内菜单仅在过关斩将中显示“过关斩将难度”下拉框，选项固定为“难度一”至“难度五”，元数据保存整数 `1..5`；该设置只影响下一局或局内重新开局，进行中的关卡与复活次数不随菜单变化。切换到其他模式时整行隐藏且不占VBox高度。
- 主菜单与局内菜单在过关斩将中还显示“机缘选择”下拉框，选项为“投票选择”与“各自选择”，元数据保存稳定ID `vote/individual`，默认投票选择并持久化到 `GameSettings.conquest_opportunity_choice_mode`；显隐与样式规则与难度下拉一致。该设置属于房主权威开局规则：开局时锁入 `match_options`，局域网客户端的局内菜单不显示该控件；单人局两种取值行为相同，仅联机2至4名玩家时产生投票与各自选择的差异。
- 1v1车轮战的主菜单与局内菜单均显示“明置候选武将”和“暗置候选武将”两项 `SpinBox`。标签使用主题次级文字色，输入框的边框、文字色和焦点态由 `BattleUIStyle` 统一绘制，内部 `LineEdit` 显式使用 `ThemeDB.fallback_font`，保证中文字体和当前主题颜色一致；两项范围、默认值及合计限制仍以游戏机制文档为准。
- `GameSettings` 在 `user://game_settings.cfg` 以格式版本1保存卡牌名称模式、UI风格、AI响应等待与游戏流程间隔（均为0.10至1.00秒，步长0.05秒）、自动身份标记、下一局人数（2至10人）、六项房主开局设置、联机玩家名与联机形象 ID。手气卡数量保存 `0/1/2/3/4/5/10/-1`，其中`-1`表示无限张；换将卡数量保存 `0/3/5/8/10/20`，随机选将牌数保存1至20。读档发生在界面首次绘制前；修改先作用于内存，0.25秒内的连续变化合并为一次完整覆写，进入后台或退出时立即保存。卡牌名称与UI风格的全界面刷新在当前GUI输入结束后的空闲帧执行。文件不保存房主地址、端口、房间密码、聊天、成员表、ENet peer 或任何对局状态。
- 主菜单顶部依次提供“模式选择”“联机设置”“所有卡牌”三个对等内容页标签：点击后只切换主菜单客户区，不弹出独立遮罩，也不覆盖顶部导航。联机设置页允许编辑最长20个 Unicode 字符的玩家名称，并从 `GameDatabase.characters` 当前登记的全部武将牌中选择联机形象；武将牌先按星穹列车、银河学者、贝洛伯格、仙舟联盟、匹诺康尼分组，未列出的扩展势力随后按势力名稳定排列，同势力内按中文名与稳定ID排序。每行最多5张、缩放为0.72倍，水平间距18像素、垂直间距16像素，超过可视高度时纵向滚动。名称去除首尾空白，空值回退“玩家”；形象保存稳定武将 ID，并在确认后写入本地设置文件。两项配置均不创建网络会话或对局状态，创建或加入房间时才提交给网关。“所有卡牌”只读取静态内容目录，不保存对局、网络或玩家设置。
- 点击“局域网联机”后，连接表单中的“玩家名称”只读显示 `GameSettings.online_player_name`，不能在该界面修改；创建房间与加入房间均提交这一全局名称和已选联机形象。连接入口另提供房主 IPv4、端口与最长32字符的房间密码，玩家若要修改名称或形象必须返回顶部“联机设置”。
- 主菜单与局内菜单的全部复选框开关均使用统一独立指示器：“自动标记身份”“自选全武将、座次与身份”“自选所有AI的武将”和“AI使用手气卡”在勾选与取消勾选时都显示20×20像素主题边框；勾选状态额外绘制2.5像素主题文字色对勾，边框默认宽2像素，指示器位于每行左侧 `(2, 5)`。过关斩将中同一自选开关必须显示为“自选武将”，主菜单与局内菜单均显示该项，但选将面板只显示“所有武将”入口，座次和身份区域保持隐藏；切回其他支持模式时恢复“自选全武将、座次与身份”文案。该指示器只改善可见性，不改变各开关的默认值、身份标记优先级、开局规则或任何身份规则。
- 其他玩家：使用无名杀 `data-position` 座次方向排列。桌面先把绝对座次旋转为从本地下家到本地上家的环形顺序，再依次放置到右侧、顶部与左侧；因此本地玩家随机座次后，视觉方向仍与规则行动顺序一致。二至三人局全部位于顶部；四至九人局先放右侧、再由右向左排列顶部座位、最后放左侧；十人局左右各放两名、顶部放五名。每个其他玩家座位由武将牌与其下方独立座次标签组成；武将牌显示势力、武将名、体力、手牌数和公开装备，座次标签只显示中文座次号。武将牌左上角可挂载通用 `CharacterCornerTextBadge`：位置位于势力徽记右下侧与竖排武将名右侧，样式固定为黑色背景、白色文字和2像素黑色描边，公开文本为空时不占画面。正式对局在鼠标悬停且武将牌未翻面时显示位于插画上方的玩家名渐变阴影，遮罩忽略鼠标且不阻断透明输入区域；Godot 原生工具提示始终为空。鼠标持续停留在本地或其他玩家武将牌0.5秒后，统一信息框会显示势力、性别、基础体力上限及按武将定义顺序排列的完整技能说明；同一来源、同一内容的公开快照高频刷新只允许更新锚点位置，禁止重新测量面板宽高，否则自动换行边界可能令行末字符在相邻两行之间振荡。选将候选仍保留独立悬停缩放反馈，点击候选只更新金色选中边框，所有候选保持当前布局坐标。`player_target_view.tscn` 的默认隐藏“牌背”覆盖层会在快照 `face_down=true` 时遮挡武将插画，透明输入区域仍位于最上层。判定牌在武将牌底边按快照顺序显示为带牌名首字的菱形；木牛“粮”数量紧跟木牛流马装备名显示。鼠标悬停其他玩家的公开装备横条时，统一信息框在横条附近显示该装备的槽位、花色点数、当前名称和完整规则说明；离开横条但仍停留在武将牌内时，经过同样0.5秒恢复该武将技能资料。任意玩家公开体力相对上一份同局快照下降时，其 `PlayerTargetView` 调用独立 `DamageShakeFeedback`，以最大7像素水平幅度和0.24秒总时长执行1次冲击位移后回正，不再左右往返；首次快照、新局体力基线和回复不会触发。
- 对局中的翻面牌背层只替换武将插画，不遮挡体力、身份、势力、武将名、手牌数、公开标记、装备区、判定区、角标及透明输入区域；武将牌再次翻为正面时立即恢复原插画。此规则只适用于角色翻面状态，不改变选将阶段暗置候选隐藏资料的既有表现。背面角色在 `phaseBefore` 翻回正面后跳过整个回合，不进入 `phaseBegin` 或任何六阶段主体。【酩酊】生效期间目标沿用 `CharacterCornerTextBadge` 显示“酩酊”，直到技能持有者下一次实际进入 `phaseBegin` 时移除；翻回正面后被跳过的回合不会令其提前失效。卢卡的“斗志”使用公开标记显示当前枚数。

- 统一选择入口：候选全部属于本地玩家且来自手牌、木牛“粮”或装备区时，直接复用底部手牌区、左侧装备区和“确定/取消”按钮，不打开遮罩窗口；普通出牌同样只启用当前 `chooseToUse.card_ids` 中的手牌、木牛“粮”或主动装备。普通请求只把可直接 `use_card/recast_card` 的实体加入 `card_ids`，主动装备本体单独加入；木牛存粮、【传冲】及其他技能/装备动作所需材料在入口未选中时必须保持暗置，不能因后台已经枚举出材料动作而整批变亮。玩家点击对应技能或装备后，界面再切换为该入口专属材料候选。木牛“粮”固定排列在普通手牌左侧。【桃】【酒】【无中生有】【闪电】仅在规则预览确认本地玩家本人是唯一合法目标时自动锁定本人；所有 `type=equipment` 且 `target_mode=self` 的装备牌也按同一通用规则自动锁定本人，不维护装备 ID 白名单。其他牌与主动装备即使仅有1名合法目标，也必须由玩家点击该武将牌。所有 `choice_type=control/bool` 的文字选项直接复用手牌上方操作区，不进入 `CardSelectionPanel`；其余五谷展示牌、他人区域牌和判定区等不完全位于本地可见区域中的候选继续使用该独立窗口，不可见手牌显示正式 `CardView` 的“牌背”覆盖层；选中时牌背外框与正面相同，使用主题 `accent` 色与 3 像素描边（【寒冰剑】弃置选牌、【过河拆桥】手牌背等与五谷丰登正面选中反馈一致），取消选中后恢复默认 2 像素主题边框。任何非候选或当前无合法动作的手牌都使用深灰禁用样式且不接收点击，但仍可在自身分区内拖动排序；装备候选先向右移动10像素，选中后再向右移动10像素，进入候选、选中或复原位置都使用0.25秒位移动画。上下文明确定义 `equipment_uid` 的装备触发询问会自动选中对应装备，玩家只需确定发动或取消放弃。点击丈八蛇矛后选择2张普通手牌作为虚拟【杀】材料，点击木牛流马后选择1张普通手牌存为“粮”；两种模式都保持装备本身选中且不移动权威区域。【顺手牵羊】与【过河拆桥】的目标区域选牌严格复用同一个固定窗口，均按手牌区、装备区、判定区纵向排列并在内容超高时使用纵向滚动；`steal_target` 与 `discard_target` 只决定后续获得或弃置语义，不改变窗口结构。正式主场景把通用选择框覆盖为820×460像素，背景滤镜读取当前风格 `shade`：崩铁风格透明度约0.82，暖木家园约0.84，高级黑金约0.85；公共只读牌禁用输入但保持正常亮度。
- 五谷丰登使用后立即创建全体可见的公共选牌窗口，不等待第一名角色完成无懈询问。窗口使用视口中心锚点与对称四边偏移，动态改变尺寸后仍保持严格居中，不会沿左上角局部坐标移出屏幕。通用模态选择层固定为150，高于手牌悬停100与拖拽101；窗口在每名玩家或 AI 依次选择期间持续保存并始终绘制在底部手牌与手牌悬停放大层之上。非当前本地选择者只读查看，底部确定/取消行隐藏。本地玩家进入与五谷选牌不同类型的【无懈可击】等响应时，公共窗口临时关闭并让出手牌区、确认和取消输入，响应结束后立即从保留的公共快照恢复；旁观客户端仍可继续显示公共牌位。最初亮出的每张牌拥有固定牌位，被取得后不删除、不补位，而是以 `(0.72, 0.72, 0.72, 0.48)` 调制色留下复制虚影；牌底 `(4, 118)` 至 `(107, 144)` 的103×26像素标签使用13像素字体显示领取者武将名。公共牌阵使用4列 `GridContainer`，每行固定4张、间距8像素，不显示“展示区”标题；窗口按实际列数收紧，4列时牌阵宽468像素，面板只保留36像素横向总边距，右侧不再保留旧820像素窗口产生的大块空白。牌位 UID 与牌面结构未变化时，后续公共状态广播只原位更新可点击状态、领取虚影和武将名标签，持续复用同一组 `CardView` 节点；只有牌位结构、名称模式或 UI 风格变化时才重建。下一名选择者只能点击仍未领取且属于当前权威请求候选的牌。
- 【投狭】获得窗口的候选来自公开弃牌堆时，`CardSelectionPanel` 单独显示“弃牌堆”分区；候选仍只接受 `candidates` 中的 UID，窗口可取消，获得或取消后都由规则层令原当前回合角色摸1张牌。其他区域牌的分区顺序与该公共弃牌堆分区互不混淆。

- 局内菜单按权威身份分组显示功能：离线玩家与局域网房主可见AI响应速度、游戏速度、下一局人数、重新开局及六项开局规则；局域网客户端隐藏全部房主权威控件，只保留能在本机生效的卡牌名称、UI风格、自动身份标记与离开入口。斗地主本局身份全明置，局内菜单额外隐藏「自动身份标记」开关（功能对明置身份无意义）。后续新增以房主为准的功能必须加入同一权威控件组，不得单独出现在非房主 UI。
- 【五谷丰登】当前选择者已选中1张展示牌后，其余未领取候选仍保持可点击；再次点击另一张会先取消旧选择再选中新牌，确认时只提交最后选中的1个稳定 UID。已领取、非当前请求候选和只读旁观牌仍不可点击。
- 五谷手牌层级：公共牌位面板固定为45层；仅当公共展示类型为 `harvest` 时，本地手牌区提升到46层，因此悬停后的1.06倍放大牌面始终位于五谷牌位上方。离开五谷展示后手牌层级恢复场景默认值，层级调整不改变任何选择资格或卡牌数值。
- 本地装备区：固定在底部左侧，由 `EquipmentStackView` 复刻 `equip_new.css` 的独立槽位布局。透明外层固定为150×148像素，高度严格等于玩家111×148手牌牌面本身，不等于175像素手牌栏；装备栏与手牌栏底边对齐。武器、防具、进攻坐骑、防御坐骑、宝物五槽始终可见，148像素按五槽平均分配为每槽29.6像素，相邻四段间距均为0像素，第一槽贴顶且最后一槽贴底。空宝物槽与其他空槽使用当前主题的深色底框和类型图标，不绘制“无”文本；已装备槽在原位置覆盖主题浅色牌面并显示类型图标、花色、点数和牌名，不能自动补到前面的空位。已废除栏位优先于异常快照中的实体装备，使用 `zone_abolished_background/border/text` 主题色和“已废除”文字固定占据原槽，禁用点击、候选、选中与卡牌悬停；该横条不是实体卡牌。已装备横条无论当前是否属于候选，都可通过鼠标悬停打开目标旁统一信息框；空槽不显示卡牌说明。装备栏范围为 `x=18..168`，手牌栏从 `x=168` 开始，两者边界零间隙相接；候选右移10像素、选中后总右移20像素，并保持高于透明手牌区域绘制。
- 坐骑槽图标：进攻坐骑槽显示 `-`，防御坐骑槽显示 `+`；图标只说明距离修正方向，不改变进攻坐骑令装备者计算距离 `-1`、防御坐骑令其他角色计算距离 `+1` 的规则数值。
- 本地技能区：固定在本地武将牌左侧，只显示技能按钮，不绘制技能区背景或状态说明。所有技能按钮固定只显示技能名前两个字并使用14像素字号；局内获得且配置总共、每回合或每轮限制的技能不在按钮内显示次数。悬停信息框与右键武将详情在对应技能名后显示“还可发动N次；每回合可发动N次；每轮可发动N次”的已配置维度完整次数文案，技能描述仍保持原文，不附加“状态：被动技能已接入规则 / 当前可发动”等开发期状态副标题；不可发动、被动、锁定与样例技能按钮虽然保持灰显且不能点击，仍允许悬停查看说明。主动技能进入可取消的内联选牌、选目标或牌目标组合后，原技能按钮保持选中且可点击；再次点击同一按钮提交 `confirmed=false` 取消整次释放，不消耗材料、目标或发动次数。响应转化技能再次点击只退出当前转化材料模式，保留原响应窗口。技能按定义顺序从右到左、从下到上排列，每行最多2个，第三个从右侧第二层开始。按钮默认62×44像素，水平与垂直间距均为6像素；技能区底边使用与本地武将牌相同的底部留白，默认均距客户区底边0像素，调整 `local_player_card_bottom_margin` 后仍保持两条底边平行对齐。`leader_skill=true` 的技能只有本地身份为领袖时创建按钮，非领袖不保留灰色按钮或空位；技能栏缓存签名同时包含武将 ID、身份与完整可见技能列表（武将固有技能 + 模式技能 + 局内临时技能，如【铁壁】授予的【琥珀】），临时技能增减时必须重建主视角右侧技能按钮。技能区右边缘与本地武将座位左边缘保留6像素，手牌区仍在最左技能按钮左侧保留8像素，因此靠近武将牌时不会覆盖手牌信息。
- 本地武将牌：视觉容器固定在底部右侧，与其他玩家共用 `PlayerTargetView` 排版，整张牌可点击选择自己，并显示本地玩家的势力、武将名、体力和手牌数；本地装备只在左侧独立装备栏显示，不在第一视角武将牌上重复绘制。主视角不显示牌面下方座次号，也不保留原26像素座次标签占位，容器只覆盖148.35×197.8像素武将牌本体；牌面底边默认贴齐客户区底边，该0像素留白由 `local_player_card_bottom_margin` 暴露并可在检查器中调整。
- 统一信息框：`InformationBoxLayer` 是牌桌唯一说明入口。手牌、本地已装备横条、其他玩家公开装备横条、技能按钮、选将候选、选将阶段公开领袖牌和本地或其他玩家正式武将牌的悬停请求都必须持续0.5秒才显示；鼠标离开、切换到新目标或打开武将详情会立即取消尚未显示的请求，已显示的信息也立即关闭。同一来源重复发送完全相同的内容时只更新锚点，不隐藏当前信息或重新等待0.5秒；首次写入自动换行内容后会在下一布局帧以340像素基准宽度测量正文，再根据估算内容面积选择240至520像素之间的动态宽度。4:3仅作为首选形状，最终宽高比通常限制在0.8至2.2，每次按20像素步长搜索更合适的宽度；短内容过宽时只补足到2.2的高度下限，特别长的内容在520像素上限后仍优先完整显示。测量期间面板保持透明，最终宽度写入后再用1帧取得真实换行高度并二次收紧到客户区内。信息组件统一解析标题、说明和结构化技能段落中的完整 `【牌名】`；名称模式改变时，已经打开的悬停框与武将详情会原位重绘并重新测量，不要求移开鼠标或重新打开。武将悬停资料中的武将名与每个技能名使用和右键详情技能名相同的主题金色，技能说明继续使用次级文字色。信息框在目标右侧10像素处显示；右侧空间不足时自动翻转到目标左侧，并与视口四边至少保留12像素。鼠标右键释放本地或其他玩家武将牌时，在桌面中心打开宽760像素的“武将详情”；面板高度按左侧0.78倍正式武将牌、右侧技能内容和底部对称留白自动计算，最小226像素、最大440像素，短内容不保留固定大块空白，超过最大高度后使用标准纵向 `ScrollContainer`。左侧区域宽180像素并填充详情主体的可用高度，缩放武将牌在该区域始终上下居中；标题使用左右等宽占位保持相对整个面板居中。右侧按武将定义顺序显示技能名和完整技能描述，相邻技能之间使用1像素主题分隔线；技能列表底部按标题栏、主体间距及主题边距动态留空，使上边框到第一个技能名与下边框到最后一行文字的距离在整像素布局后最多相差1像素。短内容整体垂直居中，可用鼠标滚轮或12像素宽的右侧拖条浏览超出内容。关闭按钮、Esc、右键或点击遮罩空白区域均可关闭。信息框背景、边框、文字、分隔线、关闭按钮、拖条与左侧武将牌全部按当前 UI 风格即时重绘，不保存主题专属颜色。
- 已释放技能的整块变淡：武将悬停资料与右键武将详情中，凡是已经释放固有额度的限定技与觉醒技，其技能名与技能描述整体不透明度降为 `0.8`，被复原后自动恢复 `1.0`。悬停资料由 `PlayerTargetView` 依据公开快照 `used_intrinsic_use_skill_ids` 为每个 `description_sections` 条目写入 `intrinsic_use_consumed` 标记，信息框据此设置该技能容器的 `modulate.a`；右键详情直接读同一快照字段设置技能条目的 `modulate.a`。两处都作用于整个技能条目容器，因此技能名、描述正文与描述内部的①②轮回节着色一并变淡，且信息框不得自行推断技能的释放状态。
- 武将资料实时刷新：`PlayerTargetView.configure_snapshot()` 始终先更新完整公开资料副本，再用独立视觉签名决定是否重建体力、装备等画面。固有、模式、临时或局内获得技能发生变化时，即使画面字段完全不变，当前武将悬停资料也以稳定 `refresh_subject=character:<player_id>` 原位更新且不重新等待0.5秒；同一武将牌内从武将资料切换到装备或判定牌仍视为新悬停目标并完整等待。已经打开的右键详情由牌桌按稳定玩家ID读取最新公开快照原位重建技能列表，不重复开关面板或离线暂停令牌。
- 机缘模式武将详情：当前模式ID属于 `MatchController.opportunity_enabled_mode_ids` 或手动机缘模式时，右键详情在技能列表后追加独立“机缘”分组。`acquired_opportunity_ids` 按实际获得顺序逐项解析品质与机缘原文，重复获得会重复显示；灰色条目明确显示“灰色机缘”，但不会出现在随机三选一中。过关斩将敌方每次达成关卡会将对应机缘直接写入同一历史，因此右键新入场敌方可查看全部累计关卡机缘。尚未获得时显示“尚未获得机缘”。机缘条目不计入技能数量，也不参与技能实例、次数或AI规则。
- 统一信息框测量自动换行的首帧，必须将根面板可继承的 `modulate` 透明度设为0，使背景与所有文字子节点一并隐藏；禁止用不会传递给子节点的 `self_modulate`，以杜绝鼠标静止悬停时在默认或旧位置一闪而过的武将资料。右键详情右侧的技能滚动区默认额外保留24像素右边距，滚动条、技能名与技能说明整体左移；该值通过 `character_skill_right_margin` 暴露，可在检查器0至64像素范围内调整。
- 停滞自修复提醒横幅：`InformationBoxLayer.show_notice(message, hold_seconds)` 在视口顶部居中显示一条全局提醒，是自动修复、人类待办提醒与局域网断线重连进度的唯一界面通道。断线重连期间牌桌以3600秒常显时长保持“正在自动重连”横幅不消失，重连成功或失败改用默认停留时长展示结果文案并自然淡出。横幅使用 `PanelContainer("NoticeBanner")+Label("NoticeLabel")` 结构，主题样式复用 `BattleUIStyle` 的 `selection_panel` 底色与 `accent` 描边，随 UI 风格切换即时重绘；节点全程 `MOUSE_FILTER_IGNORE`，不拦截任何操作。默认停留4秒（`notice_hold_seconds`，检查器1至15秒、步长0.5）、淡出0.5秒（`notice_fade_seconds`，0.1至2秒、步长0.05）、距视口上边56像素（`notice_top_margin`，8至200像素）。淡出补间使用 `TWEEN_PAUSE_PROCESS` 始终处理模式，机缘选择或离线日志暂停冻结场景树期间横幅仍能按时显示与消失；多条提醒复用同一节点直接覆盖文本并重置停留计时。牌桌在 `_on_self_repair_performed` 中按修复级别选择文案：`human_reminder` 显示“当前有待办选择等待操作，已重新发送选择提示。”，软/硬修复显示“检测到对局停滞，系统已自动修复并恢复流程。”；同一事件同时写入对局日志（局域网经既有日志复制通道到达客户端），`is_notice_visible()`/`get_notice_text()` 供界面回归断言。
- 底部装备区、手牌区、技能区、操作区和本地玩家座位容器全部锚定到客户区底边；技能区与本地座位容器另外锚定到右边，手牌区使用左右安全边距自动收缩并保留横向滚动。即使根控件直接缩小为 1152×648，所有底部区域仍完整位于客户区内。
- 战局记录由左侧108×46像素“记录”按钮控制；点击后在按钮上方展开360×176像素日志正文，再次点击“收起记录”隐藏正文。主场景根节点与背景忽略鼠标，记录或右上菜单展开时，点击未被控件消费的牌桌空白左键会同时收起二者；记录组件在离线暂停时继续监听该输入，并只发出关闭意图，由牌桌统一关闭浮层。离线 `OFFLINE` 模式展开日志时直接调用 `MatchController.acquire_gameplay_pause("offline_match_log")`，统一接口同时暂停场景树、事件运行时、AI 普通行动、AI 选牌和同时无懈计时器；收起时只释放日志自己持有的令牌。离线武将详情以 `offline_character_details` 申请另一枚独立令牌，关闭时只释放详情令牌；两个界面同时存在时必须等两枚令牌都释放才恢复。日志与统一信息框组件都使用始终处理模式，因此暂停后仍可滚动或关闭；LAN 与 REMOTE 模式打开日志或武将详情都不申请暂停。隐藏期间规则日志仍会持续追加，日志组件只发出展开状态，不读取通信模式或规则状态。

其他玩家手牌牌面不会进入本地快照。界面只渲染公开数据和本地私有数据，不通过视觉组件读取或修改 `GameState`。

## 主菜单

- 游戏启动后先显示主菜单，不自动创建 `GameState`、身份、牌堆或选将请求。
- 主菜单左侧按顺序排列“身份模式”“斗地主”“2v2”“1v1车轮战”“机缘大乱斗”“过关斩将”。斗地主预览说明为“斗地主·3或5人·地主VS农民”；2v2 预览说明为“2v2·4人·蓝方VS红方”；1v1车轮战固定2人；机缘大乱斗显示“身份模式基础 · 2—10人 · 每轮全体三选一机缘”；过关斩将固定1名本地玩家对战1名敌方AI。各模式预览左上角均不显示“标准身份局”徽章。下一局人数按模式分存：身份与机缘大乱斗分别保存2–10人，斗地主仅3/5，2v2固定4，1v1车轮战固定2，过关斩将固定2名规则角色但入口人数提示为1人。在对应模式页点击“局域网联机”会以当前稳定模式 ID 创建房间。
玩家按下“开始游戏”后，牌桌才以当前人数与所选模式创建对局并进入对应选将流程；主菜单关闭后不再覆盖局内界面。
- 主菜单采用“顶部内容页栏、左侧分区、右侧内容”的层级。顶部依次显示“模式选择”“联机设置”“所有卡牌”“对局回放”，四者以互斥选中态与底部指示线表达当前内容页，切换时只替换 y=104 起的客户区。模式选择页左侧六张模式卡片按固定顺序放入独立纵向滚动窗口，每张分别显示模式名与合法人数提示；列表标题固定在滚动窗口上方，新增模式不能通过压缩既有卡片尺寸取得空间。身份模式右侧规则提示为“随机身份 · 阵营对抗”。
- 模式列表滚轮只在指针位于 `MainMenuModeScroll` 时生效，默认每格移动72像素；滚轮、拖动纵向滑条和程序化定位始终同步 `ScrollContainer.scroll_vertical` 与 `VScrollBar.value`，设置、联机资料和大厅等模态页面打开时不拦截其自身滚轮输入。
- 选中身份模式时，右侧预览使用 `assets/art/身份模式主菜单背景.png`，以覆盖裁剪方式填充预览区，因此允许因窗口比例不同裁掉边缘，不拉伸变形。参考图中的毛玻璃游戏背景不复刻。
- 右侧底部主按钮文字固定为“开始游戏”；其左侧依次提供“局域网联机”和“设置”。“开始游戏”按当前选中模式创建离线对局；“局域网联机”打开独立大厅组件，不提前创建 `GameState`。设置浮层可修改卡牌名称、UI 风格、自动身份标记、AI 响应速度、游戏速度和当前模式人数，均复用 `GameSettings` 与既有局内菜单的同一配置入口。卡牌名称、主题、自动身份标记与速度设置即时生效，各模式人数分别在离线开局或房主开始局域网对局时生效。
- 主菜单所有底色、面板、边框、文字和按钮均从 `UIStyleRegistry` 的当前语义色读取。崩铁风格、暖木家园与高级黑金切换后同步重绘主菜单，不改变身份、体力、牌堆、伤害、回复、距离、次数、目标数、资源、概率、持续时间或任何既有界面文本。全部六张模式卡的名称与人数标签（含“2v2”“1v1车轮战”）、“机缘选择”行标签、局域网连接表单的四个行标题与“自选身份”“固定座位”两行，以及大厅设置弹窗的“自选身份”“固定座位”行都必须应用主题字体色覆盖；`res://tests/font_color_audit_test.tscn` 会遍历主场景全部静态 Label/RichTextLabel/CheckBox，任何缺失主题字体色覆盖的文本控件都会使该回归测试失败。
- 左侧六张模式卡片的持续选中态只加深内部底色，不改变金色描边与左侧强调竖线。检查器参数 `MainMenu.mode_selected_background_darkening` 作为缺省回退值，默认 `0.28`；内置主题可通过同名注册表语义精确覆盖。崩铁风格从模式卡底色 `#403B32` 得到约 `#2E2A24`，暖木家园从 `#76521F` 得到约 `#553B16`，高级黑金按参考图使用石墨灰 `#252429` 与 `0.06` 加深比例，选中后约为 `#232227`。该参数仅用于客户端视觉对比度，不改变模式选择结果或玩法数值。
- 主菜单在1280×720逻辑视口中使用54像素左右安全边距：主题内容面距左右22像素、顶部12像素、底部18像素；顶部模式栏范围为`y=22..88`，主体从`y=104`延伸至底部38像素安全边距，两者固定保留16像素间隔；根控件直接缩为1152×648时仍不得重叠。顶部品牌区宽252像素，四个内容页按钮均宽192像素；左侧模式栏最小宽286像素，固定标题高48像素，六张模式卡均保持100像素高度、相邻间距12像素、正文上下内边距14像素，模式名字号27像素、人数提示字号16像素。标题下方的模式卡区域使用只允许纵向滚动的 `ScrollContainer`，滚动条默认宽12像素并使用当前主题轨道与拖块样式；选中持久化模式或键盘切换后会自动将对应卡片完整滚入可视区。右侧预览保留透明度0.18的全图主题遮罩，左上170×66像素不透明主题标签用于覆盖裁剪后可能残留的原图品牌碎片；摘要底板位于右上24像素、顶部28像素处且尺寸366×160像素、透明度0.82；底部操作栏高92像素且透明度0.88。“设置”为112×56像素，“局域网联机”为154×56像素，“开始游戏”为250×56像素，主次操作层级不能互换。
- 设置面板宽504像素，并以视口顶部、底部各12像素的安全边距自适应高度；设置列间距5像素，1152×648时全部控件仍完整位于面板内。面板使用覆盖全屏、透明度0.86的主题模态遮罩。主菜单普通可见期间会暂存并冻结主菜单之外的牌桌焦点；设置打开期间再冻结主菜单内设置面板之外的模式与开局控件，使 Tab、Shift+Tab 与手柄导航始终停留在当前可见层。遮罩同时停止底层鼠标输入；点击面板外空白、按Esc或按“返回”均关闭设置，只恢复主菜单自身焦点并把键盘焦点交还“设置”，被覆盖牌桌要等成功进入对局后才恢复。下拉框的常态、悬停、按下和弹出列表，滑条轨道与已选区、人数文本框、复选框文字都必须读取当前主题语义色；滑条已选区使用0.72倍主题强调色透明度，人数文本选择区使用0.42倍主题强调色透明度，不能回退为与主题冲突的默认控件配色。
- 设置面板提供“背景音乐音量”“音效音量”两条滑条与“静音全部音频”一个复选框，取值范围 `0.0` 至 `1.0`、步长 `0.05`，两条滑条的文字标签以百分比显示当前数值。三者都直接写入 `GameSettings`，由 `AudioService` 订阅设置信号后实时刷新对应的音频总线，不需要重开对局；取消静音后立即恢复原有音量。滑条与复选框的文字颜色同样读取当前主题语义色，`res://tests/font_color_audit_test.tscn` 会一并检查，不得回退为与主题冲突的默认控件配色。
- “开始游戏”只发出开局请求，主菜单必须等待 `MatchController.start_match()` 返回成功后才隐藏。待机时底部操作栏不显示“身份模式已选择”或任何状态文本；人数越界、数据校验失败或后置选将初始化失败时，主菜单保持可见、重新启用开始按钮，并在底部操作栏显示控制器返回的具体拒绝原因。局内“按设置重新开局”先执行不修改状态的前置校验：失败时不清空旧日志、动画、选择表现或 `GameState`，重新展开局内菜单并让原对局继续；只有通过前置校验后发生的选将初始化失败才丢弃半成品状态并显式恢复主菜单。主菜单全屏底色使用 `MOUSE_FILTER_STOP`，前景面板没有覆盖的边缘区域也不能把输入传给隐藏的局内控件。

### 所有卡牌内容页

- `AllCardsPanel` 是与模式选择、联机设置、对局回放对等的主菜单客户区组件。页面左侧固定提供“所有武将牌”“所有游戏牌”“所有机缘牌”三个互斥子分页，首次打开默认进入所有武将牌；顶部四个内容页标签始终可见、可聚焦并可直接互相切换。页面使用与主菜单相同的左右54像素、顶部104像素、底部38像素安全边距，左侧分区栏最小宽286像素，每张分区卡高100像素。
- 三类列表不维护手写清单：所有武将牌读取 `GameDatabase.characters`，所有游戏牌读取 `GameDatabase.cards`，所有机缘牌读取 `OpportunityCatalog.get_all_cards()`。新增或移除静态内容后，再次打开页面会从对应目录重建；页面不创建 `GameState`、`PlayerState`、`CardInstance`、网络会话或机缘选择请求。
- 所有武将牌复用 `player_target_view.tscn`，先按星穹列车、银河学者、贝洛伯格、仙舟联盟、匹诺康尼分组，未列出的扩展势力随后稳定排列，同势力内按中文武将名与稳定ID排序，默认缩放0.72倍。所有游戏牌复用 `card_view.tscn`，先按基本牌、锦囊牌、装备牌排序；基本牌按杀、闪、桃、酒分组，普通/火/雷【杀】共同属于“杀”组；锦囊牌按普通锦囊、延时锦囊分组，非延时的反制锦囊归入普通锦囊；装备牌按武器、防具、进攻坐骑、防御坐骑、宝物分组，同组再按当前名称模式与稳定ID排序。每种逻辑定义只显示1张代表牌面，默认缩放0.90倍，花色点数优先取已登记牌堆中的首个对应实体。所有机缘牌复用 `opportunity_card.tscn`，包含灰色关卡机缘并沿用目录中的灰、绿、蓝、紫、橙、红顺序，默认缩放0.68倍。三类网格的水平、垂直间距均为18像素，列数按右侧可用宽度动态计算，超过高度时只纵向滚动。
- 三类图鉴共用模式选择列表的纵向滑条样式：默认宽12像素，轨道、拖块、悬停态、按下态与端点零边距均由 `BattleUIStyle.apply_main_menu_scroll_bar_style()` 生成。网格额外为右侧滑条保留28像素安全间距，使最右列卡牌向左收拢且不被拖条覆盖。
- 每个子分页独立记忆本次打开期间的关键词，关闭并重新打开所有卡牌页时清空。搜索使用去除首尾空白、英文不区分大小写的包含匹配：武将覆盖中文名、稳定ID、势力、性别、体力上限及固有技能名/说明；游戏牌覆盖稳定ID、三国杀名、崩铁杀名、规则名、类型、子类型与规则说明；机缘覆盖稳定ID、品质、完整正文及可获得技能名/说明。结果标签显示当前分类总数或“显示命中数/总数”，零命中时用独立空结果说明替代网格。
- 点击任一牌面会打开当前客户区内的完整资料模态：武将详情采用左牌面、右技能双栏，左侧复用0.78倍正式武将牌，右侧按定义顺序显示全部固有技能，技能名固定使用暖黄色 `#F4CF66`，正文使用当前主题次级文字色；标题摘要继续显示势力、性别与静态体力上限。游戏牌显示当前名称、双名称、细分类别和规则说明；机缘显示品质、原始正文，并在授予技能时追加技能唯一说明。资料遮罩默认不透明度0.90，点击面板外空白、关闭按钮或按Esc均关闭；没有资料模态时按Esc返回模式选择。卡牌名称模式变化会重建当前列表和搜索语料，UI风格变化只重绘主题，不改变分类或关键词。

### 局域网连接入口与联机大厅

- `LanLobbyPanel` 使用620×540像素中央面板与全屏主题遮罩，只负责连接入口。表单只读显示联机设置中最长20字符的玩家名，并提供房主 IPv4、1024至65535端口、最长32字符密文密码、“自选身份”复选框、“固定座位”复选框以及“创建房间 / 加入房间”；名称不能在该界面修改，默认端口为7000，同机双实例可输入127.0.0.1。“自选身份”与“固定座位”默认关闭且仅创建房间时作为房间初始设置生效，加入房间沿用房主房间的权威开关。成功登记后整个入口隐藏，不再渲染成员或开局控件。
- `OnlineLobbyPanel` 是连接成功后的独立全屏大厅。内容面距逻辑视口左右24像素、上下18像素；中央座位区从内容面局部 `(24,54)` 到 `(1208,528)`，左下聊天框为 `(24,532)..(790,674)`，右下房间控制为 `(804,532)..(1208,674)`。内容面必须使用不接管直接子节点布局的 `Panel`，不能用会强制铺满子节点的 `PanelContainer`。
- 每名真人由独立 `OnlineLobbyAvatar` 表现，不复用 `PlayerTargetView` 或正式武将牌场景。名称区域高26像素，名称与武将框间距4像素；玩家名始终显示在武将框上方。武将框固定148.35×197.8像素，占用位置沿用空位同款圆角面板规格（同一底色、描边与阴影）作为底框，玩家插画在框内四周内缩7像素嵌入并使用4像素圆角，只加载武将定义的原始插画，不显示牌框、势力、体力、技能、手牌数或悬停资料层。武将框右上角另设48×22像素、内缩4像素的身份徽记：房间开启“自选身份”时，空位与玩家形象都显示该位置绑定身份的中文文案（领袖/忠臣/反贼/内奸/地主/农民/蓝方/红方），文字与细描边使用主题 `identity_*` 语义色、底色使用高不透明金属面板色；未开启或该模式无位置身份时徽记隐藏。徽记忽略鼠标，不遮挡空位点击换位。
- 2至3人设置固定显示3个居中横向位置；4人为2上2下；5人为3上2下；其余人数按上排 `ceil(人数/2)`、下排剩余数量分配，因此8人为4上4下。每一排独立居中，同行水平间距44像素、两排垂直间距18像素；最多10人且不缩放插画。空位置显示“位置N / 空位”，本地玩家点击后请求换位，只有目标仍为空时房主才广播新位置。两个例外：1v1车轮战固定只显示2个位置（两名玩家1v1、各自选将，不再绘制第三个空位）；“自选身份”开启时位置数严格等于规则人数，使每个位置都携带有效身份。位置数规则由 `NetworkGateway.get_lobby_display_slot_count_for()` 统一提供，界面与房主换位校验不得各自维护。开启自选身份后，玩家通过点击目标空位换位来自选该位置绑定的身份。
- 左下聊天单条最多200字符，回车与“发送”共用同一入口；公共历史最多100条，格式为“玩家名：正文”，不显示时间。大厅快照刷新不得抢走正在输入聊天或编辑房间设置的焦点。
- 右下所有玩家都看到模式、真人数、总人数与密码开启状态，房间开启自选身份时摘要追加“自选身份：开”，并按固定座位开关继续追加“（座位固定）”或“（座位随机）”；房主额外看到“对局设置”和“开始游戏”。设置模态提供稳定模式 ID、最长32字符密码、“自选身份”与“固定座位”复选框，身份模式支持2至10人且人数下限动态提升到当前真人数，斗地主仅支持3或5人，2v2固定4人，1v1车轮战固定2人。切换到不支持位置身份的模式（过关斩将）时“自选身份”复选框禁用并自动取消勾选；保存后由网关权威规范化并随公共快照广播。少于2名真人时开始按钮禁用。
- 房主悬停远端玩家形象时，在插画下方显示“踢出”按钮；房主本人、普通客户端和空位不显示。踢出后远端收到明确原因并返回连接入口；同一远端地址在之后5秒内再次加入会收到剩余冷却秒数，冷却结束才可重新进入。
- 大厅打开期间冻结主菜单中大厅之外的全部可聚焦控件，背景阻断底层鼠标输入；房主设置模态进一步冻结大厅底层控件。Esc 优先关闭设置，否则执行离开；开局成功后大厅与主菜单同时隐藏，连接失败、密码错误、被踢出或房主断开时恢复连接入口并显示具体原因。
- 连接入口、联机资料、联机大厅、动态空位和踢出按钮全部从 `BattleUIStyle` 读取语义色，并同时支持“崩铁风格”“暖木家园”与“高级黑金”。桌面协调器先切换活动主题，再由主菜单统一刷新全部联机组件，避免信号顺序导致子面板短暂保留旧配色。
- 局域网客户端不显示服务器随机种子、其他玩家身份或手牌牌面。卡牌与目标高亮读取房主定向发送的合法动作副本，点击确认后仍只提交 `PlayerAction`，不能在客户端直接改写规则状态。
- `lan_lobby_ui_test.tscn` 覆盖只读连接入口、真实房主建房、空位同框的插画内嵌尺寸、名称位置、圆角 Alpha 裁切、超长房主地址自适应、2/5/8人布局、聊天焦点、换位、设置、踢出悬停、两套主题和离开恢复。`lan_custom_identity_test.tscn` 覆盖车轮战2位布局、越界换位拒绝、自选身份的位置身份徽记、2v2上蓝下红布局、开关广播，以及固定座位开关开启时按位置绑定座次、关闭时座位随机打乱而身份仍跟随大厅位置。

## 牌桌视觉层级

- 牌桌视觉保留环桌厚框与内嵌边界，默认“崩铁风格”使用近黑厚框、冷调雾面深灰桌面与低饱和金色装饰；外底为 `#111214`，外层桌面为 `#24262B`，主内容背景为 `#30333A`。浅色仅用于卡牌纸张和已装备信息条，避免全桌白底显得突兀；同时不仿制参考图中由游戏地图毛玻璃产生的紫蓝背景，也不绘制导航网格、固定星点、山脊或建筑剪影。“暖木家园”继续使用深胡桃木、暗金和深青夜景。
- `reference_backdrop.gd` 作为独立背景组件程序化绘制外底、桌框、内容面、同心环和十二段轨道刻度；起止色相同时直接绘制纯色，只有后续主题显式提供不同起止色时才启用32段纵向渐变。星点与山脊/建筑剪影由主题布尔语义独立控制。组件只接收风格标识并从注册表读取语义值，忽略鼠标输入且不读取对局状态。
- 背景组件的桌面留白、框宽、圆角和中央装饰由主题语义覆盖：崩铁风格使用34像素桌面留白、14像素黑框、30像素圆角、150像素装饰半径与0.16装饰透明度；暖木家园保持18像素桌面留白、14像素木框及相同圆角和装饰规格；高级黑金使用20像素桌面留白、8像素蓝黑细框、16像素圆角、176像素装饰半径与0.09装饰透明度。上述参数只改变背景表现，均可通过脚本顶部 `@export` 安全回退。
- 原有 `assets/ui/table_ornament.svg` 继续作为低透明度全桌星轨纹样，与程序化中央铭纹叠加使用；二者都只承担背景装饰。
- `无名杀参考代码/十周年UI/.gdignore` 将参考扩展明确隔离为开发资料，避免网页脚本、Spine 动画和海量图片被 Godot 导入或进入游戏导出包。
- 中央动画落点位于基准视口约 `(540, 250)` 至 `(740, 400)` 的透明区域；该节点只提供动画坐标，不显示任何弃牌堆 UI。
- 默认八人局的 7 名对手从本地下家起依次位于右侧 1 名、顶部 5 名和左侧 1 名；二至八人局使用参考 CSS 的原始比例，九至十人局在相同边界内对称扩展。
- 武将体力位于武将牌右下角的不透明圆角矩形容器：背景与1像素主题描边使用运行时 `StyleBoxFlat`，四角半径均为6像素并开启1像素抗锯齿。体力框右边和底边直接对齐武将牌边缘，右下圆角与武将牌6像素圆角使用相同参数，不再绘制斜边或折线。

## 统一武将牌格式

- 所有玩家武将牌以 `Node2D` 为根，固定为 148.35×197.8 像素的3:4规格，直接复用 `player_target_view.tscn` 保存的原生编辑器几何，不按座次、人数或本地/对手身份切换规格。牌面不是按钮；`PlayerTargetInputArea` 作为透明子组件只承接点击、右键详情与悬停，不接收任何卡牌拖放。
- 座次标签不属于武将牌场景，而是只在进入游戏后由 `player_seat_slot.tscn` 添加到座位容器。其他玩家标签固定为148.35×26像素、字体18像素，完整座位为148.35×223.8像素并按快照 `seat_number` 显示“一”至“十”；本地主视角实例会隐藏并清空该标签，把容器收紧为148.35×197.8像素。
- 左侧武将名竖条固定为 22×93 像素，使用 10 像素字体并按字符逐行竖排。
- 势力圆徽固定为 26×26 像素、左下手牌数角标固定为 24×24 像素；势力简称与颜色来自 `game_data/factions.json` 的 `factions` 数组。
- 右下体力边框为宽24像素起步的动态不透明圆角矩形，内部圆点使用18像素字体和-10像素纵向间距；上限1至5时高度随体力与护盾圆点总数变化，超过5时使用VBox显示加粗“当前/上限”分数，当前值、斜杠与上限值分别占一行，例如`6`、`/`、`6`从上到下纵向排列。高体力数字与数字护盾使用12像素字体，高体力分数三行额外行间距为-4像素，使纵排内容更醒目且紧凑。两种体力模式共用残血颜色：体力上限大于2时，2点使用黄色 `#E4C84F`、1点使用红色 `#EF4F55`、其余正体力使用绿色 `#44CA67`；上限1或2时仍点亮的体力保持绿色，已损失圆点使用主题暗色。护盾使用两种风格共享的灰色 `#A7ADB7`：圆点模式按点数置于体力圆点上方，数字模式在体力分数上方显示加粗灰色单值，例如`1`；护盾没有独立上限，因此不显示分母。两种数字均以同色1像素描边加粗，护盾不并入真实体力“当前/上限”。身份徽记固定为23×20像素，身份与手牌数覆盖层在武将牌资源中默认隐藏，仅正式对局开启。
- 其他玩家的公开装备按武器、防具、进攻坐骑、防御坐骑、宝物固定槽位显示，最多5条；每条为141.35×15像素，长度严格等于武将插画宽度，相邻槽位覆盖1像素，内容为花色、点数和当前名称模式下的牌名。未装备槽位不绘制普通横条但保留对应位置，后续装备不得自动补位；某栏废除时，即使没有装备也在该固定位置绘制主题废除色“× 栏位名”横条，并提供区域规则悬停说明。宝物未装备且未废除时只计算前4个槽位，实际装备或废除宝物后扩展为5槽布局。木牛流马额外在牌名后显示全体可见的“粮”数量，包括0张。第一视角本地武将牌关闭该层，改由左侧常驻五槽装备栏独立显示。
- 判定区使用22×22像素标记槽，菱形中心位于武将牌底线`y=197.8`；第一张标记左边缘距牌面左侧28像素，相邻标记边缘间距6像素，按判定区数组顺序从左到右排列并显示当前牌名的首字。判定区废除时忽略异常快照中的实体牌名并只显示1个主题废除色“废”菱形；组件通过独立布尔值绘制，不向牌名数组注入伪造延时锦囊。
- 武将牌左上角短文本只读取公开合成字段 `character_corner_text`。规则层可维护多个 `character_corner_text_entries` 来源：排序值小的文本靠上，相同排序值按来源ID稳定排列，不同文本换行，相同文本只显示1行。当前【追歼】排序值50、【安可】100；两者共存时不会互相覆盖，任一来源结束后只移除自己的条目。
- 武将牌左上角实际是一个可容纳多个元素的角标区（`CharacterCornerStack`）：按条目排序值纵向排列，文本角标与可点击按钮可同时显示、互不挤占。纯文本条目沿用 `CharacterCornerTextBadge`；带 `view_kind` 的条目渲染为 `CharacterCornerActionBadge` 按钮，按钮文本默认为声明该条目的技能名（当前【解构】）。
- 角标区在 `player_target_view.tscn` 中**必须排在 `InputArea` 之后**（即最后一个子节点）。Godot 的鼠标拾取 `_gui_find_control_at_pos` 逆序遍历子节点、先检查最后一个兄弟，而 `InputArea` 覆盖整张武将牌且 `mouse_filter` 为 `STOP`；若它排在角标区之后，点击会全部被它吞掉，按钮表现为完全点不动且不产生任何报错。角标区的 `z_index = 31` 只决定绘制层级（高于输入区的 30），**不参与**拾取排序，因此单纯调高 `z_index` 不能解决遮挡，必须依赖场景中的节点次序。`_ready` 阶段动态挂到武将牌下的 `PublicMarkers`、中央状态标记与选中标记都已设为 `MOUSE_FILTER_IGNORE`，不会二次遮挡按钮。
- 角标控件必须**先 `add_child` 进入场景树、再写入内容**。两个角标组件都用 `@onready` 取内部子节点，入树前这些引用仍是 `null`，此时写入文本会抛出“Invalid assignment ... on a base object of type 'Nil'”，并沿状态广播栈一路上抛、打断正在结算的技能（曾使【安可】【酩酊】【逐风】【追歼】四个纯文本角标全部中断）。因此 `_create_corner_badge` 只负责实例化，内容统一由 `_apply_corner_badge_spec` 在入树后写入；`reset_size()` 也必须在写入文本之后调用，否则会按空文本取到过小的宽高。`CharacterCornerTextBadge.set_display_text` 另有判空防护，保证任何时序意外都只静默跳过，而不会升级为中断性错误。该路径由 `tests/corner_badge_test.tscn` 覆盖。
- 记录牌名只读窗口的刷新时机：`_open_recorded_card_names` 在写入窗口数据后先刷新一次，再用 `call_deferred` 延迟一帧再刷新一次。该按钮可能在同一帧的规则请求处理过程中被点击，此时 `_modal_card_choice_request` 尚未清空，只读窗口会为规则请求让位而不显示；而请求在同一帧稍后结束后通常不会再有状态广播（对局静止时无广播），窗口就再也不会出现，同样表现为“按钮点了没反应”。该窗口数据在 `_on_restart_requested` 的表现清理区随旧局清空，**不能**放进 `_on_state_changed`，否则出牌阶段的持续广播会让窗口刚显示就被关闭。
- 按钮是否显示由公开数据决定：记录容器为空时不显示，记录被清空后自动隐藏，不需要任何技能主动移除条目。因此移除记录的【看破】不需要知道【解构】的存在，两个技能保持互不引用。
- 点击记录类按钮打开只读查看窗口：形式与【五谷丰登】公共展示一致（居中模态、四列牌阵、统一悬停信息框），但记录的是牌名而不是实体牌，因此每张牌面隐藏花色与点数，只显示牌名、类别与规则说明。该窗口对所有角色开放且只能查看：只保留一个“关闭”按钮，确定按钮不显示，牌面不可选中。它不构造选择请求，因此打开与关闭都不会产生任何规则动作，权威状态在前后完全一致。
- 技能需要玩家从记录牌名中挑选时（当前为【灵感】的“视为使用的牌名”与“决定目标结算方式的牌名”两步），同一批选项改以牌面形式展开：隐藏花色点数、点击牌面选中、由确定按钮提交。这与【五谷丰登】的选牌窗口共用同一组件与模态层级，区别只在于候选是牌名定义而不是实体牌。
- 角色公开标记使用直径 `20` 像素的圆形图标，中央以 `12` 像素字号显示单个字；右下角直接以 `10` 像素字号显示 `1..999` 的数量并添加 `3` 像素黑色描边，不再绘制数量小圆底板。其他角色在武将牌左侧、距牌边1像素且整体下移8像素后纵向排列，相邻圆形间距 `1` 像素；第一视角在手牌栏右上方横向排列，右边界与手牌栏右边界对齐并整体下移8像素。标记空白区域忽略鼠标，只有实际圆形图标接收悬停；悬停通过牌桌唯一 `InformationBoxLayer` 显示标记名称、数量和完整说明。
- `player_target_view.tscn` 不再包含`Status`文本节点。阵亡角色的整张武将牌覆盖0.62亮度的黑白滤镜，并在中心显示28像素红色“阵亡”；`out_of_game=true` 的存活角色则只按0.18透明度显示且不可点击，绝不显示阵亡滤镜或文字。正常武将牌始终以148.35×197.8像素竖直牌面显示；横置由 `PlayerStateOverlay` 绘制高8像素的轻量双层深灰框：1像素外框向左右各延伸6像素并只在牌外填充实体端点，1像素内框垂直缩进1像素，其透明中段严格等于武将牌宽度。双层描边只作灰色状态凸显，不应遮盖插画。横置不旋转、缩放或移动武将牌；竖置时取消该框，点击、拖放、右键详情与信息框锚点继续使用牌面的实际全局矩形。
- 当前回合角色始终使用3像素主题强调边框；普通单人选择根据活动请求的 `actor_id` 单独提亮操作者，若操作者不是当前回合角色则额外使用2像素主题合法目标边框。【无懈可击】同时响应期间读取公开 `responder_ids`，把本轮全部存活玩家统一设为操作高亮，即使某名玩家没有合法无懈候选也保持相同表现，客户端不得根据高亮判断其手牌。所有回合与操作高亮只改变武将牌底色和边框，不绘制彩色外发光。已选目标同样使用主题强调粗边；合法目标只有在不是当前回合角色时使用主题合法目标粗边，避免临时合法性覆盖回合边框。
- 每名玩家快照公开累计 `damage_taken_count`。桌面检测该计数增加时播放一次受伤抖动，不再只依赖体力下降；因此伤害完全被护盾吸收时仍有受击反馈。护盾自然减少或技能主动失去护盾不会增加该计数，也不会伪装成受到伤害。
- 势力徽记、武将名、手牌数、身份、体力、公开区、装备横条和座次字体均使用上述固定尺寸；武将插画保持牌面的主要视觉占比。

## 选将界面

- 候选区使用常驻垂直拖条；滚轮每格移动96像素，候选牌或覆盖候选区的空白内容位置的鼠标/触屏拖动超过18像素后复用同一滚动入口，拖动、滚轮与右侧拖条必须同步同一个滚动值，释放不会误选武将，确认按钮始终在滚动区外。首行与末行分别预留武将悬停放大的裁切安全留白，因此1.08倍候选不会被上方标题UI遮住。换将入口覆盖在牌面底部，尺寸96×30像素、距底边内缩12像素，文本固定为“换将 x”并显示剩余张数，原生工具提示保持关闭。座次或身份从领袖/一号位切换到普通项时，另一项自动随机补全为可用项，顶部身份标题立即同步；确认者的武将和当前座次身份即时生效，选将完成不再二次刷新场上牌面。
- 开局进入全屏选将遮罩，领袖先从随机候选中选择并立即亮出；领袖确认后，其他玩家各自在自己的客户端同时选择，所有人完成后统一亮出并关闭遮罩。
- 选将服务向每名观察者返回本人 `local_identity` 与 `local_seat_number`（及初始/预览座次字段）。全部模式（身份局/斗地主/2v2，含是否开启自选）顶部标题统一为“你的身份为：xx，你的座次为x号位，请选择你的武将”；已确认等待时动作段改为“请等待其他玩家选将”。身份片段使用对应语义色（领袖红 `#EF4F55`、反贼绿 `#44CA67`、忠臣黄 `#E4C84F`、内奸蓝 `#5E85CE`，地主/农民/蓝红同各模式色板），座次与动作文案使用主题主文字色。自选模式下点选身份/座次按钮会即时刷新标题中的身份与座次。该标题不显示、推断或泄漏其他玩家身份。AI 武将调整用途仍显示“请为某角色选择武将”，不含本人身份座次。
- 每名玩家的普通随机候选读取房主锁定的 `character_candidate_count`，范围1至20、默认5，实际显示数量不超过可用武将数。只有首任领袖选将框把所有拥有领袖技的武将额外置于普通随机候选之前，不占该数量；最终座次身份自选中除首任领袖外严格使用设置张数。真人首任领袖已在第一次面板完成全部确认，AI首任领袖延后分配时保留公开武将且候选为空。`locked_candidate_ids` 只锁定当前领袖身份中的领袖技候选，其他身份可正常换将领袖技武将。
- 候选使用正式 `PlayerTargetView` 场景，保持148.35×197.8像素 Node2D 武将牌模型；候选布局直接读取场景牌宽，不在脚本中保存重复尺寸。鼠标悬停可选武将时以0.14秒二次缓出从1.00倍过渡到1.08倍，并围绕牌面中心放大；统一信息框同时显示武将名、势力、性别、静态体力上限以及按定义顺序排列的全部技能名和描述，移开后用相同时长恢复牌面并关闭信息。点击只让所选武将显示主题强调边框，未选候选不再因统一合法状态获得彩色发光或描边；点击确认后才提交 `select_character` 标准动作。
- 领袖阶段只有领袖能看到自己的候选；领袖确认后，选将框左侧以0.78倍显示其只读正式武将牌，并使用2像素竖线与右侧本地候选分隔。没有公开领袖时竖线与领袖区域都不占位，候选区域直接从原领袖牌左边界开始。界面不再显示“领袖已亮出……其他玩家同时选择，完成……”等确认进度长文本，也不显示其他玩家具体选择。
- 当前选将框按1280×720逻辑视口使用1040×600像素普通主面板；有公开领袖时左侧只读区域从 `(40, 106)` 开始，右侧候选滚动区从 `x=214` 开始；无领袖时从 `x=40` 开始。候选始终保持148.35×197.8像素原尺寸和8像素间距，组件按可用宽度自动计算列数，内容超过一行时启用垂直滚动。确认按钮是滚动区的独立兄弟节点，固定显示在主框底部，不随候选滚动；未开启座次身份自选时，候选滚动区向下扩展至确认按钮上方，不保留隐藏控件的空白区。
- 可换的普通随机候选在悬停时于牌面底部覆盖96×30像素“换将 x”按钮，距底边内缩12像素，不占据候选行空间；从牌面移动到按钮时延迟复核鼠标位置，入口不会闪退。按钮只向桌面发出稳定武将 ID，收到下一份权威快照前统一禁用；当前领袖身份中的领袖技武将、全武将列表或换将卡用尽时不创建按钮。
- 开启“自选全武将、座次与身份”后，首任领袖仍先按第一次身份公开选将；公开武将即为该玩家最终武将。真人首任领袖的第一次面板直接显示与场上总人数相同的座次按钮及领袖、忠臣、反贼、内奸身份按钮，并与最终自选相同显示“所有武将”按钮；首次一号位和领袖身份自动高亮，点击固定确认按钮会一次提交武将、座次与身份（可从随机候选或全部已登记武将中选择）；成功后 `can_select=false`，整个面板关闭，不显示第二组选将牌或第二次确认。首任领袖为AI时先亮将，`retains_selected_character=true` 只用于真人完成后让AI复用原武将补选剩余名额，不产生玩家可见的二次面板，也不向该 AI 保留态开放“所有武将”。其他玩家进入最终自选后同样显示“所有武将”按钮以及相同座次身份控件。首次默认座次与身份已经投射到场上，不是单纯按钮高亮。座次或身份选中后，背景向对应边框语义色混合34%，字体切换为边框颜色；一号位与领袖按钮立即双向联动。有效预览会重排背景座次并恢复未确认AI为未亮将状态；首任领袖公开武将保持不变，新领袖为AI时公开其候选首张且最终确认沿用该牌，新领袖为尚未确认的人类时立即清空旧领袖牌。点击“所有武将”后主框扩展为距视口四边16像素，候选按原尺寸铺满可用宽度并在不足时垂直滚动，同时隐藏“选择座次”“选择身份”标题和按钮；右上按钮改为“返回”并左移避开常驻“菜单”，确认按钮继续固定在滚动区外。点击“返回”会恢复普通主框及原座次身份临时选择。
- 2v2 自选时座次与蓝/红按开局成队表双向联动：选座次立即切换为该座绑定色（1/4 同色、2/3 同色）；选蓝方/红方时若当前座不在同色表则自动随机到可用同色座。快照字段 `team2v2_identity_by_seat` / `team2v2_blue_seat_numbers` / `team2v2_red_seat_numbers` 供面板读取；服务端规范化为权威校验。
- 开启“自选所有AI的武将”后，初次选将完成会显示“请选择需要修改武将的角色”。房主可点击任意AI武将牌打开共用选将框，每次点击都按房主的1至20张随机选将牌数重新生成候选；若同时开启全武将自选，则保留“所有武将”按钮，但不显示座次与身份按钮。房主用“结束修改”继续开局，局域网其他玩家只显示“房主调整武将中...”。
- 手气卡阶段复用中央确定/取消操作区：确定按钮显示“使用手气卡”，取消按钮显示“不再刷新”，并显示有限剩余张数或“无限张”。已确认玩家改为“等待其他玩家确认手气卡...”，所有真人完成后才关闭询问并进入首回合。

## 局内菜单

- 右上角唯一常驻按钮文字为“菜单”，点击后显示从其下缘紧贴开始的集中面板；面板内容行间距为2像素，原独立“牌名”和“重开”按钮不再存在。
- 新启动默认显示《崩铁杀》卡牌名称，菜单内可切换为三国杀原版名称并随时切回；名称切换只重绘显示文本，不改变卡牌 ID、效果或对局状态。
- 菜单内新增“AI响应速度”滑条，默认 0.30 秒，可在 0.10 至 1.00 秒之间以 0.05 秒步长调整。该数值是每次 AI 行动或选牌响应前的等待时间，数值越小响应越快；修改后立即作用于后续 AI 计时器，不需要重开对局。
- 菜单内“游戏速度”标签使用“游戏速度：0.30秒”的两位小数格式；滑条表示流程最小间隔，默认0.30秒，可在0.10至1.00秒之间以0.05秒步长调整。相邻阶段和全部响应提示先等待该数值；普通 AI 行动的等待取游戏速度与 AI 响应速度的较大值，AI 响应牌在提示发布后再等待同一较大值，保证人类先看到窗口。修改只影响之后创建的任务，已经开始的计时器保持原时长。
- 菜单内人数输入范围按下一局模式变化：身份模式 2–10，斗地主仅 3↔5（步长 3）。输入文本会即时同步，点击“按设置重新开局”时优先读取当前键入内容并按模式规范化，随后创建对应人数的新对局并重新进入选将。
- 主菜单设置与局内菜单共同提供“自选全武将、座次与身份”“自选所有AI的武将”“手气卡数量”“AI使用手气卡”“换将卡数量”“随机选将牌数”六项房主权威设置。手气卡数量保存 `0、1、2、3、4、5、10、-1`；换将卡数量保存 `0、3、5、8、10、20`；随机选将牌数保存1至20。所有下拉框只读取选项元数据，不通过显示文字解析规则。
- 六项开局设置只在之后创建或重新开始的对局生效；创建对局后会锁定为本局规则快照。局域网客户端的局内菜单隐藏这六项及原有速度、人数和重开控件，房主与离线玩家可见；卡牌名称、UI风格和自动身份标记继续作为每名客户端自己的显示设置。
- 局内重开会在清空旧表现前调用控制器的只读前置校验。人数或全局数据校验失败时重新展开局内菜单并显示拒绝原因，当前 `GameState`、事件运行时与 AI 任务保持原局状态；通过前置校验后若新局选将初始化失败，则清空半成品运行时并返回主菜单重试。
- 仅离线过关斩将在“按设置重新开局”与“返回主菜单”之间显示“临时退出”按钮。点击时若正处于空闲的出牌询问（没有任何进行中的结算），立即存档并返回主菜单；否则请求转为挂起并关闭菜单，按钮文字变为“取消临时退出”，存档生效前可再次点击取消。挂起的请求在当前操作结算完成后的最近空闲点（出牌询问重建处或回合边界）自动存档退出；请求、取消与实际存档都会写入对局日志。存档写入本地文件后按标准返回主菜单流程结束会话；写入失败时仍按玩家意图退出，但顶部信息横幅提示本次未生成新存档。按钮显隐随对局模式与权威可见性变化，局域网与其他模式一律隐藏。
- 主菜单主操作按钮的文字随过关斩将存档存在性切换：选中过关斩将且本地存在可解析存档时显示“继续上次游戏”，点击后从存档记录的空闲点继续（回到原出牌阶段或从下一回合开始）；其他模式或无存档时保持“开始游戏”。存档恢复失败（版本或内容不兼容）时清除该存档、恢复按钮文字并在主菜单状态栏显示具体原因；过关斩将终局与全新过关斩将开局也会清除存档并同步按钮文字。
- 菜单面板的输入顺序高于动态武将牌与选将遮罩，因此选将尚未完成时仍可继续调整人数并重新开局；人数修改只在重开时生效。
- 手牌保留浅色实体纸张以保证花色和牌名可读，外框改用硬质窄圆角与深阴影；禁用纸张与类别条默认压暗38%，插画和文字使用45%亮度深灰调制，选中、悬停和类别色仍遵循原有交互语义。
- 所有 UI 风格仅调整表现层。组件继续只消费裁剪快照、发出稳定 ID 信号并提交标准动作，禁止通过视觉节点直接读取或修改规则状态。

## 出牌动画

- 规则核心使用可序列化 `CardPresentationEvent` 统一描述 `useCard`、`showCards`、`delayedJudge` 和 `judge`，内容包含表现序号、关联事件、卡牌快照、来源、目标与后续弃牌所有权，不向界面暴露权威状态对象。
- 本地玩家使用卡牌时，动画层直接接管手牌中的同一 `CardView` 节点；AI 或其他不可见来源使用牌时，也实例化同一个 `card_view.tscn` 正式牌面。本地牌从手牌区实际节点进入动画层，其他玩家的牌从对应武将牌中心进入；全部牌都用0.42秒飞向中央弃牌展示区。纯展示和普通弃牌抵达后停留0.48秒，再用0.36秒淡出；真实使用牌、延时判定牌和判定牌在响应、选牌或其他异步结算完成前持续留在中央，最终进入弃牌堆或其他权威区域后才完整停留0.48秒并淡出。
- 【火攻】展示手牌和判定阶段也使用同一动画层：`showCards` 从展示者武将牌中心飞入中央牌桌且不移动权威实体；每张延时锦囊先用 `delayedJudge` 从判定角色锚点展示，默认保留1.00秒后才由 `judge` 把牌堆顶1张判定牌直接从中央弃牌展示锚点公开，不从判定角色处打出；判定完成后默认再保留1.00秒才展示判定区下一张牌。两种间隔分别读取 `MatchController.delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds`，检查器范围均为0.00至3.00秒。上述展示都没有使用牌目标指示线。
- 本地玩家进入手牌区的正式牌先按实体 UID 创建或复用手牌容器中的 `CardView`，再从手牌可视区右侧24像素外用0.24秒移动到最终手牌位置；动画结束后同一节点继续承担选择与出牌。一次 `draw()` 摸到多张牌时，所有牌背由独立批次从同一牌堆锚点同时起飞，并按42像素横向中心间距围绕目标锚点整体居中；飞行0.24秒、停留0.10秒、淡出0.18秒，同一批不使用逐张延时。每次 `draw()` 收齐本批移动后立即开始动画，多个玩家或连续多次摸牌的批次可以同时播放，不互相等待。其他玩家的隐藏获得动画仍只显示牌背。
- `CardPresentationEvent` 明确声明后续弃牌所有权。动画层先按本局单调 `presentation_id` 去重：最近4096项保存在字典与固定环形槽位中，落后最高序号至少4096的远古重发即使已离开字典也会被拒绝，长期运行不会为每次表现永久新增键；重新开局会清空窗口并接受新局从1开始的序号；局域网客户端在同一房间内重开时由房主重播的开局绑定触发同一次清空，因此“再来一局”后的首批使用飞牌与目标指示线不会被上一局的同号序号拦截；卡牌实体 UID 的弃牌所有权认领记录也在同一入口一并清空，避免新对局的卡牌实体 UID 重新从1启用后被误判为已播放过而整局不再生成移牌与弃牌动画。随后让真实使用牌和判定牌按实体 UID 原子取得所有权；普通弃牌首次观察到实体 UID 时也登记其表现生命周期，节点接管与所有权登记之间不存在可插入重复移动的窗口。接管所有权的牌不再按固定总时长提前淡出，而是等待响应与整张牌结算完成后的最终区域移动；消费记录继续保留到权威实体进入非弃牌新区域，因此相同表现包、不同表现 ID 的迟到包、同区域无效移动或相同移动增量重复到达都不会在牌桌上方或中央生成第二张牌。玩家来源或目标不存在真实座位锚点时直接跳过短时表现，不再回退到 `(540,250)..(740,400)` 的中央锚点伪造来源或落点；新建牌面在完成父级、坐标和外观初始化后才设为可见。`CardView` 的样式与悬停刷新默认不再写入非手牌绝对纵坐标，动画牌在鼠标离开透明输入区时不会把 `position.y` 重置为0并跳到窗口顶部。`GameState.processing_card_uids` 公开当前处理区实体 UID，动画层每次快照都会核对仍被认领的中央牌面，已离开处理区但漏失最终移动通知的牌立即进入正常停留和淡出。没有对应 `useCard`、`delayedJudge` 或 `judge` 表现认领的 `processing -> discard_pile` 增量创建0张中央牌面，避免虚拟材料收尾从中央锚点凭空出现。火攻等纯 `showCards` 只按表现 ID 去重，不占用实体 UID 的未来弃牌所有权。
- 有目标的卡牌会绘制从使用者指向每名目标的4像素金色指示线；线条默认用0.24秒从来源动态延伸到目标，延伸完成后立即独立用0.36秒逐渐淡出，不等待飞牌停留或弃牌队列。多目标卡牌为每名目标保留独立武将牌中心终点，显示多根同步延伸并同步渐隐的指示线，无目标牌不绘制指示线。技能不在 `target` 或 `card_target` 选择请求中显示预览线；仅在技能实际确认发动后，从 `skill_activated` 上报的 `target_id/target_ids` 读取目标，并以同一绘制层、同一4像素金色样式播放完整“延伸→淡出”动态线。卡牌可通过 `indicator_stages` 声明顺序指示阶段；【借刀杀人】先完整播放使用者到持刀者，再播放持刀者到被要求出【杀】者，不能同时叠成两条线。
- 本地玩家无论作为使用者还是目标，统一使用手牌区上方中心作为指示锚点，默认与手牌区顶边保持8像素间距；其他玩家统一使用各自武将牌中心。因而本地玩家对其他角色使用牌时，线条从手牌区上方中心指向目标武将牌；其他角色对本地玩家使用牌时，线条从来源武将牌指向手牌区上方中心。
- 飞牌保持正式111×148像素的3:4模型和1.0倍目标缩放，全程保持0度旋转，不替换为细长牌或简化标签。多张牌同时存在时按66像素中心间距水平铺开，成员变化后使用0.18秒补位，展示手牌、判定牌、响应弃牌和普通弃牌全部进入同一中央展示队列；同一帧进入弃牌堆的多张牌按信号顺序从左到右完整显示，并作为同一批次同时使用0.36秒淡出。每张中央牌始终只保留1个收尾生命周期 Tween：无异步响应的牌覆盖0.42秒飞行与0.48秒停留，需要响应的牌在最终区域移动后按已经完成的飞行时间补足剩余飞行并重新完整停留0.48秒。动画层使用30层，高于普通牌桌和武将牌，低于40层选将遮罩与50层菜单；该层忽略鼠标输入，不会遮断点击、拖放、目标选择或确认按钮。
- 摸牌、获得和响应弃牌也通过 `card_transfer_requested` 播放区域移动；控制器会为一次 `draw()` 额外发出开始/完成批次信号。带批次标识的牌堆到手牌移动由桌面先收集、后一次性提交动画层，不能退化为每张向右偏移的顺序堆叠；带摸牌堆叠键但未进入批次接口的兼容转移同样使用0.24秒飞行、0.10秒停留和0.18秒淡出。没有批次标识的获得牌仍沿用原区域移动表现。处理区到弃牌堆的使用牌由持续到最终移牌的实体 UID 记录接管，防止响应等待后同一实体牌重复出现在中央位置。
- 重新开局会先递增动画代次，清空旧局的区域转移索引、摸牌堆叠索引和补间索引，并立即隐藏旧牌面。所有删除操作使用稳定实例 ID，摸牌堆叠数组不保存对象引用，也不把可能已经释放的 `CardView` 作为容器删除参数；上一局仍在等待的补间正常结束后先比较代次，不匹配时只释放自己的隐藏牌面，不能访问或清理新一局动画。
- 飞牌进入中央区域属于客户端结算表现。装备牌、延时锦囊等卡牌仍按规则进入装备区或判定区，动画不会改变其最终区域；同一区域重复移动不会产生新的牌面动画。
- 对手座位按玩家 ID 持久复用，普通状态快照只重建轻量视图索引，不再释放并实例化整桌武将牌。`CardView` 与 `PlayerTargetView` 缓存同时包含名称模式和 UI 风格 ID；快照内容与风格均未变化时不会重复加载插画、生成主题样式、体力圆点、装备横条或判定标记。玩家人数、本地座次、风格或实际公开状态变化时会立即失效并刷新对应节点。

## 插画预留

- 每张卡牌在牌面中部保留插画区域，花色与点数固定在左上角，牌名和类别固定在底部，不会被插画覆盖。
- 所有玩家的武将插画槽固定为 `(4, 4)` 至 `(145.35, 194.8)` 的 141.35×190.8 像素区域，覆盖牌面绝大部分面积；3:4牌面设计只扩大牌框和插画，势力徽记、竖排武将名、体力圆点、手牌数和身份徽记保持固定规格，装备横条完整铺满插画宽度，座次标签位于牌面外部。
- 本地与其他玩家使用同一插画裁切规则和 148.35×197.8 像素牌面尺寸，不使用单独缩略图组件。
- 卡牌定义继续使用可选字段 `art_path`。武将源码不填写该字段；`GameDatabase` 根据武将 `.gd` 文件的完整基础名，在 `res://game_data/characters/image/` 依次匹配同名 `.png`、`.jpg`，并把命中路径注入只读武将元数据供 `PlayerTargetView` 使用。
- 同名 PNG 与 JPG 同时存在时固定优先使用 PNG。匹配不读取武将稳定 `id` 或中文显示名，因此 `buluoniya.gd` 只对应 `buluoniya.png` 或 `buluoniya.jpg`，`sp_buluoniya.gd` 只对应 `sp_buluoniya.png` 或 `sp_buluoniya.jpg`。
- 卡牌 `art_path` 缺失、为空或无效，以及武将同名 PNG/JPG 均不存在时，界面显示统一“插画预留”占位，不中断对局。
- 卡牌资源目录与手填路径规范见 `assets/art/README.md`；武将图片命名规范见 `game_data/characters/image/README.md`。
- 卡牌插画使用覆盖裁切保持比例，武将插画同样保持比例并裁切到固定槽位；替换图片不改变控件尺寸。

## 卡牌视觉反馈

- 卡牌顶部使用4像素类别色条，颜色从当前风格的 `card_basic/card_trick/card_equipment` 语义读取；崩铁风格保留红 `#B65350`、蓝 `#4E7FA7`、金 `#A98D55` 三种类别色，暖木家园分别使用 `#A44E43/#4F718F/#8A7548`，高级黑金使用 `#A64950/#5E70AD/#B58A4C`。
- 火焰与雷电属性牌优先使用当前风格的 `card_fire/card_thunder` 语义；崩铁风格使用橙红 `#D66A46` 与亮蓝 `#5E85CE`，暖木家园使用橙红 `#C65F3F` 与蓝色 `#547FC4`，高级黑金使用橙红 `#D66A46` 与柔蓝 `#6B8BD1`。红桃、方片的红色和体力红黄绿仍作为玩法识别色保留。
- 可交互卡牌悬停时在0.12秒内缩放至1.06倍并提高绘制层级；相邻手牌继续保持当前展开或压缩位置。
- 鼠标离开后恢复原始缩放；选中卡牌仍保持14像素抬升和主题强调描边。
- `CardSelectionPanel` 中所有明置牌与手牌共用统一信息框：悬停达到0.50秒后显示牌名、花色点数、类别和规则说明。【五谷丰登】只读公共牌、【顺手牵羊】与其他区域选择中的公开牌、禁用明置牌及已领取虚影都可查看；牌背不发送说明请求。
- `control/bool` 请求若在 `context.display_candidates` 携带私有完整牌面，`CardSelectionPanel` 先按手牌、装备、判定、处理区与弃牌堆顺序显示只读牌，再在同一窗口显示文字选项按钮。只读牌保持完整亮度但 `is_interactable=false`，不会因禁用态暗置；按钮提交稳定 `control_id`，牌面UID不能被选择或随响应提交。该模式用于【勘测】观看目标手牌，且只向请求响应者显示；它不属于“选择角色区域内的牌”请求，因此必须保留自身的文字选项提示，不显示区域选牌文案。
- 私有只读展示关闭、取消或提交后立即随对应请求销毁；界面不缓存完整牌面，不把它合并进公共状态，也不允许 `target_control` 借用该窗口绕开武将牌目标选择。因而【勘测】始终是“先选目标、再私看并点文字按钮”，【秘策】始终是“在牌桌上同时选目标与按钮”。
- 类别色与动画只属于视觉反馈，卡牌合法性仍完全由规则预览和核心校验决定。

## 标准出牌流程

- 手动选目标时，所有合法且未选中的武将牌使用2像素合法色边与4像素、0.42透明度的细绿光；被选中后立即改用强调色边并移除绿光。多目标点击顺序只用于编辑，普通多目标牌、含额外目标的虚拟【杀】与群体锦囊由权威层从使用者下家起按顺时针结算，只有【借刀杀人】保留“持刀者、被【杀】者”的点击语义。
1. 点击一张手牌或木牛“粮”选择实体 UID；已选卡牌使用主题强调描边并向上抬升14像素。
2. 界面调用 `MatchController.get_card_use_preview()` 获取只读规则预览，并用当前主题的合法目标描边标记下一步目标。
3. 点击角色状态卡按顺序选择目标；再次点击已选目标可取消。若卡牌最多只需要1个目标，直接点击另一名合法角色即可替换旧目标，无需先取消。手动选目标期间，合法目标保持正常亮度并显示主题合法描边，非法且未选中的武将牌统一使用 `(0.42, 0.42, 0.42, 1.0)` 整体调制色变暗；普通浏览不应用该暗化。【桃】【酒】【无中生有】【闪电】和 `target_mode=self` 装备只有在本人是唯一合法目标时自动锁定本人，其他单目标牌即使只剩1名合法角色也仍需玩家点击。已选目标使用主题强调描边。【万箭齐发】【南蛮入侵】【桃园结义】【五谷丰登】等 `all_others/all_players` 牌由规则层自动展开目标：点击武将牌仍不会写入手动选中数组、不显示中央绿色「选中」字；但选中该牌后进入目标预览暗置态，亮起集合取 `get_card_use_preview().normalized_target_ids`（规则 `normalize_targets` 后仍可成为目标的角色），其余存活角色压暗。暗置依据是「不能成为目标」（如使用者自身在 `all_others` 中、【破风】额外回合限制），不是「效果无效」（藤甲令群体锦囊无效时仍保留在展开列表中，不暗置）。联机客户端通过合法动作字段 `normalized_target_ids` 取得同一展开列表。 已被加入目标顺序的武将牌中央常驻显示绿色有黑色描边的“选中”二字（字号28、描边6，对齐技能发动黄字格式，颜色固定为太空主题合法绿 `61c7a4`），取消选中后立即隐藏。
4. 多目标在界面中按点击顺序编辑与取消，界面最多保留3名目标；提交后权威规则层统一按当前回合角色起算的行动顺序结算。【借刀杀人】必须先点击持刀者、再点击其需要使用【杀】的角色，共选择2名；提交时已完整指定，之后不再弹出第二次目标选择。
5. 当前牌与目标组合通过预览校验后，“确定”按钮才会启用；点击或按 `Enter` 后提交标准 `use_card`。

规则核心仍会在 `submit_action()` 中执行最终校验。UI 预览仅用于引导，不能替代权威规则判断。

### 快捷操作

- `Enter`：当前牌和目标组合合法时执行“确定”。
- `Esc`：取消当前选牌与全部目标。
- 鼠标右键：与 `Esc` 相同，取消当前选择。
- `Space`：未选择卡牌且处于本地出牌阶段时结束出牌阶段。
- 本地武将牌整体可点击以选择自己；“选择自己”按钮继续作为触屏和低分辨率下的明确入口。

## 手牌拖拽排序

- `CardView` 根节点为 `Node2D`，透明 `CardInputArea` 通过 Godot 原生拖放接口提供稳定实体 UID，只请求本地显示排序，绝不复制、移动或提交权威卡牌对象。
- 将一张手牌拖到同一分区的另一张牌上：落在目标左半边插入其前，落在右半边插入其后。排序只影响当前客户端视觉顺序，卡牌区域、手牌数、实体 UID 与出牌动作均不改变。
- 普通手牌与木牛“粮”使用独立排序分区；木牛“粮”始终位于手牌区左侧，只能与其他“粮”互相排序，不能跨入普通手牌区，也不能被普通手牌跨越。
- 拖拽不再参与选牌、规则预览、目标选择或 `PlayerAction` 提交。使用牌仍必须点击牌面选中、点击武将牌选择目标，再点击“确定”或按 `Enter` 提交。

## 其他动作

- 选中定义中 `recast=true` 的普通手牌且没有选择目标时，中央“确定”直接提交 `recast_card`；当前默认牌堆中该流程用于【铁索连环】，木牛“粮”不能进入重铸。
- 木牛流马在本阶段可以存粮时作为宝物装备候选向右移动；点击装备后选择1张普通手牌并按“确定”提交 `store_wooden_ox`，若已选择目标，则该目标接收木牛流马和全部“粮”。
- 丈八蛇矛在可以使用或打出【杀】时作为武器装备候选向右移动；点击装备后选择正好2张普通手牌，出牌时再选择1名攻击范围内目标，响应时直接按“确定”打出虚拟【杀】。
- 右侧“结束阶段”提交 `end_play`，普通内联响应或效果选择期间隐藏；群体锦囊的【无懈可击】询问期间改为“不响应该锦囊”开关。
- 任何已经提交到核心的非法次数、距离、目标、区域或阶段动作都会被拒绝，并在本地玩家区显示最近一次错误原因；不可发动的技能按钮本身处于禁用状态，点击时静默忽略，不生成“该技能当前不满足发动条件。”等错误文本。

## 技能控制条

- 技能栏位于本地玩家状态与手牌之间，外层完全透明且只显示按钮；底边与本地武将牌底边平行对齐。
- 桌面根据本地武将配置中的 `skills` 数组动态生成按钮，不硬编码武将 ID 或技能数量。
- 每个按钮正文只显示技能名前两个字，悬停时由统一信息框显示完整名称、技能说明与接入状态；元数据 `lock=true` 时信息副标题标记为锁定技。技能说明中的完整 `【牌名】` 可匹配已登记卡牌的原版名或崩铁杀名，并通过 `GameDatabase.resolve_card_names_in_text()` 显示为当前名称模式对应牌名。数据库使用加载期牌名索引，并按名称模式缓存最多512条完整说明；重复打开相同技能按钮、悬停框或武将详情不会重新扫描全部卡牌。
- `trigger` 为 `sample_only` 的样例技能显示为“预留”并保持禁用；普通技能的不可发动、被动、触发、锁定和样例状态统一使用更灰的禁用色，普通、悬停、按下与禁用样式保持一致，不播放悬停动画，点击时不提交动作、不修改状态也不显示错误提示。限定技单独使用三态视觉：当前可发动时读取主题危险色显示红色背景；限定额度尚未消耗但因阶段、目标或条件暂不可发动时在同一红色上加深 `18%`；限定额度已经消耗时改用通用禁用背景再加深 `42%`、禁用边框再加深 `25%` 的深灰色。三态只读取权威快照 `used_limited_skill_ids`，不得根据按钮是否禁用推断“已经发动”。技能按钮的“已释放”表现只到深灰底色与描边为止，不改变字体不透明度；限定技与觉醒技释放后的技能名与描述变淡只发生在武将悬停资料与右键武将详情中，与按钮状态互不替代。
- 后续主动技能可在元数据中声明 `ui_enabled: true`，并由独立技能交互控制器处理选牌、选目标、确认和标准动作构建。
- 技能按钮默认尺寸为62×44像素；按定义顺序从右到左、从下到上排列，每行最多2个，水平和垂直间距均为6像素。选中技能使用3像素主题强调描边；普通可发动技能使用主题合法目标边框，限定技可发动时改用红色边框语义；不可发动技能没有选中和悬停变化。
- 主场景初始化会把旧版本遗留的 `HFlowContainer` 技能容器原位升级为 `SkillButtonGrid`，并重新应用透明技能区、175像素透明手牌区和148像素装备区高度；该兼容迁移只用于消除编辑器旧场景缓存造成的节点类型错误，不改变技能定义或按钮顺序。

## 组件职责

- `match_table.gd`：桌面协调器，渲染只读对局快照、左上轮数/牌堆/时长、当前回合与当前操作者状态，建立玩家 ID 索引并缓存静态定义，按实体 UID 对账并复用本地正式手牌节点，把对手座次旋转为本地相对行动顺序，维护普通出牌、本人手牌/装备区内联选择和公共选牌展示，请求规则预览并构建 `PlayerAction`；阶段间隔内没有活动 `chooseToUse` 请求时全部出牌控件禁用。“记录”右侧的“托管/取消托管”与“托管中...”文字点击均只提交 `set_auto_managed`，该状态变化不写入对局记录；托管滤镜高度固定175像素、从手牌左边界延伸到本地武将牌左侧8像素，技能按钮的绘制层级始终更高；遮罩拦截其余指针且所有常规操作控件禁用。局域网中它额外协调大厅、网关、房主开局和客户端本地玩家 ID，但仍不直接修改 `GameState`。
- `main_menu.gd`：管理启动前身份模式、斗地主与2v2入口、覆盖裁剪预览、主题化模式层级、模态设置、离线开局请求与局域网入口；斗地主页文案为“斗地主·3或5人·地主VS农民”，2v2页文案为“2v2·4人·蓝方VS红方·一/四同队、二/三同队”，三种模式预览均不显示左上角“标准身份局”徽章。显示设置与下一局人数统一经 `GameSettings` 保存，组件不读取或创建 `GameState`；牌桌确认房主或离线 `start_match()` 成功后调用完成入口关闭菜单，失败时组件保留入口并显示拒绝原因。
- `lan_lobby_panel.gd`：管理局域网连接参数、只读玩家名和入口模态焦点，只发出建房、加入和返回意图，不渲染已连接成员，也不创建 ENet 或权威状态。
- `online_lobby_panel.gd`：根据公共大厅快照渲染位置、聊天和房间控制，房主私有快照可额外回填明文密码；组件只发出聊天、换位、踢出、设置、开始和离开意图。
- `online_lobby_avatar.gd`：占用位置以空位同规格、透明中心且无阴影的圆角边框包裹148.35×197.8像素原始武将插画，空位置继续显示可点击的“空位”内容；圆角 shader 只裁切纹理 Alpha，不使用 CanvasItem 颜色输入调制插画，因此边框不会向角色形象叠加黑色滤镜。房主管理按钮由远端成员、房主权限与形象/踢出按钮的合并悬停状态共同决定，鼠标从插画移入“踢出”按钮不会闪烁；按钮默认宽80.35像素、高31像素、左右内缩34像素、距插画底边10像素，背景为当前主题危险色加深32%。
- `card_view.gd`：以 `Node2D` 为根渲染单张实体牌、选中反馈与正式手牌入场偏移；装备牌底部按子类型显示武器、防具、进攻坐骑、防御坐骑或宝物牌；`card_input_area.gd` 独立处理点击、悬停与拖拽数据。
- `equipment_stack_view.gd`：只接收本地装备快照、候选 UID 与选中 UID，按固定槽位渲染堆叠横牌并发出装备 UID 点击信号；不读取 `GameState`、不保存请求对象、不提交规则动作。
- `player_target_view.gd`：以 `Node2D` 为根渲染全玩家共用武将牌；牌面始终竖直，横置状态通过 `PlayerStateOverlay` 的牌外实体端点与牌内透明双层灰框表达，竖置时移除该框。正式对局的 `HoverNameShade` 在鼠标停留且武将牌未翻面时显示公开 `display_name`，节点位于插画之上且忽略鼠标，因此不会遮挡输入区域；翻面牌背位于插画之上、装备与状态 UI 之下，只替换插画。统一信息框仍按0.5秒延迟显示完整武将资料。视觉签名只包含身份、体力、横置、翻面、手牌数、装备和判定区等实际画面字段，用牌、响应与技能历史增长不会重建体力点和装备节点；`player_target_input_area.gd` 独立处理点击、右键详情与悬停，并使用牌面实际全局矩形。
- `judgment_zone_view.gd`：只接收判定牌显示名数组，在武将牌底边生成固定菱形与首字，不读取玩家或卡牌实体状态。
- `player_state_overlay.gd`：只接收存活和横置布尔值，并以 `configure_card_size()` 同步牌面几何；绘制阵亡黑白滤镜、红色文字与横置双层框，不参与死亡或连环结算。
- `player_seat_slot.tscn`：只在进入游戏后实例化，组合一个武将牌与其下方独立座次标签，不保存玩家状态或处理交互。
- `skill_button_view.gd`：渲染单个武将技能的名称、状态与说明，并发出稳定技能 ID 请求信号。
- `card_use_animation_layer.gd`：接管正式 `CardView` 节点播放使用者到中央结算区的飞牌动画，维护水平弃牌队列、同帧弃牌批量淡出、同批居中且跨批立即并行的摸牌动画、重开代次隔离，以及卡牌与技能实际发动共用的动态目标指示线。`play_skill_target_indicator(start_position, target_positions)` 复用卡牌线的0.24秒延伸与0.36秒淡出参数，不创建技能专用线条节点；历史预览键接口仅作兼容清理，不得在选择目标时调用。
- `match_menu.gd`：管理右上菜单显隐、卡牌名称、UI风格、自动身份标记、游戏与AI速度、下一局人数（按模式限制），以及六项房主开局设置。展开面板后仍将常驻“菜单”按钮提升到面板前方，因此同一按钮始终可再次点击收起菜单。所有离散规则下拉框从 `GameSettings` 标准选项构建并保存数值元数据；`set_authority_controls_visible()` 统一隐藏客户端不可修改的整行控件；`set_auto_identity_marking_visible()` 在斗地主本局隐藏自动身份标记。组件不保存颜色字典、身份推断或对局状态。
- `match_log_panel.gd`：管理“记录”按钮与日志正文显隐并发出展开状态；不读取规则状态、通信模式或日志语义。离线暂停所有权由 `match_table.gd` 协调。
- `character_selection_panel.gd`：渲染本地裁剪选将快照，在左侧显示当前公开领袖正式武将牌，在右侧以原尺寸滚动网格显示本地候选，并分别提交完整选将数据、单张换将稳定 ID或座次身份预览；领袖技锁定与剩余张数全部读取权威私有字段，非锁定随机候选在剩余张数大于0时均可显示悬停“换将 x”入口。候选牌、候选内容节点覆盖的空白区都可将超过18像素的鼠标/触屏拖动交给同一滚动入口，并与滚轮及右侧拖条共享同一滚动值，首尾行留出悬停放大安全空间。自选模式中的真人首任领袖公开阶段直接创建默认高亮的座次身份控件，确认时发出包含武将、座次和身份的单一提交；确认回包关闭权限后面板整体隐藏，不会因阶段切换再次弹出。`retains_selected_character=true` 仅兼容AI首任领袖延后补选，不作为真人界面入口；其他玩家使用正常候选与全武将入口。全量候选模式隐藏领袖区域、分隔线及座次身份控件，右上显示避开常驻菜单的“返回”按钮。候选和公开领袖牌的统一信息请求由该组件转发给牌桌唯一信息框，不绘制其他玩家完成进度长文本。组件通过 `SelectionFrame` 下的稳定相对 `NodePath` 绑定标题、状态、领袖牌区、候选滚动区、内容节点和固定确认按钮；初始化时会先为旧场景缓存补建缺失的领袖分隔线，再一次性校验全部必需节点，其他结构缺失时保持隐藏并输出单条完整诊断。
- `artwork_loader.gd`：读取可选插画路径并安全加载 `Texture2D`，无效资源统一返回空值。
- `ui_style_registry.gd`：集中登记可选风格、默认风格、中文显示名和全部语义配色，不读取任何场景或对局状态。
- `battle_ui_style.gd`：读取当前风格语义色并生成面板、长条按钮、卡牌和角色框使用的圆角、描边、边距与阴影样式，不保存设置控件。
- `reference_backdrop.gd`：程序化绘制可缩放牌桌背景，隔离参考视觉与业务场景，不保存任何对局数据。
- `decade_battle_layout.gd`：根据2至10人对局人数复刻无名杀顶部/侧边座次模板，并在窗口变化时重新布局；容器本身忽略鼠标，不参与同级控件的输入命中。
- `decade_hand_container.gd`：复刻无名杀 `updateHand()` 的展开、覆盖、选中抬升、悬停顶置、层级和按需横向滚动逻辑。

### 牌面场景与模型

- `CardView` 与 `PlayerTargetView` 都以 `Node2D` 为根，明确表达“牌”而不是按钮。`card_view.tscn` 直接保存与运行时一致的111×148像素纸张、朱红类别条、插画槽、花色点数、牌名、类别和透明输入区域，编辑器默认预览黑桃7【杀】基本牌；脚本只覆盖具体实体内容与选中/禁用状态。其内部 `Control` 子节点不能成为规则状态所有者。
- `CardView` 的类别标签以卡牌主类型和装备子类型共同解析：武器、防具、进攻坐骑、防御坐骑、宝物分别显示“武器牌”“防具牌”“进攻坐骑牌”“防御坐骑牌”“宝物牌”，只有未知装备子类型回退“装备牌”。所有手牌、选择窗、动画牌和公开展示共用该映射。
- `scenes/components/player_target_view.tscn` 是武将牌唯一的编辑器场景，原生保存 148.35×197.8 像素3:4牌框以及立绘、名称、身份、手牌数、势力、体力与装备覆盖层的最终几何信息，不包含座次节点。场景实例不会受玩家人数、座次用途或牌面内容影响。
- `player_target_view.gd` 负责绑定场景节点、渲染快照、生成动态体力圆点与装备条并处理交互；牌框与静态信息控件由场景资源维护。
- 该场景静态保存4/4体力预览，并直接使用正式运行时4点体力的几何结果：体力框位置为`(124.35, 115.8)`、尺寸为`24×82`像素，圆点容器位置为`(2, 4)`、尺寸为`20×74`像素。场景编辑器中看到的位置与游戏内标准4点体力完全一致；其他体力上限继续以相同右下对齐规则动态调整高度。体力上限大于**5点**时，圆点切换为VBox中的加粗绿色“当前/上限”分数，当前值、`/`、上限值按三行纵向排列；数字字号为12像素，三行额外行间距为-4像素。有护盾时在其上方显示相同字号的加粗灰色单值（如`1`）。护盾没有独立上限，不显示第二个数值；两类数字均使用同色**1像素**描边实现加粗效果。
- `scenes/components/player_seat_slot.tscn` 是游戏内通用座位组合场景，默认尺寸148.35×223.8像素：上方 `(0, 0)` 至 `(148.35, 197.8)` 为武将牌，下方 `(0, 197.8)` 至 `(148.35, 223.8)` 为使用18像素字体、真实控件高度26像素的独立座次标签。其他玩家直接使用完整结构；本地主视角由 `match_table.gd` 隐藏标签并把实例尺寸收紧为148.35×197.8像素。
- `scenes/components/card_view.tscn` 是卡牌唯一的编辑器场景，保存111×148像素3:4纸面、类别色条、插画、花色点数、牌名、类别和透明输入区域。主场景不再内置或复制第二套 `CardTemplate`。
- 运行时仍会按当前武将势力、卡牌类别、体力、行动状态、合法目标和选中状态覆盖必要的动态颜色与描边；这是状态反馈，不是另一套 UI。若要调整武将牌静态位置或尺寸，应直接编辑 `player_target_view.tscn`；装备横条会参考场景内名称、体力与公开区节点的位置自动避让。

武将牌和卡牌根节点均为 `Node2D`，各自的纸面 `Panel` 保存精确尺寸。所有武将牌固定为148.35×197.8像素，手牌固定为111×148像素，两者宽高比均为3:4；名称、装备和状态变化只能更新牌面内部，不得改变外部模型尺寸。

动态组件每次状态快照更新后整体重建，避免旧节点残留选择状态。卡牌默认尺寸为111×148像素，所有玩家武将牌原生场景尺寸固定为148.35×197.8像素。

外围布局继续以 1280×720 为逻辑基准并兼容 1152×648 客户区：技能栏按运行时内容使用 136 像素宽度，手牌与技能栏保留 8 像素间隔，本地座位按 148.35×223.8 像素锚定右下角且默认贴底。四至九人局单侧座位使用 0.35 纵向比例；十人局左右各两名玩家时，统一缩放为 0.90，下侧完整座位距底边201像素、上侧与下侧保留6像素间隔，且同侧共用横坐标；顶部边距为 2 像素，五张顶部座位使用 0.78、0.64、0.5、0.36、0.22 中心比例，避免座位与底部功能区或相邻座位重叠。

## 名称切换

`GameSettings.card_name_mode` 的启动默认值为 `CUSTOM`。主菜单和局内菜单内的名称按钮调用 `GameSettings.toggle_card_name_mode()`；切换后手牌、“粮”、装备、判定区、当前选择摘要、技能按钮说明、已经打开的统一悬停框与武将详情统一重绘，实体牌 ID、效果和对局状态不变。任何新增卡牌详情组件都必须调用 `GameSettings.resolve_card_name()`，技能说明必须调用 `GameDatabase.resolve_card_names_in_text()`，不得自行判断名称模式。技能原文中的完整 `【】` 可写原版名或崩铁杀名，解析器按完整括号精确匹配并映射当前模式，普通文字不参与替换；缓存键包含名称模式，因此切换后不会误用另一模式的旧说明。手牌内持续“视为”和恰好1张材料的主动转化使用共用同一牌名横条：继续绘制原实体牌面，并在牌面中央显示实际逻辑牌名；多材料或无材料虚拟牌没有唯一原牌面，不显示材料横条。

`GameSettings.ui_style_id` 的启动默认值为 `space_mono`。菜单下拉框可在“崩铁风格”“暖木家园”与“高级黑金”之间即时切换，桌面背景、静态面板、按钮、文字颜色、卡牌纸张、牌背、装备条、技能按钮、选将框、选择窗口、机缘选择弹窗、目标线和武将状态框会在当前对局中直接重绘，不需要重新开局。风格只改变客户端表现，不改写任何既有界面文本，也不修改实体牌、体力数值、目标数组、伤害、回复、AI、网络或回放数据。

`GameSettings.auto_identity_marking_enabled` 启动默认值为 `true`。菜单使用 `CheckBox` 调用 `set_auto_identity_marking_enabled()`；关闭时桌面立即隐藏共享身份模型提供的自动忠反标记，但不清空模型，开启时立即恢复。`match_table.gd` 对每名未知身份角色按“真实公开身份 > 手动非空标注 > 自动忠反标记 > 问号”渲染，不把推断写回快照。

`GameSettings.online_player_name` 启动默认值为“玩家”，`set_online_player_name()` 会去除首尾空白、把空值回退为“玩家”并限制为20个 Unicode 字符；变化时发出 `online_player_name_changed`。`GameSettings.online_avatar_character_id` 保存联机形象稳定武将 ID，变化时发出 `online_avatar_character_changed`。连接入口只读显示名称；创建或加入时同时提交名称与形象 ID。联机大厅通过 `GameDatabase.get_character()` 和 `ArtworkLoader` 解析本机插画元数据，不得把 `Texture2D`、武将节点或正式武将牌场景写入网络 payload。

武将名称统一调用 `GameDatabase.resolve_character_name(character_id)`，从 `game_data/characters` 中对应武将文件的 `display_name` 取得中文名称。武将牌、卡牌询问中的目标名称、出牌与装备目标摘要、悬停说明和本地状态摘要均不得直接显示稳定 `character_id`；卡牌询问也不得使用“玩家X”或“[AI]玩家X”等控制权名称替代已经公开的武将名。配置缺失时分别显示“未选武将”或“未知武将”，避免英文内部 ID 出现在 UI。

## 交互扩展

内联 `card_target` 请求可为唯一自身目标材料携带 `auto_target_ids_by_card_id`。玩家选中该材料后，界面先按新材料清理旧目标，再预填自身并更新确认状态；因此【传冲】方块材料转化【无中生有】时不需要点击自己的武将牌，仍须点击“确定”提交同一条权威牌目标请求。

当前弃牌、响应、火攻展示与弃牌、濒死救援、无懈可击、装备费用和技能选牌等请求，只要牌候选全部属于本地玩家的手牌、木牛或装备区，就使用牌桌内联交互；技能只选目标时直接复用武将牌目标描边与中央确认/取消按钮，技能同时选牌和目标时复用同一套手牌与目标临时集合。`target_control` 请求同时复用武将牌目标集合和手牌上方文字按钮：目标未达到权威最少数量时所有实际选项按钮禁用，真正取消按钮保持可用；目标选满后按任一实际按钮一次提交 `selected_target_ids + selected_control_id`。丈八蛇矛与木牛流马的主动入口也直接复用装备横条、手牌区和中央按钮。装备响应材料模式只允许权威请求 `choice_type="respond"` 进入；弃置或获得等普通选择点击丈八蛇矛时，装备只作为被选中的候选牌，中央确定按钮继续显示原请求语义。五谷展示牌、他人区域牌、判定牌以及带只读展示牌面的控制请求使用 `CardSelectionPanel`。全部表现只提交同一标准响应请求，不能让 UI 直接调用伤害、弃牌或移动函数。

固定从其他角色区域选择牌的弹窗，提示统一显示“请选择“目标武将名”区域内的一张牌”或相应数量；公开武将名以金色 `#e4c84f` 富文本强调，未公开时才回退公开玩家名。提示补全只作用于客户端展示副本，不改变权威候选、选择数量、暗置手牌信息或提交 UID。

固定组合请求会把 `valid_card_combinations` 作为权威合法集合。内联手牌区与 `CardSelectionPanel` 每选择1张牌，都只保留至少能与当前已选前缀共同组成某个合法完整组合的候选，其余牌立即暗置并禁止输入；取消已选牌后重新计算并恢复可兼容牌。例如【录事】先选择一张二字《崩铁杀》牌名后，所有非二字牌即时不可选。

多材料 `card_target` 请求可额外提供 `target_combinations_by_card_combination`，以规范化材料UID集合映射完整目标数组；界面在选择材料前显示可行组合目标并集，选中部分或全部材料后即时收窄目标，控制器、AI与技能最终入口继续复核同一材料组合和目标数组。映射必须按每对材料的聚合花色与颜色生成，因此两张黑色手牌的组合不会把拥有【琥珀】的角色列为合法目标，而两张红牌与一黑一红组合仍可正常选中。素裳【山倾】使用该协议在同一窗口完成两张材料与一名【杀】目标的选择；丈八蛇矛的装备材料入口使用同一颜色聚合结果生成候选。

## 事件选择协议

规则运行时通过 `ChoiceRequest` 暂停当前事件，桌面只渲染请求中的候选并提交 `ChoiceResponse`。`request_id`、`event_id`、`actor_id`、牌/目标/按钮/控制项候选、各维度选择数量和 `can_cancel/forced` 是权威校验字段；界面不保存 `GameEvent` 或 `CardInstance` 引用。`choice_type=card_target` 时，`target_ids_by_card_id` 可令不同牌刷新不同合法目标，`target_combinations_by_card_combination` 可令多张材料集合刷新专属目标组合；`choice_type=target_control` 则同时校验目标数量与唯一非空 `control_id`，取消必须清空两者并提交 `confirmed=false`。公开弃牌堆候选使用 `CardSelectionPanel` 的“弃牌堆”分区，只有 `candidates` 中的 UID 可提交。当前桌面的 `PlayerAction.choose_cards`、`use_card`、`use_skill` 和 `end_play` 会由控制器转换成同一响应结构。

多步技能选择按“每步一个请求”的顺序推进，每一步都可能被取消，界面只需按当前请求渲染，不感知后续步骤。以【灵感】为例：第一段是控制项选择（`control_options` 给出记录中的牌名，取消即整体放弃且不消耗阶段次数），第二段是零候选确认（`confirmed=false` 表示不使用目标重定向，直接进入目标选择），第三段又是控制项选择（候选自动排除【无懈可击】与第一段已选牌名）。第二、三段取消都不会中断发动，只回退到“按效果牌名自身的目标规则结算”；次数只在“视为使用”真正成立后才消耗，因此**任一步取消都不占用本阶段额度**，界面无需在取消后额外提示或禁用按钮。当最终目标模式是 `all_others`、`all_players`、`self` 或 `self_wounded` 时不会出现目标选择步骤（自指牌自动以使用者为目标，不需要再点一下自己），界面直接跟随结算推进；记录中只有一张可用牌名时也不会出现“是否改按另一张牌结算”的确认步骤。所有段共用同一套 `ChoiceRequest` 与 `ChoiceResponse`，牌名选项以 `control_id` 回传稳定牌ID，界面再按当前名称模式解析为显示名。

技能被永久移除后界面必须实时收敛：控制器调用 `remove_all_skills_permanently` 卸载全部技能实例并广播状态，`skills_permanently_removed` 随公开快照下发。本地技能区据此重建为空（技能栏缓存签名包含该标记），其他玩家的悬停信息与右键详情也不再列出任何技能条目，表现为“该技能已从武将身上移除”，而不是灰显或保留占位。

全部 `chooseToUse`、响应、弃牌和效果选牌请求共享 `EventScheduler` 的全局请求 ID 命名空间。控制器必须在运行时登记成功并取得唯一 `request_id` 后才启用手牌/装备区内联选择或显示 `CardSelectionPanel`；玩家提交后也必须先由运行时确认接收，再清理控制器中的待选上下文。旧提交回调只允许关闭相同 ID 的表现，不能覆盖同步创建的下一请求。登记失败、过期响应或 ID 不匹配不会关闭有效交互、推进阶段或移动卡牌。

出牌阶段的 `chooseToUse` 请求只展示当前可直接使用、重铸的实体牌 ID 与可点击主动装备本体，桌面直接以该集合控制每张手牌、木牛“粮”与装备的普通交互状态；技能动作或装备动作中的材料 UID 不属于普通候选。提交一张牌或装备主动动作后，控制器先关闭该请求并完成整张牌的材料、逐目标响应与效果结算，再在仍处于出牌阶段时创建下一请求，避免【桃园结义】等多目标锦囊的后续【无懈可击】询问覆盖新出牌请求而导致手牌全部灰显，也避免【传冲】、木牛流马等入口结算后把所有材料手牌错误显示为可直接使用。主动技能按钮走同一顺序：先用技能按钮完成当前 `chooseToUse`，再由技能自身创建子选择；技能若同步结算完毕且没有任何待办子选择（典型例子是【天裁】①这类不创建子选择的轮回节），控制器立即重建出牌请求并**同步广播新快照**。界面只从快照的 `current_choice_request` 判断自己是否处于本地出牌阶段，漏发这次广播会让界面停在“无请求”状态——手牌全部不可点击、确定按钮保持禁用、取消与结束阶段按钮消失，只有技能按钮仍然亮起（技能按钮直接查询规则层可发动状态，不读该快照字段），必须再点一次技能按钮才会被动恢复。补发条件是重建后 `_has_active_play_choice()` 为真；阶段被规则取消或被流程间隔接管时沿用各自既有广播路径，不重复广播。点击“结束阶段”提交取消响应，进入弃牌阶段。响应、弃牌、火攻、五谷和濒死救援沿用相同请求入口，因此不需要为每张牌创建独立 UI 规则。响应转换技能必须由玩家先点击当前亮起的技能按钮，桌面才把该技能的材料改为可选并随提交携带准确 `response_skill_id`；未点击技能时材料保持暗置，规则层也拒绝隐式转换。【罡风】因此不会预先把全部黑色牌自动当成【杀】。每名救援者首次收到的单个提示会明确显示目标达到1点体力尚需回复的点数，并列出对应卡牌源码在当前角色关系下允许的救援牌名；当前规则仍表现为濒死者候选同时包含【桃】与【酒】，其他救援者只包含【桃】。当前救援者每打出1张后若目标仍未达到1点，会立即再次询问同一救援者；其取消后才推进到下一名尚未询问的角色，遍历完一轮后不重新询问全体角色。

网络请求和本地请求使用相同快照字段；非响应者的 `GameState.to_dict()` 会裁剪牌候选和活动过滤上下文。旧事件、错误 actor、重复 UID、非法数量或已结束事件的响应不会改变选中状态、牌区或阶段。

## 移动端与结算交互补充

- 武将牌长按 `0.50` 秒且移动不超过 `18` 逻辑像素时显示信息，优先命中公开装备或延时锦囊，未命中时显示武将资料；释放仅关闭信息，不追加选目标。双击详情的最大间隔为 `0.32` 秒、落点容差为 `24` 逻辑像素；桌面右键仍可打开详情。
- “联机设置”是顶部四个对等主菜单内容页之一：打开时隐藏默认 `MainMenuFrame`，`OnlineSettingsPanel` 使用与主菜单客户区相同的安全边距（左右54、顶部104、底部38）。页面内部采用“左侧分区列表 + 右侧纵向编辑区”：左侧列表最小宽286像素、分区卡高100像素并带主题强调竖线；右侧不再显示“联机资料”徽章与“当前资料”摘要框，玩家名称与联机形象列表填满详情上半区，当前形象说明放在形象标题行右侧。右侧内容以纵向分栏排布——上方为名称/形象滚动区，下方固定为高92像素操作栏（取消160×56、保存并返回250×56），操作栏不与武将牌区域重叠，`z_index=20` 仅用于防止 Node2D 武将牌绘制压过按钮。形象列表启用与选将一致的拖动手势转发，超过可视高度时纵向滚动；滚动容器裁剪内容，避免最后一行武将牌输入区溢出到操作栏。顶部“模式选择”“联机设置”“所有卡牌”“对局回放”保持可见、可聚焦且可直接切换；打开期间只冻结客户区与开局控件，不冻结顶部标签。保存、取消或点击“模式选择”恢复默认内容并同步顶部选中态。它只编辑玩家名称和形象，不创建网络会话，也不使用设置类全屏遮罩。
- 本地延时锦囊标记继续位于手牌上方并距手牌 `6` 像素；角色公开标记主体直径固定20像素、中央单字12像素、右下数量字10像素与黑色描边3像素，不绘制数量小圆，相邻间距固定1像素。其他角色标记位于武将牌左侧，距牌边1像素并整体下移8像素；第一视角标记横排位于手牌栏右上方，右边界对齐手牌栏右边界并下移8像素，本地武将牌底部不重复显示。
- 对局记录展开层级为 `z_index=35`，高于阵亡表现的 `30` 层；正文顶部紧贴顶部信息面板下边，底部始终位于“记录”按钮上方，采用双锚点响应不同视口。
- 终局操作区在两个按钮上方显示“对局结算，游戏胜利/失败/平局”。胜负读取权威 `winner` 与本地身份：身份局对应 `leader_and_loyalists/rebels/renegade`，斗地对应 `landlords/peasants` 与本地 `landlord/peasant`；旧回放缺少胜者字段时显示中性“对局结算”。

## 主菜单模式列表

- 左侧模式列表按“身份模式”“斗地主”“2v2”“1v1车轮战”“机缘大乱斗”“过关斩将”排列；选中后写入 `GameSettings.next_match_mode` 并调整人数范围提示，持续选中卡片的内部底色按主题操作色加深 `0.28`。
- `MainMenuModeScroll` 的纵向轨道与常态、悬停、按下拖块均使用零上下内容边距、零阴影的专用 `StyleBoxFlat`；宽度默认12像素且可在8至24像素调整。滚动值为最小或最大时拖块必须分别贴合轨道顶部或底部，不保留通用面板样式自带的8像素端点缝隙。
- 身份模式与机缘大乱斗支持2至10人并分别保存人数，斗地主仅允许3/5人，2v2固定4人，1v1车轮战固定2人；人数 SpinBox 会按当前模式把非法人数规范化为合法值。过关斩将的模式卡人数提示为“单人1人 / 联机2-4人”，离线开局固定单人；进入局域网大厅后其“人数”表示玩家数（2至4），房间摘要显示“玩家数：N（敌方AI等量）”，房主设置中的人数 SpinBox 按2至4收敛。
- 过关斩将的机缘选择弹窗在投票模式下把本地提示文字换为“机缘投票时间：请把票投给一张机缘卡”，各自选择沿用“选择机缘时间：请选择一张机缘卡”。两种模式都让全体参与者在同一阶段同时获得操作权：本地玩家只要仍在 `pending_chooser_ids` 中且尚未提交就显示可点击卡面，提交后卡牌禁用，状态区改为“你已完成选择，等待其余N名玩家……”并只显示待提交人数；仅剩一名待选者时显示“等待X选择机缘……”。投票内容在全员完成前不出现在其他观察者界面。收齐后所有客户端统一显示每名玩家所投机缘与当选机缘，默认保留 **2.0秒** 再进入效果结算；候选牌位、悬停动画、禁用反馈与稳定卡ID提交协议与普通三选一完全一致。
- 身份徽记：地主显示“地”（色同领袖红），农民显示“农”（色同反贼绿）。

## 机缘卡与全体选择弹窗

- `OpportunityCardView` 使用独立 `res://scenes/components/opportunity_card.tscn`，固定尺寸180×240像素，牌面不放置插画、标题或品质文字，只显示需求提供的完整规则正文。绿、蓝、紫、橙、红品质分别以对应主色的深色背景与亮色4像素边框表达，整体保持武将牌式竖向比例、圆角与阴影。
- 可交互机缘卡复用正式卡牌悬停动态：以牌面中心为缩放基点，在0.12秒内按二次缓出曲线放大至1.06倍，绘制层级临时提升至100，品质背景提亮0.08且边框从4像素增加至5像素。鼠标离开后以相同时长恢复；选择提交导致牌面禁用时也立即开始复原，不能停留在放大或顶层状态。选择弹窗的卡面不向父级报告最小尺寸；普通与悬停 `StyleBoxFlat` 同时固定4像素内容区内缩，故放大、边框变化和文本布局均不会重排候选牌位、弹窗或带技能名机缘的内部文字。每次配置卡面时只创建普通与悬停两份 `StyleBoxFlat`，后续进入、离开、禁用均复用对应资源，避免快速移动鼠标时产生样式分配抖动。
- 机缘定义含 `skill_id` 时，鼠标进入牌面还会通过弹窗转发统一 `information_requested`，标题显示完整技能名，副标题为“机缘可获得技能”，正文读取技能源码唯一描述并解析当前牌名模式；没有技能的机缘只播放牌面悬停动画，不创建空信息框。鼠标离开、提交选择或牌面释放时统一撤销说明。
- `OpportunityChoicePanel` 使用全屏遮罩和居中弹窗横排三张机缘卡，绘制层级为180。遮罩、主框、强调边与状态文字颜色全部读取当前 UI 风格；风格切换只重绘这些视觉属性，不修改“选择机缘时间”或等待提示。选择阶段即使 `SceneTree` 已暂停仍保持 `PROCESS_MODE_ALWAYS`。投票选择与各自选择使用同一套开放规则：只要本地观察者仍在 `pending_chooser_ids` 中且尚未提交，就显示本人候选并允许操作；其他观察者只能看到完成进度，投票模式下还不能读取票面正文。
- 本地点击任一机缘卡后，三张卡的内部透明按钮立即禁用并降低明度，直到权威快照确认，防止快速连点重复提交；规则端统一复核待选成员资格（全部参与者同时开放），并始终复核候选稳定 ID、提交者本人候选和流程阶段。
- 投票收齐后的 `revealing` 阶段不再显示可交互候选，而是按玩家公开名称逐行显示“玩家→所投机缘”的品质与正文，并单独显示 `winner_card_id` 对应的当选牌。所有观察者消费同一份公开结果，默认展示 **2.0秒**；表现层不得本地重算票数或自行选择平票结果。
- 离线开启“控制所有角色”时，唯一第一视角落在 `pending_chooser_ids` 的首名待操作角色，提交后自动切到下一名待操作角色，玩家可以替每名本地控制角色依次完成提交（权威待提交集合始终同时开放，轮换只是本地观察者切换，不改变谁能选的规则）。投票选择与各自选择共用该入口。离场但仍存活的角色同样会成为选择者，弹窗与动作入口不得因 `out_of_game=true` 跳过其候选。全部角色选择完成前不执行任何机缘效果；各自选择完成后关闭弹窗并进入逆时针结算，投票选择必须先经过结果公开阶段再进入相同的权威效果队列。

## 酒加伤滤镜

- 当角色 `wine_bonus>0` 时，武将牌叠加半透明红色滤镜；角色开始使用普通、火或雷【杀】时，在进入防具、【闪】或伤害窗口前读取本次 `+1` 伤害并立即把 `wine_bonus` 清零、发布公开快照，滤镜同步隐藏。若本回合没有使用【杀】，正常结束或中断回合时也立即清零并刷新；滤镜只读快照公开字段，不改变规则数值。

## 对局日志展示

- 左侧“记录”展开后显示权威控制器输出的永久语义日志。
- `MatchLogPanel` 始终以字符串数组保留本局全部日志；面板折叠时 `RichTextLabel` 保持空文本，不解析、排版或滚动隐藏历史。展开时通过一次合并写入恢复完整记录；展开期间同一帧到达的多条日志也合并为一次正文追加。收起只释放表现文档，不删除历史；重新开局或加入新局才同时清空历史与正文。
- 角色统一写作“武将名（X号位）”；用牌/技能带目标；阶段起止与回合横线分隔；弃置逐张列出。详细句式见《游戏机制与玩法内容》对局日志格式。
- 技能发动、获得、失去及“因技能”原因统一显示数据库中文技能名，稳定英文 ID 只保留在结构化历史中。获得牌时，若当前全部存活角色均已知该实体牌面，日志写出花色、点数与牌名；仍含未知观察者时只写“一张牌/一张手牌”，界面不得自行从本地私有快照补全。

## 离场与牌堆排序交互

离场角色的 `PlayerTargetView` 禁用整张武将牌输入区域，并以 `(1,1,1,0.18)` 调制显示。该状态优先于目标选择的灰暗态，离场角色永远不显示为可选目标；返回游戏后的下一份公开快照恢复正常输入和不透明度。

`CardSelectionPanel` 对 `choice_type="arrange"` 显示“牌堆顶”和“牌堆底”两行。全部候选初始位于顶行；点击牌面在两行间移动，拖动可调整行内顺序或跨行位置。每行从左至右表达更靠近该行顶部到更靠近底部：顶行左侧最先摸到，底行左侧比右侧更靠近实际牌堆顶。确认按钮仅在全部 UID 恰好出现一次时启用，提交后由规则层以 `top_count_N` 校验，不把拖动节点、坐标或容器传入规则状态。

外部弃置选择若包含因技能保护而不可弃置的公开装备，界面仍展示该牌以维持区域信息，但不把其 UID 放入可选集合，表现为暗置且不能点击。这样玩家能理解“不可弃置”的来源，同时网络或脚本伪造提交仍会被权威端拒绝。

## 轮回技说明高亮

- `SkillDescriptionView` 继承 `RichTextLabel`，是轮回技说明的统一只读视图。组件保存完整纯文本原文，并按①至⑩切分轮回节；不写入 BBCode，不改标点、卡牌名称或技能说明字符串。
- 当前轮回节使用当前 UI 风格的 `accent` 高亮色，其他轮回节使用 `text_muted` 淡色。第一个轮回节之前的“轮回技、触发条件”等前缀，以及最后一节句末之后的轮回数解释或跨节共同效果，继续使用 `text_secondary` 普通正文色。例如【聚寇】最后的手牌上限规则不会因当前节改变而淡化。
- 局内本地技能按钮悬停、任意武将牌悬停、武将右键详情都从公开玩家快照的 `reincarnation_skills[skill_id].section_index` 读取当前节。`MatchTable` 和 `PlayerTargetView` 只转发静态技能定义与该数值，不持有技能运行时实例。
- 主菜单“所有卡牌”的武将详情、尚未获得的机缘技能说明及其他局外静态资料没有运行时轮回状态，固定以轮回数初始状态①高亮。普通技能和没有①②序号的单节轮回技保持普通单色正文。
- 分段解析对轮回节数无武将特例：【堪杀】、【天裁】与【永劫】的①②③使用同一规则，【泛音】的①②③④同样按带圈序号分段。【升变】这类无带圈序号的单节轮回技不伪造局部高亮；其轮回数仍由权威状态正常记录。“军功”动态授予的【奇袭】从同一公开技能列表生成，标记移除后下一份快照同步移除对应技能条目。
- 主题切换调用 `refresh_ui_style()` 重新使用语义色绘制现有分段；`get_plain_description()` 始终返回原文，搜索、辅助查询与回归测试不会读取富文本内部控制码。
- 富文本高度需要一个界面布局帧才能稳定。统一悬浮框仍按正文长度动态扩宽：`hover_panel_compact_text_character_count` 默认 `24` 个可见字符，超出后按 `hover_panel_width_per_extra_text_character=1.0` 像素提供确定性宽度下限，再受原有最小宽 `240`、最大宽 `520`、宽高比 `0.8..2.2` 与视口安全区共同约束。该补偿只影响排版，不改变技能文本或规则状态。
