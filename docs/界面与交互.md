- `无名杀参考代码/十周年UI/equip_new.css`：左下独立装备槽及五种固定装备位。
- `参考图/ScreenShot_2026-07-14_065613_670.jpg`：顶部/侧边武将牌、中央留空、底部操作提示、本地武将牌和技能按钮的整体层级。
- `参考图/局内角色武将牌示例.png`：势力圆徽、左侧竖排武将名、右侧体力圆点、左下手牌数角标、顶部身份徽记和武将牌下方中文座次号。

## 视觉布局

主场景采用参考无名杀的 1280×720 环桌卡牌布局；布局、尺寸与交互语义保持稳定，配色由设置中的 UI 风格独立决定。默认使用“崩铁风格”，并保留“暖木家园”供玩家即时切换：

- 逻辑视口的标准基准分辨率为 1280×720；默认启动窗口为 1152×648，为系统标题栏、窗口边框和任务栏保留空间。界面使用 `canvas_items` 与 `keep` 宽高比策略完整显示逻辑视口；底部与右侧关键区域同时使用边缘锚点，因此编辑器嵌入运行未应用画布拉伸时也不会超出客户区。
- Android 设备使用固定横屏方向，不跟随旋转传感器反复切换正反横屏，避免系统连续重建渲染表面；1280×720 逻辑画布按 `keep` 策略等比缩放到实际屏幕，16:9、18:9、19.5:9 与 20:9 等比例通过居中留边吸收多余区域，不拉伸牌面、不裁切按钮，也不让刘海、挖孔或圆角侵入逻辑画布。应用使用沉浸式全屏但关闭 edge-to-edge，系统安全区域由 Android 窗口边界负责；HiDPI 保持开启，逻辑像素与物理像素由 Godot 统一换算。
- Android 使用 Vulkan 驱动与 Godot Mobile 渲染方法，桌面端继续保留原有 Compatibility 渲染路径。移动端全局VSync开启，`AndroidDisplayStability`在Android窗口创建完成及应用从后台恢复时把最大帧率设置为60 FPS；组件不进行每帧轮询。该组合用于稳定一加Ace 5等120Hz高刷屏与高通Adreno交换链节奏，避免刷新率切换、旋转表面重建或前后台恢复造成整屏闪烁。

- 左上角：只显示当前第几轮、摸牌堆剩余牌数和对局时长，不再显示当前行动角色、回合总序号或阶段名称。信息框位于 `(18, 18)`，尺寸为156×84像素；时长从本局创建时开始按单调时钟累计，格式为“分:秒”，终局后冻结。右上角保留一个“菜单”入口，供已开始的对局调整设置或重新开局。局内菜单集中提供卡牌名称切换、UI 风格切换、自动身份标记复选框、AI 响应速度、游戏速度、按设置重新开局和下一局2至10人设置；风格、身份标记与速度即时生效，人数修改只影响下一局。菜单分支在场景初始化后提升至真实 GUI 命中最前端；全屏座次容器仍忽略鼠标，只由武将牌的透明输入子组件接收点击，因此动态武将牌和选将遮罩都不能遮断菜单。
- 主菜单与局内菜单中的“卡牌名称”均使用与“UI风格”相同的“左侧标签 + 右侧下拉框”格式，选项固定为“崩铁杀”和“三国杀”，元数据使用 `GameSettings.NameMode` 枚举；切换只重绘前端文本。局内菜单另提供“返回主菜单”按钮，退出时释放当前对局运行时、保留显示设置和下一局人数，并恢复主菜单焦点。
- `GameSettings` 在 `user://game_settings.cfg` 以格式版本1保存卡牌名称模式、UI风格、AI响应等待（0.05至1.00秒，步长0.05秒）、游戏流程间隔（0.1至1.0秒，步长0.1秒）、自动身份标记、下一局人数（2至10人）、联机玩家名与联机形象 ID。读档发生在界面首次绘制前；修改先作用于内存，0.25秒内的连续变化合并为一次完整覆写，进入后台或退出时立即保存。卡牌名称与UI风格的全界面刷新在当前GUI输入结束后的空闲帧执行。文件不保存房主地址、端口、房间密码、聊天、成员表、ENet peer 或任何对局状态。
- 主菜单顶部“模式选择”右侧固定提供“联机设置”。该模态允许编辑最长20个 Unicode 字符的玩家名称，并从 `GameDatabase.characters` 当前登记的全部武将牌中选择联机形象；武将牌按中文名称稳定排序，每行最多5张、缩放为0.72倍，水平间距18像素、垂直间距16像素，超过可视高度时纵向滚动。名称去除首尾空白，空值回退“玩家”；形象保存稳定武将 ID，并在确认后写入本地设置文件。两项配置均不创建网络会话或对局状态，创建或加入房间时才提交给网关。
- 点击“局域网联机”后，连接表单中的“玩家名称”只读显示 `GameSettings.online_player_name`，不能在该界面修改；创建房间与加入房间均提交这一全局名称和已选联机形象。连接入口另提供房主 IPv4、端口与最长32字符的房间密码，玩家若要修改名称或形象必须返回顶部“联机设置”。
- “自动标记身份”复选框在勾选与取消勾选时都显示独立20×20像素主题边框；勾选状态额外绘制2.5像素主题文字色对勾，边框默认宽2像素。该指示器只改善可见性，不改变默认开启、手动标记优先级或任何身份规则。
- 其他玩家：使用无名杀 `data-position` 座次方向排列。桌面先把绝对座次旋转为从本地下家到本地上家的环形顺序，再依次放置到右侧、顶部与左侧；因此本地玩家随机座次后，视觉方向仍与规则行动顺序一致。二至三人局全部位于顶部；四至九人局先放右侧、再由右向左排列顶部座位、最后放左侧；十人局左右各放两名、顶部放五名。每个其他玩家座位由武将牌与其下方独立座次标签组成；武将牌显示势力、武将名、体力、手牌数和公开装备，座次标签只显示中文座次号。正式对局在鼠标悬停且武将牌未翻面时显示位于插画上方的玩家名渐变阴影，遮罩忽略鼠标且不阻断透明输入区域；Godot 原生工具提示始终为空。鼠标持续停留在本地或其他玩家武将牌0.5秒后，统一信息框会显示势力、性别、基础体力上限及按武将定义顺序排列的完整技能说明；选将候选仍保留独立悬停缩放反馈，点击候选只更新金色选中边框，所有候选保持当前布局坐标。`player_target_view.tscn` 的默认隐藏“牌背”覆盖层会在快照 `face_down=true` 时遮挡这些牌面信息，透明输入区域仍位于最上层。判定牌在武将牌底边按快照顺序显示为带牌名首字的菱形；木牛“粮”数量紧跟木牛流马装备名显示。鼠标悬停其他玩家的公开装备横条时，统一信息框在横条附近显示该装备的槽位、花色点数、当前名称和完整规则说明；离开横条但仍停留在武将牌内时，经过同样0.5秒恢复该武将技能资料。任意玩家公开体力相对上一份同局快照下降时，其 `PlayerTargetView` 调用独立 `DamageShakeFeedback`，以最大7像素水平幅度和0.24秒总时长执行1次冲击位移后回正，不再左右往返；首次快照、新局体力基线和回复不会触发。
- 托管表现：本地玩家在“记录”右侧点击“托管”后，透明度0.76的黑色滤镜从手牌栏左边界横向延伸至本地武将牌左侧8像素处，高度固定等于175像素手牌栏，并拦截鼠标输入；本地技能按钮始终绘制在滤镜上方。文字每0.45秒在“托管中.”、“托管中..”与“托管中...”之间循环，点击该文字区域会立即提交结束手动托管的请求，“取消托管”按钮也保留可点击。所有托管玩家的武将牌底部显示3像素描边“托管中”，联机掉线托管显示“已离线，托管中”。离线托管不能在客户端取消；这些数值只影响客户端视觉与输入隔离，不修改牌、体力、伤害、次数或 AI 决策数值。
- 十人局的其他玩家座位统一按0.90比例缩放；下侧完整座位（武将牌与座次标签）距客户区底边固定201像素，使座次标签始终与“记录”按钮保持2像素间距；上侧完整座位位于下侧上方，并固定保留6像素间隔。顶部仍距上边缘2像素并保留五张顶部座位的0.78、0.64、0.50、0.36、0.22中心比例。每侧上下两张牌共用同一横坐标并形成同列平行排布；本地为五号位时，左上、左下依次为三号位、四号位，右上、右下依次为七号位、六号位。主视角武将牌默认贴齐客户区底边，为右侧下方座位保留3.2像素垂直安全距离；这些数值只影响客户端几何。
- 身份牌先随机分配；选将完成后旋转座次数组，使领袖固定为一号位，再按顺时针排列二号位、三号位和后续座位。界面座次标签读取快照 `seat_number`；真实玩家名称按最终座次写为“玩家1”“玩家2”等，内置 AI 写为“[AI]玩家1”“[AI]玩家2”等。公开领袖身份徽记显示“领”，忠臣、反贼和内奸分别显示“忠”“反”“内”。身份徽记的背景与边框透明度均为0%，场景颜色 Alpha 固定为1.0，不使用半透明身份底板。未知身份徽记“？”允许本地玩家点击并在“？”、“忠”、“反”、“内”四个单字选项中添加、修改或清除客户端标注；重新选择“？”会删除本地推测。默认开启的“自动标记身份”根据共享身份模型的公开用牌忠反信号为其他未知角色显示“忠”或“反”，关闭开关后恢复手动标注或“？”，重新开启时保留本局已有推断。手动非空标注优先于自动结果，真实身份公开后立即覆盖全部本地推测并禁止再次标记。自动与手动标注都不写入规则状态、网络或回放。稳定 `player_id` 只用于网络、回放和实体所有权。
- 牌桌中心：完全留空作为卡牌使用与弃牌结算的视觉区域，不绘制弃牌堆边框、牌堆数量或固定占位图。
- 手牌区：固定在底部中央，使用111×148像素的3:4竖版卡牌；透明外层不绘制背景框，栏高固定为175像素，为148像素牌面、18像素选中抬升与1.06倍悬停补偿共同保留完整空间。空间充足时以2像素间隔展开，空间不足时自动重叠，每张牌至少露出64像素。选中牌向上移动18像素，选中与取消选中分别使用0.025秒位移动画；选中并悬停时仍完整位于手牌滚动框内，不会被框外内容裁切。可见手牌即使当前不可使用，也会在鼠标悬停时通过统一信息框显示花色点数、类别、当前名称和完整规则说明；牌背不显示信息。实体手牌视为另一张牌时，底部原牌名、插画和类别保持不变，牌面中心显示22像素高的类别色细条，横条以16像素文字显示视为后的名称，类别色底板不透明度为0.90；悬停框标题仍使用原牌名、副标题追加“视为【新牌名】”，说明改为当前逻辑牌效。只有1个技能时手牌右边界延伸到第一技能按钮左侧8像素；技能数大于等于2时右边界缩短到第二技能按钮左侧8像素。
- 手牌排序：鼠标移动超过8像素后，直接拖动原 `CardView` 实体跟随鼠标，不创建拖拽预览、副本或额外实体 UID；拖至同一分区牌面的左半边或右半边，分别插入目标前或后，释放在空白处则恢复原排序。此操作只保存本客户端的显示顺序。木牛“粮”是独立分区，固定在普通手牌左侧，双方均不可跨界排序；即使当前卡牌不可用于出牌或响应，仍可在自身分区内排序。
- Android 将触点统一转换为标准鼠标指针事件，使 `Button`、`OptionButton`、`HSlider`、`SpinBox`、`LineEdit`、弹出菜单与滚动容器复用Godot完整GUI协议；自定义卡牌与武将输入组件在该模式下忽略原始`InputEventScreenTouch/InputEventScreenDrag`，防止同一次触摸重复提交。轻点卡牌等价于桌面左键选择，移动至少8逻辑像素后直接拖动原手牌实体；稳定长按卡牌0.45秒显示规则说明。轻点武将牌选择目标，稳定长按0.50秒打开详情，同一次长按释放不会再追加选择。
- Android打开“联机设置”时初始焦点落在保存按钮，不自动聚焦玩家名称输入框，因此不会无操作弹出软键盘；玩家主动点击名称框后，触摸指针可定位光标、移动到“玩家”末尾、退格删除或选择文本。打开“局域网联机”时初始焦点仍为创建房间按钮，房主IPv4、端口和密码只有主动点击后才打开对应输入交互。
- Android首次进入联机大厅时初始焦点落在“关闭房间/离开房间”按钮，不自动聚焦聊天输入框；连接成功隐藏入口、关闭联机资料、关闭房主设置、返回连接入口及正式进入对局时，`MobileKeyboardGuard`会释放当前`LineEdit/TextEdit`焦点并调用系统软键盘关闭接口。只有玩家主动点击聊天、名称、IP、端口或密码文本框时才显示输入法；发送聊天后保持输入焦点属于玩家已主动发起的连续输入流程。
- Android 返回手势或实体返回键由独立 `AndroidBackAdapter` 转换为 `ui_cancel`：优先关闭当前设置、联机面板、武将详情或取消选牌；若当前没有可取消层，则对局中打开/关闭右上局内菜单，主菜单顶层再次返回时退出应用。该组件只规范化平台输入，不读取或修改规则状态。
- 操作区：固定在手牌区上方且不绘制任何面板背景，只显示具体询问提示与操作按钮；内联询问不再重复显示“响应询问｜已选择0张｜需要1至1张”一类通用摘要。普通出牌未选中或选中卡牌时都不显示“未选择卡牌｜点击牌面选牌，拖动手牌可调整同分区顺序”文本框；选中牌后的说明标签只显示卡牌效果，不显示“牌名｜目标：角色｜”等重复状态文本；牌名由牌面表达，目标由武将牌高亮表达。没有本地出牌、响应、弃牌或效果选择时整组隐藏。146×42像素的“确定”和“取消”作为中央主按钮，水平间距固定为28像素；112×36像素的朱红色“回合结束”脱离交互面板并固定在取消按钮右侧，不与取消按钮相交；不再显示“重铸”和“存木牛”按钮。所有技能的 `choice_type=control/bool` 互斥文字询问都不得弹出独立窗口：按声明顺序将前两项直接替换为原“确定/取消”位置的选项按钮，剩余项与真正“取消”按需继续追加在同一操作行；点击后直接提交对应稳定选项，Esc、右键和真正取消按钮统一提交 `confirmed=false`。因此【振旗】费用显示“弃置手牌”“失去体力”“取消”，【冰封】显示其两个效果选项与“取消”，后续同类技能必须复用此规范。群体锦囊询问本地玩家是否使用【无懈可击】时，该按钮临时改为“不响应该锦囊”：点击后使用深灰状态并立即放弃当前询问，同一实体锦囊本次处理区生命周期内的后续无懈询问自动提交空响应；再次点击可取消，锦囊离开处理区后自动恢复“回合结束”。
- 本地玩家死亡但对局未结束，或 `game_over=true` 时，手牌区上方操作区不再隐藏：原“确定/取消”位置显示“重新开始”和“返回主菜单”。“重新开始”读取局内菜单当前2至10人设置并走相同前置校验与开局流程；“返回主菜单”释放本局运行时而不结算新的胜负。两按钮仍为146×42像素，不影响伤害、死亡奖惩、人数分配或其他规则数值。
- 操作区初始化：`MatchTable` 通过主场景直属路径取得 `InteractionPanel`，不依赖场景唯一名称元数据；进入场景树时会统一校正透明样式、主按钮规格与间距、禁用样式、旧按钮隐藏状态和右侧回合结束按钮层级，使旧场景缓存不能产生空节点访问或恢复已废弃布局。所有不可提交的确定、取消及同类交互按钮固定使用深灰背景、低对比度边框和灰色文字；禁用期间不接收输入，也不切换悬停或按下外观。
- 统一选择入口：候选全部属于本地玩家且来自手牌、木牛“粮”或装备区时，直接复用底部手牌区、左侧装备区和“确定/取消”按钮，不打开遮罩窗口；普通出牌同样只启用当前 `chooseToUse.card_ids` 中的手牌、木牛“粮”或主动装备。木牛“粮”固定排列在普通手牌左侧。【桃】【酒】和【无中生有】选中后会自动锁定本地玩家本人；所有 `type=equipment` 且 `target_mode=self` 的装备牌也按同一通用规则自动锁定本人，不维护装备 ID 白名单。其他牌与主动装备即使仅有1名合法目标，也必须由玩家点击该武将牌。所有 `choice_type=control/bool` 的文字选项直接复用手牌上方操作区，不进入 `CardSelectionPanel`；其余五谷展示牌、他人区域牌和判定区等不完全位于本地可见区域中的候选继续使用该独立窗口，不可见手牌显示正式 `CardView` 的“牌背”覆盖层。任何非候选或当前无合法动作的手牌都使用深灰禁用样式且不接收点击，但仍可在自身分区内拖动排序；装备候选先向右移动10像素，选中后再向右移动10像素，进入候选、选中或复原位置都使用0.25秒位移动画。上下文明确定义 `equipment_uid` 的装备触发询问会自动选中对应装备，玩家只需确定发动或取消放弃。点击丈八蛇矛后选择2张普通手牌作为虚拟【杀】材料，点击木牛流马后选择1张普通手牌存为“粮”；两种模式都保持装备本身选中且不移动权威区域。【顺手牵羊】的 `steal_target` 窗口会按非空手牌区、装备区、判定区动态增大，并把三个区域并列显示；每列使用正式111×148像素牌面、8像素间距自动换行，纵横滚动均关闭，因此无需滑动即可同时选择三个区域的牌。正式主场景把通用选择框覆盖为820×460像素，背景滤镜读取当前风格 `shade`：崩铁风格透明度约0.82，暖木家园约0.84；公共只读牌禁用输入但保持正常亮度。
- 五谷丰登使用后立即创建全体可见的公共选牌窗口，不等待第一名角色完成无懈询问。窗口使用视口中心锚点与对称四边偏移，动态改变尺寸后仍保持严格居中，不会沿左上角局部坐标移出屏幕。通用模态选择层固定为150，高于手牌悬停100与拖拽101；窗口在每名玩家或 AI 依次选择期间持续保存并始终绘制在底部手牌与手牌悬停放大层之上。非当前本地选择者只读查看，底部确定/取消行隐藏。本地玩家进入与五谷选牌不同类型的【无懈可击】等响应时，公共窗口临时关闭并让出手牌区、确认和取消输入，响应结束后立即从保留的公共快照恢复；旁观客户端仍可继续显示公共牌位。最初亮出的每张牌拥有固定牌位，被取得后不删除、不补位，而是以 `(0.72, 0.72, 0.72, 0.48)` 调制色留下复制虚影；牌底 `(4, 118)` 至 `(107, 144)` 的103×26像素标签使用13像素字体显示领取者武将名。公共牌阵使用4列 `GridContainer`，每行固定4张、间距8像素，不显示“展示区”标题；窗口按实际列数收紧，4列时牌阵宽468像素，面板只保留36像素横向总边距，右侧不再保留旧820像素窗口产生的大块空白。下一名选择者只能点击仍未领取且属于当前权威请求候选的牌。

- 局内菜单按权威身份分组显示功能：离线玩家与局域网房主可见“AI响应速度”“游戏速度”“下一局游戏人数”“按设置重新开局”；局域网客户端隐藏这四项，只保留能在本机生效的卡牌名称、UI风格、自动身份标记与离开入口。后续新增以房主为准的功能必须加入同一权威控件组，不得单独出现在非房主 UI。
- 【五谷丰登】当前选择者已选中1张展示牌后，其余未领取候选仍保持可点击；再次点击另一张会先取消旧选择再选中新牌，确认时只提交最后选中的1个稳定 UID。已领取、非当前请求候选和只读旁观牌仍不可点击。
- 五谷手牌层级：公共牌位面板固定为45层；仅当公共展示类型为 `harvest` 时，本地手牌区提升到46层，因此悬停后的1.06倍放大牌面始终位于五谷牌位上方。离开五谷展示后手牌层级恢复场景默认值，层级调整不改变任何选择资格或卡牌数值。
- 本地装备区：固定在底部左侧，由 `EquipmentStackView` 复刻 `equip_new.css` 的独立槽位布局。透明外层固定为150×148像素，高度严格等于玩家111×148手牌牌面本身，不等于175像素手牌栏；装备栏与手牌栏底边对齐。武器、防具、进攻坐骑、防御坐骑、宝物五槽始终可见，148像素按五槽平均分配为每槽29.6像素，相邻四段间距均为0像素，第一槽贴顶且最后一槽贴底。空宝物槽与其他空槽使用当前主题的深色底框和类型图标，不绘制“无”文本；已装备槽在原位置覆盖主题浅色牌面并显示类型图标、花色、点数和牌名，不能自动补到前面的空位。已装备横条无论当前是否属于候选，都可通过鼠标悬停打开目标旁统一信息框；空槽不显示卡牌说明。装备栏范围为 `x=18..168`，手牌栏从 `x=168` 开始，两者边界零间隙相接；候选右移10像素、选中后总右移20像素，并保持高于透明手牌区域绘制。
- 坐骑槽图标：进攻坐骑槽显示 `-`，防御坐骑槽显示 `+`；图标只说明距离修正方向，不改变进攻坐骑令装备者计算距离 `-1`、防御坐骑令其他角色计算距离 `+1` 的规则数值。
- 本地技能区：固定在本地武将牌左侧，只显示技能按钮，不绘制技能区背景或状态说明。每个按钮固定只显示技能名前两个字，完整名称、说明与状态改由目标旁统一信息框显示；不可发动、被动、锁定与样例技能按钮虽然保持灰显且不能点击，仍允许悬停查看说明。技能按定义顺序从右到左、从下到上排列，每行最多2个，第三个从右侧第二层开始。按钮默认62×44像素，水平与垂直间距均为6像素；技能区底边使用与本地武将牌相同的底部留白，默认均距客户区底边0像素，调整 `local_player_card_bottom_margin` 后仍保持两条底边平行对齐。`leader_skill=true` 的技能只有本地身份为领袖时创建按钮，非领袖不保留灰色按钮或空位；身份与武将 ID 共同作为技能栏缓存签名，重新开局身份改变时会正确重建。技能区右边缘与本地武将座位左边缘保留6像素，手牌区仍在最左技能按钮左侧保留8像素，因此靠近武将牌时不会覆盖手牌信息。
- 本地武将牌：视觉容器固定在底部右侧，与其他玩家共用 `PlayerTargetView` 排版，整张牌可点击选择自己，并显示本地玩家的势力、武将名、体力和手牌数；本地装备只在左侧独立装备栏显示，不在第一视角武将牌上重复绘制。主视角不显示牌面下方座次号，也不保留原26像素座次标签占位，容器只覆盖148.35×197.8像素武将牌本体；牌面底边默认贴齐客户区底边，该0像素留白由 `local_player_card_bottom_margin` 暴露并可在检查器中调整。
- 统一信息框：`InformationBoxLayer` 是牌桌唯一说明入口。手牌、本地已装备横条、其他玩家公开装备横条、技能按钮、选将候选、选将阶段公开领袖牌和本地或其他玩家正式武将牌的悬停请求都必须持续0.5秒才显示；鼠标离开、切换到新目标或打开武将详情会立即取消尚未显示的请求，已显示的信息也立即关闭。同一来源重复发送完全相同的内容时只更新锚点，不隐藏当前信息或重新等待0.5秒；首次写入自动换行内容后会在下一布局帧以340像素基准宽度测量正文，测量期间面板保持透明，尺寸和位置稳定后才显形，再把宽度动态限制在240至520像素并尽量按4:3调整；特别长的内容优先完整显示，允许高度超过比例目标。武将悬停资料中的武将名与每个技能名使用和右键详情技能名相同的主题金色，技能说明继续使用次级文字色。信息框在目标右侧10像素处显示；右侧空间不足时自动翻转到目标左侧，并与视口四边至少保留12像素。鼠标右键释放本地或其他玩家武将牌时，在桌面中心打开宽760像素的“武将详情”；面板高度按左侧0.78倍正式武将牌、右侧技能内容和底部对称留白自动计算，最小226像素、最大440像素，短内容不保留固定大块空白，超过最大高度后使用标准纵向 `ScrollContainer`。左侧区域宽180像素并填充详情主体的可用高度，缩放武将牌在该区域始终上下居中；标题使用左右等宽占位保持相对整个面板居中。右侧按武将定义顺序显示技能名和完整技能描述，相邻技能之间使用1像素主题分隔线；技能列表底部按标题栏、主体间距及主题边距动态留空，使上边框到第一个技能名的距离等于下边框到最后一行文字的距离。短内容整体垂直居中，可用鼠标滚轮或12像素宽的右侧拖条浏览超出内容。关闭按钮、Esc、右键或点击遮罩空白区域均可关闭。信息框背景、边框、文字、分隔线、关闭按钮、拖条与左侧武将牌全部按当前 UI 风格即时重绘，不保存主题专属颜色。
- 统一信息框测量自动换行的首帧，必须将根面板可继承的 `modulate` 透明度设为0，使背景与所有文字子节点一并隐藏；禁止用不会传递给子节点的 `self_modulate`，以杜绝鼠标静止悬停时在默认或旧位置一闪而过的武将资料。右键详情右侧的技能滚动区默认额外保留24像素右边距，滚动条、技能名与技能说明整体左移；该值通过 `character_skill_right_margin` 暴露，可在检查器0至64像素范围内调整。
- 底部装备区、手牌区、技能区、操作区和本地玩家座位容器全部锚定到客户区底边；技能区与本地座位容器另外锚定到右边，手牌区使用左右安全边距自动收缩并保留横向滚动。即使根控件直接缩小为 1152×648，所有底部区域仍完整位于客户区内。
- 战局记录由左侧108×46像素“记录”按钮控制；点击后在按钮上方展开360×176像素日志正文，再次点击“收起记录”隐藏正文。离线 `OFFLINE` 模式展开日志时直接调用 `MatchController.acquire_gameplay_pause("offline_match_log")`，统一接口同时暂停场景树、事件运行时、AI 普通行动、AI 选牌和同时无懈计时器；收起时只释放日志自己持有的令牌。离线武将详情以 `offline_character_details` 申请另一枚独立令牌，关闭时只释放详情令牌；两个界面同时存在时必须等两枚令牌都释放才恢复。日志与统一信息框组件都使用始终处理模式，因此暂停后仍可滚动或关闭；LAN 与 REMOTE 模式打开日志或武将详情都不申请暂停。隐藏期间规则日志仍会持续追加，日志组件只发出展开状态，不读取通信模式或规则状态。

其他玩家手牌牌面不会进入本地快照。界面只渲染公开数据和本地私有数据，不通过视觉组件读取或修改 `GameState`。

## 主菜单

- 游戏启动后先显示主菜单，不自动创建 `GameState`、身份、牌堆或选将请求。玩家按下“开始游戏”后，牌桌才以当前人数创建标准身份局并进入既有选将流程；主菜单关闭后不再覆盖局内界面。
- 主菜单采用“顶部模式栏、左侧模式选择、右侧模式预览、底部操作”的层级。顶部先显示“模式选择”，其右侧固定显示“联机设置”；左侧模式列表仍只提供“身份模式”，不存在隐藏的第二种玩法。左侧卡片只显示放大的“身份模式”和“2-10人”，不显示“当前仅开放身份模式 / 更多玩法敬请期待”。右侧规则提示固定为“随机身份 · 阵营对抗”。
- 选中身份模式时，右侧预览使用 `assets/art/身份模式主菜单背景.png`，以覆盖裁剪方式填充预览区，因此允许因窗口比例不同裁掉边缘，不拉伸变形。参考图中的毛玻璃游戏背景不复刻。
- 右侧底部主按钮文字固定为“开始游戏”；其左侧依次提供“局域网联机”和“设置”。“开始游戏”直接创建离线身份局；“局域网联机”打开独立大厅组件，不提前创建 `GameState`。设置浮层可修改卡牌名称、UI 风格、自动身份标记、AI 响应速度、游戏速度和游戏人数，均复用 `GameSettings` 与既有局内菜单的同一配置入口。游戏人数范围为2至10人，默认8人；卡牌名称、主题、自动身份标记与速度设置即时生效，人数分别在离线开局或房主开始局域网对局时生效。
- 主菜单所有底色、面板、边框、文字和按钮均从 `UIStyleRegistry` 的当前语义色读取。崩铁风格与暖木家园切换后同步重绘主菜单，不改变身份、体力、牌堆、伤害、回复、距离、次数、目标数、资源、概率或持续时间。
- 主菜单在1280×720逻辑视口中使用54像素左右安全边距：主题内容面距左右22像素、顶部12像素、底部18像素；顶部模式栏范围为`y=22..88`，主体从`y=104`延伸至底部38像素安全边距，两者固定保留16像素间隔；根控件直接缩为1152×648时仍不得重叠。顶部品牌区宽252像素，“模式选择”和“联机设置”按钮均宽192像素；左侧模式栏最小宽286像素，身份模式卡高100像素并使用主题强调竖线，其中“身份模式”为27像素、“2-10人”为16像素。右侧预览保留透明度0.18的全图主题遮罩，左上170×66像素不透明主题标签用于覆盖裁剪后可能残留的原图品牌碎片；摘要底板位于右上24像素、顶部28像素处且尺寸366×160像素、透明度0.82；底部操作栏高92像素且透明度0.88。“设置”为112×56像素，“局域网联机”为154×56像素，“开始游戏”为250×56像素，主次操作层级不能互换。
- 设置面板为504×464像素，并使用覆盖全屏、透明度0.86的主题模态遮罩。主菜单普通可见期间会暂存并冻结主菜单之外的牌桌焦点；设置打开期间再冻结主菜单内设置面板之外的模式与开局控件，使 Tab、Shift+Tab 与手柄导航始终停留在当前可见层。遮罩同时停止底层鼠标输入；点击面板外空白、按Esc或按“返回”均关闭设置，只恢复主菜单自身焦点并把键盘焦点交还“设置”，被覆盖牌桌要等成功进入对局后才恢复。下拉框的常态、悬停、按下和弹出列表，滑条轨道与已选区、人数文本框、复选框文字都必须读取当前主题语义色；滑条已选区使用0.72倍主题强调色透明度，人数文本选择区使用0.42倍主题强调色透明度，不能回退为与主题冲突的默认控件配色。
- “开始游戏”只发出开局请求，主菜单必须等待 `MatchController.start_match()` 返回成功后才隐藏。待机时底部操作栏不显示“身份模式已选择”或任何状态文本；人数越界、数据校验失败或后置选将初始化失败时，主菜单保持可见、重新启用开始按钮，并在底部操作栏显示控制器返回的具体拒绝原因。局内“按设置重新开局”先执行不修改状态的前置校验：失败时不清空旧日志、动画、选择表现或 `GameState`，重新展开局内菜单并让原对局继续；只有通过前置校验后发生的选将初始化失败才丢弃半成品状态并显式恢复主菜单。主菜单全屏底色使用 `MOUSE_FILTER_STOP`，前景面板没有覆盖的边缘区域也不能把输入传给隐藏的局内控件。

### 局域网连接入口与联机大厅

- `LanLobbyPanel` 使用620×540像素中央面板与全屏主题遮罩，只负责连接入口。表单只读显示联机设置中最长20字符的玩家名，并提供房主 IPv4、1024至65535端口、最长32字符密文密码以及“创建房间 / 加入房间”；名称不能在该界面修改，默认端口为7000，同机双实例可输入127.0.0.1。成功登记后整个入口隐藏，不再渲染成员或开局控件。
- `OnlineLobbyPanel` 是连接成功后的独立全屏大厅。内容面距逻辑视口左右24像素、上下18像素；中央座位区从内容面局部 `(24,54)` 到 `(1208,528)`，左下聊天框为 `(24,532)..(790,674)`，右下房间控制为 `(804,532)..(1208,674)`。内容面必须使用不接管直接子节点布局的 `Panel`，不能用会强制铺满子节点的 `PanelContainer`。
- 每名真人由独立 `OnlineLobbyAvatar` 表现，不复用 `PlayerTargetView` 或正式武将牌场景。名称区域高26像素，名称与插画间距4像素；玩家名始终显示在插画上方。插画区域固定148.35×197.8像素，只加载武将定义的原始插画，不显示牌框、势力、体力、技能、身份、手牌数或悬停资料层。
- 2至3人设置固定显示3个居中横向位置；4人为2上2下；5人为3上2下；其余人数按上排 `ceil(人数/2)`、下排剩余数量分配，因此8人为4上4下。每一排独立居中，同行水平间距44像素、两排垂直间距18像素；最多10人且不缩放插画。空位置显示“位置N / 空位”，本地玩家点击后请求换位，只有目标仍为空时房主才广播新位置。
- 左下聊天单条最多200字符，回车与“发送”共用同一入口；公共历史最多100条，格式为“[时间] 玩家名：正文”。大厅快照刷新不得抢走正在输入聊天或编辑房间设置的焦点。
- 右下所有玩家都看到模式、真人数、总人数与密码开启状态；房主额外看到“对局设置”和“开始游戏”。设置模态提供稳定模式 ID、2至10人总人数和最长32字符密码，人数下限动态提升到当前真人数；当前唯一可选且可实际开局的模式为“身份模式”。少于2名真人时开始按钮禁用。
- 房主悬停远端玩家形象时，在插画下方显示“踢出”按钮；房主本人、普通客户端和空位不显示。踢出后远端收到明确原因并返回连接入口；同一远端地址在之后5秒内再次加入会收到剩余冷却秒数，冷却结束才可重新进入。
- 大厅打开期间冻结主菜单中大厅之外的全部可聚焦控件，背景阻断底层鼠标输入；房主设置模态进一步冻结大厅底层控件。Esc 优先关闭设置，否则执行离开；开局成功后大厅与主菜单同时隐藏，连接失败、密码错误、被踢出或房主断开时恢复连接入口并显示具体原因。
- 连接入口、联机资料、联机大厅、动态空位和踢出按钮全部从 `BattleUIStyle` 读取语义色，并同时支持“崩铁风格”与“暖木家园”。桌面协调器先切换活动主题，再由主菜单统一刷新全部联机组件，避免信号顺序导致子面板短暂保留旧配色。
- 局域网客户端不显示服务器随机种子、其他玩家身份或手牌牌面。卡牌与目标高亮读取房主定向发送的合法动作副本，点击确认后仍只提交 `PlayerAction`，不能在客户端直接改写规则状态。
- `lan_lobby_ui_test.tscn` 覆盖只读连接入口、真实房主建房、纯插画形象尺寸、名称位置、圆角 Alpha 裁切、超长房主地址自适应、2/5/8人布局、聊天焦点、换位、设置、踢出悬停、两套主题和离开恢复。

## 牌桌视觉层级

- 牌桌视觉保留环桌厚框与内嵌边界，默认“崩铁风格”使用近黑厚框、冷调雾面深灰桌面与低饱和金色装饰；外底为 `#111214`，外层桌面为 `#24262B`，主内容背景为 `#30333A`。浅色仅用于卡牌纸张和已装备信息条，避免全桌白底显得突兀；同时不仿制参考图中由游戏地图毛玻璃产生的紫蓝背景，也不绘制导航网格、固定星点、山脊或建筑剪影。“暖木家园”继续使用深胡桃木、暗金和深青夜景。
- `reference_backdrop.gd` 作为独立背景组件程序化绘制外底、桌框、内容面、同心环和十二段轨道刻度；起止色相同时直接绘制纯色，只有后续主题显式提供不同起止色时才启用32段纵向渐变。星点与山脊/建筑剪影由主题布尔语义独立控制。组件只接收风格标识并从注册表读取语义值，忽略鼠标输入且不读取对局状态。
- 背景组件的桌面留白与框宽由主题语义覆盖：崩铁风格使用34像素桌面留白和14像素黑框，外侧20像素区域使用中性深色纯色；暖木家园保持18像素桌面留白和14像素木框。桌面圆角为30像素、中央装饰半径为150像素、装饰透明度为0.16；这些表现参数均在脚本顶部通过 `@export` 暴露。
- 原有 `assets/ui/table_ornament.svg` 继续作为低透明度全桌星轨纹样，与程序化中央铭纹叠加使用；二者都只承担背景装饰。
- `无名杀参考代码/十周年UI/.gdignore` 将参考扩展明确隔离为开发资料，避免网页脚本、Spine 动画和海量图片被 Godot 导入或进入游戏导出包。
- 中央动画落点位于基准视口约 `(540, 250)` 至 `(740, 400)` 的透明区域；该节点只提供动画坐标，不显示任何弃牌堆 UI。
- 默认八人局的 7 名对手从本地下家起依次位于右侧 1 名、顶部 5 名和左侧 1 名；二至八人局使用参考 CSS 的原始比例，九至十人局在相同边界内对称扩展。
- 武将体力位于武将牌右下角的不透明圆角矩形容器：背景与1像素主题描边使用运行时 `StyleBoxFlat`，四角半径均为6像素并开启1像素抗锯齿。体力框右边和底边直接对齐武将牌边缘，右下圆角与武将牌6像素圆角使用相同参数，不再绘制斜边或折线。

## 统一武将牌格式

- 所有玩家武将牌以 `Node2D` 为根，固定为 148.35×197.8 像素的3:4规格，直接复用 `player_target_view.tscn` 保存的原生编辑器几何，不按座次、人数或本地/对手身份切换规格。牌面不是按钮；`PlayerTargetInputArea` 作为透明子组件只承接点击、右键详情与悬停，不接收任何卡牌拖放。
- 座次标签不属于武将牌场景，而是只在进入游戏后由 `player_seat_slot.tscn` 添加到座位容器。其他玩家标签固定为148.35×26像素、字体18像素，完整座位为148.35×223.8像素并按快照 `seat_number` 显示“一”至“十”；本地主视角实例会隐藏并清空该标签，把容器收紧为148.35×197.8像素。
- 左侧武将名竖条固定为 22×93 像素，使用 10 像素字体并按字符逐行竖排。
- 势力圆徽固定为 26×26 像素、左下手牌数角标固定为 24×24 像素；势力简称与颜色来自 `game_data/factions.json` 的 `factions` 数组。
- 右下体力边框为宽24像素起步的动态不透明圆角矩形，内部圆点使用18像素字体和-10像素纵向间距；上限1至5时高度随体力与护盾圆点总数变化，超过5时显示数字。体力上限大于2的角色在当前体力为2时，全部仍点亮圆点变为黄色；当前体力为1时变为红色；其他正体力状态为绿色。体力上限为1或2的角色，其仍点亮圆点始终为绿色，已损失圆点继续使用主题暗色。护盾使用两种风格共享的灰色 `#A7ADB7`：圆点模式按点数置于体力圆点上方，体力数字模式同步显示“盾+数值”，不把护盾并入“当前/上限”。身份徽记固定为23×20像素，身份与手牌数覆盖层在武将牌资源中默认隐藏，仅正式对局开启。
- 其他玩家的公开装备按武器、防具、进攻坐骑、防御坐骑、宝物固定槽位显示，最多5条；每条为141.35×15像素，长度严格等于武将插画宽度，相邻槽位覆盖1像素，内容为花色、点数和当前名称模式下的牌名。未装备槽位不绘制横条但保留对应位置，后续装备不得自动补位；宝物未装备时只计算前4个槽位，实际装备宝物后才扩展为5槽布局。木牛流马额外在牌名后显示全体可见的“粮”数量，包括0张。第一视角本地武将牌关闭该层，改由左侧常驻五槽装备栏独立显示。
- 判定区使用22×22像素标记槽，菱形中心位于武将牌底线`y=197.8`；第一张标记左边缘距牌面左侧28像素，相邻标记边缘间距6像素，按判定区数组顺序从左到右排列并显示当前牌名的首字。
- `player_target_view.tscn` 不再包含`Status`文本节点。阵亡角色的整张武将牌覆盖0.62亮度的黑白滤镜，并在中心显示28像素红色“阵亡”。正常武将牌始终以148.35×197.8像素竖直牌面显示；横置由 `PlayerStateOverlay` 绘制高8像素的轻量双层深灰框：1像素外框向左右各延伸6像素并只在牌外填充实体端点，1像素内框垂直缩进1像素，其透明中段严格等于武将牌宽度。双层描边只作灰色状态凸显，不应遮盖插画。横置不旋转、缩放或移动武将牌；竖置时取消该框，点击、拖放、右键详情与信息框锚点继续使用牌面的实际全局矩形。
- 当前回合角色始终使用3像素主题强调边框；普通单人选择根据活动请求的 `actor_id` 单独提亮操作者，若操作者不是当前回合角色则额外使用2像素主题合法目标边框。【无懈可击】同时响应期间读取公开 `responder_ids`，把本轮全部存活玩家统一设为操作高亮，即使某名玩家没有合法无懈候选也保持相同表现，客户端不得根据高亮判断其手牌。所有回合与操作高亮只改变武将牌底色和边框，不绘制彩色外发光。已选目标同样使用主题强调粗边；合法目标只有在不是当前回合角色时使用主题合法目标粗边，避免临时合法性覆盖回合边框。
- 每名玩家快照公开累计 `damage_taken_count`。桌面检测该计数增加时播放一次受伤抖动，不再只依赖体力下降；因此伤害完全被护盾吸收时仍有受击反馈。护盾自然减少或技能主动失去护盾不会增加该计数，也不会伪装成受到伤害。
- 势力徽记、武将名、手牌数、身份、体力、公开区、装备横条和座次字体均使用上述固定尺寸；武将插画保持牌面的主要视觉占比。

## 可切换 UI 风格组件规范

- `ui_style_registry.gd` 只维护稳定风格 ID、设置显示名与语义配色；当前注册 `space_mono`（崩铁风格）和 `decade_wood`（暖木家园），默认 ID 为 `space_mono`。显示名变化不修改稳定 ID，新增风格必须复用现有语义键，不得在业务组件中按主题名称写分支。
- `GameSettings.ui_style_id` 只保存当前风格 ID，并通过 `ui_style_changed` 通知桌面；`BattleUIStyle` 只负责把当前风格的语义色转换为面板、按钮、描边和阴影样式。`main.tscn` 继续作为桌面组合入口，卡牌和武将牌的几何仍分别只在 `card_view.tscn` 与 `player_target_view.tscn` 维护。
- 崩铁风格核心色为：中性外底 `#111214`、外层桌面 `#24262B`、雾面内容背景 `#30333A`、黑色桌框 `#1D1D1D`、金色边框 `#BFA86C`、金色强调 `#D4B55F`、浅金合法目标 `#F1DFAA`、主操作背景 `#403B32`。卡牌纸张继续使用 `#F4F1E9`，确保浅色只出现在需要阅读的局部信息面。暖木家园核心色继续使用外底 `#120D0C`、桌面 `#20202D`、内桌垫 `#151725`、桌框 `#4A2818`、暗金边框 `#A8834F`、强调色 `#EFC76D`、合法目标 `#61C7A4`、主操作背景 `#76521F`。完整语义色由注册表作为唯一代码来源。
- 武将状态卡采用窄圆角内嵌框：当前回合角色使用3像素主题强调边，当前操作者使用提亮背景与2像素合法目标边，合法目标使用3像素合法目标边，已选目标使用3像素主题强调边；上述状态均不附加彩色外发光。崩铁风格保留 `game_data/factions.json` 提供的武将势力色，其中星穹列车为列车灰 `#8A919C`、贝洛伯格为寒冰蓝 `#58B8E8`；同时保留卡牌类别与属性色、体力红黄绿、护盾灰色、红黑花色和其他玩法识别色。
- 本地武将框与其他角色遵循同一动态状态规则；装备区和技能区外层保持透明，左上对局信息区与可折叠记录入口使用1至2像素主题边框。中央确定与取消保持146×42像素和28像素水平间距，右侧回合结束保持112×36像素；风格只改变颜色、描边、牌背和纸张，不改变控件尺寸，禁用交互按钮保持低对比度且没有悬停反馈。
- 技能实际发动时，桌面在发动者武将牌中心显示短暂的技能名提示；文字使用黑色描边以避免混入插画，绘制层级高于手牌和飞牌。`skill_activated` 同时携带已确认的可序列化上下文；其中 `target_id` 或 `target_ids` 存在时，动画层以与卡牌完全相同的4像素金色线条从发动者动态延伸至目标并用0.36秒淡出。选择目标期间不显示预览线，只保留武将牌描边。该表现不改变对局状态；同一发动同时写入对局日志。

## 选将界面

- 开局进入全屏选将遮罩，领袖先从随机候选中选择并立即亮出；领袖确认后，其他玩家各自在自己的客户端同时选择，所有人完成后统一亮出并关闭遮罩。
- 每名玩家默认随机展示5张可选武将牌；数量读取 `MatchController.character_candidate_count`，后续可扩展，实际显示数量不超过武将库总数。
- 候选使用正式 `PlayerTargetView` 场景，保持148.35×197.8像素 Node2D 武将牌模型；候选布局直接读取场景牌宽，不在脚本中保存重复尺寸。鼠标悬停可选武将时以0.14秒二次缓出从1.00倍过渡到1.08倍，并围绕牌面中心放大；统一信息框同时显示武将名、势力、性别、静态体力上限以及按定义顺序排列的全部技能名和描述，移开后用相同时长恢复牌面并关闭信息。点击只让所选武将显示主题强调边框，未选候选不再因统一合法状态获得彩色发光或描边；点击确认后才提交 `select_character` 标准动作。
- 领袖阶段只有领袖能看到自己的候选；领袖确认后，选将框左侧以0.78倍显示其只读正式武将牌，并使用2像素竖线与右侧本地候选分隔。没有公开领袖时竖线与领袖区域都不占位，候选区域直接从原领袖牌左边界开始。界面不再显示“领袖已亮出……其他玩家同时选择，完成……”等确认进度长文本，也不显示其他玩家具体选择。
- 当前选将框按1280×720逻辑视口使用1040×540像素主面板；有领袖时左侧只读区域从 `(40, 106)` 开始，右侧候选区域从 `x=214` 开始；无领袖时从 `x=40` 开始。默认5张候选以14像素间距水平排列，候选数量变化时由组件读取正式牌宽重新计算位置，不在桌面脚本保存五张牌的固定坐标。

## 局内菜单

- 右上角唯一常驻按钮文字为“菜单”，点击后显示集中面板；原独立“牌名”和“重开”按钮不再存在。
- 新启动默认显示《崩铁杀》卡牌名称，菜单内可切换为三国杀原版名称并随时切回；名称切换只重绘显示文本，不改变卡牌 ID、效果或对局状态。
- 菜单内新增“AI响应速度”滑条，默认 0.30 秒，可在 0.05 至 1.00 秒之间以 0.05 秒步长调整。该数值是每次 AI 行动或选牌响应前的等待时间，数值越小响应越快；修改后立即作用于后续 AI 计时器，不需要重开对局。
- 菜单内“游戏速度”标签只显示“游戏速度：0.3秒”这一数值格式；滑条表示流程最小间隔，默认0.3秒，可在0.1至1.0秒之间以0.1秒步长调整。相邻阶段和全部响应提示先等待该数值；普通 AI 行动的等待取游戏速度与 AI 响应速度的较大值，AI 响应牌在提示发布后再等待同一较大值，保证人类先看到窗口。修改只影响之后创建的任务，已经开始的计时器保持原时长。
- 菜单内人数输入范围为2至10，默认继承控制器的8人配置。输入文本会即时同步，点击“按设置重新开局”时优先读取当前键入内容并限制到合法范围，随后创建对应人数的新对局并重新进入选将。
- 局内重开会在清空旧表现前调用控制器的只读前置校验。人数或全局数据校验失败时重新展开局内菜单并显示拒绝原因，当前 `GameState`、事件运行时与 AI 任务保持原局状态；通过前置校验后若新局选将初始化失败，则清空半成品运行时并返回主菜单重试。
- 菜单面板的输入顺序高于动态武将牌与选将遮罩，因此选将尚未完成时仍可继续调整人数并重新开局；人数修改只在重开时生效。
- 手牌保留浅色实体纸张以保证花色和牌名可读，外框改用硬质窄圆角与深阴影；禁用纸张与类别条默认压暗38%，插画和文字使用45%亮度深灰调制，选中、悬停和类别色仍遵循原有交互语义。
- 所有 UI 风格仅调整表现层。组件继续只消费裁剪快照、发出稳定 ID 信号并提交标准动作，禁止通过视觉节点直接读取或修改规则状态。

## 出牌动画

- 规则核心使用可序列化 `CardPresentationEvent` 统一描述 `useCard`、`showCards`、`delayedJudge` 和 `judge`，内容包含表现序号、关联事件、卡牌快照、来源、目标与后续弃牌所有权，不向界面暴露权威状态对象。
- 本地玩家使用卡牌时，动画层直接接管手牌中的同一 `CardView` 节点；AI 或其他不可见来源使用牌时，也实例化同一个 `card_view.tscn` 正式牌面。本地牌从手牌区实际节点进入动画层，其他玩家的牌从对应武将牌中心进入；全部牌都用0.42秒飞向中央弃牌展示区。纯展示和普通弃牌抵达后停留0.48秒，再用0.36秒淡出；真实使用牌、延时判定牌和判定牌在响应、选牌或其他异步结算完成前持续留在中央，最终进入弃牌堆或其他权威区域后才完整停留0.48秒并淡出。
- 【火攻】展示手牌和判定阶段也使用同一动画层：`showCards` 从展示者武将牌中心飞入中央牌桌且不移动权威实体；每张延时锦囊先用 `delayedJudge` 从判定角色锚点展示，默认保留1.00秒后才由 `judge` 把牌堆顶1张判定牌直接从中央弃牌展示锚点公开，不从判定角色处打出；判定完成后默认再保留1.00秒才展示判定区下一张牌。两种间隔分别读取 `MatchController.delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds`，检查器范围均为0.00至3.00秒。上述展示都没有使用牌目标指示线。
- 本地玩家进入手牌区的正式牌先按实体 UID 创建或复用手牌容器中的 `CardView`，再从手牌可视区右侧24像素外用0.24秒移动到最终手牌位置；动画结束后同一节点继续承担选择与出牌。一次 `draw()` 摸到多张牌时，所有牌背由独立批次从同一牌堆锚点同时起飞，并按42像素横向中心间距围绕目标锚点整体居中；飞行0.24秒、停留0.10秒、淡出0.18秒，同一批不使用逐张延时。每次 `draw()` 收齐本批移动后立即开始动画，多个玩家或连续多次摸牌的批次可以同时播放，不互相等待。其他玩家的隐藏获得动画仍只显示牌背。
- `CardPresentationEvent` 明确声明后续弃牌所有权。动画层先按本局单调 `presentation_id` 去重，再让真实使用牌和判定牌按实体 UID 原子取得所有权；普通弃牌首次观察到实体 UID 时也登记其表现生命周期，节点接管与所有权登记之间不存在可插入重复移动的窗口。接管所有权的牌不再按固定总时长提前淡出，而是等待响应与整张牌结算完成后的最终区域移动；消费记录继续保留到权威实体进入非弃牌新区域，因此相同表现包、不同表现 ID 的迟到包、同区域无效移动或相同移动增量重复到达都不会在牌桌上方或中央生成第二张牌。玩家来源或目标不存在真实座位锚点时直接跳过短时表现，不再回退到 `(540,250)..(740,400)` 的中央锚点伪造来源或落点；新建牌面在完成父级、坐标和外观初始化后才设为可见。`CardView` 的样式与悬停刷新默认不再写入非手牌绝对纵坐标，动画牌在鼠标离开透明输入区时不会把 `position.y` 重置为0并跳到窗口顶部。`GameState.processing_card_uids` 公开当前处理区实体 UID，动画层每次快照都会核对仍被认领的中央牌面，已离开处理区但漏失最终移动通知的牌立即进入正常停留和淡出。没有对应 `useCard`、`delayedJudge` 或 `judge` 表现认领的 `processing -> discard_pile` 增量创建0张中央牌面，避免虚拟材料收尾从中央锚点凭空出现。火攻等纯 `showCards` 只按表现 ID 去重，不占用实体 UID 的未来弃牌所有权。
- 有目标的卡牌会绘制从使用者指向每名目标的4像素金色指示线；线条默认用0.24秒从来源动态延伸到目标，延伸完成后立即独立用0.36秒逐渐淡出，不等待飞牌停留或弃牌队列。多目标卡牌为每名目标保留独立武将牌中心终点，显示多根同步延伸并同步渐隐的指示线，无目标牌不绘制指示线。技能不在 `target` 或 `card_target` 选择请求中显示预览线；仅在技能实际确认发动后，从 `skill_activated` 上报的 `target_id/target_ids` 读取目标，并以同一绘制层、同一4像素金色样式播放完整“延伸→淡出”动态线。卡牌可通过 `indicator_stages` 声明顺序指示阶段；【借刀杀人】先完整播放使用者到持刀者，再播放持刀者到被要求出【杀】者，不能同时叠成两条线。
- 本地玩家无论作为使用者还是目标，统一使用手牌区上方中心作为指示锚点，默认与手牌区顶边保持8像素间距；其他玩家统一使用各自武将牌中心。因而本地玩家对其他角色使用牌时，线条从手牌区上方中心指向目标武将牌；其他角色对本地玩家使用牌时，线条从来源武将牌指向手牌区上方中心。
- 飞牌保持正式111×148像素的3:4模型和1.0倍目标缩放，全程保持0度旋转，不替换为细长牌或简化标签。多张牌同时存在时按66像素中心间距水平铺开，成员变化后使用0.18秒补位，展示手牌、判定牌、响应弃牌和普通弃牌全部进入同一中央展示队列；同一帧进入弃牌堆的多张牌按信号顺序从左到右完整显示，并作为同一批次同时使用0.36秒淡出。每张中央牌始终只保留1个收尾生命周期 Tween：无异步响应的牌覆盖0.42秒飞行与0.48秒停留，需要响应的牌在最终区域移动后按已经完成的飞行时间补足剩余飞行并重新完整停留0.48秒。动画层使用30层，高于普通牌桌和武将牌，低于40层选将遮罩与50层菜单；该层忽略鼠标输入，不会遮断点击、拖放、目标选择或确认按钮。
- 摸牌、获得和响应弃牌也通过 `card_transfer_requested` 播放区域移动；控制器会为一次 `draw()` 额外发出开始/完成批次信号。带批次标识的牌堆到手牌移动由桌面先收集、后一次性提交动画层，不能退化为每张向右偏移的顺序堆叠；带摸牌堆叠键但未进入批次接口的兼容转移同样使用0.24秒飞行、0.10秒停留和0.18秒淡出。没有批次标识的获得牌仍沿用原区域移动表现。处理区到弃牌堆的使用牌由持续到最终移牌的实体 UID 记录接管，防止响应等待后同一实体牌重复出现在中央位置。
- 重新开局会先递增动画代次，清空旧局的区域转移索引、摸牌堆叠索引和补间索引，并立即隐藏旧牌面。所有删除操作使用稳定实例 ID，摸牌堆叠数组不保存对象引用，也不把可能已经释放的 `CardView` 作为容器删除参数；上一局仍在等待的补间正常结束后先比较代次，不匹配时只释放自己的隐藏牌面，不能访问或清理新一局动画。
- 飞牌进入中央区域属于客户端结算表现。装备牌、延时锦囊等卡牌仍按规则进入装备区或判定区，动画不会改变其最终区域；同一区域重复移动不会产生新的牌面动画。
- 对手座位按玩家 ID 持久复用，普通状态快照只重建轻量视图索引，不再释放并实例化整桌武将牌。`CardView` 与 `PlayerTargetView` 缓存同时包含名称模式和 UI 风格 ID；快照内容与风格均未变化时不会重复加载插画、生成主题样式、体力圆点、装备横条或判定标记。玩家人数、本地座次、风格或实际公开状态变化时会立即失效并刷新对应节点。

## 插画预留

- 每张卡牌在牌面中部保留插画区域，花色与点数固定在左上角，牌名和类别固定在底部，不会被插画覆盖。
- 所有玩家的武将插画槽固定为 `(4, 4)` 至 `(145.35, 194.8)` 的 141.35×190.8 像素区域，覆盖牌面绝大部分面积；3:4牌面设计只扩大牌框和插画，势力徽记、竖排武将名、体力圆点、手牌数和身份徽记保持固定规格，装备横条完整铺满插画宽度，座次标签位于牌面外部。
- 本地与其他玩家使用同一插画裁切规则和 148.35×197.8 像素牌面尺寸，不使用单独缩略图组件。
- 卡牌定义继续使用可选字段 `art_path`。武将源码不填写该字段；`GameDatabase` 根据武将 `.gd` 文件的完整基础名，在 `res://game_data/characters/image/` 依次匹配同名 `.png`、`.jpg`，并把命中路径注入只读武将元数据供 `PlayerTargetView` 使用。
- 同名 PNG 与 JPG 同时存在时固定优先使用 PNG。匹配不读取武将稳定 `id` 或中文显示名，因此 `buluoniya.gd` 只对应 `buluoniya.png` 或 `buluoniya.jpg`，`sp_buluoniya.gd` 只对应 `sp_buluoniya.png` 或 `sp_buluoniya.jpg`。
- 卡牌 `art_path` 缺失、为空或无效，以及武将同名 PNG/JPG 均不存在时，界面显示统一“插画预留”占位，不中断对局。
- 卡牌资源目录与手填路径规范见 `assets/art/README.md`；武将图片命名规范见 `game_data/characters/image/README.md`。
- 卡牌插画使用覆盖裁切保持比例，武将插画同样保持比例并裁切到固定槽位；替换图片不改变控件尺寸。

## 卡牌视觉反馈

- 卡牌顶部使用4像素类别色条，颜色从当前风格的 `card_basic/card_trick/card_equipment` 语义读取；崩铁风格保留红 `#B65350`、蓝 `#4E7FA7`、金 `#A98D55` 三种类别色，暖木家园分别使用 `#A44E43/#4F718F/#8A7548`。
- 火焰与雷电属性牌优先使用当前风格的 `card_fire/card_thunder` 语义；崩铁风格使用橙红 `#D66A46` 与亮蓝 `#5E85CE`，暖木家园使用橙红 `#C65F3F` 与蓝色 `#547FC4`。红桃、方片的红色和体力红黄绿仍作为玩法识别色保留。
- 可交互卡牌悬停时在0.12秒内缩放至1.06倍并提高绘制层级；相邻手牌继续保持当前展开或压缩位置。
- 鼠标离开后恢复原始缩放；选中卡牌仍保持14像素抬升和主题强调描边。
- 类别色与动画只属于视觉反馈，卡牌合法性仍完全由规则预览和核心校验决定。

## 标准出牌流程

1. 点击一张手牌或木牛“粮”选择实体 UID；已选卡牌使用主题强调描边并向上抬升14像素。
2. 界面调用 `MatchController.get_card_use_preview()` 获取只读规则预览，并用当前主题的合法目标描边标记下一步目标。
3. 点击角色状态卡按顺序选择目标；再次点击已选目标可取消。若卡牌最多只需要1个目标，直接点击另一名合法角色即可替换旧目标，无需先取消；若当前仅有1名合法候选，界面会自动选择并锁定该目标，等待玩家点击“确定”或按`Enter`。已选目标使用主题强调描边。【万箭齐发】【南蛮入侵】【桃园结义】等 `all_others/all_players` 牌由规则层自动展开目标，武将牌不显示手动合法目标色，点击不会写入选中目标或改变牌面选中色。
4. 多目标在界面中按点击顺序编辑与取消，界面最多保留3名目标；提交后权威规则层统一按当前回合角色起算的行动顺序结算。【借刀杀人】必须先点击持刀者、再点击其需要使用【杀】的角色，共选择2名；提交时已完整指定，之后不再弹出第二次目标选择。
5. 当前牌与目标组合通过预览校验后，“确定”按钮才会启用；点击或按 `Enter` 后提交标准 `use_card`。

规则核心仍会在 `submit_action()` 中执行最终校验。UI 预览仅用于引导，不能替代权威规则判断。

### 快捷操作

- `Enter`：当前牌和目标组合合法时执行“确定”。
- `Esc`：取消当前选牌与全部目标。
- 鼠标右键：与 `Esc` 相同，取消当前选择。
- `Space`：未选择卡牌且处于本地出牌阶段时结束出牌阶段。
- 本地武将牌整体可点击以选择自己；“选择自己”按钮继续作为触屏和低分辨率下的明确入口。

## 手牌拖拽排序

- `CardView` 根节点为 `Node2D`，透明 `CardInputArea` 通过 Godot 原生拖放接口提供稳定实体 UID，只请求本地显示排序，绝不复制、移动或提交权威卡牌对象。
- 将一张手牌拖到同一分区的另一张牌上：落在目标左半边插入其前，落在右半边插入其后。排序只影响当前客户端视觉顺序，卡牌区域、手牌数、实体 UID 与出牌动作均不改变。
- 普通手牌与木牛“粮”使用独立排序分区；木牛“粮”始终位于手牌区左侧，只能与其他“粮”互相排序，不能跨入普通手牌区，也不能被普通手牌跨越。
- 拖拽不再参与选牌、规则预览、目标选择或 `PlayerAction` 提交。使用牌仍必须点击牌面选中、点击武将牌选择目标，再点击“确定”或按 `Enter` 提交。

## 其他动作

- 选中定义中 `recast=true` 的普通手牌且没有选择目标时，中央“确定”直接提交 `recast_card`；当前默认牌堆中该流程用于【铁索连环】，木牛“粮”不能进入重铸。
- 木牛流马在本阶段可以存粮时作为宝物装备候选向右移动；点击装备后选择1张普通手牌并按“确定”提交 `store_wooden_ox`，若已选择目标，则该目标接收木牛流马和全部“粮”。
- 丈八蛇矛在可以使用或打出【杀】时作为武器装备候选向右移动；点击装备后选择正好2张普通手牌，出牌时再选择1名攻击范围内目标，响应时直接按“确定”打出虚拟【杀】。
- 右侧“回合结束”提交 `end_play`，普通内联响应或效果选择期间隐藏；群体锦囊的【无懈可击】询问期间改为“不响应该锦囊”开关。
- 任何已经提交到核心的非法次数、距离、目标、区域或阶段动作都会被拒绝，并在本地玩家区显示最近一次错误原因；不可发动的技能按钮本身处于禁用状态，点击时静默忽略，不生成“该技能当前不满足发动条件。”等错误文本。

## 技能控制条

- 技能栏位于本地玩家状态与手牌之间，外层完全透明且只显示按钮；底边与本地武将牌底边平行对齐。
- 桌面根据本地武将配置中的 `skills` 数组动态生成按钮，不硬编码武将 ID 或技能数量。
- 每个按钮正文只显示技能名前两个字，悬停时由统一信息框显示完整名称、技能说明与接入状态；元数据 `lock=true` 时信息副标题标记为锁定技。技能说明中的完整 `【原版牌名】` 通过 `GameDatabase.resolve_card_names_in_text()` 显示为当前名称模式对应牌名。
- `trigger` 为 `sample_only` 的样例技能显示为“预留”并保持禁用；不可发动、被动、触发、锁定和样例技能统一使用更灰的禁用色，普通、悬停、按下与禁用样式保持一致，不播放悬停动画，点击时不提交动作、不修改状态也不显示错误提示。
- 后续主动技能可在元数据中声明 `ui_enabled: true`，并由独立技能交互控制器处理选牌、选目标、确认和标准动作构建。
- 技能按钮默认尺寸为62×44像素；按定义顺序从右到左、从下到上排列，每行最多2个，水平和垂直间距均为6像素。选中技能使用3像素主题强调描边，可发动技能使用主题合法目标边框；不可发动技能没有选中和悬停变化。
- 主场景初始化会把旧版本遗留的 `HFlowContainer` 技能容器原位升级为 `SkillButtonGrid`，并重新应用透明技能区、175像素透明手牌区和148像素装备区高度；该兼容迁移只用于消除编辑器旧场景缓存造成的节点类型错误，不改变技能定义或按钮顺序。

## 组件职责

- `match_table.gd`：桌面协调器，渲染只读对局快照、左上轮数/牌堆/时长、当前回合与当前操作者状态，建立玩家 ID 索引并缓存静态定义，按实体 UID 对账并复用本地正式手牌节点，把对手座次旋转为本地相对行动顺序，维护普通出牌、本人手牌/装备区内联选择和公共选牌展示，请求规则预览并构建 `PlayerAction`；阶段间隔内没有活动 `chooseToUse` 请求时全部出牌控件禁用。“记录”右侧的“托管/取消托管”与“托管中...”文字点击均只提交 `set_auto_managed`，托管滤镜高度固定175像素、从手牌左边界延伸到本地武将牌左侧8像素，技能按钮的绘制层级始终更高；遮罩拦截其余指针且所有常规操作控件禁用。局域网中它额外协调大厅、网关、房主开局和客户端本地玩家 ID，但仍不直接修改 `GameState`。
- `main_menu.gd`：管理启动前唯一身份模式、覆盖裁剪预览、主题化模式层级、模态设置、离线开局请求与局域网入口。显示设置与下一局人数统一经 `GameSettings` 保存，组件不读取或创建 `GameState`；牌桌确认房主或离线 `start_match()` 成功后调用完成入口关闭菜单，失败时组件保留入口并显示拒绝原因。
- `lan_lobby_panel.gd`：管理局域网连接参数、只读玩家名和入口模态焦点，只发出建房、加入和返回意图，不渲染已连接成员，也不创建 ENet 或权威状态。
- `online_lobby_panel.gd`：根据公共大厅快照渲染位置、聊天和房间控制，房主私有快照可额外回填明文密码；组件只发出聊天、换位、踢出、设置、开始和离开意图。
- `online_lobby_avatar.gd`：占用位置以空位同规格、透明中心且无阴影的圆角边框包裹148.35×197.8像素原始武将插画，空位置继续显示可点击的“空位”内容；圆角 shader 只裁切纹理 Alpha，不使用 CanvasItem 颜色输入调制插画，因此边框不会向角色形象叠加黑色滤镜。房主管理按钮由远端成员、房主权限与形象/踢出按钮的合并悬停状态共同决定，鼠标从插画移入“踢出”按钮不会闪烁；按钮默认宽80.35像素、高31像素、左右内缩34像素、距插画底边10像素，背景为当前主题危险色加深32%。
- `card_view.gd`：以 `Node2D` 为根渲染单张实体牌、选中反馈与正式手牌入场偏移；装备牌底部按子类型显示武器、防具、进攻坐骑、防御坐骑或宝物牌；`card_input_area.gd` 独立处理点击、悬停与拖拽数据。
- `equipment_stack_view.gd`：只接收本地装备快照、候选 UID 与选中 UID，按固定槽位渲染堆叠横牌并发出装备 UID 点击信号；不读取 `GameState`、不保存请求对象、不提交规则动作。
- `player_target_view.gd`：以 `Node2D` 为根渲染全玩家共用武将牌；牌面始终竖直，横置状态通过 `PlayerStateOverlay` 的牌外实体端点与牌内透明双层灰框表达，竖置时移除该框。正式对局的 `HoverNameShade` 在鼠标停留且武将牌未翻面时显示公开 `display_name`，节点位于插画之上且忽略鼠标，因此不会遮挡输入区域；统一信息框仍按0.5秒延迟显示完整武将资料。视觉签名只包含身份、体力、横置、翻面、手牌数、装备和判定区等实际画面字段，用牌、响应与技能历史增长不会重建体力点和装备节点；`player_target_input_area.gd` 独立处理点击、右键详情与悬停，并使用牌面实际全局矩形。
- `judgment_zone_view.gd`：只接收判定牌显示名数组，在武将牌底边生成固定菱形与首字，不读取玩家或卡牌实体状态。
- `player_state_overlay.gd`：只接收存活和横置布尔值，并以 `configure_card_size()` 同步牌面几何；绘制阵亡黑白滤镜、红色文字与横置双层框，不参与死亡或连环结算。
- `player_seat_slot.tscn`：只在进入游戏后实例化，组合一个武将牌与其下方独立座次标签，不保存玩家状态或处理交互。
- `skill_button_view.gd`：渲染单个武将技能的名称、状态与说明，并发出稳定技能 ID 请求信号。
- `card_use_animation_layer.gd`：接管正式 `CardView` 节点播放使用者到中央结算区的飞牌动画，维护水平弃牌队列、同帧弃牌批量淡出、同批居中且跨批立即并行的摸牌动画、重开代次隔离，以及卡牌与技能实际发动共用的动态目标指示线。`play_skill_target_indicator(start_position, target_positions)` 复用卡牌线的0.24秒延伸与0.36秒淡出参数，不创建技能专用线条节点；历史预览键接口仅作兼容清理，不得在选择目标时调用。
- `match_menu.gd`：管理右上菜单显隐、卡牌名称操作、UI 风格下拉框、自动身份标记复选框、游戏速度滑条、AI响应速度滑条和下一局2至10人人数输入。风格选项从 `UIStyleRegistry` 构建，自动标记开关写入 `GameSettings`，组件不保存颜色字典、身份推断或对局状态。
- `match_log_panel.gd`：管理“记录”按钮与日志正文显隐并发出展开状态；不读取规则状态、通信模式或日志语义。离线暂停所有权由 `match_table.gd` 协调。
- `character_selection_panel.gd`：渲染本地裁剪选将快照，在左侧显示已亮出的领袖正式武将牌，在右侧显示本地候选并提交稳定武将 ID；候选和公开领袖牌的统一信息请求由该组件转发给牌桌唯一信息框，不绘制其他玩家完成进度长文本。组件通过 `SelectionFrame` 下的稳定相对 `NodePath` 绑定标题、状态、领袖牌区、候选区和确认按钮；初始化时会先为旧场景缓存补建缺失的领袖分隔线，再一次性校验全部必需节点，其他结构缺失时保持隐藏并输出单条完整诊断，不再对多个空实例连续赋值。
- `artwork_loader.gd`：读取可选插画路径并安全加载 `Texture2D`，无效资源统一返回空值。
- `ui_style_registry.gd`：集中登记可选风格、默认风格、中文显示名和全部语义配色，不读取任何场景或对局状态。
- `battle_ui_style.gd`：读取当前风格语义色并生成面板、长条按钮、卡牌和角色框使用的圆角、描边、边距与阴影样式，不保存设置控件。
- `reference_backdrop.gd`：程序化绘制可缩放牌桌背景，隔离参考视觉与业务场景，不保存任何对局数据。
- `decade_battle_layout.gd`：根据2至10人对局人数复刻无名杀顶部/侧边座次模板，并在窗口变化时重新布局；容器本身忽略鼠标，不参与同级控件的输入命中。
- `decade_hand_container.gd`：复刻无名杀 `updateHand()` 的展开、覆盖、选中抬升、悬停顶置、层级和按需横向滚动逻辑。

### 牌面场景与模型

- `CardView` 与 `PlayerTargetView` 都以 `Node2D` 为根，明确表达“牌”而不是按钮。`card_view.tscn` 直接保存与运行时一致的111×148像素纸张、朱红类别条、插画槽、花色点数、牌名、类别和透明输入区域，编辑器默认预览黑桃7【杀】基本牌；脚本只覆盖具体实体内容与选中/禁用状态。其内部 `Control` 子节点不能成为规则状态所有者。
- `CardView` 的类别标签以卡牌主类型和装备子类型共同解析：武器、防具、进攻坐骑、防御坐骑、宝物分别显示“武器牌”“防具牌”“进攻坐骑牌”“防御坐骑牌”“宝物牌”，只有未知装备子类型回退“装备牌”。所有手牌、选择窗、动画牌和公开展示共用该映射。
- `scenes/components/player_target_view.tscn` 是武将牌唯一的编辑器场景，原生保存 148.35×197.8 像素3:4牌框以及立绘、名称、身份、手牌数、势力、体力与装备覆盖层的最终几何信息，不包含座次节点。场景实例不会受玩家人数、座次用途或牌面内容影响。
- `player_target_view.gd` 负责绑定场景节点、渲染快照、生成动态体力圆点与装备条并处理交互；牌框与静态信息控件由场景资源维护。
- 该场景静态保存4/4体力预览，并直接使用正式运行时4点体力的几何结果：体力框位置为`(124.35, 115.8)`、尺寸为`24×82`像素，圆点容器位置为`(2, 4)`、尺寸为`20×74`像素。场景编辑器中看到的位置与游戏内标准4点体力完全一致；其他体力上限继续以相同右下对齐规则动态调整高度。
- `scenes/components/player_seat_slot.tscn` 是游戏内通用座位组合场景，默认尺寸148.35×223.8像素：上方 `(0, 0)` 至 `(148.35, 197.8)` 为武将牌，下方 `(0, 197.8)` 至 `(148.35, 223.8)` 为使用18像素字体、真实控件高度26像素的独立座次标签。其他玩家直接使用完整结构；本地主视角由 `match_table.gd` 隐藏标签并把实例尺寸收紧为148.35×197.8像素。
- `scenes/components/card_view.tscn` 是卡牌唯一的编辑器场景，保存111×148像素3:4纸面、类别色条、插画、花色点数、牌名、类别和透明输入区域。主场景不再内置或复制第二套 `CardTemplate`。
- 运行时仍会按当前武将势力、卡牌类别、体力、行动状态、合法目标和选中状态覆盖必要的动态颜色与描边；这是状态反馈，不是另一套 UI。若要调整武将牌静态位置或尺寸，应直接编辑 `player_target_view.tscn`；装备横条会参考场景内名称、体力与公开区节点的位置自动避让。

武将牌和卡牌根节点均为 `Node2D`，各自的纸面 `Panel` 保存精确尺寸。所有武将牌固定为148.35×197.8像素，手牌固定为111×148像素，两者宽高比均为3:4；名称、装备和状态变化只能更新牌面内部，不得改变外部模型尺寸。

动态组件每次状态快照更新后整体重建，避免旧节点残留选择状态。卡牌默认尺寸为111×148像素，所有玩家武将牌原生场景尺寸固定为148.35×197.8像素。

外围布局继续以 1280×720 为逻辑基准并兼容 1152×648 客户区：技能栏按运行时内容使用 136 像素宽度，手牌与技能栏保留 8 像素间隔，本地座位按 148.35×223.8 像素锚定右下角且默认贴底。四至九人局单侧座位使用 0.35 纵向比例；十人局左右各两名玩家时，统一缩放为 0.90，下侧完整座位距底边201像素、上侧与下侧保留6像素间隔，且同侧共用横坐标；顶部边距为 2 像素，五张顶部座位使用 0.78、0.64、0.5、0.36、0.22 中心比例，避免座位与底部功能区或相邻座位重叠。

## 名称切换

`GameSettings.card_name_mode` 的启动默认值为 `CUSTOM`。主菜单和局内菜单内的名称按钮调用 `GameSettings.toggle_card_name_mode()`；切换后手牌、“粮”、装备、判定区、当前选择摘要和技能说明统一重绘，实体牌 ID、效果和对局状态不变。任何新增卡牌详情组件都必须调用 `GameSettings.resolve_card_name()`，技能说明必须调用 `GameDatabase.resolve_card_names_in_text()`，不得自行判断名称模式。

`GameSettings.ui_style_id` 的启动默认值为 `space_mono`。菜单下拉框可在“崩铁风格”与“暖木家园”之间即时切换，桌面背景、静态面板、按钮、文字、卡牌纸张、牌背、装备条、技能按钮、选将框、选择窗口、目标线和武将状态框会在当前对局中直接重绘，不需要重新开局。风格只改变客户端表现，不修改实体牌、体力数值、目标数组、伤害、回复、AI、网络或回放数据。

`GameSettings.auto_identity_marking_enabled` 启动默认值为 `true`。菜单使用 `CheckBox` 调用 `set_auto_identity_marking_enabled()`；关闭时桌面立即隐藏共享身份模型提供的自动忠反标记，但不清空模型，开启时立即恢复。`match_table.gd` 对每名未知身份角色按“真实公开身份 > 手动非空标注 > 自动忠反标记 > 问号”渲染，不把推断写回快照。

`GameSettings.online_player_name` 启动默认值为“玩家”，`set_online_player_name()` 会去除首尾空白、把空值回退为“玩家”并限制为20个 Unicode 字符；变化时发出 `online_player_name_changed`。`GameSettings.online_avatar_character_id` 保存联机形象稳定武将 ID，变化时发出 `online_avatar_character_changed`。连接入口只读显示名称；创建或加入时同时提交名称与形象 ID。联机大厅通过 `GameDatabase.get_character()` 和 `ArtworkLoader` 解析本机插画元数据，不得把 `Texture2D`、武将节点或正式武将牌场景写入网络 payload。

武将名称统一调用 `GameDatabase.resolve_character_name(character_id)`，从 `game_data/characters` 中对应武将文件的 `display_name` 取得中文名称。武将牌、卡牌询问中的目标名称、出牌与装备目标摘要、悬停说明和本地状态摘要均不得直接显示稳定 `character_id`；卡牌询问也不得使用“玩家X”或“[AI]玩家X”等控制权名称替代已经公开的武将名。配置缺失时分别显示“未选武将”或“未知武将”，避免英文内部 ID 出现在 UI。

## 交互扩展

当前弃牌、响应、火攻展示与弃牌、濒死救援、无懈可击、装备费用和技能选牌等请求，只要牌候选全部属于本地玩家的手牌、木牛或装备区，就使用牌桌内联交互；技能只选目标时直接复用武将牌目标描边与中央确认/取消按钮，技能同时选牌和目标时复用同一套手牌与目标临时集合。丈八蛇矛与木牛流马的主动入口也直接复用装备横条、手牌区和中央按钮。五谷展示牌、他人区域牌和判定牌选择使用 `CardSelectionPanel`。全部表现只提交同一标准响应请求，不能让 UI 直接调用伤害、弃牌或移动函数。

固定组合请求会把 `valid_card_combinations` 作为权威合法集合。内联手牌区与 `CardSelectionPanel` 每选择1张牌，都只保留至少能与当前已选前缀共同组成某个合法完整组合的候选，其余牌立即暗置并禁止输入；取消已选牌后重新计算并恢复可兼容牌。例如【录事】先选择一张二字规则牌名后，所有非二字牌即时不可选。

## 事件选择协议

规则运行时通过 `ChoiceRequest` 暂停当前事件，桌面只渲染请求中的候选并提交 `ChoiceResponse`。`request_id`、`event_id`、`actor_id`、牌/目标/按钮候选、各维度选择数量和 `can_cancel/forced` 是权威校验字段；界面不保存 `GameEvent` 或 `CardInstance` 引用。`choice_type=card_target` 时，`target_ids_by_card_id` 可令不同牌刷新不同合法目标。当前桌面的 `PlayerAction.choose_cards`、`use_card`、`use_skill` 和 `end_play` 会由控制器转换成同一响应结构。

全部 `chooseToUse`、响应、弃牌和效果选牌请求共享 `EventScheduler` 的全局请求 ID 命名空间。控制器必须在运行时登记成功并取得唯一 `request_id` 后才启用手牌/装备区内联选择或显示 `CardSelectionPanel`；玩家提交后也必须先由运行时确认接收，再清理控制器中的待选上下文。旧提交回调只允许关闭相同 ID 的表现，不能覆盖同步创建的下一请求。登记失败、过期响应或 ID 不匹配不会关闭有效交互、推进阶段或移动卡牌。

出牌阶段的 `chooseToUse` 请求只展示当前可以进入出牌动作的实体牌 ID，桌面直接以该 ID 集合控制每张手牌、木牛“粮”与全部元数据声明的主动装备交互状态；提交一张牌或装备主动动作后，控制器先关闭该请求并完成整张牌的材料、逐目标响应与效果结算，再在仍处于出牌阶段时创建下一请求，避免【桃园结义】等多目标锦囊的后续【无懈可击】询问覆盖新出牌请求而导致手牌全部灰显。点击“回合结束”提交取消响应，进入弃牌阶段。响应、弃牌、火攻、五谷和濒死救援沿用相同请求入口，因此不需要为每张牌创建独立 UI 规则。响应转换技能必须由玩家先点击当前亮起的技能按钮，桌面才把该技能的材料改为可选并随提交携带准确 `response_skill_id`；未点击技能时材料保持暗置，规则层也拒绝隐式转换。【罡风】因此不会预先把全部黑色牌自动当成【杀】。每名救援者首次收到的单个提示会明确显示目标达到1点体力尚需回复的点数，并列出对应卡牌源码在当前角色关系下允许的救援牌名；当前规则仍表现为濒死者候选同时包含【桃】与【酒】，其他救援者只包含【桃】。当前救援者每打出1张后若目标仍未达到1点，会立即再次询问同一救援者；其取消后才推进到下一名尚未询问的角色，遍历完一轮后不重新询问全体角色。

网络请求和本地请求使用相同快照字段；非响应者的 `GameState.to_dict()` 会裁剪牌候选和活动过滤上下文。旧事件、错误 actor、重复 UID、非法数量或已结束事件的响应不会改变选中状态、牌区或阶段。
