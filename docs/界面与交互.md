# 界面与交互

## 无名杀对照基准

局内界面以项目内置参考资料为实现基准，不依赖参考扩展的运行时脚本：

- `无名杀参考代码/十周年UI/decadeLayout.css`：二至八人座次百分比、左右侧座位和顶部对称布局。
- `无名杀参考代码/十周年UI/layout_new.css`：底部手牌区、操作控制条、108×150 牌面和横向滚动边界。
- `无名杀参考代码/十周年UI/extension.js` 的 `updateHand()`：手牌完整展开、等距覆盖、最小露出宽度和超宽滚动算法。
- `无名杀参考代码/十周年UI/equip_new.css`：左下独立装备槽及五种固定装备位。
- `参考图/ScreenShot_2026-07-14_065613_670.jpg`：顶部/侧边武将牌、中央留空、底部操作提示、本地武将牌和技能按钮的整体层级。
- `参考图/局内角色武将牌示例.png`：势力圆徽、左侧竖排武将名、右侧体力圆点、左下手牌数角标、顶部身份徽记和武将牌下方中文座次号。

Godot 版本只复刻布局规则、视觉层级与操作语义，不加载参考扩展的 JavaScript、CSS、Spine 或图片资源，也不让 UI 直接接触权威状态。

## 视觉布局

主场景采用参考无名杀的 1280×720 环桌卡牌布局，同时保持《崩铁杀》的深青、木色与金色视觉语言：

- 逻辑视口的标准基准分辨率为 1280×720；默认启动窗口为 1152×648，为系统标题栏、窗口边框和任务栏保留空间。界面使用 `canvas_items` 与 `keep` 宽高比策略完整显示逻辑视口；底部与右侧关键区域同时使用边缘锚点，因此编辑器嵌入运行未应用画布拉伸时也不会超出客户区。

- 左上角：只显示当前第几轮、摸牌堆剩余牌数和对局时长，不再显示当前行动角色、回合总序号或阶段名称。信息框位于 `(18, 18)`，尺寸为156×84像素；时长从本局创建时开始按单调时钟累计，格式为“分:秒”，终局后冻结。右上角只保留一个“菜单”入口。菜单面板集中提供卡牌名称切换、按设置重新开局和下一局2至10人设置，人数修改不影响正在进行的对局。菜单分支在场景初始化后提升至真实 GUI 命中最前端；全屏座次容器仍忽略鼠标，只由武将牌的透明输入子组件接收点击，因此动态武将牌和选将遮罩都不能遮断菜单。
- 其他玩家：使用无名杀 `data-position` 座次方向排列。桌面先把绝对座次旋转为从本地下家到本地上家的环形顺序，再依次放置到右侧、顶部与左侧；因此本地玩家随机座次后，视觉方向仍与规则行动顺序一致。二至三人局全部位于顶部；四至九人局先放右侧、再由右向左排列顶部座位、最后放左侧；十人局左右各放两名、顶部放五名。每个游戏内座位由武将牌与其下方独立座次标签组成；武将牌显示势力、武将名、体力、手牌数和公开装备，座次标签只显示中文座次号。鼠标悬停任一正式对局武将牌时，牌面上部显示与武将牌等宽的148.35×32像素、从黑色向下渐变透明的阴影，并以10像素字体显示该玩家名称；选将候选不显示玩家名阴影。`player_target_view.tscn` 的默认隐藏“牌背”覆盖层会在快照 `face_down=true` 时遮挡这些牌面信息，透明输入区域仍位于最上层。判定牌在武将牌底边按快照顺序显示为带牌名首字的菱形；木牛“粮”数量紧跟木牛流马装备名显示，悬停说明保留全部公开名称。
- 身份牌先随机分配；选将完成后旋转座次数组，使主公固定为一号位，再按顺时针排列二号位、三号位和后续座位。界面座次标签读取快照 `seat_number`；真实玩家名称按最终座次写为“玩家1”“玩家2”等，内置 AI 写为“[AI]玩家1”“[AI]玩家2”等。未知身份徽记“？”允许本地玩家点击并在忠臣、反贼、内奸三项中添加或修改客户端标注；标注不写入规则状态、AI、网络或回放，真实身份公开后立即覆盖标注并禁止再次标记。稳定 `player_id` 只用于网络、回放和实体所有权。
- 牌桌中心：完全留空作为卡牌使用与弃牌结算的视觉区域，不绘制弃牌堆边框、牌堆数量或固定占位图。
- 手牌区：固定在底部中央，使用111×148像素的3:4竖版卡牌；透明外层不绘制背景框，栏高固定为175像素，为148像素牌面、18像素选中抬升与1.06倍悬停补偿共同保留完整空间。空间充足时以2像素间隔展开，空间不足时自动重叠，每张牌至少露出64像素。选中牌向上移动18像素，选中与取消选中分别使用0.025秒位移动画；选中并悬停时仍完整位于手牌滚动框内，不会被框外内容裁切。只有1个技能时手牌右边界延伸到第一技能按钮左侧8像素；技能数大于等于2时右边界缩短到第二技能按钮左侧8像素。
- 操作区：固定在手牌区上方且不绘制任何面板背景，只显示具体询问提示与操作按钮；内联询问不再重复显示“响应询问｜已选择0张｜需要1至1张”一类通用摘要。没有本地出牌、响应、弃牌或效果选择时整组隐藏。146×42像素的“确定”和“取消”作为中央主按钮，水平间距固定为28像素；112×36像素的朱红色“回合结束”脱离交互面板并固定在取消按钮右侧，不与取消按钮相交；不再显示“重铸”和“存木牛”按钮。群体锦囊询问本地玩家是否使用【无懈可击】时，该按钮临时改为“不响应该锦囊”：点击后使用深灰状态并立即放弃当前询问，同一实体锦囊本次处理区生命周期内的后续无懈询问自动提交空响应；再次点击可取消，锦囊离开处理区后自动恢复“回合结束”。
- 操作区初始化：`MatchTable` 通过主场景直属路径取得 `InteractionPanel`，不依赖场景唯一名称元数据；进入场景树时会统一校正透明样式、主按钮规格与间距、禁用样式、旧按钮隐藏状态和右侧回合结束按钮层级，使旧场景缓存不能产生空节点访问或恢复已废弃布局。所有不可提交的确定、取消及同类交互按钮固定使用深灰背景、低对比度边框和灰色文字；禁用期间不接收输入，也不切换悬停或按下外观。
- 统一选择入口：候选全部属于本地玩家且来自手牌、木牛“粮”或装备区时，直接复用底部手牌区、左侧装备区和“确定/取消”按钮，不打开遮罩窗口；普通出牌同样只启用当前 `chooseToUse.card_ids` 中的手牌、木牛“粮”或主动装备。木牛“粮”固定排列在普通手牌左侧。任何非候选或当前无合法动作的手牌都使用深灰禁用样式且不接收点击或拖动；装备候选先向右移动10像素，选中后再向右移动10像素，进入候选、选中或复原位置都使用0.25秒位移动画。上下文明确定义 `equipment_uid` 的装备触发询问会自动选中对应装备，玩家只需确定发动或取消放弃。点击丈八蛇矛后选择2张普通手牌作为虚拟【杀】材料，点击木牛流马后选择1张普通手牌存为“粮”；两种模式都保持装备本身选中且不移动权威区域。五谷展示牌、他人区域牌和判定区等不完全位于本地可见区域中的候选继续使用 `CardSelectionPanel`，不可见手牌显示正式 `CardView` 的“牌背”覆盖层。正式主场景把通用选择框覆盖为820×460像素，背景滤镜透明度为0.42；公共只读牌禁用输入但保持正常亮度。
- 五谷丰登使用后立即创建全体可见的公共选牌窗口，不等待第一名角色完成无懈询问。窗口使用视口中心锚点与对称四边偏移，动态改变尺寸后仍保持严格居中，不会沿左上角局部坐标移出屏幕。窗口在每名玩家或 AI 依次选择期间持续保存；非当前本地选择者只读查看，底部确定/取消行隐藏。本地玩家进入与五谷选牌不同类型的【无懈可击】等响应时，公共窗口临时关闭并让出手牌区、确认和取消输入，响应结束后立即从保留的公共快照恢复；旁观客户端仍可继续显示公共牌位。最初亮出的每张牌拥有固定牌位，被取得后不删除、不补位，而是以 `(0.72, 0.72, 0.72, 0.48)` 调制色留下复制虚影；牌底 `(4, 118)` 至 `(107, 144)` 的103×26像素标签使用13像素字体显示领取者武将名。公共牌阵使用4列 `GridContainer`，每行固定4张、间距8像素，不显示“展示区”标题；窗口按实际列数收紧，4列时牌阵宽468像素，面板只保留36像素横向总边距，右侧不再保留旧820像素窗口产生的大块空白。下一名选择者只能点击仍未领取且属于当前权威请求候选的牌。
- 本地装备区：固定在底部左侧，由 `EquipmentStackView` 复刻 `equip_new.css` 的独立槽位布局。透明外层固定为150×175像素，与手牌栏等高；武器、防具、进攻坐骑、防御坐骑、宝物五槽始终可见，相邻间距固定3像素，并平均分配全部高度，默认每槽32.6像素。空宝物槽与其他空槽一样显示深胡桃色底框和类型图标，不绘制“无”文本；已装备槽在原位置覆盖浅米色牌面并显示类型图标、花色、点数和牌名，不能自动补到前面的空位。装备栏范围为 `x=18..168`，手牌栏从 `x=168` 开始，两者边界零间隙相接；候选右移10像素、选中后总右移20像素，并保持高于透明手牌区域绘制。
- 本地技能区：固定在本地武将牌左侧，只显示技能按钮，不绘制技能区背景或状态说明。每个按钮固定只显示技能名前两个字，完整名称、说明与状态保留在工具提示中；技能按定义顺序从右到左、从下到上排列，每行最多2个，第三个从右侧第二层开始。按钮默认62×44像素，水平与垂直间距均为6像素。
- 本地武将牌：视觉容器固定在底部右侧，与其他玩家共用 `PlayerTargetView` 排版，整张牌可点击选择自己，并显示本地玩家的势力、武将名、体力和手牌数；本地装备只在左侧独立装备栏显示，不在第一视角武将牌上重复绘制。独立标签显示每局随机分配的真实中文座次号。
- 底部装备区、手牌区、技能区、操作区和本地玩家座位容器全部锚定到客户区底边；技能区与本地座位容器另外锚定到右边，手牌区使用左右安全边距自动收缩并保留横向滚动。即使根控件直接缩小为 1152×648，所有底部区域仍完整位于客户区内。
- 战局记录由左侧108×46像素“记录”按钮控制；点击后在按钮上方展开360×176像素日志正文，再次点击“收起记录”隐藏正文。折叠只改变可见性，隐藏期间规则日志仍会持续追加。

其他玩家手牌牌面不会进入本地快照。界面只渲染公开数据和本地私有数据，不通过视觉组件读取或修改 `GameState`。

## 牌桌视觉层级

- 牌桌视觉参考无名杀“十周年 UI”的实木包边、暗金内框和低对比度夜景远景，但不直接依赖参考扩展目录中的运行时资源。
- `reference_backdrop.gd` 作为独立背景组件程序化绘制近黑外底、深胡桃木桌框、夜色天幕、26个固定星点、山脊/建筑剪影、古金同心环和十二段星轨刻度；组件忽略鼠标输入，不读取对局状态。
- 背景组件默认使用 18 像素桌面留白、14 像素木框宽度、30 像素桌面圆角、150 像素中央装饰半径和 0.16 装饰透明度；这些表现参数均在脚本顶部通过 `@export` 暴露。
- 原有 `assets/ui/table_ornament.svg` 继续作为低透明度全桌星轨纹样，与程序化中央铭纹叠加使用；二者都只承担背景装饰。
- `无名杀参考代码/十周年UI/.gdignore` 将参考扩展明确隔离为开发资料，避免网页脚本、Spine 动画和海量图片被 Godot 导入或进入游戏导出包。
- 中央动画落点位于基准视口约 `(540, 250)` 至 `(740, 400)` 的透明区域；该节点只提供动画坐标，不显示任何弃牌堆 UI。
- 默认八人局的 7 名对手从本地下家起依次位于右侧 1 名、顶部 5 名和左侧 1 名；二至八人局使用参考 CSS 的原始比例，九至十人局在相同边界内对称扩展。
- 武将体力位于武将牌右下角的不透明圆角矩形容器：背景与1像素暗金描边使用场景内 `StyleBoxFlat`，四角半径均为6像素并开启1像素抗锯齿。体力框右边和底边直接对齐武将牌边缘，右下圆角与武将牌6像素圆角使用相同参数，不再绘制斜边或折线。

## 统一武将牌格式

- 所有玩家武将牌以 `Node2D` 为根，固定为 148.35×197.8 像素的3:4规格，直接复用 `player_target_view.tscn` 保存的原生编辑器几何，不按座次、人数或本地/对手身份切换规格。牌面不是按钮；`PlayerTargetInputArea` 作为透明子组件承接点击和卡牌拖放。
- 座次标签不属于武将牌场景，而是只在进入游戏后由 `player_seat_slot.tscn` 添加到每位玩家牌面下方；标签固定为 148.35×26 像素，字体为 18 像素，座位容器总尺寸为 148.35×223.8 像素，座次按快照 `seat_number` 显示为“一”至“十”。
- 左侧武将名竖条固定为 22×93 像素，使用 10 像素字体并按字符逐行竖排。
- 势力圆徽固定为 26×26 像素、左下手牌数角标固定为 24×24 像素；势力简称与颜色来自 `game_data/factions.json` 的 `factions` 数组。
- 右下体力边框为宽24像素的动态不透明梯形，内部圆点使用18像素字体和-10像素纵向间距；上限1至5时高度随圆点数量变化，超过5时显示数字。身份徽记固定为23×20像素，身份与手牌数覆盖层在武将牌资源中默认隐藏，仅正式对局开启。
- 其他玩家的公开装备按武器、防具、进攻坐骑、防御坐骑、宝物固定槽位显示，最多5条；每条为141.35×15像素，长度严格等于武将插画宽度，相邻槽位覆盖1像素，内容为花色、点数和当前名称模式下的牌名。未装备槽位不绘制横条但保留对应位置，后续装备不得自动补位；宝物未装备时只计算前4个槽位，实际装备宝物后才扩展为5槽布局。木牛流马额外在牌名后显示全体可见的“粮”数量，包括0张。第一视角本地武将牌关闭该层，改由左侧常驻五槽装备栏独立显示。
- 判定区使用22×22像素标记槽，菱形中心位于武将牌底线`y=197.8`；第一张标记左边缘距牌面左侧28像素，相邻标记边缘间距6像素，按判定区数组顺序从左到右排列并显示当前牌名的首字。
- `player_target_view.tscn` 不再包含`Status`文本节点。阵亡角色的整张武将牌覆盖0.62亮度的黑白滤镜，并在中心显示28像素红色“阵亡”；存活横置角色使用2.5像素灰色链环组成的链条水平穿过牌面正中心。
- 当前回合角色始终使用3像素亮金边框；普通单人选择根据活动请求的 `actor_id` 单独提亮操作者，若操作者不是当前回合角色则额外使用2像素青绿色边框。【无懈可击】同时响应期间读取公开 `responder_ids`，把本轮全部存活玩家统一设为操作高亮，即使某名玩家没有合法无懈候选也保持相同表现，客户端不得根据高亮判断其手牌。所有回合与操作高亮只改变武将牌底色和边框，不绘制青绿色外发光。已选目标同样使用亮金粗边；合法目标只有在不是当前回合角色时使用青绿色粗边，避免临时合法性覆盖回合金框。
- 势力徽记、武将名、手牌数、身份、体力、公开区、装备横条和座次字体均使用上述固定尺寸；武将插画保持牌面的主要视觉占比。

## 十周年风格组件规范

- `main.tscn` 是桌面、菜单、选将遮罩与静态面板的组合入口；卡牌静态牌面只在 `card_view.tscn` 维护，武将牌静态牌面只在 `player_target_view.tscn` 维护。`BattleUIStyle` 只为势力色、卡牌类型、选中和合法目标等运行时状态提供动态颜色与描边。
- 武将状态卡采用窄圆角内嵌金属框：普通状态使用暖黑底与暗金边，当前回合角色使用3像素亮金边，当前操作者使用提亮木金底与2像素青绿边，合法目标使用青绿粗边，已选目标使用亮金粗边；上述状态均不附加彩色外发光。
- 本地武将框与其他角色遵循同一动态状态规则，不再永久占用亮金边；装备区和技能区外层保持透明，左上对局信息区与可折叠记录入口继续使用1至2像素暗金边。
- 操作按钮采用参考扩展的横向金属按钮比例：中央确定与取消均为146×42像素暖金强调按钮并保持28像素水平间距；右侧回合结束为112×36像素朱红按钮。菜单内部操作继续使用各自既有样式，按钮状态只改变颜色与描边，不改变控件尺寸；禁用交互按钮保持深灰且没有悬停反馈。

## 选将界面

- 开局进入全屏选将遮罩，主公先从随机候选中选择并立即亮出；主公确认后，其他玩家各自在自己的客户端同时选择，所有人完成后统一亮出并关闭遮罩。
- 每名玩家默认随机展示5张可选武将牌；数量读取 `MatchController.character_candidate_count`，后续可扩展，实际显示数量不超过武将库总数。
- 候选使用正式 `PlayerTargetView` 场景，保持148.35×197.8像素 Node2D 武将牌模型；候选布局直接读取场景牌宽，不在脚本中保存重复尺寸。鼠标悬停可选武将时以0.14秒二次缓出从1.00倍过渡到1.08倍，并围绕牌面中心放大；移开后用相同时长恢复。点击只让所选武将显示亮金边框，未选候选不再因统一合法状态获得青绿色发光或描边；点击确认后才提交 `select_character` 标准动作。
- 主公阶段只有主公能看到自己的候选；主公确认后，选将框左侧以0.78倍显示其只读正式武将牌，并使用2像素竖线与右侧本地候选分隔。没有公开主公时竖线与主公区域都不占位，候选区域直接从原主公牌左边界开始。界面不再显示“主公已亮出……其他玩家同时选择，完成……”等确认进度长文本，也不显示其他玩家具体选择。
- 当前选将框按1280×720逻辑视口使用1040×540像素主面板；有主公时左侧只读区域从 `(40, 106)` 开始，右侧候选区域从 `x=214` 开始；无主公时从 `x=40` 开始。默认5张候选以14像素间距水平排列，候选数量变化时由组件读取正式牌宽重新计算位置，不在桌面脚本保存五张牌的固定坐标。

## 局内菜单

- 右上角唯一常驻按钮文字为“菜单”，点击后显示集中面板；原独立“牌名”和“重开”按钮不再存在。
- 新启动默认显示三国杀卡牌名称，菜单内可切换为《崩铁杀》自定义名称并随时切回；名称切换只重绘显示文本，不改变卡牌 ID、效果或对局状态。
- 菜单内新增“AI响应速度”滑条，默认 0.30 秒，可在 0.05 至 1.00 秒之间以 0.05 秒步长调整。该数值是每次 AI 行动或选牌响应前的等待时间，数值越小响应越快；修改后立即作用于后续 AI 计时器，不需要重开对局。
- 菜单内人数输入范围为2至10，默认继承控制器的8人配置。输入文本会即时同步，点击“按设置重新开局”时优先读取当前键入内容并限制到合法范围，随后创建对应人数的新对局并重新进入选将。
- 菜单面板的输入顺序高于动态武将牌与选将遮罩，因此选将尚未完成时仍可继续调整人数并重新开局；人数修改只在重开时生效。
- 手牌保留浅色实体纸张以保证花色和牌名可读，外框改用硬质窄圆角与深阴影；禁用纸张与类别条默认压暗38%，插画和文字使用45%亮度深灰调制，选中、悬停和类别色仍遵循原有交互语义。
- 十周年风格仅调整表现层。组件继续只消费裁剪快照、发出稳定 ID 信号并提交标准动作，禁止通过视觉节点直接读取或修改规则状态。

## 出牌动画

- 规则核心使用可序列化 `CardPresentationEvent` 统一描述 `useCard`、`showCards`、`delayedJudge` 和 `judge`，内容包含表现序号、关联事件、卡牌快照、来源、目标与后续弃牌所有权，不向界面暴露权威状态对象。
- 本地玩家使用卡牌时，动画层直接接管手牌中的同一 `CardView` 节点；AI 或其他不可见来源使用牌时，也实例化同一个 `card_view.tscn` 正式牌面。本地牌从手牌区实际节点进入动画层，其他玩家的牌从对应武将牌中心进入；全部牌都飞向中央弃牌展示区，默认飞行时间为 0.42 秒，抵达后停留 0.48 秒，再用 0.36 秒淡出。
- 【火攻】展示手牌和判定阶段也使用同一动画层：`showCards` 从展示者武将牌中心飞入中央牌桌且不移动权威实体；每张延时锦囊先用 `delayedJudge` 从判定角色锚点展示，默认保留1.00秒后才由 `judge` 把牌堆顶1张判定牌直接从中央弃牌展示锚点公开，不从判定角色处打出；判定完成后默认再保留1.00秒才展示判定区下一张牌。两种间隔分别读取 `MatchController.delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds`，检查器范围均为0.00至3.00秒。上述展示都没有使用牌目标指示线。
- 本地玩家摸牌或从其他区域获得牌时，先按实体 UID 创建或复用手牌容器中的正式 `CardView`，再从手牌可视区右侧 24 像素外用 0.42 秒移动到最终手牌位置；动画结束后同一节点继续承担选择与出牌。其他玩家的隐藏获得动画仍只显示牌背。
- `CardPresentationEvent` 明确声明后续弃牌所有权。动画层先按本局单调 `presentation_id` 去重，再让真实使用牌和判定牌按实体 UID 原子取得所有权；节点接管与所有权登记之间不存在可插入重复移动的窗口。若响应等待超过 0.42 秒飞行、0.48 秒停留和0.36秒淡出，后续从处理区进入弃牌堆只消费一次所有权；消费记录继续保留到权威实体进入非弃牌新区域，因此相同表现包、不同表现 ID 的迟到包或相同移动增量重复到达都不会在牌桌上方或中央生成第二张牌。火攻等纯 `showCards` 只按表现 ID 去重，不占用实体 UID 的未来弃牌所有权。
- 有目标的卡牌会绘制从使用者指向每名目标的4像素金色指示线；线条默认用0.24秒从来源动态延伸到目标，延伸完成后立即独立用0.36秒逐渐淡出，不等待飞牌停留或弃牌队列。多目标卡牌为每名目标保留独立武将牌中心终点，显示多根同步延伸并同步渐隐的指示线，无目标牌不绘制指示线。
- 本地玩家无论作为使用者还是目标，统一使用手牌区上方中心作为指示锚点，默认与手牌区顶边保持8像素间距；其他玩家统一使用各自武将牌中心。因而本地玩家对其他角色使用牌时，线条从手牌区上方中心指向目标武将牌；其他角色对本地玩家使用牌时，线条从来源武将牌指向手牌区上方中心。
- 飞牌保持正式111×148像素的3:4模型和1.0倍目标缩放，全程保持0度旋转，不替换为细长牌或简化标签。多张牌同时存在时按66像素中心间距水平铺开，成员变化后使用0.18秒补位，展示手牌、判定牌、响应弃牌和普通弃牌全部进入同一中央展示队列；同一帧进入弃牌堆的多张牌按信号顺序从左到右完整显示，并作为同一批次同时使用0.36秒淡出。每张中央牌使用1个生命周期 Tween 覆盖0.42秒飞行与0.48秒停留，不再创建2个 SceneTreeTimer 等待协程。动画层使用30层，高于普通牌桌和武将牌，低于40层选将遮罩与50层菜单；该层忽略鼠标输入，不会遮断点击、拖放、目标选择或确认按钮。
- 摸牌、获得和响应弃牌也通过 `card_transfer_requested` 播放区域移动。本地玩家所有进入手牌区的牌只登记实体 UID；包含该牌的快照到达后，手牌容器按 UID 创建或复用唯一正式 `CardView`，这个节点从手牌可视区右边缘外24像素处用0.42秒进入自身最终布局位置并显示正面，动画结束后不销毁，继续作为可选择和可拖放的真实手牌。其他玩家连续摸牌时，每张实体牌都实例化正式 `CardView` 并显示“牌背”覆盖层，按0.08秒间隔依次开始飞行，并以每张向右18像素、向上3像素的偏移堆叠显示；其他玩家的获得动画继续使用公开玩家锚点。处理区到弃牌堆的使用牌由持续到最终移牌的实体 UID 记录接管，防止响应等待后同一实体牌重复出现在中央位置。
- 重新开局会先递增动画代次，清空旧局的区域转移索引、摸牌堆叠索引和补间索引，并立即隐藏旧牌面。所有删除操作使用稳定实例 ID，摸牌堆叠数组不保存对象引用，也不把可能已经释放的 `CardView` 作为容器删除参数；上一局仍在等待的补间正常结束后先比较代次，不匹配时只释放自己的隐藏牌面，不能访问或清理新一局动画。
- 飞牌进入中央区域属于客户端结算表现。装备牌、延时锦囊等卡牌仍按规则进入装备区或判定区，动画不会改变其最终区域。
- 对手座位按玩家 ID 持久复用，普通状态快照只重建轻量视图索引，不再释放并实例化整桌武将牌。`CardView` 与 `PlayerTargetView` 缓存包含名称模式的配置签名；快照内容未变化时不会重复加载插画、生成主题样式、体力圆点、装备横条或判定标记。玩家人数、本地座次或实际公开状态变化时仍会立即失效并刷新对应节点。

## 插画预留

- 每张卡牌在牌面中部保留插画区域，花色与点数固定在左上角，牌名和类别固定在底部，不会被插画覆盖。
- 所有玩家的武将插画槽固定为 `(4, 4)` 至 `(145.35, 194.8)` 的 141.35×190.8 像素区域，覆盖牌面绝大部分面积；3:4牌面设计只扩大牌框和插画，势力徽记、竖排武将名、体力圆点、手牌数和身份徽记保持固定规格，装备横条完整铺满插画宽度，座次标签位于牌面外部。
- 本地与其他玩家使用同一插画裁切规则和 148.35×197.8 像素牌面尺寸，不使用单独缩略图组件。
- 卡牌和武将定义统一使用可选字段 `art_path`，值为 `res://` 开头的 Godot 资源路径。
- `art_path` 缺失、为空、文件不存在或资源不能加载为 `Texture2D` 时，界面显示统一“插画预留”占位，不中断对局。
- 推荐资源目录为 `res://assets/art/cards/` 和 `res://assets/art/characters/`，具体命名及示例见 `assets/art/README.md`。
- 卡牌插画使用覆盖裁切保持比例，武将插画同样保持比例并裁切到固定槽位；替换图片不改变控件尺寸。

## 卡牌视觉反馈

- 卡牌顶部使用 4 像素类别色条：基本牌为朱红色、锦囊牌为靛青色、装备牌为青铜色。
- 火焰属性牌优先使用橙红色，雷电属性牌优先使用蓝色，便于不阅读说明时快速辨认属性。
- 可交互卡牌悬停时在0.12秒内缩放至1.06倍并提高绘制层级；相邻手牌继续保持当前展开或压缩位置。
- 鼠标离开后恢复原始缩放；选中卡牌仍保持 14 像素抬升和金色描边。
- 类别色与动画只属于视觉反馈，卡牌合法性仍完全由规则预览和核心校验决定。

## 标准出牌流程

1. 点击一张手牌或木牛“粮”选择实体 UID；已选卡牌使用金色描边并向上抬升 14 像素。
2. 界面调用 `MatchController.get_card_use_preview()` 获取只读规则预览，并用青色描边标记下一步合法目标。
3. 点击角色状态卡按顺序选择目标；再次点击已选目标可取消。若卡牌最多只需要1个目标，直接点击另一名合法角色即可替换旧目标，无需先取消；若当前仅有1名合法候选，界面会自动选择并锁定该目标，等待玩家点击“确定”或按`Enter`。已选目标使用金色描边。
4. 多目标在界面中按点击顺序编辑与取消，界面最多保留 3 名目标；提交后除借刀杀人的两个语义目标外，权威规则层统一按当前回合角色起算的行动顺序结算。
5. 当前牌与目标组合通过预览校验后，“确定”按钮才会启用；点击或按 `Enter` 后提交标准 `use_card`。

规则核心仍会在 `submit_action()` 中执行最终校验。UI 预览仅用于引导，不能替代权威规则判断。

### 快捷操作

- `Enter`：当前牌和目标组合合法时执行“确定”。
- `Esc`：取消当前选牌与全部目标。
- 鼠标右键：与 `Esc` 相同，取消当前选择。
- `Space`：未选择卡牌且处于本地出牌阶段时结束出牌阶段。
- 本地武将牌整体可点击以选择自己；“选择自己”按钮继续作为触屏和低分辨率下的明确入口。

## 拖拽出牌流程

- `CardView` 根节点为 `Node2D`，透明 `CardInputArea` 通过 Godot 原生拖放接口提供稳定实体 UID，不复制或移动权威卡牌对象。
- 开始拖动卡牌时，该牌会同步成为当前已选牌，并立即刷新合法目标。
- 将卡牌拖放到青色角色卡，会依次完成选牌与选目标；随后点击“确定”或按 `Enter` 提交动作。
- 非法目标、死亡角色和未处于本地出牌阶段的卡牌不会接受拖放。
- 自身目标牌会自动选择并锁定本地玩家；普通牌只有 1 名合法目标时同样自动锁定，全体目标牌不要求手动选目标，由规则层按存活座次自动展开。

点击与拖拽共用 `_selected_card_uid`、`_selected_target_ids`、规则预览和 `PlayerAction` 提交入口，因此不存在两套出牌规则。

## 其他动作

- 选中定义中 `recast=true` 的普通手牌且没有选择目标时，中央“确定”直接提交 `recast_card`；当前默认牌堆中该流程用于【铁索连环】，木牛“粮”不能进入重铸。
- 木牛流马在本阶段可以存粮时作为宝物装备候选向右移动；点击装备后选择1张普通手牌并按“确定”提交 `store_wooden_ox`，若已选择目标，则该目标接收木牛流马和全部“粮”。
- 丈八蛇矛在可以使用或打出【杀】时作为武器装备候选向右移动；点击装备后选择正好2张普通手牌，出牌时再选择1名攻击范围内目标，响应时直接按“确定”打出虚拟【杀】。
- 右侧“回合结束”提交 `end_play`，普通内联响应或效果选择期间隐藏；群体锦囊的【无懈可击】询问期间改为“不响应该锦囊”开关。
- 任何非法次数、距离、目标、区域或阶段都会由核心拒绝，并在本地玩家区显示最近一次错误原因。

## 技能控制条

- 技能栏位于本地玩家状态与手牌之间，外层完全透明且只显示按钮。
- 桌面根据本地武将配置中的 `skills` 数组动态生成按钮，不硬编码武将 ID 或技能数量。
- 每个按钮正文只显示技能名前两个字，悬停时显示完整名称、技能说明与接入状态。
- `trigger` 为 `sample_only` 的样例技能显示为“预留”。点击后只展示说明和“规则效果尚未接入”提示，不提交动作、不修改状态。
- 后续主动技能可在元数据中声明 `ui_enabled: true`，并由独立技能交互控制器处理选牌、选目标、确认和标准动作构建。
- 技能按钮默认尺寸为62×44像素；按定义顺序从右到左、从下到上排列，每行最多2个，水平和垂直间距均为6像素。选中技能使用3像素金色描边，可发动技能使用青绿色边框。
- 主场景初始化会把旧版本遗留的 `HFlowContainer` 技能容器原位升级为 `SkillButtonGrid`，并重新应用透明技能区、透明手牌区和175像素装备区高度；该兼容迁移只用于消除编辑器旧场景缓存造成的节点类型错误，不改变技能定义或按钮顺序。

## 组件职责

- `match_table.gd`：桌面协调器，渲染对局快照、左上轮数/牌堆/时长、当前回合与当前操作者状态，按实体 UID 对账并复用本地正式手牌节点，把对手座次旋转为本地相对行动顺序，维护普通出牌、本人手牌/装备区内联选择和公共选牌展示，请求规则预览并构建 `PlayerAction`；不计算选将候选或保存菜单人数。
- `card_view.gd`：以 `Node2D` 为根渲染单张实体牌、选中反馈与正式手牌入场偏移；`card_input_area.gd` 独立处理点击、悬停与拖拽数据。
- `equipment_stack_view.gd`：只接收本地装备快照、候选 UID 与选中 UID，按固定槽位渲染堆叠横牌并发出装备 UID 点击信号；不读取 `GameState`、不保存请求对象、不提交规则动作。
- `player_target_view.gd`：以 `Node2D` 为根渲染全玩家共用纵版武将牌；`player_target_input_area.gd` 独立处理点击和卡牌拖放。
- `judgment_zone_view.gd`：只接收判定牌显示名数组，在武将牌底边生成固定菱形与首字，不读取玩家或卡牌实体状态。
- `player_state_overlay.gd`：只接收存活和横置布尔值，绘制阵亡黑白滤镜、红色文字与中心链条，不参与死亡或连环结算。
- `player_seat_slot.tscn`：只在进入游戏后实例化，组合一个武将牌与其下方独立座次标签，不保存玩家状态或处理交互。
- `skill_button_view.gd`：渲染单个武将技能的名称、状态与说明，并发出稳定技能 ID 请求信号。
- `card_use_animation_layer.gd`：接管正式 `CardView` 节点播放使用者到中央结算区的飞牌动画，维护水平弃牌队列、同帧弃牌批量淡出、同一玩家连续摸牌的顺序堆叠、重开代次隔离，以及每次出牌独立的动态延伸目标指示线。
- `match_menu.gd`：管理右上菜单显隐、卡牌名称操作、AI响应速度滑条和下一局2至10人人数输入，通过信号或全局设置请求桌面更新。
- `match_log_panel.gd`：管理“记录”按钮与日志正文显隐，不读取规则状态或日志语义。
- `character_selection_panel.gd`：渲染本地裁剪选将快照，在左侧显示已亮出的主公正式武将牌，在右侧显示本地候选并提交稳定武将 ID；不绘制其他玩家完成进度长文本。组件通过 `SelectionFrame` 下的稳定相对 `NodePath` 绑定标题、状态、主公牌区、候选区和确认按钮；初始化时会先为旧场景缓存补建缺失的主公分隔线，再一次性校验全部必需节点，其他结构缺失时保持隐藏并输出单条完整诊断，不再对多个空实例连续赋值。
- `artwork_loader.gd`：读取可选插画路径并安全加载 `Texture2D`，无效资源统一返回空值。
- `battle_ui_style.gd`：集中提供十周年风格面板、长条按钮、卡牌和角色框使用的颜色、圆角、描边、边距与阴影样式。
- `reference_backdrop.gd`：程序化绘制可缩放牌桌背景，隔离参考视觉与业务场景，不保存任何对局数据。
- `decade_battle_layout.gd`：根据2至10人对局人数复刻无名杀顶部/侧边座次模板，并在窗口变化时重新布局；容器本身忽略鼠标，不参与同级控件的输入命中。
- `decade_hand_container.gd`：复刻无名杀 `updateHand()` 的展开、覆盖、选中抬升、悬停顶置、层级和按需横向滚动逻辑。

### 牌面场景与模型

- `CardView` 与 `PlayerTargetView` 都以 `Node2D` 为根，明确表达“牌”而不是按钮。`card_view.tscn` 直接保存与运行时一致的111×148像素纸张、朱红类别条、插画槽、花色点数、牌名、类别和透明输入区域，编辑器默认预览黑桃7【星穹斩】基本牌；脚本只覆盖具体实体内容与选中/禁用状态。其内部 `Control` 子节点不能成为规则状态所有者。
- `scenes/components/player_target_view.tscn` 是武将牌唯一的编辑器场景，原生保存 148.35×197.8 像素3:4牌框以及立绘、名称、身份、手牌数、势力、体力与装备覆盖层的最终几何信息，不包含座次节点。场景实例不会受玩家人数、座次用途或牌面内容影响。
- `player_target_view.gd` 负责绑定场景节点、渲染快照、生成动态体力圆点与装备条并处理交互；牌框与静态信息控件由场景资源维护。
- 该场景静态保存4/4体力预览，并直接使用正式运行时4点体力的几何结果：体力框位置为`(124.35, 115.8)`、尺寸为`24×82`像素，圆点容器位置为`(2, 4)`、尺寸为`20×74`像素。场景编辑器中看到的位置与游戏内标准4点体力完全一致；其他体力上限继续以相同右下对齐规则动态调整高度。
- `scenes/components/player_seat_slot.tscn` 是游戏内座位组合场景，尺寸固定为 148.35×223.8 像素：上方 `(0, 0)` 至 `(148.35, 197.8)` 为武将牌，下方 `(0, 197.8)` 至 `(148.35, 223.8)` 为使用 18 像素字体、真实控件高度 26 像素的独立座次标签。它只由 `match_table.gd` 在进入对局后实例化。
- `scenes/components/card_view.tscn` 是卡牌唯一的编辑器场景，保存111×148像素3:4纸面、类别色条、插画、花色点数、牌名、类别和透明输入区域。主场景不再内置或复制第二套 `CardTemplate`。
- 运行时仍会按当前武将势力、卡牌类别、体力、行动状态、合法目标和选中状态覆盖必要的动态颜色与描边；这是状态反馈，不是另一套 UI。若要调整武将牌静态位置或尺寸，应直接编辑 `player_target_view.tscn`；装备横条会参考场景内名称、体力与公开区节点的位置自动避让。

武将牌和卡牌根节点均为 `Node2D`，各自的纸面 `Panel` 保存精确尺寸。所有武将牌固定为148.35×197.8像素，手牌固定为111×148像素，两者宽高比均为3:4；名称、装备和状态变化只能更新牌面内部，不得改变外部模型尺寸。

动态组件每次状态快照更新后整体重建，避免旧节点残留选择状态。卡牌默认尺寸为111×148像素，所有玩家武将牌原生场景尺寸固定为148.35×197.8像素。

外围布局继续以 1280×720 为逻辑基准并兼容 1152×648 客户区：技能栏按运行时内容使用 136 像素宽度，手牌与技能栏保留 8 像素间隔，本地座位按 148.35×223.8 像素锚定右下角。四至九人局单侧座位使用 0.35 纵向比例；十人局左右各两名玩家时，下侧座位同样使用 0.35 纵向比例并向牌桌内侧错列 162.35 像素，顶部边距为 2 像素；五张顶部座位使用 0.78、0.64、0.5、0.36、0.22 中心比例，避免座位与底部功能区或相邻座位重叠。

## 名称切换

`GameSettings.card_name_mode` 的启动默认值为 `ORIGINAL`。菜单内的名称按钮调用 `GameSettings.toggle_card_name_mode()`；切换后手牌、“粮”、装备、判定区和当前选择摘要统一重绘，实体牌 ID、效果和对局状态不变。任何新增卡牌详情组件都必须调用 `GameSettings.resolve_card_name()`，不得自行判断名称模式。

武将名称统一调用 `GameDatabase.resolve_character_name(character_id)`，从 `game_data/characters` 中对应武将文件的 `display_name` 取得中文名称。武将牌、卡牌询问中的目标名称、出牌与装备目标摘要、悬停说明和本地状态摘要均不得直接显示稳定 `character_id`；卡牌询问也不得使用“玩家X”或“[AI]玩家X”等控制权名称替代已经公开的武将名。配置缺失时分别显示“未选武将”或“未知武将”，避免英文内部 ID 出现在 UI。

## 交互扩展

当前弃牌、响应、火攻展示与弃牌、濒死救援、无懈可击和装备费用等请求，只要候选全部属于本地玩家的手牌、木牛或装备区，就使用牌桌内联交互；丈八蛇矛与木牛流马的主动入口也直接复用装备横条、手牌区和中央按钮。五谷展示牌、他人区域牌和判定牌选择使用 `CardSelectionPanel`。两种表现都只提交同一标准动作或响应请求，不能让 UI 直接调用伤害、弃牌或移动函数。

## 事件选择协议

规则运行时通过 `ChoiceRequest` 暂停当前事件，桌面只渲染请求中的候选并提交 `ChoiceResponse`。`request_id`、`event_id`、`actor_id`、候选 UID、选择数量和 `can_cancel/forced` 是权威校验字段；界面不保存 `GameEvent` 或 `CardInstance` 引用。当前桌面的 `PlayerAction.choose_cards`、`use_card` 和 `end_play` 会由控制器转换成同一响应结构。

全部 `chooseToUse`、响应、弃牌和效果选牌请求共享 `EventScheduler` 的全局请求 ID 命名空间。控制器必须在运行时登记成功并取得唯一 `request_id` 后才启用手牌/装备区内联选择或显示 `CardSelectionPanel`；玩家提交后也必须先由运行时确认接收，再清理控制器中的待选上下文。旧提交回调只允许关闭相同 ID 的表现，不能覆盖同步创建的下一请求。登记失败、过期响应或 ID 不匹配不会关闭有效交互、推进阶段或移动卡牌。

出牌阶段的 `chooseToUse` 请求只展示当前可以进入出牌动作的实体牌 ID，桌面直接以该 ID 集合控制每张手牌、木牛“粮”与全部元数据声明的主动装备交互状态；提交一张牌或装备主动动作后，控制器先关闭该请求并完成整张牌的材料、逐目标响应与效果结算，再在仍处于出牌阶段时创建下一请求，避免【桃园结义】等多目标锦囊的后续【无懈可击】询问覆盖新出牌请求而导致手牌全部灰显。点击“回合结束”提交取消响应，进入弃牌阶段。响应、弃牌、火攻、五谷和濒死救援沿用相同请求入口，因此不需要为每张牌创建独立 UI 规则。每名救援者首次收到的单个提示会明确显示目标达到1点体力尚需回复的点数，并列出对应卡牌源码在当前角色关系下允许的救援牌名；当前规则仍表现为濒死者候选同时包含【桃】与【酒】，其他救援者只包含【桃】。当前救援者每打出1张后若目标仍未达到1点，会立即再次询问同一救援者；其取消后才推进到下一名尚未询问的角色，遍历完一轮后不重新询问全体角色。

网络请求和本地请求使用相同快照字段；非响应者的 `GameState.to_dict()` 会裁剪牌候选和活动过滤上下文。旧事件、错误 actor、重复 UID、非法数量或已结束事件的响应不会改变选中状态、牌区或阶段。
