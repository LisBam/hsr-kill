# 游戏机制与玩法内容

> “控制所有角色”关闭时会废弃旧AI驱动令牌、恢复被接管角色的基础AI，并重新安排当前选择或出牌动作，避免接管期间取消的异步任务令对局停滞。

> 离线设置提供“控制所有角色”，默认关闭并可在进行中的离线对局即时切换。该能力只接管正式回合行动、技能询问、牌响应、濒死救援与其他规则操作；初次选将、车轮战抓将/阵容确认和手气卡仍由原真人与内置AI分别处理。关闭后立即恢复最初真人第一视角并把临时接管角色交还基础AI。局域网房主与客户端均隐藏并强制忽略该设置，它不改变任何身份、牌数、伤害、回复、次数、概率或持续时间。

> 当前主菜单模式列表固定按“身份模式”“斗地主”“2v2”“1v1车轮战”“机缘大乱斗”“过关斩将”排列，共6张模式卡片；左侧标题固定高48像素，标题下方为独立纵向滚动窗口，卡片均保持原版100像素高度且相邻间距12像素。1v1车轮战固定2人并显示默认6名明置候选与4名暗置候选；机缘大乱斗支持2至10人并独立保存人数；过关斩将固定显示1人并创建2个规则角色。

本文档是《崩铁杀》当前游戏设计、规则实现和数值体系的唯一权威快照。代码、配置、界面或测试与本文不一致时，必须同步校正，不能在其他文档维护第二套冲突规则。

> 界面布局采用参考无名杀“十周年 UI”的环桌层级，但配色改为可切换设置。默认稳定 ID 为 `space_mono`，设置显示名为“崩铁风格”：外底为中性深色 `#111214`，外层桌面为 `#24262B`，主内容背景为冷调雾面深灰 `#30333A`，厚框为 `#1D1D1D`，边框为 `#BFA86C`，强调色为 `#D4B55F`，合法目标色为 `#F1DFAA`，主操作背景为 `#403B32`。卡牌纸张保留局部浅色 `#F4F1E9`，不把参考图的小面积信息白底放大成全桌亮底；参考图中的紫蓝区域来自游戏地图的毛玻璃效果，同样不属于本主题且不在牌桌中仿制。该风格使用34像素桌面留白和14像素黑框，外侧20像素区域为中性深色纯色；不叠加全桌滤镜，不绘制导航网格、固定星点、山脊或建筑剪影。武将势力色、卡牌类别与属性色、红黑花色、体力红黄绿和危险提示仍作为必要语义色保留。可选 `decade_wood` 的显示名为“暖木家园”，稳定 ID 不变，继续使用18像素桌面留白、14像素木框及外底 `#120D0C`、桌面 `#20202D`、桌框 `#4A2818`、边框 `#A8834F` 和强调色 `#EFC76D`。逻辑视口保持 1280×720，默认启动窗口为 1152×648。风格与窗口适配都不改变身份、体力、距离、伤害、牌堆、阶段、次数、目标数、持续时间或资源消耗等任何玩法数值；界面仍只渲染只读快照并提交标准动作。

> 游戏启动后先显示主菜单，不自动创建对局状态。主菜单顶部“模式选择”右侧固定提供“联机设置”，左侧模式列表按“身份模式”“斗地主”“2v2”“1v1车轮战”“机缘大乱斗”“过关斩将”排列；六张卡片分别显示模式名与合法人数提示，持续选中态将主题操作色加深 `0.28`，崩铁风格约为 `#2E2A24`，暖木家园约为 `#553B16`。“联机设置”允许设置最长20个 Unicode 字符的玩家名称，并从当前数据库全部现有武将牌中选择联机形象；名称空值回退“玩家”，形象保存稳定武将 ID。创建或加入房间后，联机大厅同步该稳定 ID 并在本机解析为纯武将插画。选中身份模式后右侧以 `assets/art/身份模式主菜单背景.png` 覆盖裁剪显示预览，允许裁掉边缘而不拉伸原图，规则提示固定为“随机身份 · 阵营对抗”，且不复刻参考图的游戏毛玻璃背景。待机时底部操作栏不显示“身份模式已选择”或其他状态文本。“开始游戏”按钮位于预览底部，其左侧依次为“局域网联机”和“设置”；前者打开 ENet 直连入口，成功后进入独立联机大厅，后者调整本地设置。设置可调整《崩铁杀》/三国杀名称、崩铁风格/暖木家园风格、自动身份标记、AI 响应速度、游戏速度和下局人数（身份模式与机缘大乱斗分别支持2至10人且默认8人；斗地主仅3或5人；2v2、1v1车轮战与过关斩将固定2个规则角色），默认身份模式8人；名称、风格、自动身份标记与速度切换即时作用于后续显示或计时任务，人数在离线开局或创建局域网房间时作为初始大厅设置。开始后左上角156×91像素信息框始终显示第几轮；关卡、轮次、牌堆剩余数与对局时长统一使用回退字体和16像素字号；过关斩将额外并列显示第几关，并同时显示摸牌堆剩余牌数和对局时长；时长从本局创建时开始累计并在终局冻结，不再显示当前行动角色、回合总序号或阶段名称。右上角局内“菜单”继续提供同一组设置及重新开局，全屏座次容器忽略鼠标。“卡牌名称”与“UI风格”两个下拉按钮及其弹出列表完整使用当前主题的常态、悬停、按下、焦点、禁用、面板和条目悬停样式，鼠标移入不会恢复 Godot 默认皮肤。菜单输入顺序高于动态武将牌与选将遮罩，键入人数会即时同步，选将阶段也可继续调整并重新开局。左侧“记录”按钮为108×46像素，点击后在上方展开360×176像素对局日志；离线 `OFFLINE` 模式展开时通过令牌式对局暂停接口同时暂停场景树、事件运行时和全部 AI 行动/选牌计时器，收起时只释放日志自己的令牌。对局记录或右上局内菜单展开后，点击未被 GUI 控件消费的牌桌空白左键会收起所有已展开的这两类浮层；两者同时打开时会同时关闭。离线武将详情使用另一枚暂停令牌，关闭时只释放详情令牌；日志和详情同时打开时必须等两枚令牌都释放才恢复。LAN 与 REMOTE 打开任一界面都不暂停。底部装备、手牌、技能、操作区和本地武将牌均使用底边锚点。界面回归测试会把根控件直接调整为1152×648，并通过真实鼠标移动、按下和释放事件验证主菜单、联机资料、局内菜单、风格切换、自动身份标记、日志、武将详情、人数输入和连续重开。上述设置和主菜单仅改变界面与开局入口，不修改伤害、回复、阶段次数、响应次数、资源消耗、触发概率或持续时间。

> 下局人数以模式为单位独立保存：身份模式与机缘大乱斗各为 `2..10` 人、默认 `8`；斗地主为 `3` 或 `5` 人、默认 `3`；2v2 为 `4` 人；1v1车轮战与过关斩将均为 `2` 人。切换到人数恰好相同的另一模式时，模式 ID 仍必须写入本地设置，不能因显示人数未变而丢失本次选择。

> 主菜单与局内菜单还共同保存六项房主开局规则：全武将座次身份自选、AI武将调整、手气卡数量、AI使用手气卡、换将卡数量和随机选将牌数。手气卡档位为关闭/1/2/3/4/5/10张/无限张，换将卡档位为关闭/3/5/8/10/20张，随机选将牌数为1至20张；普通模式默认随机选将5张，过关斩将的随机选将独立默认12张、换将卡独立默认关闭。创建对局后实际数值锁入 `GameState.match_options`，客户端局内菜单不显示这些权威控件。

> 主菜单的客户端视觉参数固定为：1280×720逻辑视口下主题内容面保留左右22像素、顶部12像素、底部18像素边距，顶部栏保留54像素左右安全边距并位于`y=22..88`，主体同样保留54像素左右安全边距、顶部`y=104`、底部安全边距38像素，顶部与主体间隔16像素；顶部品牌区宽252像素，“模式选择”与“联机设置”按钮宽度均为192像素，左侧模式栏最小宽286像素，固定标题高48像素，五张模式卡片均高100像素、相邻间距12像素、正文上下内边距14像素，模式名字号27像素、人数提示字号16像素。标题下方的卡片区域使用独立纵向滚动窗口，水平滚动禁用，主题化滚动条默认宽12像素；选择视口外模式后自动把该卡完整滚入可视区，不压缩标题、卡片、字号或间距。卡片选中态内部底色按主题操作色加深0.28，金色描边与左侧强调竖线保持不变。预览全图主题遮罩透明度0.18，左上170×66像素不透明主题标签覆盖裁剪后可能残留的原图品牌碎片；右上摘要底板距右24像素、距顶28像素、尺寸366×160像素且透明度0.82；底部操作栏高92像素且透明度0.88；“设置”按钮112×56像素、“局域网联机”按钮154×56像素、“开始游戏”按钮250×56像素。设置面板宽504像素并与视口顶部、底部各保留12像素，设置列间距5像素；局域网连接入口为620×540像素，联机设置面板为1040×620像素；三者均使用全屏主题遮罩拦截底层鼠标输入。联机设置中的形象候选使用正式148.35×197.8像素武将牌的0.72倍缩放，每行最多5张，水平间距18像素、垂直间距16像素；已连接联机大厅则显示不缩放的148.35×197.8像素纯插画。主菜单可见时冻结主菜单之外的牌桌焦点；打开设置、联机设置、连接入口或联机大厅时再冻结当前模态之外的主菜单焦点，使 Tab、Shift+Tab 与手柄导航始终停留在当前可见层，关闭模态只恢复主菜单焦点，成功进入对局后才恢复牌桌焦点。设置面板可通过外部左键、Esc或“返回”关闭；联机设置通过Esc、“取消”或“保存并返回”关闭；连接入口与联机大厅通过Esc或各自返回/离开按钮关闭，房主设置模态的Esc只关闭设置。滑条已选区和人数文本选择区分别使用0.72与0.42倍主题强调色透明度。主菜单全屏底色停止向局内控件传递鼠标输入。开局请求只有在 `start_match()` 成功后才隐藏主菜单；各模式人数范围与数据配置的前置校验失败不会清空旧局，初始入口保留主菜单、局内入口重新展开局内菜单；通过前置校验后的选将初始化失败会丢弃半成品状态、保留或恢复主菜单、恢复开始按钮并显示具体错误。以上尺寸、透明度、焦点、主题控件和错误反馈均只影响客户端入口，不改变身份数量、基础摸牌数、体力、伤害、回复、目标、次数、资源消耗、概率或持续时间。

> 全部玩家的武将牌以 `Node2D` 为根，牌面尺寸固定为148.35×197.8像素；卡牌固定为111×148像素。其他玩家的中文座次号由牌面下方148.35×26像素的独立座位区域显示，本地主视角不显示座次号且容器不保留该26像素区域；真实玩家按旋转后的座次命名为“玩家X”，内置 AI 命名为“[AI]玩家X”。正式对局在鼠标悬停且武将牌未翻面时显示玩家名渐变阴影，不显示状态摘要或 Godot 原生工具提示；鼠标持续停留在本地或其他玩家武将牌0.5秒后，通过统一信息框显示势力、性别、基础体力上限及完整技能资料；右键本地或其他玩家武将牌打开统一武将详情。身份23×20与手牌数24×24标识默认隐藏，仅正式对局开启；身份徽记背景与边框透明度均为0%（Alpha为1.0），不使用半透明样式。公开身份、手动标记和自动标记的字体统一按身份语义色显示：领袖红 `#EF4F55`、反贼绿 `#44CA67`、忠臣黄 `#E4C84F`、内奸蓝 `#5E85CE`；未知身份使用主题次级文字色。未知身份的徽记、自动标记回退项与本地标注菜单统一使用 ASCII 半角 `?`；菜单固定显示“?”、“忠”、“反”、“内”四个单字，选择“?”会清除已有推测，真实身份公开后标注失效。半角字符用于保证 Android 字体回退环境稳定显示。右下体力框为宽24像素的不透明动态圆角矩形：1至5点上限使用18像素圆点和-10像素纵向间距，高于5点以当前值、`/`、上限值三行纵向显示“当前/上限”数字。体力上限大于2时，当前体力2点使用黄色 `#E4C84F`，1点使用红色 `#EF4F55`，3点及以上使用绿色 `#44CA67`；体力上限为1或2的角色，其仍点亮体力始终使用绿色 `#44CA67`。已损失体力使用当前主题暗色。护盾使用灰色 `#A7ADB7`：圆点体力模式下按护盾点数显示在体力圆点上方，数字体力模式下显示为独立灰色单值，护盾不并入当前体力或体力上限。其他玩家公开装备最多5条、每条高15像素；第一视角本地武将牌不重复显示装备。武将名只从 `game_data/characters` 中对应武将文件的 `display_name` 解析；卡牌询问、出牌目标与装备目标摘要优先显示该武将名，不显示“玩家X”或“[AI]玩家X”。这些颜色和标注只属于客户端展示，不替代真实身份、不改变实际体力、护盾、胜负阵营或玩法数值。

> **体力与护盾数字呈现以本段为准：**体力上限大于**5点**时，右下体力框改为VBox内纵向排列的加粗绿色“当前/上限”分数，当前值、`/`、上限值分别占一行，例如`6`、`/`、`6`从上到下排列，数字字号为**12像素**、三行额外行间距为**-4像素**，且不因残血改为黄色或红色；护盾存在时，其上方显示相同字号的加粗灰色单值，例如`1`。护盾规则没有独立上限，因此不显示分母；两类数字均采用对应文字色的**1像素**描边加粗。1至5点体力仍维持原有圆点、残血黄红与护盾圆点规则。

> 局域网连接入口使用620×540像素中央面板，玩家名最长20字符并由主菜单“联机设置”统一保存；进入“局域网联机”后只读显示名称，不能修改。`GameSettings` 以格式版本1写入 `user://game_settings.cfg`，持久化卡牌名称模式、UI风格、AI响应等待0.05至1.00秒（步长0.05秒）、流程间隔0.1至1.0秒（步长0.1秒）、自动身份标记、下一局2至10人人数、玩家名和形象 ID；不保存地址、端口、密码、聊天、成员表、ENet会话或对局状态。默认端口7000且允许1024至65535，房间密码最长32字符。成功创建或加入后进入独立全屏联机大厅：玩家名区域高26像素，距插画4像素；联机形象使用空位同规格、透明中心无阴影边框包裹148.35×197.8像素武将插画，不显示武将牌 UI或黑色蒙层。2至3人设置显示3个单排位置，4人2上2下，5人3上2下，8人4上4下，其余4至10人按上排向上取整、下排剩余数量对称布局；同行间距44像素、上下排间距18像素。玩家点击空位可换位，房主悬停远端形象可踢出，鼠标移入踢出按钮时入口保持可见；踢出按钮默认80.35×31像素、左右内缩34像素、距插画底边10像素，并将主题危险色加深32%。左下聊天单条最多200字符并保留最近100条，右下房主设置身份模式、2至10人总人数与密码；至少2名真人才能开始，空余规则座位由 AI 补齐。房主最多接纳9名远端客户端，即最多10名真人。公共快照只显示是否存在密码，明文密码仅留在房主本机。主动离开房间时，连接入口同时复位会话标记和禁用的建房/加入按钮；关闭房间仍先从 `SceneMultiplayer` 卸载旧 ENet peer 再关闭套接字，因而同一端口可立即再次建房。大厅全部 UI 同时支持崩铁风格与暖木家园。以上数值只控制局域网会话与入口，不改变标准身份局的身份表、4张起始手牌、体力、伤害、回复、距离、次数、目标数、资源消耗、概率或持续时间。

## 一、模式边界

- 当前正式模式包括标准身份局、斗地主、2v2、1v1车轮战、机缘大乱斗与过关斩将；机缘大乱斗继承身份规则，过关斩将使用独立的单人闯关规则。
- 标准身份局与机缘大乱斗支持 2 至 10 人；过关斩将固定为1名本地玩家加1名AI（规则角色数为2），其他模式按各自章节限制人数。
- 支持离线单机与局域网 ENet 直连。局域网由1名房主权威结算，至少2名真人开始，真人不足总人数时由 AI 补位；不提供公网匹配、重连或主机迁移。
- 不实现国战玩法，不包含国战双将、暗将、势力明置、野心家和国战专属牌。
- 当前武将势力展示元数据为星穹列车（`xingqionglieche`，列车灰 `#8A919C`）、贝洛伯格（`beiluoboge`，寒冰蓝 `#58B8E8`）、仙舟联盟（`xianzhou`）和星核猎手（`xinghelieshou`）共 4 组，只用于武将牌颜色与徽记，不改变标准身份局的阵营关系。
- 默认演示为8人局，身份配置为1名领袖、2名忠臣、4名反贼和1名内奸。对局创建时对全部身份洗牌，同时在0至7中独立随机分配本地人类玩家座次；本地玩家、领袖和一号位互不绑定，其余7个座次由基础 AI 控制。
- 当前27名已登记武将共引用53个唯一正式技能，均已进入实际规则与配套 AI 结算；具体武将、技能原文和数值以“正式武将技能”及“十六、新势力、武将与机制快照”为准。

### 开局自选与换将

- 房主可将每名玩家的普通随机候选设为1至20张，默认5张；仅首任领袖阶段把拥有领袖技的全部武将固定排列在领袖候选最前方，不占普通候选数量。AI首任领袖在本次全部合法候选中使用本局随机源随机选择1名，固定种子下结果可复现，领袖技固定前缀不构成选择优先级；最终自选阶段除首任领袖外，每人严格只收到设置数量的随机候选。真人首任领袖在第一次面板一次确认武将、座次与身份，后续不再收到候选或确认面板，AI首任领袖则保留已公开武将并在真人完成后补选剩余座次身份。
- 换将卡只能设置为关闭、3、5、8、10或20张。每次成功替换消耗1张，结果不会与本人的现有候选或已确认武将重复；领袖技武将仅在当前领袖身份中不可换将，其他身份可以换入或换出领袖技武将。武将库没有可用结果时由权威服务拒绝。
- 开启全武将座次身份自选后，仍按第一次随机身份让首任领袖先公开选将。真人首任领袖的第一次面板同时显示初始座次与身份并一次性确认三项，确认后从其他玩家选将流程排除；首任领袖为AI时先公开武将但暂不占用最终座次身份。其余真人再选择随机候选或全武将、座次与身份；每次有效预览立即刷新牌桌顺序、身份与AI展示，最终确认占用名额。全部真人完成后，AI复用已经公开的领袖武将并使用剩余名额自动确认。
- 首任领袖为AI且真人均未确认一号位领袖时，房主必须先驱动该AI确认一号位与领袖身份，再驱动其他AI；它复用首次公开的稳定武将ID，保证选将左侧的首任领袖预览与正式开局领袖一致。真人已经确认一号位领袖时，该AI才按剩余座次与身份确认，公开武将仍不改变。

### 内容源码自动发现

- 当前卡牌库由 `game_data/cards` 中46个独立卡牌文件组成；每个文件保存完整卡牌信息与效果函数，新增文件会被 `GameDatabase` 自动发现，不需要修改集中卡牌表或效果 ID 白名单。
- Android等导出包内的脚本目录项可能以`.gd.remap`、`.gdc`或`.gde`存在；内容数据库会将其规范化为原始`.gd`路径后加载。主公当前APK已确认包含`assets/game_data/cards/*.gdc`。该兼容层保证导出后牌堆不会因卡牌库为空而校验失败，联机形象与选将也能读取完整武将库。
- 客户端设置变化使用0.25秒合并保存窗口；进入Android后台或退出设置节点时立即写入。卡牌名称与UI风格变化在GUI输入结束后的空闲帧刷新界面。该延迟只优化本地文件I/O和界面重绘，不改变AI响应、游戏流程、技能时机或任何玩法数值。
- 卡牌的同步效果、逐目标效果、选牌恢复、响应恢复、专用无懈恢复和延时判定均由对应卡牌源码拥有；`CardEffectResolver` 只负责通用调度。普通【杀】、火【杀】和雷【杀】共享专属牌族组件以避免复制相同的武器与响应流程，其他锦囊不经过集中牌效分发。三者规则牌名均为【杀】；“火【杀】”“雷【杀】”只表示伤害属性，牌面仍固定显示两个字“火杀”“雷杀”。
- 目标顺序与组合校验、濒死救援、回合开始/结束状态、延时锦囊传递、响应材料、装备主动动作和 AI 牌值均由卡牌源码或元数据提供；控制器与基础 AI 不再维护具体卡牌 ID 白名单。
- 【无懈可击】AI按所有锦囊的动态目标收益统一决定奇偶响应，不为单张锦囊写死判断。仅剩最后1张时，普通锦囊收益先乘 **0.45** 并扣 **1.5** 储备值；跳阶段、致命伤害、摸至少 **2** 张牌、目标体力不高于 **1** 的回复，以及拆取价值至少 **5.0** 的公开装备或响应者自己可见资源属于关键牌效，不乘0.45且只扣 **0.5** 储备值。该规则只改变AI是否使用【无懈可击】，不改变任何锦囊的实际效果、摸牌数、伤害或回复数值。

### 斗地主模式

- 主菜单左侧与“身份模式”并列的“斗地主”入口；稳定模式 ID 为 `doudizhu`，下一局模式写入 `GameSettings.next_match_mode`。
- **仅支持 3 人或 5 人**。
- 身份牌：`landlord`（地主）、`peasant`（农民）。
- 阵营配置（**随机玩家，不固定身份座次**）：
  - 3 人：身份数量池为 `[landlord, peasant, peasant]`，开局使用本局随机源洗牌后分配；洗牌后的物理座次保持不变，不会把地主旋转到一号位。

- **首回合**：由当前物理座次中第一名地主开始；该先手选择不重排玩家数组，因此不改变牌桌展示、距离或随机身份座次。
- **身份全明置**：地主与农民开局即对所有玩家公开，无需身份标记或隐藏身份。
- **选将**：地主 **不等于** 领袖。无领袖优先选将；全员同时选将；不公开展示地主武将；农民界面不显示领袖武将牌；不注入领袖技固定候选。
- **选将完成写回**：全员确认后，控制器在 `PHASE_COMPLETE` 时对 **全部玩家** 统一 `_apply_character` 写入 `character_id` 并亮将（含地主与自选路径）。身份局旧逻辑曾跳过“领袖玩家 ID”或假定自选阶段已逐人写入；斗地地主仅缓存为首名 `leader_player_id` 且即时亮将仅限 `PHASE_CUSTOM`，若不在完成边界统一写回会出现“未选武将”。开启座次身份自选时，完成前每次确认仅即时投射座次/身份，武将仍在完成时统一亮出。
- **地主开局加成**：体力上限 **+1**（任意人数）；获得模式技能 **飞扬**、**跋扈**（进入武将技能信息与技能栏）。

- **胜负**：
	- 地主方：击杀全部农民 → 获胜方字符串 `landlords`。

  - 只有 `alive=false` 的死亡角色算作被击杀；`out_of_game=true` 的离场地主或农民仍计入阵营存活，不会触发胜负。
- 终局表现：`winner=landlords/peasants` 时，本地身份为对应 `landlord/peasant` 显示“对局结算，游戏胜利”，否则“游戏失败”；不得仅识别身份局四阵营而把斗地胜方映射成失败。

- **人数设置按模式分存**：六种模式各自保存下一局人数；斗地主仅允许 **3 或 5**（设置上下键在 3↔5 间切换）。
- **斗地主人数与身份表**：三人一地主两农民；五人两地主三农民。身份表只定义人数配比，随机对局不固定地主玩家；仅开启自选座次身份时，地主名额按可选座次槽位校验。旧版六人配置已废弃，入口与规范化均只接受 3/5。

### 2v2 模式

- 身份牌：`blue`（蓝方）、`red`（红方）；界面徽记单字为「蓝」「红」，完整文案为「蓝方」「红方」。
- **座次与队伍（固定成队关系）**：
  - 一号位与四号位必定同队；
  - 二号位与三号位必定同队。
- **身份分配**：开局随机整表 50% 概率互换蓝红（基准表 `["blue","red","red","blue"]` 或互换后 `["red","blue","blue","red"]`）。身份在开局时 **全明置**，无需隐藏或自动身份标记。
- **无体力加成**；**不安装**斗地主模式技能（飞扬/跋扈/共苦）。
- **选将**：与斗地主相同为全员同时选将（`uses_simultaneous_selection`），不领袖优先、不按身份旋转座次；一号位固定为首回合行动者。
- **自选座次与身份**（开启“全武将座次身份自选”时）：不绑定“首任一号位身份”（`get_first_seat_identity()` 返回空字符串），但 **座次与蓝/红按开局成队表双向绑定**——1/4 同色、2/3 同色（整表开局 50% 互换蓝红后写入 `team2v2_identity_by_seat`）。选座次时身份自动同步为该座绑定色；选蓝/红时座次自动落到仍可用的同色座（优先保持当前同色座）。UI 即时联动，服务端 `_normalize_custom_seat_identity` 为权威校验，拒绝“3 号蓝位却选红方”等错位组合。真人与 AI 均须在确认武将时同时提交有效 `seat_number`（1–4）与 `identity`（`blue`/`red`）。AI 自动补位优先沿用首次随机座次，身份取绑定表对应色；**不会**像身份局那样预留并 `erase(1)` 一号位，避免只剩一号位时空列表提交 `seat_number=-1` 反复提示“请选择有效座次”并卡死选将。
- **起始手牌**：基准起始手牌数不变；**四号位初始手牌数 +1**（相对基准多 1 张）。
- **首回合摸牌**：**一号位**在全场 **第 1 个回合**的摸牌阶段基础摸牌数为 **1**（其余回合与其余座次仍为默认 **2**）。
- **死亡奖惩**：
  - 击杀任何人（含队友）**无**击杀惩罚、无摸三；
  - 队友死亡后（不论由谁击杀），**每名存活队友各摸 1 张牌**（类型 `teammate_draw`）。
- **胜负**：
  - 蓝方全部出局 → 红方获胜，胜方字符串 `red_team`；
  - 红方全部出局 → 蓝方获胜，胜方字符串 `blue_team`。
  - “全部出局”只统计 `alive=false` 的死亡；某方最后一名存活角色离场时仍计入该方存活，对局继续。
- 终局表现：`winner=blue_team/red_team` 时，本地身份为对应 `blue/red` 显示“对局结算，游戏胜利”，否则“游戏失败”。
- 局域网大厅可选 `team2v2` /“2v2”，人数输入固定为 4（下限不低于当前真人数，上限 4）。

#### 模式技能（原文）

- **飞扬**：判定阶段开始时，若你的判定区内有牌，你可以弃置两张手牌，然后弃置判定区内的一张牌
- **跋扈**：锁定技，准备阶段，你摸一张牌。你于出牌阶段内使用【杀】的次数上限+1。
- **共苦**：当队友死亡后，你可以回复1点体力或摸两张牌。AI 读取 `selected_control_id`：当前体力低于上限时优先选择“回复1点体力”（评分4.0），满体力时“回复”评分为0.0、优先选择“摸两张牌”（评分3.5）；受伤时摸牌评分2.0仍低于回复。

### 机缘大乱斗模式

- 稳定模式ID为 `opportunity_brawl`，支持 **2至10人**，身份配置、身份公开、领袖体力加成、选将、4张起始手牌、胜负与死亡奖惩均继承身份模式；该模式独立于 `identity`，不会把机缘组件自动加入普通身份局。
- `OpportunitySystem` 是可插拔节点组件。`MatchController.opportunity_enabled_mode_ids` 默认只包含 `opportunity_brawl`；其他2至10人模式若需要复用，可在检查器追加模式ID，不需要复制触发、候选或效果代码。
- 每轮开始时锁定本轮在场角色数 `N`，每名角色的普通回合开始触发概率统一为 `1/N`：2人50%、3人33.333%、4人25%、5人20%、6人16.667%、7人14.286%、8人12.5%、9人11.111%、10人10%。额外回合不获得新的机缘概率检定，避免同一角色因额外回合取得更多本轮机会。
- 一轮内至多随机触发一次全体机缘。若本轮所有普通回合开始均未触发，则最后一名普通回合角色完成结束阶段后立即强制触发，再进入额外回合队列或正常下家。
- 触发“选择机缘时间”后，离线权威端申请 `opportunity_selection` 暂停令牌，暂停场景树、事件运行时与普通AI延时；联机网络节点保持 `PROCESS_MODE_ALWAYS`，确保远端选择仍可送达。每名仍存活角色获得 **3张互不重复** 的私有候选，离场但未死亡的角色同样参与三选一并可通过模式级动作入口提交；其他观察者只能知道其是否已选，不能看到候选正文或最终卡面。
- 全体角色均完成选择后才释放选择暂停并开始效果。效果顺序从触发时的当前回合角色开始，沿完整座次数组**逆时针**逐名执行，只跳过已经死亡的角色，离场但存活角色仍结算自己的机缘；其自用摸牌、回复、体力上限、手牌上限、获得牌和获得技能效果显式允许离场状态，目标类机缘仍只能选择存活在场目标。伤害、失去体力、移牌、装备离开与濒死产生的新选择必须先完整结算，之后才能继续下一张机缘。
- 离线“控制所有角色”开启时，第一视角会依次切换到当前机缘选择者，主公可亲自完成每名角色的三选一；关闭时只有原真人选择自己的机缘，其余角色由基础AI在自己的3张候选中估值选择。
- 机缘卡使用独立 `180×240` 像素场景，比例模仿武将牌；**没有插画**，卡面只显示主公给出的规则正文。随机品质以整张卡面的绿色、蓝色、紫色、橙色、红色底色和边框表达；灰色仅用于关卡专属机缘，可在右键历史或调试卡面显示灰色，但绝不进入三选一。可交互卡悬停时以中心点在0.12秒内按二次缓出放大至1.06倍，层级提高到100，品质背景提亮0.08、边框由4像素增加至5像素；离开或提交选择后恢复原尺寸、颜色、边框和层级。该动画在机缘选择暂停期间仍运行，只改变客户端表现，不修改候选、权重、效果或结算顺序。

#### 机缘与卡牌区域术语

- **交换武将牌**：交换两名角色当前武将牌对应的武将ID、体力上限、势力、性别与武将牌上的技能。势力和性别由交换后的武将ID实时解析；当前体力不交换，但若高于交换后的体力上限则同步降至新上限。身份、座位、手牌、装备、判定牌、护盾、局内获得技能、临时技能和模式技能均不交换。
- **武将牌上的技能**：仅指开局时由武将定义 `skills` 数组默认写在武将牌上的固有技能，不包括对局中获得的技能、临时技能或身份/模式技能。交换武将牌时只卸载旧固有技能并安装新固有技能；其他来源的技能实例、次数和使用历史仍归原角色。
- **场上的牌**：所有角色装备区与判定区内的牌，不包括任何角色的手牌、木牛流马“粮”、处理区、摸牌堆或弃牌堆。
- **一名角色场上的牌**：该角色装备区与判定区内的牌。
- **角色区域内的牌/区域内的牌**：若卡面未进一步限定，继续指对应角色普通手牌区、装备区与判定区内的牌；木牛流马“粮”不计入该区域。

#### 局内获得技能与手牌上限

- `PlayerState.acquired_skills` 保存机缘等局内永久获得技能的来源、每回合/每轮/总共限制、当前回合/当前轮/累计已用次数及对应跟踪编号；与固有、模式、临时技能共用 `skill_instances_by_player`，因此触发、主动按钮、AI评分和信息框都使用原技能代码。
- `PlayerState.acquired_opportunity_ids` 按实际获得顺序保存本局机缘稳定ID并允许重复。普通三选一在全体完成私有选择后才统一写入公开历史，避免提前泄露其他角色卡面；过关斩将敌方在每次达成关卡时直接写入对应机缘。两类来源均由右键武将详情显示“机缘”分组与每项品质、原始规则正文。效果汇总缓存不进入公开快照，不能替代、裁剪或改变这份展示历史。
- 相同技能已经存在时不重复安装，也不会叠加第二套技能状态。每回合限制随 `turn_number` 自动恢复，每轮限制随 `round_number` 自动恢复，额外回合不增加 `round_number`；达到明确总次数时由权威端在最后一次效果完整成立后卸载。技能按钮始终只显示技能名前两个字，剩余次数仅在悬停与右键武将详情的技能名后按“还可发动N次；每回合可发动N次；每轮可发动N次”显示已配置维度的完整文字。
- `PlayerState.hand_limit_bonus` 默认0，可由多张机缘永久累加；最终手牌上限为 `max(当前体力 + hand_limit_bonus, 0)`。


### 轮次与额外回合

- **一轮**以当前行动顺序中第一名存活且未离场角色（通常为一号位，阵亡则顺延）的**主回合**为锚点；该角色进入回合时，若本回合**不是**额外回合，则 `round_number` 加一，并在该角色“回合开始时”之前触发 `roundStart`（每轮开始时）。
- **额外回合**（例如某些技能获得的额外行动）**不得**增加 `round_number`，也**不得**再次触发 `roundStart`。
- 因此“一号位回合开始”不等于“新一轮开始”：同一轮中一号位若获得额外回合，不会重复结算轮开始效果。

### 胜利条件

- 领袖与忠臣：所有反贼和内奸均死亡，且领袖存活。
- 反贼：领袖死亡时，只要场上不是仅剩 1 名内奸，反贼方获胜。
- 内奸：领袖死亡时，场上仅剩 1 名存活内奸，该内奸获胜。

### 死亡奖惩

- 任意角色杀死反贼：击杀者摸 3 张牌。
- 领袖杀死忠臣：领袖弃置全部手牌和全部装备。
- 无来源伤害造成死亡：没有击杀奖励或惩罚。

## 三、武将与体力

- 开局必须先完成选将，选将阶段不发起始手牌、不进入回合阶段。
- 领袖先单独选将并立即亮出；领袖确认后，其他玩家再同时选择，所有非领袖玩家完成后同时亮出。
- “随机选将牌数”由房主设置为1至20张，默认5张；实际普通随机候选不超过当前可用武将数。领袖选将框额外把全部拥有 `leader_skill=true` 技能的武将固定放在普通随机候选之前，这些固定牌不占随机牌数。
- 候选列表只对对应玩家可见。领袖选择立即公开；非领袖在全员完成前只公开“已确认”状态，不公开具体武将。
- 所有人完成选将后，每名玩家获得4张起始手牌；身份牌先随机分配，随后将玩家数组旋转为领袖一号位，并由一号位领袖开始首回合。预留参数 `first_turn_seat_number` 不参与标准身份局判定。
- 当前武将基础体力上限为3或4点，由 `game_data/characters` 中各武将文件的 `max_hp` 配置。
- 对局人数不少于5人时，领袖在武将基础体力上限上增加1点；2至4人局不增加。
- 丹恒、杰帕德、希儿、雪衣、素裳基础上限为4。
- 三月七、布洛妮娅、姬子、娜塔莎、寒鸦、桂乃芬、佩拉、玲可基础上限为3。
- 普通回复不能超过体力上限。
- 体力可以在伤害后降至 0 或负数，用于计算濒死所需回复量；只要角色仍存活且体力不大于0，濒死前置时机的取消或中立化标志就不能单独跳过濒死，处理器必须已经把体力恢复到1点或以上、确认死亡或令角色离场才能终止入口。
- 每名角色初始护盾为0，护盾没有上限且可以叠加；普通回复、失去体力和体力上限变化都不会自动增减护盾。
- 获得护盾使用技能语法 `who.shield(count, source)`；`who` 是获得护盾的角色操作对象，`source` 是护盾来源角色操作对象，`count` 必须为正整数。
- 失去护盾使用技能语法 `who.loseShield(count, source)`；只减少现有护盾并最低收敛到0。失去1点护盾不算失去体力，也不算受到伤害，不产生伤害历史、属性连环、濒死或任何“体力值受到伤害”触发。
- 同一对局内任意玩家公开体力相对上一份快照下降时，武将牌播放一次水平受伤反馈：最大位移7像素、总时长0.24秒，只执行1次冲击位移后回正，不再左右往返。首次快照、新局初始体力和回复不会触发；该反馈不改变实际伤害量、体力、濒死时机、无敌时间、冷却、概率、资源消耗或持续时间。

## 四、开局与回合流程

### 开局数值

- 每名玩家默认起始摸4张牌；`gameDrawBefore/gameDrawBegin` 被规则取消时本局跳过起始发牌但仍开始首回合。
- 第一回合固定由领袖开始；领袖在身份确认后固定为一号位，其他角色按顺时针成为二号位及后续座次，本地玩家座次不会覆盖该顺序。
- 默认完整牌堆共 162 张。
- 摸牌堆耗尽时，将全部弃牌堆洗回摸牌堆；处理区、装备区、判定区、手牌与木牛“粮”不参与重洗。
- 摸牌堆与弃牌堆同时为空时立即产生 `GameEndEvent` 并以平局结束：普通摸牌原因为 `deck_empty_draw`，判定取牌为 `deck_empty_judgment`，公共亮牌为 `deck_empty_reveal`。该规则不造成伤害、回复或额外资源变化。

### 开局自定义与手气卡

- 自选确认时序以本条为准：首次随机身份产生首任领袖与按该领袖旋转的一号位真实座次，并作为按钮默认选中值。真人首任领袖的第一次公开选将快照直接开放座次身份控件，`select_character` 必须同时携带武将ID、座次号和身份ID；确认后三项一次落定，该稳定玩家从 `PHASE_CUSTOM` 待选集合排除，权威随机历史只记录1次选将，客户端不再收到第二次可选快照。首任领袖为AI时可先只确认公开武将，`retains_selected_character=true` 仅用于该AI在真人完成后复用同一武将补选剩余名额，不用于真人二次面板。每次有效预览或玩家确认都会立即投射当前完整座次身份，确认者的新武将只应用一次；最终身份变化后按当前身份重算基础体力，全部完成时不再重新刷新场上座次或武将。首任领袖公开武将始终保留；领袖改为未确认真人时清空当前领袖的公开牌，改为AI时仅公开该AI的预览候选。选择一号位会成为领袖，选择领袖会成为一号位；离开一号位或领袖时，另一项从可用项中随机补全为非一号位座次或非领袖身份。只有当前领袖身份中的领袖技武将不可换将，其他身份可换入或换出领袖技武将。
- AI补选顺序以首任领袖保留状态为最高优先级：全部真人确认后，保留公开武将但尚未确认座次身份的首任AI领袖优先提交；若一号位与领袖仍可用，必须同时取得二者。该优先级不改变真人已经确认的一号位或领袖选择，也不触及伤害、体力、摸牌、次数、概率、资源消耗或持续时间数值。
- 首任AI领袖的首次武将选择在本次全部合法候选内完全随机，不会消耗换将卡；领袖技固定候选只决定首任领袖候选区的前置展示和换将限制，不限制随机范围。该随机只决定武将ID，不改变身份数量、座次、体力、伤害、摸牌、次数、概率、资源消耗或持续时间数值。
- 房主可开启“自选全武将、座次与身份”。开启后仍先随机分配第一次身份，并由该首任领袖完成公开选将；真人首任领袖在同一面板可从随机候选或全部已登记武将中确认武将，并同时确认座次与身份后立即完成，不会进入其他玩家的后续选将集合。其他真人同样从随机候选或全部已登记武将中选择武将、座次与身份；AI首任领袖只在所有真人确认后使用剩余名额完成自身分配（AI 保留武将补交座次身份时不开放全武将入口）。自选界面继续显示本人第一次身份与当前公开领袖武将；每名玩家确认时立即投射其最终座次、身份与武将，全部确认后不再重复刷新已投射的场上状态。座次号范围为1至本局总人数且不可重复，身份数量严格等于对应人数的标准身份分布。身份局：选择一号位会自动改为领袖，选择领袖会自动改为一号位，最终一号位固定为领袖。斗地主：地主固定一号位（五人另固定三号位）；自选时选 1/3 号位自动为地主、选其他座次自动为农民，选地主自动落到可用 1/3 号位、选农民自动落到非地主座；自选预览只重排座次与身份，**不会**套用身份局“一号位 AI 领袖提前亮将”逻辑。斗地主自选阶段为 `PHASE_OTHERS` 同时确认：完成时对全部玩家统一应用已确认武将并亮将；完成前自选确认只投射座次与身份，不逐人提前亮将。
- “换将卡数量”由房主设置为关闭、3张、5张、8张、10张或20张，内部值依次为 `0、3、5、8、10、20`。每名玩家分别拥有对应张数；悬停普通随机候选后可消耗1张，只替换该牌位为当前候选之外的另一名随机武将。候选已经覆盖全部可替换武将时不显示换将入口。只有当前领袖身份中的领袖技武将不可作为换将目标；领袖身份的换将结果不补入领袖技武将，其他身份可正常换入或换出领袖技武将。失败请求不消耗张数。全武将列表不提供换将按钮。
- 房主可开启“自选所有AI的武将”。初次选将结束后、技能安装和起始手牌发放前进入AI调整阶段；房主每次点击一名AI都会按“随机选将牌数”重新随机发放候选，可反复替换武将或直接结束。若同时开启全武将自选，AI选将框可打开全部武将，但不能修改AI的座次与身份。局域网只有房主能提交，其他玩家只等待。
- “手气卡数量”可选关闭、一张、两张、三张、四张、五张、十张或无限张；内部值依次为 `0、1、2、3、4、5、10、-1`。阶段发生在全部武将调整结束、每人起始手牌发放完成之后和领袖首回合之前。一次刷新会把该玩家当前全部起始手牌洗回摸牌堆、清除旧私有牌面知识、重新洗牌并重发相同张数；不进入弃牌堆，不作为普通摸牌，不触发普通摸牌时机。有限张数每次成功刷新减少1张，无限张不递减；玩家点击“不再刷新”后不能重新进入。
- 所有真人都确认“不再刷新”后才开始游戏。AI关闭“AI使用手气卡”时直接保留手牌；开启时获得与玩家相同的有限张数。无限模式下真人不设上限，AI为避免极端随机序列阻塞开局，单局每名AI最多自动尝试20次。最后一名参与者完成后，权威阶段立即从 `starting_hand_mulligan` 切换为 `round_start`，并清除手气卡私有快照字段，再派发首轮 `roundStart`；即使该时机创建可取消技能选择，也不会继续显示或接受手气卡操作。

### 标准回合阶段

1. 开始阶段。
2. 判定阶段。
3. 摸牌阶段。
4. 出牌阶段。
5. 弃牌阶段。
6. 结束阶段。

相邻标准阶段、额外出牌阶段、结束阶段到下一回合之间默认保留0.3秒流程间隔；菜单“游戏速度”允许在0.1至1.0秒之间以0.1秒步长调整，数值越小推进越快。当前阶段的 End/After 等规则时机先完整完成，间隔期间不创建下一阶段生命周期，也没有可提交的 `chooseToUse` 请求；到期后仍属于同一对局、行动角色和阶段才进入下一阶段。该间隔只限制流程展示，不修改六阶段顺序、摸牌数、手牌上限、使用次数、伤害、回复、目标数、响应次数、触发概率、资源消耗或持续时间。

摸牌阶段基础摸 2 张牌。弃牌阶段的基础手牌上限等于当前体力，最低为 0；只统计 `hand` 区域中的普通手牌，木牛流马的全部“粮”位于 `wooden_ox` 区域且不计入上限。超出部分必须由当前角色直接在自己的普通手牌区选择足量卡牌并确认弃置，不打开独立选择窗口。

每个出牌阶段先派发 `phaseUseBegin`；描述为“出牌阶段开始时”的技能必须在该 Begin 回调内立即完成询问，确认或取消且父事件排空后才创建唯一的普通 `chooseToUse` 请求。随后每个出牌阶段持续存在一个 `chooseToUse` 请求。该请求的普通牌 `card_ids` 只包含可直接执行 `use_card` 或 `recast_card` 的手牌/木牛“粮”，主动装备本体由独立装备入口加入；木牛存粮、【传冲】等技能或装备动作使用的手牌材料即使已经存在合法动作，也必须保持暗置，直到玩家点击对应装备或技能按钮并进入专用材料选择。木牛可以把任意普通手牌存为“粮”，包括当前不能直接使用的响应牌、次数耗尽牌与无合法目标牌；提交时由已点亮的木牛装备 UID 完成 `chooseToUse`，材料 UID 只用于木牛专用复核，因此未发动木牛时这些牌仍保持灰显不可选。AI 在响应延迟结束后会把最新合法动作与活动请求快照逐项比对；若【传冲】等动态技能按钮或装备入口已经变化，先系统取消旧请求并立即按当前状态重建，再在同一次驱动中决策，不提交到过期候选，也不额外等待一轮 AI 延迟。使用实体牌、通过 `use_zhangba` 使用丈八蛇矛的虚拟【杀】、重铸或木牛存粮成功后立即创建下一请求，直到玩家明确结束；只有已经进入 `phaseUseEnd/phaseUseAfter` 的阶段生命周期会在选择恢复后继续结束阶段，普通牌效结算不会提前推进到弃牌阶段。结束出牌不消耗卡牌、体力或其他资源。请求本身没有冷却，默认截止时间为0毫秒，表示离线模式不自动超时。

延时锦囊严格按判定区数组顺序逐张结算。每张牌先进入处理区并以 `delayedJudge` 在判定角色位置公开展示，正式对局默认等待1.00秒后才进行无懈可击询问与实际判定；本张牌完成后默认再保留判定结果1.00秒，才展示下一张延时锦囊。两段时间分别由 `delayed_judgment_preview_seconds` 与 `delayed_judgment_result_pause_seconds` 配置，检查器范围均为0.00至3.00秒；无 `match_id` 的纯规则预演跳过表现等待。延时锦囊的无懈可击询问、`judgeBefore/judgeBegin` 改判定技能和判定伤害引发的濒死救援都属于判定阶段内部选择。【戏法】调整牌堆期间原延时牌继续留在处理区，排序完成后才翻开最终牌并决定跳过、传递或弃置。存在未完成选择时不能提前进入基础摸2张的摸牌阶段，也不能创建出牌请求；选择完成后从同一张延时锦囊继续，处理完全部判定牌后再推进阶段。兵粮寸断判定不为梅花时完整跳过本回合基础摸2张，但仍进入出牌阶段；乐不思蜀判定不为红桃时完成摸牌后跳过出牌阶段，直接进入弃牌、结束和下名角色回合。即将进入一名角色的回合时，在 `phaseBefore` 及其中“直到下个回合开始”的维护清理完成后检查翻面：若其武将牌背面向上，则立即翻回正面，跳过准备、判定、摸牌、出牌、弃牌和结束阶段，并直接转交下名存活角色。

所有自动展开的全体目标均按使用者起算的环形行动顺序结算：包含使用者的牌先检查使用者本人，排除使用者的牌先检查其下一名存活角色，然后按座次继续并在末位后回到一号位。每名候选会独立应用卡牌目标条件、来牌限制与使用者技能目标限制，不合法角色只从本牌目标数组中移除；剩余数量达到卡牌最少目标数即可使用，合法目标降为0且最少目标数为1时才拒绝。方天画戟和铁索连环等手动多目标在权威提交后也按当前回合角色起算的行动顺序重排。【借刀杀人】使用时先按“持刀者、被【杀】者”声明两个目标；实际本牌 `target_ids` 与目标时机只保留持刀者，第二名角色写入结算上下文供持刀者直接响应【杀】，不再弹出二次选目标窗口。【无懈可击】不再按座次逐人等待：每轮把全部存活玩家同时加入公开响应名单，拥有合法候选的玩家分别取得私有请求，权威端按合法响应实际到达顺序结算首张牌并关闭同轮其他请求；成功后开启下一轮反无懈，完整一轮无人响应才结束。无合法候选的玩家不产生阻塞窗口，但始终与持牌玩家使用相同操作高亮。连环传导和濒死救援仍从当前回合角色开始按存活座次顺序处理。濒死救援只遍历一轮座次，每名存活角色最多完成一次询问；一名响应者出牌后目标仍低于1点体力时只继续询问该响应者，其取消后再推进到下一名尚未询问的角色。

普通响应牌与同时无懈的私有提示在权威请求暂停规则后，等待当前游戏速度间隔才向对应玩家显示；请求在等待期间失效或重开时不显示旧提示。AI普通行动等待游戏速度和AI响应速度的较大值；AI响应牌在提示发布后再等待同一较大值，避免使用提示等待时间提前决策。

翻面状态固定分为正面向上与背面向上。对正面向上的角色执行翻面会令其背面向上；对背面向上的角色执行翻面会令其正面向上。背面向上的角色即将进入回合时按上段规则翻回正面并跳过整个回合；正面角色正常进入回合。连环状态与翻面状态相互独立。

### 额外回合与额外出牌阶段

- 技能角色语法 `who.addPhase()` 使 `who` 获得1个额外完整回合。多个额外回合按加入队列的顺序执行；全部额外回合结束后恢复原当前角色原本的正常下家。等待期间已经死亡或离场的目标跳过，不转移给其他角色。
- 额外完整回合包含开始、判定、摸牌、出牌、弃牌和结束六个标准阶段，摸牌阶段基础摸2张、弃牌阶段手牌上限规则与普通回合相同，并重置回合级使用次数和历史。
- 额外出牌阶段只包含1个新的出牌阶段，不额外执行摸牌、弃牌或结束阶段。每次新阶段清空阶段用牌历史，重新计算【杀】基础每阶段1次限制与所有“每阶段限一次”技能次数，不与原出牌阶段共享；【酒】的每回合1次限制仍共享当前回合历史。每个排队阶段在登记时保存明确后继：普通出牌阶段及其之前取得的阶段结束后进入弃牌阶段；弃牌阶段开始、结束时机或其选择窗口中取得的阶段在当前弃牌阶段完整结束后执行，结束后直接进入结束阶段且不重复弃牌；`phaseEnd` 取得的阶段结束后直接完成已经派发过的回合尾部，再进入额外回合或正常下家。选择窗口临时显示为 `choice` 时以其 `resume_phase` 作为真实插入位置，不会把弃牌阶段插入误判成普通出牌阶段插入。若嵌套选择完成时已有阶段切换任务，恢复逻辑等待该任务而不以普通后继覆盖；阶段恢复新暴露的技能后续会继续排空，因此【永屹】额外弃牌询问不会吞掉随后登记的1个额外出牌阶段。
- 独立额外出牌阶段允许阶段执行者不是当前正常回合角色。控制器在开始前保存原回合角色、公开阶段、阶段索引和 AI 行动计数，为执行者建立完整 `phaseUseBefore/Begin/End/After`、独立的【杀】次数与阶段用牌历史；阶段结束、执行者死亡或离场后恢复原回合展示，并按创建技能保存的稳定上下文继续“然后”效果。独立阶段中再次取得的额外出牌阶段会先依次执行，全部结束后才返回原回合，不进入阶段执行者自己的普通弃牌阶段。
- “某主要阶段变为出牌阶段”属于阶段转换，不属于额外出牌阶段，也不等于跳过原阶段后补阶段。转换后的阶段直接派发一套普通 `phaseUse` 生命周期、显示“出牌阶段开始/结束”、重置阶段级【杀】与技能次数，然后进入原主要阶段队列的下一个槽位；不会派发原阶段的 `Skipped` 时机、不会写“跳过判定/摸牌/弃牌”日志，也不会写“获得/开始额外出牌阶段”日志。转换后的出牌阶段内若另有技能真正获得额外出牌阶段，该额外阶段继承当前转换槽位的正确后继。

### 弃牌堆统计与角色术语

- “进入弃牌堆”按实体牌实际移动到 `discard_pile` 计算，不论来源或原因；使用与响应结算、主动弃置、弃牌阶段、判定、重铸、装备离区、未领取展示牌和其他规则移动均计入。
- 每条实体移动记录保存发生时的全局回合号、当前回合角色与阶段。限定“此回合出牌阶段进入弃牌堆”时，必须同时满足指定 `turn_number`、指定 `turn_player_id`、`phase=play`、实际进入弃牌堆且当前仍留在弃牌堆；同一实体 UID 多次符合时只作为1张候选。
- “从牌堆或弃牌堆中获得一张指定牌”固定先从摸牌堆顶部向下检索，取得其中最顶上的该牌；摸牌堆没有任何该牌时，才从弃牌堆顶部向下检索并取得其中最顶上的该牌。检索不会洗牌，也不改变其他牌的相对顺序。
- “从牌堆中获得一张满足条件的牌”只从摸牌堆顶部向下检索首张匹配实体，不回退弃牌堆、不触发重洗，也不改变未命中牌的相对顺序。当前过滤器可按定义ID、定义ID集合、共享牌效、属性集合或卡牌类型组合筛选；【勘测】的属性【杀】固定要求 `effect_id=slash` 且属性为火焰或雷电，【桃】固定要求定义ID为 `tao`。
- “其他角色”指不为技能持有者本人的角色，不依据势力、身份或阵营关系判断；选择目标时仍需满足存活且未离场等通用合法性。
- 技能文本使用“a/b，然后c/d”时，选项严格按斜杠位置配对：`a→c`、`b→d`。第一项选择只触发第一项后续效果，第二项选择只触发第二项后续效果。
- 规则术语“使一名角色横置时”仅指令竖直角色变为横置；令横置角色竖直或状态没有变化均不满足该条件。事件来源角色是执行状态切换的角色，被横置的角色是事件目标。
- 顺序效果中的某一项在结算时没有合法目标、材料、选项或其他必要条件时，该项视为不可触发并直接跳过，不弹出空选择，也不改选不符合原文的对象；同一效果中仍然可执行的后续内容继续按原文结算。等待玩家选择期间条件失效时同样只跳过已经不可执行的对应项。
- “领袖技”只在角色身份为领袖时拥有并显示；非领袖角色不显示灰色占位按钮，也不安装触发器或参与 AI 技能牌效估值。

### 标准技能时机规则

规则层登记221个无名杀兼容监听事件和4个主动技能入口。事件使用 `Before → Begin → 主体 → End → After` 生命周期；同一阶段只有成功进入 Begin 后才会派发 End/After，被跳过时派发 `Skipped`，被取消时派发 `Cancelled`。标准六阶段分别使用 `phaseZhunbei`、`phaseJudge`、`phaseDraw`、`phaseUse`、`phaseDiscard`、`phaseJieshu` 前缀。阶段生命周期保存 `body/end_emitted/after_emitted` 游标；Begin、End或After触发选择时，确认或取消后从保存游标继续，不重复阶段主体和已派发时机，也不会丢失已登记的额外阶段。所有通过 `SkillDefinition.subscribe_timing()` 注册的普通技能默认组合持有者有效性条件，持有者死亡、离场或状态缺失后不再接收新时机；只有规则明确设计为失效后继续触发的技能，才可覆盖 `can_trigger_while_owner_inactive(event)`。主动技能枚举与提交同样要求持有者存在、存活且未离场，旧界面按钮、旧网络请求或伪造动作不能绕过。技能效果出现嵌套选择时，可把“然后”之后的步骤登记到技能延迟结算队列；当前选择和同一时机续列全部完成后才恢复该步骤，避免同步调用栈继续执行或永久等待。摸牌阶段另有 `phaseDrawBegin1` 与 `phaseDrawBegin2` 两个严格升序的摸牌数量修改窗口，基础值仍为2张。

技能元数据始终包含布尔 `lock`、`half_locked` 与 `leader_skill`，默认均为 `false`；完整锁定技必须把 `lock` 填写为 `true`，满足条件时强制执行且不允许玩家取消。技能正文前段不为锁定技、后段出现“锁定技”标签时属于半锁定技：从“锁定技”标签开始的后段均视为锁定技，标签之前的前段仍是非锁定技，可显式填写 `half_locked=true`，基类也会按标签位于正文中段自动识别。“非锁定技失效”会关闭完整非锁定技和半锁定技的非锁定前段，包括主动按钮、响应入口、规则修正与新触发收益；完整锁定技与半锁定技显式登记的锁定后段继续生效，持续效果的到期/死亡清理也继续执行。例如【百折】失效时不能再消耗2枚“斗志”视为使用【决斗】，但受到或造成1点伤害后获得“斗志”的锁定后段仍生效。多个失效来源按稳定来源ID叠加，只有全部解除后才恢复非锁定技。领袖技必须把 `leader_skill` 填写为 `true`，安装、显示与 AI 钩子统一要求持有者身份为 `leader`。“出牌阶段开始时”的技能固定在 `phaseUseBegin` 回调内直接创建询问，不得等普通出牌阶段已经开放技能按钮后再询问。

`phaseAfter` 只派发1次。若回合结束后技能继续创建确认、判定、选牌或统一结果展示间隔，控制器保存已结束角色并暂停轮末计算；全部后续完成后才恢复额外回合或正常下家，不能因判定暂时没有选择窗口就提前切换当前回合角色。【投狭】的判定、【戏法】排序、获得或取消以及当前回合角色摸1张牌均属于同一回合尾部。

开局顺序为 `gameStart → 每名角色 enterGame → gameDrawBefore → gameDrawBegin → 默认每人4张起始手牌 → gameDrawAfter → 手气卡（开启时） → roundStart → 首回合`。手气卡完成后先公开 `round_start` 阶段，再派发 `roundStart`，使该时机的技能选择与已结束的开局确认界面严格分离。若规则取消 `gameDrawBefore` 或 `gameDrawBegin`，只跳过起始手牌分发、手气卡与 `gameDrawAfter`，但对局仍由领袖开始首回合；该取消规则不会改变牌堆总数162、默认回合摸牌2张或任何卡牌数值。

一张牌的标准顺序为 `useCardBefore → useCardBegin → useCard0 → useCard1 → yingbian → useCard2 → useCard → useCardToPlayer → useCardToTarget → useCardToPlayered → useCardToTargeted → 逐目标内容 → useCardEnd → useCardAfter`。四个指定目标时机按“先让全部当前目标通过同一组，再进入下一组”处理，期间允许动态增删目标、排除目标和设置直击。单个目标的效果使用 `useCardToBefore/Begin/End/After` 包裹；【杀】的 `shaBefore/Begin/Hit/Miss/Damage/End/After` 嵌套在该目标内容中，结束时先完成 `shaEnd/shaAfter`，再完成 `useCardToEnd/useCardToAfter`。这些窗口只增加技能可监听边界，不改变【杀】基础1点伤害、每阶段1次基础使用限制或【闪】响应规则。

实体牌区域变化统一派发获得、失去、弃置、装备和判定区时机。从手牌进入弃牌堆的复合顺序为 `loseBefore → discardBefore → loseBegin → discardBegin → 实际移动 → loseEnd → discardEnd → cardsDiscardEnd → loseAfter → discardAfter → cardsDiscardAfter → loseToDiscardpileAfter`；从牌堆摸入手牌则由 `drawBefore/Begin` 包裹 `gainBefore/Begin/End/After`，最后派发 `drawEnd/After`。临时视为牌只在实体位于手牌区时替换逻辑定义，离开手牌区的统一移动边界自动恢复原定义；作为使用或响应材料进入处理区时，本次逻辑牌效果仍使用离手前的视为定义。时机系统不复制持久实体牌，不改变 UID，也不增加额外摸牌或弃牌数量。

触发角色关系分为 `player`、`source`、`target`、`global`。前三者只有技能持有者 ID 与事件相应角色一致时才触发，`global` 监听任意角色；同一时机按 `first_do`、优先级、当前回合起算座次、注册顺序和 `last_do` 排列。主动技能入口严格为 `phaseUse`、`chooseToUse`、`chooseToRespond`、`chooseCard` 四种，入口只决定候选出现位置，实际次数、费用、目标、伤害、回复和冷却仍由技能自身 `can_activate/activate` 负责。

## 七、基本牌机制

### 杀

- 普通【杀】、火【杀】和雷【杀】的规则牌名都为【杀】，共同满足所有写作“【杀】”的牌、技能、响应和次数条件；“火”“雷”只区分伤害属性。实体牌面与界面仍显示两个字“火杀”“雷杀”，不把显示文本改成带书名号或分隔符的形式。
- 每个普通或额外出牌阶段基础限用 1 次，各出牌阶段独立统计。
- 基础目标数为 1，必须在攻击范围内。
- 目标打出 1 张闪则抵消，否则受到 1 点伤害。
- 普通【杀】造成普通伤害，火【杀】造成火焰伤害，雷【杀】造成雷电伤害。
- 诸葛连弩使杀没有次数限制。
- 酒使本回合声明使用的下一张杀伤害基数 +1；多目标杀共享该伤害基数。
- 方天画戟：若使用的杀是最后 1 张手牌，额外目标数上限 +2，即最多 3 个目标。

### 闪

- 只在杀或万箭齐发等响应窗口中使用。
- 每使用 1 张闪抵消当前要求的 1 次响应。

### 桃

- 出牌阶段仅可对已受伤的自己使用，回复 1 点体力。
- 濒死流程中，任意存活角色可对濒死角色使用桃；这是唯一允许【桃】指定其他角色的时机。
- 若濒死角色体力低于 0，可能需要连续使用多张桃，直至体力至少为 1。

### 酒

- 正常出牌阶段每回合限用 1 次。
- 正常使用只能指定使用者自己，满体力或已受伤时均可使用；其于当前回合使用的下一张杀伤害基数 +1。
- 未消耗的酒加值在当前回合结束时清除，不会保留到后续回合。
- 濒死角色可对自己使用酒，回复 1 点体力；其他角色不能用酒救援。

## 八、锦囊机制与数值

- 过河拆桥：弃置目标手牌、装备区或判定区中的 1 张牌。
- 顺手牵羊：获得距离 1 的目标区域中 1 张牌。
- 决斗：目标先响应杀，双方轮流；首次不能响应的一方受到对方造成的 1 点普通伤害。
- 借刀杀人：使用时按顺序指定1名装备武器的其他角色和其攻击范围内1名被【杀】的角色，共2个声明目标；实际本牌只有持刀者进入目标时机，第二名角色不作为本牌目标。持刀者直接对已声明角色使用1张【杀】，否则把武器交给锦囊使用者手牌。
- 无中生有：只能对使用者自己使用，摸 2 张牌。
- 无懈可击：每使用 1 张会翻转一次锦囊抵消状态；奇数张令原锦囊失效，偶数张令其恢复生效。同一角色只要仍有无懈可击，可在后续响应轮次再次响应。每轮同时公开高亮全部存活玩家，合法候选仍属于各玩家私有信息；首个到达权威端并通过实体 UID、当前区域与 `wuxie` 响应模式复核的提交结算，同轮其余请求立即失效。完整一轮的最后一名响应者明确放弃时直接按当前奇偶状态结束，不会把0张牌误作失效实体并无限重建同一轮；只有实际提交1张牌但消费时实体失效才重新建立合法轮次。无牌玩家不出现只能取消的阻塞窗口，但高亮与持牌玩家完全一致。群体锦囊询问本地玩家时，右侧112×36像素按钮临时改为“不响应该锦囊”；开启后立即以0张牌放弃当前询问，并在同一实体锦囊本次处理区生命周期内自动以0张牌放弃后续无懈询问。开关不消耗卡牌、体力或次数，可在锦囊结算期间再次点击取消，锦囊离开处理区后自动清除。
- AI无懈的队友决策保护：原锦囊尚未被抵消时，若来源为响应AI的正态度队友，且目标为该队友本人或该AI本人，AI固定放弃使用【无懈可击】，即使该锦囊的动态结果为负。来源为敌方时仍正常评估；原锦囊已被抵消时，AI仍可按无懈奇偶规则使用反无懈恢复队友锦囊。
- 万箭齐发：每名其他角色响应 1 张闪，否则受到来源造成的 1 点普通伤害。
- 南蛮入侵：每名其他角色响应 1 张杀，否则受到来源造成的 1 点普通伤害。
- 桃园结义：每名已受伤角色回复 1 点体力；逐目标无懈询问与全部目标结算完成后，若使用者仍处于出牌阶段，再创建下一次出牌请求，后续响应不能覆盖该请求。
- 五谷丰登：亮出等于目标数的牌，每名目标依次获得 1 张，剩余牌弃置。使用后立即创建全体玩家可见的公共选牌展示；窗口数据在全部目标依次完成选择前持续存在。公共窗口使用中心锚点和对称偏移保持居中；本地进入无懈等不同类型的响应时临时隐藏窗口并让出手牌与操作按钮输入，响应结束后从同一公共快照恢复。公共牌阵每行固定4张，牌间距8像素，4列宽468像素，不显示“展示区”标题；最多10名玩家时显示3行。仍有未领取牌时先派发 `wuguRemained`，再把这些牌置入弃牌堆。异步选择全部完成后，整牌 `content` 只读取已写入的完成状态并进入唯一 `contentAfter`，不会再次亮牌或重复创建选择请求。
- 五谷当前选择者的本地暂存选择固定为1张；点击另一张尚未领取的展示牌会替换旧选择，而非因达到上限而禁用其余候选。此交互只改变确认前的客户端暂存 UID，不改变亮牌数量、每名角色获得1张、目标顺序或弃置数量。
- 闪电：判定为黑桃 2 至 9时，目标受到 3 点无来源雷电伤害并弃置闪电；其他结果移动给下一名合法角色。若全场没有其他合法目标，则回到原角色判定区。
- 乐不思蜀：判定不为红桃时，跳过本回合出牌阶段。
- 铁索连环：选择包括使用者自己在内的1至2名角色，逐名切换横置/重置状态；在普通手牌区选中后不选择目标而点击中央“确定”，直接重铸并弃置自身、摸1张牌，不提供独立“重铸”按钮。AI 枚举全部合法单目标与不重复双目标组合，并比较整组收益后决定使用或重铸，不再固定只指定1名目标。
- 火攻：可以包括使用者在内的1名有手牌角色为目标。目标展示 1 张手牌；使用者弃置 1 张同花色手牌后，对目标造成 1 点火焰伤害。 使用者即使没有同花色手牌也必须出现可取消的弃牌询问，禁止静默跳过以免泄露手牌信息（隐私规则；无懈可击并行链除外）。
- 兵粮寸断：距离限制为 1；判定不为梅花时，跳过本回合摸牌阶段。
- 水淹七军：目标询问是否弃置装备区全部牌；若选择不弃装备，则受到来源造成的 1 点普通伤害。

普通锦囊在对每个目标生效前分别进入一条独立的无懈可击响应链。【无懈可击】的使用目标是“即将对当前这一名角色生效的锦囊效果”：奇数张无懈令当前目标的效果无效，偶数张恢复生效；一张无懈不能取消整张多目标锦囊。每条链的一轮响应同时面向全部存活玩家，若多名玩家均可响应，则先提交且权威校验通过者结算；同轮迟到结果不能覆盖已进入下一轮的状态。当前目标完成或被抵消后，原锦囊按既定行动顺序继续结算下一目标，全部目标完成后才从处理区进入弃牌堆。因此【南蛮入侵】与【万箭齐发】会对所有其他存活角色逐名询问并结算，任一异步响应不能提前结束后续目标。延时锦囊使用结算结束后先进入判定区，在判定阶段实际效果生效前进入无懈可击响应链，不在初次放置时重复开启响应窗口。当前基础响应策略根据身份友敌、锦囊收益方向和当前奇偶状态决定是否响应。

## 九、装备机制与数值

- 装备牌子类别稳定值由 `EquipmentSubtype` 统一定义：武器 `weapon`、防具 `armor`、进攻坐骑 `offensive_mount`、防御坐骑 `defensive_mount`、宝物 `treasure`。每项与同名装备槽一一对应；未知子类别不能参与按子类别检索、直接装备或槽位映射。
- 过关斩将第14关的“不同子类别装备”按上述稳定值去重，优先从摸牌堆和弃牌堆已有牌中随机取用；某个子类别没有可用牌时不以其他子类别补足，因此实际装备数可低于4。

### 武器

- 诸葛连弩：杀无次数限制。
- 青釭剑：本张杀对目标结算期间忽略其防具；武器触发选择异步恢复后会重新读取当前武器，确保后续防具判定仍被跳过。
- 雌雄双股剑：攻击者和目标性别均为男性/女性且不同，可选择发动；发动后目标选择弃 1 张手牌，否则攻击者摸 1 张；未知性别不触发。
- 贯石斧：杀被闪抵消时，若攻击者在贯石斧本体之外还有至少 2 张手牌或装备，可选择并弃置正好 2 张其他牌令杀继续生效；贯石斧本体不进入费用候选、不自动选中且不能被伪造提交弃置，取消时保留闪的抵消结果。两张费用中的最后手牌触发嵌套技能时，先完成该技能，再从武器后的稳定阶段恢复原杀；费用仍只弃置2张，命中后基础伤害仍为1点。
- 青龙偃月刀：杀被闪抵消时，可再使用 1 张杀追击同一目标，不检查距离。
- 丈八蛇矛：出牌或响应规则允许使用/打出【杀】且持有至少2张普通手牌时，武器横条向右移动10像素成为可点击候选。点击后必须选择正好2张不同的普通手牌，不能选择木牛“粮”或装备牌；两张材料作为1张无花色、无点数、无颜色的虚拟【杀】使用或打出。出牌时仍受每阶段【杀】次数、攻击范围和目标合法性限制，材料依次进入处理区并在整张虚拟【杀】结算后进入弃牌堆，丈八蛇矛本身保持装备；虚拟【杀】不满足方天画戟的“最后1张手牌”条件。
- 方天画戟：实际使用的杀是手牌区最后 1 张手牌时，最多额外指定 2 个目标；木牛“粮”不属于手牌，不能据此触发。
- “造成伤害时”与“将造成伤害时”统一指实际护盾、体力扣减之前；“造成伤害后”才指伤害已经扣减后的尾部。当前逐项审计结果：寒冰剑在【杀】伤害前可防止伤害；剑势与麒麟弓使用【杀】专属 `shaDamage` 前置时机；古锭刀在通用伤害数值修正阶段令伤害+1；还阳使用通用 `damageBegin4` 前置时机先回复。再现、山倾红桃、摄伏与无邪的原文均为“造成伤害后”，继续使用伤害成立后的时机，不前移。
- 麒麟弓：杀造成正数伤害时，可从目标装备区明确选择并弃置 1 张进攻坐骑或防御坐骑；取消时不弃置。麒麟弓使用【杀】专属 `shaDamage` 前置事件，选择创建时目标尚未承受本次伤害，选择完整结束后才进入通用伤害扣减。
- 寒冰剑：杀将造成伤害时，只要目标手牌区或装备区有牌，可选择发动并防止伤害，然后从这些区域选择弃置 1 至 2 张牌；寒冰剑不能弃置判定区牌，取消发动时正常造成伤害。
- 古锭刀：杀对没有手牌的目标造成伤害时，伤害 +1。
- 朱雀羽扇：使用普通【杀】时可选择发动；确认后整张【杀】转换为火【杀】并对全部目标造成火焰伤害，取消时仍为普通【杀】。
- 银月枪：攻击范围为3。持有者在回合外使用或打出1张黑色手牌后，先收到可取消的银月枪发动请求；确认发动后令攻击范围内1名角色通过统一响应询问选择是否打出1张闪，未打出时由持有者对其造成1点普通伤害；木牛“粮”不属于手牌，不能触发。发动请求排在原黑色牌响应子事件完成之后，不能覆盖或跳过原【闪】、【杀】、【无懈可击】等响应上下文。

### 防具

- 八卦阵：需要闪时判定；红色判定视为打出 1 张闪。黑色判定只令本次八卦阵响应失败，随后回到同一个【闪】响应时机，排除本次已判定的八卦阵并继续允许玩家选择手牌或木牛“粮”中的【闪】；没有其他合法候选时仍可放弃响应。
- 仁王盾：黑色杀无效。
- 白银狮子：受到大于 1 点的伤害时改为 1 点；存活且受伤时失去白银狮子，回复 1 点体力。
- 藤甲：普通【杀】、南蛮入侵和万箭齐发无效；受到火焰伤害时伤害 +1。

防具实际生效时（阻挡【杀】或群体锦囊、修正受到伤害、八卦阵判定、白银狮子离区回复），持有者武将牌中心以技能发动同款短暂样式显示防具名。该客户端提示不改变黑色【杀】无效、火焰伤害 `+1`、白银狮子伤害封顶为1、回复1点或任何判定结果。

八卦阵、闪电、乐不思蜀和兵粮寸断共用同一判定流程：延时锦囊先创建 `delayedJudge` 展示自身并默认等待1.00秒，再创建 `judge`，从牌堆顶取1张牌进入处理区，并直接从中央弃牌展示锚点出现，不从判定角色位置打出；记录 `judgeResult` 后创建 `cardsDiscard` 进入弃牌堆。延时锦囊的结果默认再停留1.00秒后才处理下一张。八卦阵红色判定仍只视为打出1张闪，黑色判定后继续原【闪】响应且同一次响应不再提供该八卦阵；闪电仍仅在黑桃2至9时造成3点雷电伤害；乐不思蜀仍在非红桃时跳过出牌阶段；兵粮寸断仍在非梅花时跳过摸牌阶段。判定展示和动画不修改上述花色、点数、伤害、阶段或响应数值。

### 木牛流马

- 每个出牌阶段限发动 1 次；可以发动时宝物横条用0.25秒向右移动10像素，点击选中后再用0.25秒右移10像素，取消候选或选中时用0.25秒复原。点击木牛流马进入存粮选择，不提供独立“存木牛”按钮。
- 每次必须从普通手牌区选择正好 1 张牌扣置为“粮”。
- 发动后可选择 1 名其他存活角色，将木牛流马和全部“粮”转移到其装备区。
- “粮”对持有者可见，在底部手牌区固定显示于普通手牌最左侧，可像手牌一样使用或打出。
- 木牛流马因转移到他人装备区而离开时，“粮”随宝物转移。
- 木牛流马移动到手牌、弃牌堆等非装备区时，其下全部“粮”进入弃牌堆。
- “粮”可以使用或打出，但不属于普通手牌，不计入弃牌阶段手牌上限，不能作为丈八蛇矛材料，也不能重铸；重铸合法动作只接受普通手牌区中配置 `recast=true` 的实体牌。

## 十、伤害、连环、濒死与死亡

标准伤害时机依次为 `damageBefore → damageBegin → damageBegin1 → 来源武器修正 → damageBegin2 → damageBegin3 → 目标防具修正 → damageBegin4 → damage_before兼容事件 → 优先扣减护盾并以剩余值扣减体力 → damage或damageZero → damage_after兼容事件与实际扣体力时的hp_reduced → 濒死/死亡 → damageSource → damageEnd → damageAfter → 按最终伤害点数逐次damagePointAfter → 属性连环传导`。任一标准前置窗口取消时改派 `damageCancelled`；四个 Begin 数字窗口的 `amount` 会逐级传递，调用方提供的父牌UID、逻辑目标数等可序列化来源上下文也会贯穿四个窗口。`damage`、兼容 `damage_after`、`hp_reduced`、`damageSource`、`damageEnd`、`damageAfter` 和每个 `damagePointAfter` 任一时机若创建选择，后续阶段保存稳定游标并等待该选择及同一时机剩余触发全部完成；属性连环的子伤害也必须完整结束后再返回父伤害的下一名横置角色。因此【摄伏】在 `damageSource` 的获牌/弃装备选择不会阻断目标在 `damageAfter` 的【永屹】确认，两者保持原时机顺序和全部原数值。

### 护盾、伤害与失去体力

- 造成伤害的技能语法为 `source.damage(count, who)`：`source` 对 `who` 造成 `count` 点普通伤害。技能需要其他属性伤害时可使用第三个参数 `normal/fire/thunder`；卡牌规则仍可直接调用完整控制器端口。
- 受到伤害时先扣除护盾。若伤害值大于护盾，剩余部分才扣除体力；例如3点伤害命中1点护盾时，护盾降至0并失去2点体力。
- 护盾完整吸收伤害时，角色体力不变，但本次调用仍属于有效伤害，会产生 `damage_after`、造成伤害记录和受到伤害记录；事件中的 `amount` 是最终伤害值，`shield_absorbed` 是护盾吸收值，`hp_lost` 是实际失去的体力值。
- 技能文本“受到1点伤害”或“造成1点伤害”按本次最终伤害值逐点结算：最终造成X点正数伤害，就在整次 `damageAfter` 完成后按第1点至第X点连续发动或依次询问X次，每个 `damagePointAfter.amount` 固定为1，并同时提供从1开始的 `damage_point_index` 与 `damage_total_amount=X`。例如一次受到2点伤害时，“当你受到1点伤害后，你可摸一张牌”会连续询问2次，每次独立决定是否摸1张。护盾吸收不减少最终伤害点数，因此2点伤害被2点护盾完全吸收时仍结算2次；伤害被取消或最终为0时结算0次。直接失去体力不属于伤害，不触发逐点伤害时机。
- 每次最终正数伤害都会令目标公开累计受伤计数增加1并触发武将牌受击抖动；即使护盾吸收了全部伤害，抖动仍会播放。单纯获得、减少或失去护盾不会增加该计数。
- 技能文本“当你的体力值受到伤害”专指伤害结算后 `hp_lost>0`，即伤害实际穿透护盾并扣减体力。护盾完整抵消时虽然仍存在伤害事实和标准伤害时机，但不满足该措辞；直接失去体力也不满足，因为它不是伤害。
- 失去护盾只减少护盾；例如失去1点护盾时，不产生体力减少、伤害事实、伤害时机或濒死，也不会触发“失去体力”“受到伤害”或“体力值受到伤害”类效果。
- 失去体力的技能语法为 `who.loseHp(count, source)`。失去体力直接扣除 `who` 的 `count` 点体力，不扣除护盾，不经过武器、防具、伤害增减、伤害历史、属性连环、`damage_before` 或 `damage_after`。
- `loseHp` 只产生独立的 `lose_hp_before`、`lose_hp_after` 事件；来源角色用于日志、事件和回放追溯，不被视为伤害来源或死亡击杀者。
- 受到伤害类与造成伤害类技能只订阅 `damage_before`、`damage_after` 等伤害事件，因此只能由 `damage` 触发，`loseHp` 不能触发这些技能。
- 伤害穿透护盾而实际扣减体力时，以及 `loseHp` 直接扣减体力时，都会产生 `hp_reduced`，分别使用 `reduction_type=damage` 与 `reduction_type=lose_hp`。因此二者都属于“体力值减少”，但仍保持独立的伤害语义。
- 角色因任一方式降至0点或以下都会进入濒死；`loseHp` 造成的死亡按无击杀来源处理，不触发击杀反贼摸3张或领袖击杀忠臣弃牌等伤害击杀奖惩。

- 普通【杀】、决斗、南蛮入侵和万箭齐发基础伤害为 1。
- 火攻基础火焰伤害为 1。
- 闪电伤害为 3，来源 ID 为 -1。
- 酒加值为 +1。
- `wine_used` 与 `wine_bonus` 是场上公开回合状态，进入所有观察者快照；它们只公开是否已经使用【酒】及下一张【杀】的伤害加值，不公开任何手牌牌面。
- 古锭刀加值为 +1。
- 藤甲受到火焰伤害加值为 +1。
- 白银狮子把任何大于 1 的单次伤害改为 1。

横置角色受到火焰或雷电伤害后重置，并把最终伤害值从当前回合角色开始按存活座次依次传导给其他仍横置的角色。传导伤害不会再次发起新的传导链，但每名受伤横置角色都会重置。传导到其他角色时重新应用该角色自己的防具修正。

“横置一名角色”按状态切换处理：目标未横置时变为横置；目标已经横置而再次受到横置效果时改为竖置，不会保持横置且静默无效。

角色体力降至 0 或以下进入濒死。`dyingBefore`、`dyingBegin`、濒死登记与 `dying` 使用稳定开始游标依次推进；任一时机中的技能若弃牌、摸牌或创建选择，控制器先保存最内层游标，完成该技能全部嵌套触发和“然后”步骤后再检查最新体力，期间不提前创建求桃请求或执行死亡。`dyingBefore` 或 `dyingBegin` 处理器可以通过回复体力或确认死亡结束入口，但仅设置取消或中立化而未修正角色状态时，控制器仍继续建立濒死队列，禁止出现体力不大于0、`alive=true` 且 `dying=false` 的静默存活状态。离场角色进入濒死后仍正常派发 `dyingBefore/dyingBegin/dying` 和 `dying_begin`，但不询问任何角色使用【桃】或【酒】，而是立即进入死亡流程；死亡流程先令其返场、清除限时离场轮次并派发 `enterGame`，然后才依次派发 `dieBefore/dieBegin/die` 并完成死亡。普通在场角色的救援从当前回合角色开始按存活座次只遍历一轮，每名角色最多完成一次询问；窗口提示一次性显示目标达到1点体力所需的救援牌数 `1 - 当前体力`。其他救援者的窗口只包含【桃】，濒死者本人的同一个窗口同时包含【桃】与【酒】，由玩家直接选择其一或取消。每张【桃】或自救【酒】回复1点体力；当前响应者出牌后若目标仍低于1点体力，立即再次询问同一响应者并把提示所需数量减1，直到目标达到1点或该响应者取消。取消后推进到下一名尚未询问的角色，遍历结束后不重新开启全体第二轮。无人救援时角色死亡并先公开身份：若此时已满足胜负条件，立即终止一切结算并结束游戏，不继续死亡弃牌、奖惩、群体牌后续目标、响应、伤害、回复、摸牌或使用牌结束区域移动；若对局继续，再弃置死者全部手牌、装备、判定牌和木牛“粮”并执行奖惩。当前回合角色在任意结算路径死亡且对局继续时，死亡尾部立即取消其旧出牌窗口、只派发一次中断 `phaseOver`，跳过未开始阶段并从下名存活角色开始新回合；死亡中断标记阻止响应、阶段回调或异步续接重复安排轮转。

求桃成功具有独立的完成结算：目标体力达到1点或以上后，控制器立即把目标移出濒死队列、清除濒死状态、记录 `dyingAfter`、派发 `dying_end`，然后才恢复被暂停的当前卡牌目标或判定阶段。每张【桃】或自救【酒】固定回复1点体力，该完成结算不额外改变体力数值。

救援响应牌离开牌源后若触发新的选择，已消费救援牌和濒死流程都会保留：例如拥有【冥谶】的角色用最后1张手牌【桃】救援时，顺序固定为桃先进入弃牌堆、【冥谶】选择1名角色、该角色获得1张【无中生有】、若其不是寒鸦则对自己造成1点雷属性伤害、随后原桃对原濒死目标回复1点。该插入不增加或减少桃、无中生有、伤害与回复的数量，不重新消费桃，也不提前清除或遗失濒死队列。

## 十一、当前交互选择策略

### 人类玩家出牌

- `InteractionPanel` 不绘制背景，只承载提示文本与中央按钮；没有本地出牌、响应、弃牌或效果选择时整组隐藏。
- 内联响应与选牌只显示具体规则提示，不显示“响应询问｜已选择0张｜需要1至1张”一类通用数量摘要。
- 中央“确定”和“取消”均为146×42像素主题主按钮，水平间距为28像素；“结束阶段”为112×36像素主题按钮并独立固定在取消按钮右侧，两者不相交，仅在本地出牌阶段且没有内联选择时显示。该按钮提交的动作语义仍是结束当前出牌阶段并进入弃牌阶段，仅调整客户端文字。不可提交的确定、取消及同类交互按钮固定显示低亮度背景、低对比度边框与灰色文字，禁用期间没有悬停或按下动画。
- 标准流程固定为“选择1张卡牌 → 按规则选择目标 → 确定”。
- 卡牌拖拽只用于调整本地手牌显示顺序：鼠标移动超过8像素后直接移动原 `CardView` 实体，绝不创建拖拽预览或新手牌；落到同一分区另一张牌的左半边或右半边，分别插入目标前或后，空白处释放则恢复原顺序。普通手牌与木牛“粮”不可跨分区，木牛始终位于左侧；拖拽不再选择任何角色或目标。
- 合法候选目标使用当前风格的 `legal_target` 描边，已选卡牌与已选目标使用 `accent` 描边；崩铁风格对应 `#F1DFAA/#D4B55F`，暖木家园对应 `#61C7A4/#EFC76D`。手牌选中向上移动18像素，选中和取消选中动画时长均为0.025秒。
- 多目标选择在界面中只保留点击顺序便于取消与展示，权威提交后按当前行动顺序结算。界面最多保存3名目标；方天画戟满足最后1张手牌条件时可使用【杀】指定最多3名目标。【借刀杀人】必须按“持刀者、被【杀】者”顺序在使用时声明2名角色，实际本牌目标时机只处理首名持刀者，后续不再创建独立目标选择。
- 【借刀杀人】的目标指示线分两阶段顺序播放：先从使用者指向持刀者，第一条完成后再从持刀者指向被要求出【杀】者。持刀者打出【杀】时进入完整【杀】结算；拒绝或没有合法【杀】时，其武器转移到锦囊使用者手牌，父锦囊随后正常收尾。
- 【桃】【酒】【无中生有】及所有 `type=equipment`、`target_mode=self` 的装备牌会自动选择并锁定本人，仍需玩家点击“确定”或按 `Enter` 后才会结算；其他普通单目标牌即使当前恰好只有1名合法目标也保持手动选择。全体目标牌由规则层按存活座次自动展开并逐名过滤当前非法目标，不要求人工逐个选择；选择【万箭齐发】【南蛮入侵】【桃园结义】【五谷丰登】等 `all_others/all_players` 牌后，点击武将牌仍不写入手动选中数组、不显示中央绿色「选中」字，但进入目标预览暗置态：亮起集合为 `normalize_targets` 后的合法目标（`normalized_target_ids`），其余存活角色压暗。暗置依据是“不能成为目标”（如 `all_others` 下的使用者、【破风】额外回合限制），不是“效果无效”（藤甲等不从展开列表移除）。规则限制使其只剩1名合法目标时仍直接使用该唯一数组，不强制补足原本的全体人数。
- 卡牌规则修正后的最大目标数为1时，点击另一名合法角色会直接把旧目标替换为新目标，无需先点旧目标取消；方天画戟满足条件时最大目标数为3，因此仍使用多目标追加与取消流程。
- 当前组合未通过目标数、距离、次数、区域或阶段校验时，“确定”保持禁用；提交后规则核心仍执行第二次权威校验。
- 普通出牌阶段只有出现在当前 `chooseToUse` 合法实体 UID 集合中的牌或主动装备可点击；响应专用牌、次数耗尽、没有合法目标或其他当前无合法动作的牌全部禁用灰显。全部正式手牌仍可在各自分区内拖动排序。禁用纸张与类别条压暗38%，插画和文字保留45%亮度；这些数值仅为视觉参数。
- `Enter` 在当前组合可提交时等价于点击“确定”；`Esc` 和鼠标右键取消当前选择；未选牌时按 `Space` 等价于点击“结束阶段”。这些快捷操作不改变动作类型、次数限制或校验顺序。
- 弃牌阶段、【闪】/【杀】/【桃】/【酒】/【无懈可击】响应、火攻展示与同花色弃牌等候选全部来自本人手牌或木牛“粮”的请求，直接在底部手牌区选择；木牛“粮”固定显示于普通手牌最左侧。请求候选若同时包含本人的装备牌，也继续在左侧装备区直接选择；可选装备用0.25秒向右移动10像素，选中后再用0.25秒右移10像素，复原同样使用0.25秒。装备触发请求会按权威上下文中的装备 UID 自动选中对应横条，玩家不需要再次点击装备，只需确定或取消。手牌和装备共用同一临时 UID 顺序与“确定/取消”按钮。固定组合请求每选1张牌都会依据 `valid_card_combinations` 立即暗置所有无法补成合法完整组合的候选，取消后重新恢复兼容牌。丈八蛇矛在允许使用或打出【杀】时复用该装备入口，点击后选择正好2张普通手牌作为材料；木牛流马在本阶段尚未发动时复用该入口，点击后选择正好1张普通手牌，并可选择1名其他存活角色接收木牛和全部“粮”。响应转换技能必须先点击亮起的技能按钮才会开放材料选择并提交准确技能 ID；【罡风】不会自动把黑色牌视为【杀】。非候选手牌深灰显示且不可交互；“确定”只有在材料、目标或请求数量满足规则后启用，“取消”只对规则允许放弃的请求启用，其中濒死救援的【桃】与【酒】询问都允许取消。
- 五谷公共展示牌、过河拆桥、顺手牵羊以及其他包含公共展示牌、他人区域牌或判定牌的候选继续使用独立选择窗口。【过河拆桥】与【顺手牵羊】使用同款820×460像素固定窗口，手牌区、装备区、判定区纵向排列，内容超高时使用纵向滚动；两个请求只分别执行弃置1张与获得1张，不再维护专用布局。水淹七军或装备技能产生的选择若候选全部属于当前本地玩家的手牌、木牛或装备区，则使用牌桌内联选择。两种界面都提交同一 `choose_cards` 动作，不改变响应次数、牌数或区域规则。
- `choice_type=control/bool` 的互斥文字选项直接使用手牌上方操作区，每项提交稳定 `selected_control_id`；真正取消只表示不发动，不能承担斜杠文本中的第二项实际效果。`choice_type=target_control` 在同一请求中同时提交武将目标与文字选项：目标未达到请求数量时所有实际效果按钮禁用，真正取消按钮始终可用；选中目标后才可按效果按钮确认。【秘策】固定使用该协议同时选择1名其他角色与“出牌阶段”或“弃牌阶段”。该界面协议不改变选项对应的卡牌数、体力值、摸牌量、回复量或次数。
- 不显示独立“重铸”按钮；当前默认牌堆中只有【铁索连环】配置 `recast=true`，从普通手牌选中且没有选择目标时点击“确定”提交重铸，木牛“粮”即使是铁索连环也不能重铸。
- 不显示独立“存木牛”按钮；木牛流马的每阶段1次存粮改为点击宝物横条发动。
- 菜单、日志、牌面比例与动画队列等界面表现不改变卡牌伤害、回复量、摸牌数、距离、次数限制、触发概率或持续时间等玩法数值。

### 技能界面与正式技能

- 本地武将的技能按钮显示在玩家状态与手牌之间；可见数量为武将固有技能 + 模式技能 + 局内临时技能，技能区外层透明且只显示按钮，不显示背景框、状态标签或其他内容。

### 统一询问与选择

所有底层规则均通过统一动作或规则操作端口执行。涉及牌或响应的流程先由控制器发出 `card_choice_requested`，玩家与 AI 都通过 `choose_cards` 提交；AI 只能在候选动作中选择，不能直接执行移动或伤害。

运行时统一结构为 `ChoiceRequest/ChoiceResponse`。请求必须同时校验 request ID、event ID、响应者、牌/目标/按钮候选和各维度选择数量；`card_target` 还会复核所选牌与目标的组合映射。本地 UI 的 `choose_cards` 只是兼容封装，AI、网络与超时托管最终写入相同响应结构。取消、迟到、跨事件响应、重复目标或非法牌目标组合不会消耗牌、体力、次数或其他资源。

所有出牌、响应、弃牌和效果选牌共用事件调度器分配的全局唯一 request ID。请求只有登记成功后才可展示，提交只有被运行时确认后才会清理待选状态并继续结算；该协议只保证交互流程可恢复，不增加冷却时间、触发概率、资源消耗、持续时间或任何卡牌数值。

出牌阶段选中卡牌后，【桃】【酒】【无中生有】【闪电】及 `target_mode=self` 的装备牌，仅在规则预览确认使用者本人是唯一合法目标时自动写入本人；其他牌与主动装备即使仅剩1名合法目标，也必须由本地玩家点击该目标。全体目标仍由规则层自动展开。手动选择目标期间，非法且未选中的武将牌整体使用 `(0.42, 0.42, 0.42, 1.0)` 调制色变暗；合法目标、已选目标、普通浏览和规则自动展开目标保持原亮度。常规选牌说明栏只显示卡牌静态效果；未选牌时不显示“未选择卡牌｜点击牌面选牌，拖动手牌可调整同分区顺序”文本框。手牌临时视为另一张牌时，权威逻辑继续以当前视为定义结算并在离开手牌时恢复实体定义；快照同时携带 `original_definition_id`。恰好1张实体材料的主动转化牌在本次使用表现中携带 `presentation_original_definition_id/view_as_definition_id`。两种情况都由客户端保持原牌名、插画和类别，在牌面中央22像素高的横条显示实际逻辑牌名；横条默认16像素文字，背景使用完全不透明的卡牌纸张白色，边框使用逻辑牌的属性或类别色，文字按实体花色使用牌名红色或深色。多材料和无材料虚拟牌没有唯一原牌面，不生成材料横条。上述变化只调整输入与表现，不改变伤害、回复、摸牌、目标数量、距离、次数、冷却、概率、资源消耗或持续时间。

当任意出牌因玩家响应或选择而暂停时，控制器先恢复并排空原 `CardUseEvent` 的全部逐目标结算，只有确认仍处于出牌阶段且不存在待处理选择后，才重新创建 `chooseToUse` 请求；【桃园结义】的多名目标无懈询问不能覆盖这个新请求或令剩余手牌全部灰显。若当前角色由 AI 控制，再以同一阶段令牌只安排1个后续 AI 任务。AI 自己收到响应、弃牌、火攻展示、五谷等选牌请求时也会暂停到提交时再继续，不能同步跳过表现。AI 的普通动作、同步主动技能和普通选择完成后统一进入同一个进度恢复出口；策略提交失败时使用规则层完整合法动作回退，默认重试2次，仍无解时只中断该请求及其事件并释放对应暂停令牌，父流程与整局继续运行。该恢复不额外增加 AI 动作数，单个出牌阶段上限仍为64个动作。

- 火攻：目标直接在自己的手牌区选择展示牌，展示牌通过 `showCards` 公开并从展示者武将牌中心以正式111×148像素牌面飞入中央牌桌；实体牌仍留在目标手牌区，纯展示不会占用该实体未来真实弃置时的动画。使用者再在自己的手牌区选择是否弃置同花色手牌。若本次因取消、费用失效、无懈抵消、伤害被取消或最终伤害降为0而未造成正数伤害，AI 在该使用者本回合内记录目标并避免再次对其使用【火攻】；下一回合清除记录。 无同花色手牌时仍打开可取消弃牌窗，禁止因候选为空自动取消。
- 弃牌阶段：当前角色只按普通手牌数计算超出手牌上限的牌并在普通手牌区选择足量卡牌；木牛“粮”数量不参与上限与弃牌数量计算。
- 无懈可击、桃、酒、杀、闪等本人手牌响应：先创建响应询问，再在本地手牌区内联选择；只有 `negate` 牌效实际提供 `wuxie` 响应，普通锦囊配置 `response_pattern: wuxie` 只表示该牌效可被无懈，不能将【顺手牵羊】当【无懈可击】打出。无懈每轮公共高亮全部存活玩家，私有请求只发送给拥有合法候选的玩家，且卡牌询问中的目标名称使用公开武将名。成功打出的【无懈可击】属于锦囊牌并派发 `respond` 时机；【智识】同时监听普通锦囊的 `useCard` 与响应锦囊的 `respond`，每次均可摸1张牌。AI 无懈等待到期时若玩法树仍处于暂停，会保留同一请求重新等待，恢复后继续决策，不会丢失请求并把结算卡在询问阶段。群体锦囊的“不响应”开关以父锦囊实体 UID 为边界自动提交空响应，同名下一张牌不会继承；玩家关闭开关后，后续询问恢复正常显示。濒死者的桃与酒候选属于同一个请求。雌雄双股剑、贯石斧、青龙偃月刀、寒冰剑、麒麟弓、朱雀羽扇、银月枪等非锁定装备仍由玩家决定是否发动，但询问出现时会自动选中对应装备；费用牌全部位于当前本地玩家手牌、木牛或装备区时直接在对应区域选择，包含他人或判定区候选时才进入独立窗口，AI 与玩家走同一提交入口。
- 八卦阵响应：当角色需要使用或打出【闪】时，立即先询问是否发动【八卦阵】，首个窗口只包含八卦阵本身。判定为红色时视为打出1张【闪】；玩家取消或判定为黑色时，本响应时机排除该八卦阵并恢复普通手牌、木牛“粮”、转化技能与其他装备响应候选，不会重复询问同一八卦阵。
- 银月枪：回合外使用或打出黑色手牌后，攻击范围内目标通过统一询问决定是否打出【闪】；未打出时由持有者造成1点普通伤害。
- 水淹七军：目标有装备时弃全部装备，否则受到 1 点伤害。

统一选择只改变操作入口，不改变卡牌数值与状态结构。界面和 AI 都不能直接修改 `GameState`，网络与回放记录请求序号、确认状态、所选实体牌 UID、目标 ID、按钮 ID和控制项。

## 十二、AI 与网络数值

- 游戏速度默认0.30秒，可在局内菜单调整为0.10至1.00秒，步长0.10秒；它是相邻阶段、人类响应提示和全部自动响应的全局最小间隔。
- AI 响应速度默认等待0.30秒/次，可在局内菜单调整为0.05至1.00秒，步长0.05秒；AI普通行动等待“AI响应速度”和“游戏速度”的较大值，响应牌与同时无懈先显示经过游戏速度延时的提示，再开始同一较大值的AI等待。
- 单个 AI 出牌阶段最多 64 个动作，超过后自动结束出牌阶段。
- AI手气卡按最终座次计算后置比例 `(座次-1)/(总人数-1)`；一号位基础防御需求为1.0分，线性增加至末号位2.5分。起手中的【闪】计1.0分、【桃】计1.25分、【酒】计0.75分、防具计1.0分、防御坐骑计0.5分；防御得分低于当前位置需求时刷新。起手总牌值还必须达到“手牌张数×3.5”，否则即使防御达标也刷新；数组型同名牌价值按配置的第1张、第2张及后续边际价值依次读取，超出数组长度后沿用最后一项。以上数值只影响开局换牌决策，不修改卡牌效果、实际牌数、体力、伤害或距离。
- AI 固定数量多选默认最多枚举 256 个组合；检查器允许范围为 16 至 1024，步长 16。达到上限后保留稳定枚举顺序中的前若干组，最终选择仍经过权威数量与候选校验。
- AI 直接资源收益统一按1张牌等于1点基础资源、1点体力等于2点基础资源计算，即1点体力等于2张牌；随后再乘观察者对目标的态度比例。自身直接获得1张牌与回复1点体力通常分别形成2.0分和4.0分。未知牌原始牌质、重铸和卡牌保留价值仍使用独立的4.5分尺度，不表示直接牌数收益。
- AI 普通选择提交失败时默认最多重试2次，检查器允许范围为0至5次；回退动作必须来自同一完整合法动作枚举并保留固定牌组、响应技能 ID、目标、按钮与控制项。耗尽后只中断对应无解请求，不中断整局。
- 标准身份 AI 的隐藏身份初始暴露度为0.0，身份公开或领袖固定为1.0。行为目标的暴露度绝对值小于0.2、处于0.2至小于0.4、处于0.4至小于0.6、达到0.6时，身份参照权重依次为0、0.5、0.8、1.0；内奸目标固定为0，禁止通过未暴露目标的真实身份反推行动者。单目标行为基础步长为0.2，多目标为0.1；只有加权行为符合行动者自身收益时才增加，正收益小于1.0时只增加一半，唯一目标为本人时不增加。忠臣作用于暴露度严格为0且可感知牌效为0的其他目标时追加0.1弱收益。本地观察者本人为内奸且执行反向行为时按0.2/0.1减少；其他角色每次更新后的总暴露度乘2.0。卡牌 `ai.expose` 额外累加，最终暴露度限制在-0.5至0.95。
- 忠臣和反贼只有在符合自身收益的行为形成正暴露后才分别定型为忠、反，误操作不会贴成相反身份；标记定型后不再翻转。内奸可按本次行为对领袖阵营的方向暂标忠或反，后续出现相反行为时清空并永久终结自动猜测；无存活反贼时不新增内奸反标。存在忠反标记时态度最低使用0.5可信权重；全部反贼已有行为暴露时，其他零暴露隐藏非反贼角色最低使用0.3权重。切换对局时暴露度、范围为-1.0至1.0的诊断信号、标记及终结状态全部清空。
- 【无懈可击】的额外暴露值为0.2，但只有原锦囊使用者暴露度非0且响应者不是当前目标本人时才记录，忠反方向按原锦囊目标牌效与响应后的抵消奇偶计算。普通用牌以最终目标和用牌前状态记录：回复牌对满体力目标的动态结果为0，【铁索连环】对未横置目标按-0.5、对已横置目标按+0.5区分施加与解除连环。濒死救援只有卡牌效果实际成功后才记录，【桃】沿用 `target_result=2.0` 对真实濒死目标计算，本人自救不标记。【天坠】成功造成目标行为时按 `target_result=-1.0` 记录，【军势】成功令角色摸牌、【行军】成功给予额外回合、【振旗】成功令另一角色摸牌或回复时均按 `target_result=1.0` 记录；【领航】重铸由来源角色自主决定，不额外记录姬子的目标身份行为。未确认、执行失败、纯自用或强制锁定效果不形成技能身份线索。
- 【无懈可击】AI 在判断是否响应时同样读取卡牌动态逐目标结果。对已横置角色使用【铁索连环】代表解除连环，结果固定为正收益 `+0.5`；因此正态度队友不使用【无懈可击】抵消该次效果。正态度队友对AI本人使用动态结果为负的锦囊时，第一轮同样固定保留【无懈可击】，相信队友具有战术意图。该评分只决定是否响应，不改变横置切换、无懈奇偶链或任何牌数。
- 【振旗】费用选项 AI 先取费用支付者对其他合法贝洛伯格角色的最高正态度，再除以2.0；弃置手牌分支扣1.0，失去1点体力分支扣2.0，结果严格大于0才发动。强制弃牌按候选牌保留价值取最低者，布洛妮娅的强制受益目标按自身可感知态度取最高者。【领航】确认收益为姬子对事件来源角色的态度除以2.0；来源角色重铸时从所有普通手牌选择保留价值最低者，未知牌质价值4.5减该牌保留价值严格大于0才重铸，否则取消。以上分数只影响 AI 选择，不改变实际1张牌、1点体力、1点回复或每回合1次规则。
- 【加护】AI 把1点护盾按2.5分估值，把从竖直切换为横置按1.0分机会成本估值，只为正态度角色发动。【冰封】AI 把竖直横置角色按1.5分基础状态价值估算，把弃置1张未知手牌按统一单牌基础值1.0分估算；对敌人时，只有“弃置目标1张手牌并令原牌无效”的净效果严格大于原牌继续生效才发动。它也会主动枚举对横置队友使用单目标负收益牌的动作：移除该牌负收益、加入竖置收益，并通过【冰封】令原牌对队友无效。每回合每名目标的已用额度从公开 `skill_history` 判断，不读取隐藏运行时变量。
- 【永屹】AI 把1点护盾按2.5分估值。伤害后分支按当前“手牌数−当前体力”的正超限量估算额外弃牌数，预计优先弃置最低保留价值手牌，并按0.55权重折算弃牌成本；只有护盾收益严格高于该成本才发动。弃牌阶段分支固定摸取1张未知牌，按2.0分计入收益，再把每张当前可主动使用牌按0.8分估值、可命中敌人的【杀】额外计4.0分；第二段1点普通自伤若被护盾吸收，则每点按2.5分扣除，穿透护盾的体力减少按统一“1点体力=2张牌”资源值扣除。4体力且无护盾、没有现有可用牌时，摸1张牌与失去1点体力的基础评分相抵为0.0，不压过取消；无护盾且当前体力不大于1时固定评为-100.0，避免AI主动进入濒死。该评分不改变玩家询问、自伤、实际摸1张牌或额外阶段规则。
- 【罡风】AI 按标准雷【杀】完整估算目标、响应与属性连环收益，再扣除黑色材料牌保留价值的0.45倍，优先消耗低价值材料。【疾雨】为普通、火与雷【杀】动作统一增加4.0分；罡风、全垒、倾力和丈八蛇矛等转化动作会先构造实际虚拟用牌代理，再经过与实体牌相同的被动技能评分链，因此这4.0分也会计入转化后实际拥有的【杀】，不依赖仅雷【杀】专用元数据。疾雨把令未横置原目标调整至横置按1.5分估值，原目标已横置时该部分为0；目标选择分支的优先项固定获得6.0分：目标没有已知【闪】时选“1.不可响应此【杀】”，有已知【闪】时选“2.令其横置一名角色”；若丹恒攻击范围内存在敌对候选且这些敌对候选均已横置，则不检查【闪】并固定选择第二项，因为不存在新增敌方横置的风险。丹恒随后优先横置敌人或把已横置队友调整为竖直。
- 防酒杀AI参考无名杀公开源码提交 `e18a8256e01ab1357e4c7472349dceb3d0aa1a3a`。真实【杀】响应伤害每高于1点1点，使用【闪】的评分增加4.0；伤害不小于响应者当前体力+护盾时再增加8.0，确保致命酒杀优先保命。敌方已经获得酒加成、持有已知【杀】且在攻击范围内时，AI最后1张【闪】的保留价值在非致命威胁下增加2.0、致命威胁下增加6.0，多名威胁只取最高值。主动使用【杀】时，`wine_bonus=1` 令预期伤害从1提高到2；每多1点伤害使目标及属性连环伤害效果倍率乘2.0，并按体力+护盾判断预期击杀。以上均只改变AI评分，不改变酒固定+1伤害、【闪】响应合法性、护盾结算或实际伤害。
- 【药理】AI 的目标基础收益先按统一1张牌资源值计算，再加已损失体力每点+2.2、手牌每张+0.25且最多+1.5；残血目标按本轮行动距离每个座次差加入0.15修正，拥有【焕发】时再加入目标额外出牌价值的0.7倍。唯一红色手牌交给满体力自己时-3.0，材料保留价值按0.3倍扣除，敌对目标额外-6.0。【焕发】只在目标具有可用手牌时按“1.0+手牌数×0.7（手牌部分最多3.5）”计入阶段价值，响应专用牌和满体力【桃】不计；技能声明价值必须满足自身材料条件，【药理】固定要求至少1张红色普通手牌。娜塔莎自身没有任何可用行动时确认固定为-20.0分；若本轮后续存在明确持有【药】且价值更高的友方，则保留每轮1次额度。
- 【军势】【星火】【药理】【摄伏】的直接牌数收益、【天坠】【冥谶】的体力变化、【还阳】的回复均使用“1点体力=2张牌”统一资源函数。【冥谶】选择自己只计算获得2张牌；选择其他角色时，获得2张牌与失去1点体力的基础资源值正好抵消，能令敌方进入濒死时额外+8.0，横置目标按态度×0.35修正属性连环风险。【录事】按未知摸1张牌质价值4.5减去两张费用牌完整保留价值估分；若所选牌覆盖寒鸦全部普通手牌且拥有【冥谶】，额外+7.0。AI 同步完成【录事】且没有产生嵌套【冥谶】选择时，控制器会继续创建出牌请求并安排下一动作。
- 【还阳】AI 在雪衣受伤时使用伤害牌指定距离1以内目标，按回复1点体力的统一资源收益加分，对自身通常为+4.0；安全体力下以属性伤害指定横置自己再+3.5，体力为1时指定自己-20.0。【摄伏】首次伤害牌基础+1.0，敌方原目标每件装备再+1.2；获牌目标基础按统一1张牌资源值计算，低手牌友方获得额外补牌修正，一字牌对友方每点已损失体力+1.4，四字牌对友方固定+1.5并按低手牌追加修正。选择原伤害目标时再按其装备数量与敌我态度评估后续弃置。
- “自动标记身份”默认开启，可在战斗菜单用复选框即时关闭或重新开启。开启时，其他未知身份角色的徽记读取上述共享行为标记，只会自动显示“忠”“反”或 ASCII 半角 `?`；本地玩家本人不自动标记，没有内置 AI 策略时也继续观察公开用牌、有效无懈响应和已上报技能行为。手动选择“忠”“反”“内”优先于自动标记，真实身份公开后优先级最高且态度计算不再读取旧猜测。关闭只隐藏自动徽记，不清空本局暴露、标记或终结状态，重新开启会立即恢复当前推断。该开关、推断和徽记均不修改权威身份、胜负阵营、体力、伤害、牌数、次数、概率、资源消耗或持续时间。
- 自动身份标记复选框的20×20像素未选边框、2像素描边及2.5像素选中对勾只属于客户端可访问性表现；主菜单与局内菜单使用同一主题语义色，取消勾选后边框仍可见。
- AI 局势强度按“手牌数 + 装备数×1.5 + 体力×2”计算单名角色基础值，体力最高按6计；领袖使用“基础值×1.2+5”，忠臣使用“基础值×0.8+3”，反贼使用“基础值+4”并从领忠净值扣除。领袖基础强度低于12且反贼总强度高于30时局势额外-1，低于6且反贼总强度高于15时再-1，低于4时再-1。
- AI 伤害目标状态倍率：目标1点体力为2.5倍，2点体力为1.8倍；目标0张手牌通常为1.5倍，需要响应【杀】或【闪】时为1.7倍；1张手牌为1.3倍，2张为1.1倍，3张及以上为0.5倍。这些倍率只影响 AI 决策，不修改实际伤害、响应次数或卡牌结算数值。
- AI 已知响应与生存修正：目标已知拥有所需【闪】或【杀】时，预期伤害倍率再乘0.35；没有已知【闪】但装备【八卦阵】时再乘0.65；1点体力目标已知拥有【桃】或仅供本人自救的【酒】时，预期击杀倍率再乘0.7。这些修正只用于决策，不消耗、展示或改变目标手牌。
- AI 威胁值为 `condition + 已知伤害牌数×0.6 + 公开武器×1.0`，再乘 `max(-态度/5.0, 0.25)`。领袖危险度为 `max(3-领袖体力,0)×2 + max(2-领袖手牌数,0) + 敌方condition总和×0.15`；反贼全部计入，反贼清空后内奸也计入。领袖体力2点及以下进入高危区，危险度达到4.0时触发更强保护或集火权重。
- 领忠方对已公开或已标记反贼施加负面效果时，威胁按0.3、领袖危险按0.45加入评分；反贼攻击领袖增加 `3.0+领袖危险×0.7`，攻击忠臣增加 `威胁×0.2`，领袖危险达到4.0时攻击忠臣再减1.5。场上仍有反贼时领忠攻击内奸减1.0，反贼清空后加2.5；反贼仅剩1名及以下时攻击内奸减2.0。领忠为领袖施加正面效果按领袖危险×0.8加分；反贼扶助反贼增加 `1.5+威胁×0.1`。
- 内奸以局势绝对值1为控场阈值：领忠局势大于1时压制领袖或忠臣，反贼局势小于-1时压制反贼；正确控场目标加3.0，帮助优势方或攻击弱势方减2.0。均势时按目标condition×0.2压制强者。多人局中，内奸对1点体力领袖施加预期致命负面效果减12.0；领袖危险达到4.0时为领袖施加正面效果加6.0。
- 濒死救援基础收益为8.0；自救额外加6.0且只扣除救援牌一半价值，每额外缺少1点回复量减1.5。忠臣救领袖额外加8.0，多人局内奸救领袖加7.0，反贼救领袖减20.0；反贼救已公开或已标记反贼、内奸扶助弱势阵营均加4.0，领忠救忠臣加3.0。救援牌按完整保留价值扣分；救援者仅剩1点体力且目标不是领袖时再减3.0。正态度被救者没有手牌再减2.5；从下一名存活角色起计算行动距离，第2个座次开始每远1席减0.75、最多减3.0；判定区有【乐不思蜀】减2.5，有【兵粮寸断】减1.5。
- AI 识别公开防具：未无视防具时，仁王盾会令黑色【杀】的确定无效目标收益为0，藤甲会令普通【杀】、【南蛮入侵】与【万箭齐发】的确定无效目标收益为0，火焰伤害目标收益乘2.0。若一张实体【杀】或伤害类群体锦囊的全部实际目标均被上述防具拦截，AI先叠加卡牌与技能联动收益，再移除仅用于动作排序的 `order` 分；剩余收益严格大于0才使用。因此单纯攻击不会消耗实体牌，但【星火】等仍能产生独立正收益的技能可保留无效【杀】。青釭剑等无视防具效果会跳过该预判。
- AI 的属性伤害连环评估会把首个横置目标以外的全部横置存活角色纳入：自己横置的传导自伤损失乘1.5，任一传导受击者为1血时乘2.5，自己1血时额外减12.0分；伤害类群体锦囊逐名检查1血友方。预计击杀已确认反贼加3.0分，击杀已确认队友减8.0分，主公击杀忠臣再减 `12.0 + 2.0×(主公手牌数+装备数)` 分，对应规则中的摸3张和弃置全部手牌、装备。未知身份不会读取真实身份；上述全为AI决策数值，不改变实际伤害或死亡奖惩。
- 可取消 AI 选择只有最高确认分大于0时才确认；不可取消选择必须提交合法结果。零材料技能确认必须由技能上下文声明 `ai_allow_confirm=true`；零牌费用加目标请求会同时枚举零牌目标与一牌目标动作。
- AI 对卡牌与武将静态元数据使用按定义 ID 的只读副本缓存，同一定义重复评分不再重复深拷贝；同一合法动作集合内的技能 AI 实例按技能 ID 复用并在选定动作后释放。缓存数量最多等于本评估器实际查询到的定义种类，保存0份玩家快照、合法动作或选择结果，不改变0.05至1.00秒响应设置、每阶段64动作上限、最多256组默认多选枚举或任何 AI 评分数值。
- 【借刀杀人】无懈效用：队友对持刀者本人使用时，持刀者对敌人打出【杀】和拒绝后把武器交给队友都属于团队正收益，因此第一张【无懈可击】为负收益；若锦囊已经被抵消，反无懈按奇偶规则倾向恢复其生效。该判断只改变 AI 决策，不修改【杀】次数、武器转移或无懈链规则。
- 【焕发】AI：敌方、中立或没有任何实际出牌机会的目标固定按 `-20.0` 分取消；已使用本回合1次【酒】、回复条件不成立、场上无可操作区域牌、没有其他持武器角色或只有响应专用牌均不算行动机会。该数值只用于保留每轮1次技能额度，不改变额外出牌阶段规则。
- 46种已登记卡牌全部使用自身 GD 文件中的 `ai` 配置；【铁索连环】额外枚举包括自身在内的全部合法单目标与不重复双目标组合，并按每名目标当前横置状态反转收益；恰好只有2名存活在场角色的1v1局面中固定选择重铸并摸1张，不再评估使用目标。【借刀杀人】直接枚举“持刀者、被【杀】者”的完整合法双目标动作。【闪电】【木牛流马】【丈八蛇矛】也有卡牌文件内专属判断。53个由正式武将引用的唯一技能均在自身技能 GD 文件中提供配套 AI。
- 网络协议版本为 3；保留 `leader` 身份值与 `leader_player_id`、`leader_character_id` 选将字段，并新增大厅密码、形象、位置、聊天、踢出与房间设置协议；旧协议封包不接受。

## 十四、安卓平台与触控规则

- Android 应用逻辑视口固定为1280×720，使用 `canvas_items + keep` 等比缩放；启动方向固定为单一横屏，不使用旋转传感器动态切换方向。16:9、18:9、19.5:9、20:9等设备只改变画布缩放和留边，不改变牌面、座位或玩法数值。
- Android 采用沉浸式全屏、关闭 edge-to-edge 并启用 HiDPI；刘海、挖孔、圆角与系统栏由安全窗口边界隔离，不裁切1280×720逻辑画布。
- Android 使用Vulkan驱动与Godot Mobile渲染方法，开启VSync并限制最大帧率为60 FPS；应用从后台恢复时重新应用一次显示策略。上述数值只控制显示稳定性，用于避免120Hz高刷新率设备产生交换链闪烁，不改变游戏计时、AI延时或规则事件速度。
- 触屏轻点卡牌执行选择，移动至少8逻辑像素后进入手牌拖动；卡牌长按阈值为0.45秒、允许18逻辑像素抖动。触屏轻点武将牌执行目标选择；武将详情长按阈值为0.50秒、允许18逻辑像素抖动。同一次长按释放不会追加一次选择。
- Android触点转换为标准鼠标指针后统一驱动下拉框、滑条、数字框、文本框、弹出菜单和按钮；自定义卡牌及武将组件忽略同一手势的原始触点以防重复。联机设置打开时不自动弹出输入法，玩家主动点击名称、IP、端口或密码输入区域后才能编辑与定位光标。
- Android进入联机大厅时不自动聚焦聊天输入框；连接成功、关闭文本设置、返回连接入口和正式进入对局时统一释放文本焦点并隐藏软键盘。该行为只管理客户端输入法可见性，不修改聊天内容、连接参数、房间状态或游戏规则。
- Android 返回键优先执行当前界面的取消或返回；无活动取消层时，对局中切换局内菜单，主菜单顶层返回时退出应用。
- Android APK 最低SDK为23、目标SDK为35，仅导出ARM64-v8a架构；局域网需要 `INTERNET` 与网络状态权限，默认ENet端口仍为7000。
- 平台适配不改变身份、体力、伤害、回复、摸牌、弃牌、距离、目标数、次数、概率、资源消耗、持续时间、牌堆数量或AI估值。

## 十五、本轮机制与玩法快照

- 正常出牌阶段【酒】每回合限 `1` 次，对自己使用后仅使下一张【杀】伤害 `+1`，即基数从 `1` 变为 `2`；不回复体力。濒死时本人使用仍回复 `1` 点体力。加伤生效期间（`wine_bonus>0`）该角色武将牌叠加半透明红色滤镜；使用普通、火、雷或【借刀杀人】要求打出的【杀】时，先保存本次 `+1` 伤害并立即把公开 `wine_bonus` 清为 `0`，在防具、【闪】或伤害窗口出现前移除滤镜。若未使用【杀】，回合正常结束或中断时也立即清零并移除滤镜。AI先读取本阶段全部合法动作的完整直接评分，再比较“酒后同一【杀】的完整评分 + 实际增伤 - 0.5分机会成本”；只有该链路严格高于直接【杀】且酒杀总收益为正时才使用【酒】，同分仅加0.01分以稳定保证先酒后杀。本阶段次数已尽、无合法后续【杀】、无合法敌方目标、伤害被完全拦截或白银狮子令加伤仍封顶为 `1` 时均不使用，因此不会在【杀】后空喝【酒】再结束回合。
- 【白银狮子】装备区离开时，受伤持有者回复 `1` 点体力；AI将该真实回复计入敌我拆取、获得、弃置费用和同名防具替换收益。其单次预期承伤同步封顶为 `1`，因此酒杀等大于1点伤害不再获得虚假的额外伤害收益；无视防具时不应用此上限。规则回复量与实际伤害封顶值均不变。
- 【铁索连环】对未横置角色施加横置、对已横置角色解除横置。三人及以上局面中，AI对每个不利连环目标额外扣 `0.75` 分，避免把横置敌方误判为可继续横置的收益；1v1恰好2名存活在场角色时无条件重铸并摸1张。
- 【桃园结义】只对受伤存活角色结算，每名回复 `1` 点体力；满体力角色不进入无懈或回复事件。
- 局内获得的受限技能以 `total_limit`、`per_turn_limit` 与 `per_round_limit` 记录总共、每回合与每轮上限，数值 `0` 表示该维度不限次数。界面从权威使用记录计算剩余次数：总共显示“还可发动N次”，每回合显示“每回合可发动N次”，每轮显示“每轮可发动N次”；三项只附在悬停信息与右键武将详情的技能名后，不显示在技能按钮正文中。
- 角色摸牌、判定或亮牌时若牌堆为空，先洗回弃牌堆；牌堆和弃牌堆都为空则以 `winner="draw"` 立即平局，结算界面显示“对局结算，游戏平局”。
- 移动端武将牌长按信息阈值 `0.50` 秒、移动容差 `18` 像素；双击详情间隔 `0.32` 秒、落点容差 `24` 像素。本地延时锦囊区高 `22` 像素、距手牌 `6` 像素；均为客户端表现数值。


## 对局日志格式

对局日志面向玩家阅读，统一使用下列固定句式；不输出技能详细效果说明或额外出牌阶段技能 ID 括号。

- **角色名**：`武将名（X号位）`，座次取 `players` 数组顺序（一号位起），中文数字一至十。
- **回合分隔**：每名角色进入回合开始阶段时先输出一行 `————————`，紧接着输出“角色的回合开始”；之后才记录回合开始技能与准备阶段日志。
- **阶段**：`xx阶段开始。` / `xx阶段结束。`；额外出牌阶段写作 `额外出牌阶段开始/结束`，不附技能 ID。
- **用牌**：实体牌写作 `xx使用了♠A【杀】` 形式，花色符号为♠♥♣♦，点数 1=A、11=J、12=Q、13=K；无花色无点数的虚拟牌仍写作 `【牌名】`。有目标时追加 `，目标为yy。`（多目标用顿号连接）。
- **技能**：`xx发动了【技能名】`；有目标时追加 `，目标为yy。`；不写“将某牌当某牌使用”等效果细项。
- **技能名称**：结构化历史继续保存稳定技能 ID，但所有玩家可见日志、技能获得/失去、判定原因和其他“因技能”句式必须通过数据库解析为中文技能名；定义异常时显示“未知技能”，不得把英文内部 ID 直接写入日志。
- **获得牌**：实体移动到手牌后，若其知识集合包含当前全部存活角色，写出花色、点数和牌名；若任一存活角色未知，则只写“一张牌”或“一张手牌”。从牌堆或弃牌堆按指定条件获得的牌会重置为获得者私有，因此继续隐藏牌名；五谷丰登等全体已知展示牌继续写出具体牌面。
- **弃置**：从手牌、装备、判定区或木牛等玩家区域移入弃牌堆时，逐张记录 `xx弃置了♠7【闪】。`（花色点数规则与用牌相同）；弃牌阶段结束另记完成弃置汇总。处理区结算弃置不重复记入，避免与用牌/打出日志叠写。

## 十七、本局结算统计与连续重开规则

- 每名角色从开局起累计五项公开终局统计：`累计造成伤害`、`累计受到伤害`、`累计回复体力`、`累计摸牌`、`累计击杀`。伤害以最终有效伤害值累计，护盾吸收的部分仍分别计入造成与受到伤害；被取消或最终伤害为 `0` 的事件不计入。属性连环传导形成的每个实际伤害事件分别累计到同一来源与对应目标。
- 回复只按实际增加的体力累计；超出体力上限的溢出不计。来源角色无论回复自身或其他角色都会获得对应累计回复值；没有角色来源的系统回复不归属任何角色。车轮战或过关斩将的直接补满体力不是普通回复事件，不计入此项。
- 摸牌只统计 `draw()` 实际从牌堆移入手牌的数量；牌堆、弃牌堆都为空而导致请求提前中断的未获得部分不计。击杀只统计有效来源击败其他角色的真实死亡，以及车轮战换将、过关斩将敌方换将对应的武将击败；无来源死亡与自杀不计。
- 对局结束时自动展示全角色结算列表，列顺序固定为“角色、造成伤害、受到伤害、回复体力、摸牌、击杀”。关闭左上角“关闭”后，终局操作区在“重新开始”与“返回主菜单”之间显示“结算界面”，可重复查看同一局统计。
- 未显式传入回放种子（`seed=0`）的每次开局统一混合四项数据生成本局64位种子：Unix系统时间按 `1,000,000` 倍换算的微秒值、进程内单调微秒值、进程号乘质数 `8191`、控制器自增序号乘质数 `104729`。主菜单进入、退出斗地主后重新进入、局内“按设置重新开局”和终局“重新开始”全部调用同一入口；同一进程连续重开依靠单调微秒与序号区分，完整退出后重进依靠Unix微秒与进程号区分。该种子统一驱动本地座位、地主/农民身份、武将候选与牌堆洗牌。离线自动斗地主额外保证相邻两局不会出现完全相同的本地“座次+身份”组合：先按本局随机源正常抽取，若两项都与上一局相同，则从身份不同的其他合法座次中随机改选；只有异常自定义身份表不存在不同身份时才退回任意其他座次。显式非零种子、关闭随机座次及局域网固定映射不应用该跨局约束，继续保持回放、测试与联机座次可复现。
- 素裳：仙舟联盟女性，体力 `4`。【剑势】对每名【杀】伤害目标可判定，红色使该次伤害 `+1`。【山倾】每回合限 `1` 次，以恰好 `2` 张自有牌生成普通【杀】；红桃等量回复、方块摸 `1`、黑桃无距离、梅花弃目标区域 `1` 张，同花色只触发 `1` 次。
- 桂乃芬：仙舟联盟女性，体力 `3`。【戏法】每次观看牌堆顶至多 `2` 张，可将 `0..2` 张按任意顺序置顶，其余置底；牌堆仅余 `1` 张且弃牌堆非空时，弃牌洗入原顶牌下方补足第 `2` 张，原顶牌不会被覆盖或改变顺序。【投狭】每轮限 `1` 次，只回收指定回合出牌阶段进入弃牌堆且仍在其中的同花色牌，最多获得 `1` 张，也可取消；最后原当前回合角色固定摸 `1` 张。
- 【投狭】获得窗口的公开候选由 `get_turn_play_discard_candidates()` 按回合号、行动角色、`phase=play`、进入区域 `discard_pile`、当前仍在弃牌堆和判定花色共同筛选；`CardSelectionPanel` 将这些候选放入独立“弃牌堆”分区，避免把合法候选误归入未渲染的未知区域。
- 佩拉：贝洛伯格女性，体力 `3`。【追歼】准备阶段弃置 `1` 张手牌或装备并选择 `1` 名其他角色，其下一次实际火焰或雷电伤害固定 `+1`；取消、归零与普通伤害不消耗，护盾全额吸收仍消耗，最迟持续到佩拉下个回合开始。目标只显示来源唯一、排序 `50` 的武将牌左上角“追歼”提示，不带公开标记；AI从该提示条目的来源ID识别友方追歼，对火焰、雷电伤害给予固定 `+4.0` 集火评分。【秘策】自己的回合结束时同时选择 `1` 名其他角色和 `1` 个阶段分支；目标与佩拉各执行不同的一项，弃牌分支固定先摸 `1` 张，全部阶段完成后才推进正常下家。
- 玲可：贝洛伯格女性，体力 `3`。【勘测】每个出牌阶段限 `1` 次，私看 `1` 名其他角色的全部手牌，然后从摸牌堆顶部向下获得首张火/雷属性【杀】或首张【桃】；不存在时获得 `0` 张，不回退弃牌堆。【求生】为锁定技，进入濒死时若普通手牌至少 `1` 张且其中没有【桃】或【酒】，弃置进入效果前的全部普通手牌，并在嵌套失牌结算完成后把体力回复至 `1` 点。
