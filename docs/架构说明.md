# 架构说明

## 总体原则

项目采用单向依赖的五层结构：静态数据层负责声明内容，状态与规则层负责权威结算，动作协议层统一外部输入，AI/网络适配层提供不同操作来源，UI 层只渲染快照并提交动作。任何界面、AI 或网络模块都不得直接改写 `GameState`。

```text
JSON 配置
  ↓
GameDatabase → CardInstance / PlayerState / GameState
                         ↓
PlayerAction → MatchController → CardRuleService / CardEffectResolver / IdentityRules
                         ↓
             RuleEventBus + 状态快照
                ↙          ↓          ↘
              UI       AICoordinator   NetworkGateway
```

## 模块职责

### 自动加载节点

- `GameSettings`：保存全局卡牌名称模式。它不保存对局状态，切换后通过信号通知界面刷新。
- `GameDatabase`：读取并校验卡牌、牌堆、势力、武将和技能 JSON。配置通过唯一 ID 建立索引，调用方获得深拷贝；势力索引只保存牌面名称、简称和颜色，不参与身份局胜负判定。

### 数据结构

- `CardInstance`：实体牌 UID、配置 ID、花色、点数、区域和所有者。
- `PlayerState`：身份、武将、体力、存活状态、手牌、装备区、判定区、连环状态、回合标记和木牛“粮”。
- `GameState`：玩家数组、摸牌堆、弃牌堆、处理区、当前阶段、回合数、动作序号与胜负状态。
- `PlayerAction`：统一操作结构，当前支持 `use_card`、`recast_card`、`store_wooden_ox` 和 `end_play`。

### 权威规则层

- `MatchController`：创建对局、推进阶段、执行区域移动、处理判定、伤害、濒死、死亡、连环、奖惩和胜负。
- `CardRuleService`：只做距离、攻击范围、次数、目标、区域和延时锦囊同名校验，不执行效果。
- `CardEffectResolver`：按 `effect_id` 执行基本牌、锦囊和装备效果，只通过控制器公开的规则操作端口改变状态。
- `IdentityRules`：集中维护 2 至 10 人身份表、胜负条件和死亡奖惩类型。
- `RuleEventBus`：按优先级同步派发 `RuleEvent`。武将技能、装备扩展和模式规则可订阅事件，不需反向引用控制器。

### 外部适配层

- `AICoordinator`：管理玩家与 AI 策略映射，把权威完整快照和合法动作交给策略选择。
- `BasicAIPolicy`：示例启发式策略。它不能修改状态，只返回可序列化动作。
- `NetworkGateway`：封装离线、局域网和远程模式的消息协议、序号与收发信号。
- `match_table.gd`：渲染本地裁剪快照、维护临时选择、读取只读规则预览并构建 `PlayerAction`。
- `card_view.gd`：单张实体牌 UI 组件，只处理牌面、选中反馈与拖放数据。
- `player_target_view.gd`：全玩家共用的纵版武将牌组件，渲染势力、竖排武将名、体力圆点、手牌数、座次号、公开装备和目标反馈，只处理点击与卡牌拖放信号。
- `skill_button_view.gd`：武将技能元数据展示组件，只发出技能 ID 请求，不调用规则效果。
- `artwork_loader.gd`：卡牌与武将共用的可选插画加载边界，只返回 `Texture2D` 或空值。
- `battle_ui_style.gd`：动态 UI 的统一样式工厂，集中维护颜色、圆角、描边、内容边距与阴影。
- `decade_battle_layout.gd`：无状态座次布局组件，只消费角色视图数组和总人数，按无名杀百分比模板写入 Control 几何信息。全屏容器自身使用 `MOUSE_FILTER_IGNORE`，输入只由动态武将牌子节点处理。
- `decade_hand_container.gd`：无状态手牌容器，只根据子节点数量和可视宽度计算重叠、抬升与滚动范围。

`assets/ui/table_ornament.svg` 是代码仓库内的矢量桌面装饰资源。它不包含输入或规则逻辑，可由后续主题资源替换；中央牌堆与阶段区域的数据仍只来自本地裁剪快照。

`MatchController.get_card_use_preview()` 是 UI 使用的只读查询边界。它返回当前卡牌是否可提交、合法候选目标、规范化目标、目标模式和说明文本，不返回 `GameState`、`PlayerState` 或 `CardInstance` 对象引用。点击出牌与拖拽出牌最终仍统一构造 `PlayerAction` 并进入 `submit_action()`。

座次与手牌排版不再由 `match_table.gd` 保存像素表。桌面只把动态视图交给布局组件；布局组件不认识玩家身份、卡牌效果、阶段或动作协议，因此可独立替换主题和分辨率模板。

技能栏通过 `GameDatabase.get_skill()` 读取技能元数据深拷贝。预留技能点击只更新界面说明；实际技能必须由独立规则组件实现，并通过标准动作或 `RuleEventBus` 接入，不能由 `SkillButtonView` 或 `match_table.gd` 直接修改状态。

插画路径属于静态表现元数据，不写入 `CardInstance` 或对局快照。`CardView` 和全玩家共用的 `PlayerTargetView` 只把数据定义的 `art_path` 交给 `ArtworkLoader`，因此插画缺失不会影响规则层、AI 或网络层。本地玩家与其他玩家使用同一武将牌类，差异仅来自布局尺寸和快照可见性。

## 触发事件

当前核心提供以下长期稳定事件名：

- `phase_start`：回合开始阶段。
- `phase_finish`：回合结束阶段。
- `card_used`：实体牌进入处理区并声明目标后。
- `damage_before`：伤害扣减前，可修改 `amount` 或取消。
- `damage_after`：伤害扣减后、濒死结算前。
- `recover_after`：实际回复完成后。
- `dying_begin`：角色进入濒死流程时。

技能组件通过 `RuleEventBus.subscribe(event_name, owner, callback, priority)` 注册，组件卸载时使用 `unsubscribe_owner(owner)` 清理。优先级数值越大越先执行。

## 状态可见性

`GameState.to_dict(viewer_id, reveal_private)` 是唯一快照入口：

- 本人可见自己的身份、手牌与木牛“粮”。
- 他人只看到手牌数量和“粮”数量。
- 装备区、判定区、体力、存活与连环状态始终公开。
- `reveal_private=true` 仅供权威 AI、服务器调试与回放使用。

## 设计边界

工程不实现国战身份、势力明置、双将、暗将和国战专属牌。样例武将技能当前只提供数据接口，不批量实现角色库。所有后续扩展应新增配置或独立组件，避免把角色 ID、UI 节点或网络模式硬编码进规则服务。
