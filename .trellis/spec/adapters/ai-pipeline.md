# AI 流水线

> 权威来源：`docs/AI模块.md`、`AI相关内容.md`、`docs/架构说明.md` 外部适配层。
> 内容侧（卡牌 `ai` 字典、技能配套 AI）见 [`../content/content-ai.md`](../content/content-ai.md)。

---

## 一、四层结构与职责

| 层 | 文件 | 职责 |
|---|---|---|
| 协调 | `scripts/ai/ai_coordinator.gd` | 管理玩家与 AI 策略映射，把**权威完整快照**和**合法动作**交给策略选择；共享 `IdentityAIModel` 观察公开用牌 |
| 身份观察 | `scripts/ai/identity_ai_model.gd` | 局势、真实态度、隐藏身份暴露度、角色 `condition`、忠反标记 |
| 身份战略 | `scripts/ai/identity_strategy_evaluator.gd` | 领袖危险、威胁、阵营集火、内奸控场、濒死救援 |
| 牌效评估 | `scripts/ai/noname_ai_evaluator.gd` | 卡牌价值、目标牌效、装备替换、重铸、响应、无懈、弃牌与区域牌选择 |
| 动作选择 | `scripts/ai/basic_ai_policy.gd` | 只在核心提供的合法动作中选择最高正收益动作；无正收益则结束出牌阶段 |

**AI 属于启发式效用系统，不是完整搜索树**；不预演任意深度的未来回合、未知随机判定或全部技能组合。

## 二、动作协议（不可逾越的边界）

- AI **不直接造成伤害、回复体力、移动牌、修改身份或推进阶段**。
- AI **不能修改状态，只返回可序列化动作**。
- `AICoordinator` 把统一选择动作转换为标准 `ChoiceResponse`。
- 完整链路：

```text
合法动作集合（core 生成）
  → 策略评分
  → 返回动作 / ChoiceResponse
  → 统一进入权威校验
  → 失败时使用规则层完整合法动作回退（有限重试）
```

- 最高主动动作分必须**严格大于 0**，否则 `end_play`。
- 可取消请求只有最高确认分**严格大于 0** 才确认。
- **不可取消请求必须选择合法结果**，即使所有结果均为负分。

## 三、缓存与性能红线

`IdentityAIModel` 在**单次同步决策边界**内：

1. 先完成固定身份观察同步；
2. 再额外遍历**最多 10 名玩家各 1 次**，建立玩家 ID、存活身份人数、身份首名玩家与存活总数索引；
3. 按需复用局势与反贼暴露判断；
4. **返回动作前，连同技能实例一起清空。**

> **绝不跨决策缓存权威快照或决策结果。**

其余约定：

- 策略、`NonameAIEvaluator` 与 `IdentityStrategyEvaluator` 分别缓存数据库返回的**静态元数据独立副本**。
- 同一合法动作集合内**按技能 ID 复用纯 AI 技能实例**。
- 身份战略层**禁止**直接按隐藏目标的真实身份分支；只能使用公开身份或临时标记。
- `tests/performance_and_pacing_test.tscn` 会验证 10 人快照在 256 轮候选查询中的单次决策玩家索引开销——**这是性能红线**。

---

## 四、与内容的接口

- 卡牌基础价值、目标收益方向、无懈收益方向**读取卡牌元数据**，`BasicAIPolicy` **不维护具体卡牌 ID 表**。
- 技能文件通过 `append_play_phase_actions()` 与评分钩子提供专属 AI。
- 资源换算统一走 `NonameAIEvaluator.score_resource_change()` 与公开常量，**不得重复声明比例**。

## 五、身份战略数值（改动需同步文档）

详见 `docs/AI模块.md`，以下是既有基线（仅影响决策偏好，**不改变实际规则数值**）：

| 项 | 基线 |
|---|---|
| 行为收益型暴露 | 单目标步长 `0.2`，多目标 `0.1`；收益绝对值 < `5.0` 时只加一半；内奸伪装按同一步长降低；暴露度限制 `-0.5` ~ `0.95`，公开身份与领袖固定 `1.0` |
| 忠反信号阈值 | 达 `0.2` 形成 `loyalist` 标记，达 `-0.2` 形成 `rebel` 标记；标记存在时态度最低用 `0.5` 可信权重 |
| 目标威胁 | `condition + 已知伤害牌数×0.6 + 公开武器×1.0`，再乘 `max(-态度/5.0, 0.25)` |
| 领袖危险 | `max(3-领袖体力,0)×2 + max(2-领袖手牌数,0) + 敌方condition总和×0.15` |
| 濒死救援基础收益 | `8.0`；自救额外 `+6.0` 且只扣救援牌一半价值；忠臣救领袖额外 `+8.0`；反贼救领袖 `-20.0` |
| 已知响应牌 | 有【闪】/【杀】预期伤害乘 `0.35`；无【闪】但有【八卦阵】乘 `0.65`；1 点体力且有【桃】/自救【酒】击杀倍率乘 `0.7` |

> 这些数值只影响 AI 评分，**不会展示、消耗或修改目标手牌**。

## Quality Check

- [ ] AI 改动未让 AI 直接修改状态或推进阶段。
- [ ] 选将阶段的 AI 等待门禁只由**阶段性质**与**实时控制权**决定（`MatchController._should_defer_ai_character_selection()` + 只读阶段判据 `CharacterSelectionService.is_simultaneous_selection_phase()`）。不得改回由「全武将座次身份自选」开关决定——该开关关闭时身份模式同样处于同时选将阶段，AI 提前确认会把武将变成「已被其他玩家选择」而使真人提交被拒；也不得为此新增超时、轮询或配置项。
- [ ] 未新增卡牌/技能 ID 白名单；评分只读元数据。
- [ ] 判断敌我只用 `get_attitude(快照, 响应者, 来源) > 0.0`：AI 层**没有** host/MatchController，**禁止**调用 `are_teammates()` 或任何需要权威规则状态的友方判定；隐藏身份暴露度为 `0` 时态度同样为 `0`，因此“已确认友方”与“同阵营”是两个不同口径，不要混用。
- [ ] 需要“某角色是否拥有某类技能”时走**通用元数据**累计（如 `get_snapshot_sell_blood_value()`；枚举口径为固有技能 + `mode_skill_ids` + `temporary_skills` + `acquired_skills` 去重），不要在评估器内枚举具体技能 ID 或写 ID 白名单——新增同类技能只需在自身文件声明元数据，评估器与调用方都不应改动。
- [ ] 未跨决策缓存快照、决策结果或技能实例。
- [ ] 不可取消请求的负分兜底逻辑仍然存在。
- [ ] 已补全通用决策逻辑（不止需求明示分支），并说明补全内容与作用域。
- [ ] 已跑 `tests/ai_policy_test.tscn`，涉及长局性能时加跑 `performance_and_pacing_test.tscn`。
- [ ] `docs/AI模块.md` 与《游戏机制与玩法内容》已同步数值。
