# 界面与表现层开发规范

> 覆盖 `scripts/ui/`（43 个组件）与 `scenes/`。
> 权威文档：[`docs/界面与交互.md`](../../../docs/界面与交互.md)、[`docs/架构说明.md`](../../../docs/架构说明.md) 的 UI 模块职责。

---

## 层职责与边界

UI 层**只做两件事**：

1. **渲染**权威端下发的**观察者裁剪快照**。
2. 把玩家意图构造成 **`PlayerAction`** 提交回权威端。

明确禁止：

- 读取 `GameState`、`MatchController` 或技能运行时实例。
- 直接改写任何规则状态。
- 自行推算规则结论（如从日志、体力差或牌区差推算统计值）。

`match_table.gd` 是桌面协调器：它只读保存控制器刚生成的裁剪快照，按玩家 ID 建立当帧索引，按实体 UID 对账复用正式手牌节点与座位节点，并维护出牌临时选择、读取只读规则预览、构造 `PlayerAction`。**它也不改写状态。**

## Pre-Development Checklist（开工前必读）

- [ ] 确认组件只消费**快照数据**，不需要控制器/网络模式引用。
- [ ] 确认所需要的数据已经在快照里；若不在，先评估是否应新增快照字段（属于 `core` 层改动）。
- [ ] 颜色、圆角、描边、边距一律经 `BattleUIStyle` / `UIStyleRegistry` 读取，**不新增主题专属颜色常量**。
- [ ] 新增文本控件时，确认已获得统一主题字体色覆盖。
- [ ] 明确节点的父容器与层级（手牌层级、公共模态窗口层级、覆盖层层级）。
- [ ] 确认是否需要每帧处理；不需要时**不注册 `_process`**。
- [ ] 检查是否可复用既有组件（`CardView`、`PlayerTargetView`、`InformationBoxLayer` 等），避免第二套实现。

## Quality Check（完成前自检）

- [ ] 组件未读取 `GameState` / `MatchController` / 技能实例。
- [ ] 组件未改写规则状态；只发出意图信号或构造 `PlayerAction`。
- [ ] 所有颜色与样式经主题层读取，无硬编码主题色。
- [ ] 新增文本控件已纳入统一字体色覆盖（跑 `font_color_audit_test.tscn`）。
- [ ] 禁用状态只阻止**规则动作**，仍允许查看信息。
- [ ] 技能按钮在它自己的发动流程期间保持禁用（`_get_in_flight_skill_release_id()`），取消只由取消按钮提交。
- [ ] 未过度使用 `_process`；空闲时应关闭帧处理。
- [ ] 高频刷新路径已做节点/布局复用与结构签名跳过。
- [ ] 未知身份等占位文本使用 **ASCII 半角**字符（避免 Android 字体回退缺字）。
- [ ] 已跑 `tests/ui_layout_test.tscn`（涉及布局时）。
- [ ] `docs/界面与交互.md` 已同步。

## 常见错误

| 错误 | 后果 |
|---|---|
| 在 UI 里 `controller.host.xxx()` 直接改状态 | 绕过统一权威，LAN 下客户端与房主状态分裂 |
| 硬编码颜色/字号而不走主题 | 切换 UI 风格时该处不跟随，主题一致性破坏 |
| 新增 `Label` 却没纳入字体色覆盖 | `font_color_audit_test` 失败；深色场景下白字不可读 |
| 每帧 `_process` 轮询对局时长/状态 | 违反性能约定，长局卡顿 |
| 为同一数据写第二套渲染逻辑 | 违反复用，表现不一致 |
| 用中文全角占位符表示未知身份 | Android 字体回退缺字，显示异常 |
| 技能发动流程中仍让该技能按钮可点击，并把再次点击当作取消 | 第二次点击被技能源码的“取消 = 放弃当前段”分支接住，表现为“点一下就跳到下一段”或整次发动静默中止；按钮应在该技能自己的流程期间禁用，取消只走取消按钮 |
