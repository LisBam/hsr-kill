# UI 组件模式与视觉规格

> 权威来源：`docs/架构说明.md` 的 UI 模块职责清单、`docs/界面与交互.md`。

---

## 一、组件分工范式

### 1. 协调器 vs 子组件

`match_table.gd` 负责**协调**，子组件负责**单一表现**。子组件通过信号把意图交回协调器：

- `information_requested` / `information_dismissed` —— 统一信息框契约（`equipment_stack_view.gd`、`skill_button_view.gd`、`card_view.gd`、`player_target_view.gd` 共用）。
- `close_requested` / `cancel_requested` / 各类 `*_requested` —— 纯意图，由协调器决定如何处理。

**组件不持有第二份业务状态。** 例：`match_menu.gd` 的过关斩将"临时退出"只发出信号并关闭面板，预约状态由桌面按控制器权威查询回写。

### 2. 无状态表现组件

以下组件只接收纯值并渲染，不感知规则：

| 组件 | 只接收 |
|---|---|
| `judgment_zone_view.gd` | 牌名数组 |
| `player_state_overlay.gd` | 存活与横置两个布尔值 |
| `decade_battle_layout.gd` | 角色视图数组 + 总人数 |
| `decade_hand_container.gd` | 子节点数量、悬停索引、可视宽度 |

**新增表现先判断能否做成无状态组件**——这是本项目降低耦合的主要手段。

### 3. 静态内容与对局状态分离

`all_cards_panel.gd`、`online_settings_panel.gd`、`match_replay_panel.gd` 只读取静态定义或本机文件，**不创建** `GameState`、`PlayerState`、`CardInstance`、选择请求或网络消息。

## 二、输入处理约定

- 正式牌面以 `Node2D` 为根；**输入由透明子组件处理**（如 `card_input_area.gd`、`player_target_input_area.gd`）。
- 透明输入区域必须保持在**覆盖层之上**（如牌背覆盖层）、且 `MOUSE_FILTER` 按需设置：全屏容器自身用 `MOUSE_FILTER_IGNORE`。
- 卡牌：点击、悬停与拖放；拖放**只处理本地手牌排序**，不产生规则动作。拖放松手必须先在容器登记释放点（`DecadeHandContainer.begin_card_settle`）、再提交重排请求，顺序颠倒会让落位过渡从槽位而不是鼠标释放点开始。
- 武将牌：左键、右键详情与公开装备指针坐标。
- 只有**点击选牌与点击目标**才构造 `PlayerAction` 并进入 `submit_action()`。
- 牌的禁用态用调制色（未选中非法目标为 `(0.42, 0.42, 0.42, 1.0)`），**不改变规则候选**。

### 4. 询问形态只有两条通道（不要新写第三条）

`choice_type` 决定询问走哪条通道，分流集中在 `match_table.gd` 的 `_is_inline_hand_choice()` / `_is_inline_control_choice()`：

| 通道 | 适用条件 | 表现 |
|---|---|---|
| 操作区内联 | 选项是**纯文字**（`control` / `bool` / `target_control` / `card_position`），且 `context` 里没有 `display_candidates` / `card_name_candidates` | 候选在牌手区/装备区点亮；选项渲染为操作行按钮（前两项复用确定/取消按钮，第 3 项起追加），请求已声明取消选项时不再追加通用取消按钮 |
| 独立遮罩窗口 `CardSelectionPanel` | 必须在窗口内**看牌面或牌名候选**（展示他人区域牌、牌名候选、排序、私有候选） | 0.76 遮罩 + 面板 |

- 需要展示私密牌面或牌名候选的询问**必须**留在独立窗口，否则内容会被操作行遮住；反过来说，选项全是文字时**不应**再开窗口——同一种语义有两套实现会导致重复代码与多余的点击路径。
- 选项的可用性由**选项自身**决定（`_is_inline_control_option_submittable()`）：声明为取消的选项恒可提交，其余选项必须同时满足手牌维度与目标维度；界面不得硬编码任何选项 ID、技能名或张数口径。
- 新增文字选项类询问时，正确做法是让分流判定接受它，而不是在窗口里再加一个分支。

## 三、视觉规格（固定像素，改动需同步文档）

| 元素 | 规格 |
|---|---|
| 实体卡牌 | **111 × 148** 像素（3:4） |
| 武将牌 | **148.35 × 197.8** 像素（3:4，竖直） |
| 装备横条读取的插画宽度 | 141.35 像素 |
| 牌名标签 | 纸张白色底、4 像素间距、对应边框 |
| 单项公开标记 `PlayerMarkerBadge` | 20 像素圆形、12 像素单字、10 像素数量字；数量在右下角并用 3 像素黑色描边；相邻间距 1 像素 |
| 其他角色标记 | 距牌面 1 像素、整体下移 8 像素 |
| 摸牌动画 | 0.24 秒飞行、0.10 秒停留、0.18 秒淡出；本机批次以**正面**逐张飞向各自手牌槽位，其他观察者的同批牌背按 **42 像素**横向间距整体居中 |
| 本机获得牌落位 | **直飞最终槽位**：收到区域移动时只登记飞行起点与 `{card, origin, started, batch}` 门闸，等包含该牌的权威快照布局出它自己的槽位之后才起飞；终点由 `_get_local_hand_card_slot_center` 从容器刚写入的槽位反推。落地回调解除门闸的那一帧正式节点直接出现在同一槽位，全程只有一段连续飞行 |
| 进入本机手牌区的牌面 | **一律显示正面**（`_should_show_card_back()` 把「目标是本机手牌」排在牌堆判定之前）：该牌落地后就是本人可见的手牌，途中显示牌背会出现落地瞬间的翻面突变。牌背只保留给其他观察者不可见的私有牌面（他人手牌/木牛、他人摸牌） |
| 获得牌飞行的明暗镜像 | 飞行牌面必须与它即将变成的正式手牌**观感一致**：每次快照重配正式节点后调用 `_sync_local_hand_gain_flight_appearance()`，用 `CardView.is_content_dimmed()` / `set_content_dimmed()` 只镜像「禁用压暗」观感（**不**改 `is_interactable`，飞行中的牌仍不可点击）。落地帧同一帧把飞行牌面 `visible = false`，画面里只剩落在槽位上的正式节点——否则会看到亮度跳变，且不可见的上层牌面会拦截手牌点击 |
| 本机获得牌门闸保持 | 门闸期间正式节点被按在飞行起点，该点位于手牌滚动区之外因而被裁剪不可见；**禁止用 `visible=false` 隐藏待落位节点**，`_layout_cards()` 只统计 `visible` 子节点，隐藏会改变其他手牌的槽位 |
| 中央展示牌被获得 | `CardUseAnimationLayer.take_over_active_card(uid)` 取走队列中同 UID 的牌面本身作为飞行牌面（不新建第二张），剩余成员按 `queue_reflow_duration`（0.18 秒）重新以弃牌中心为轴居中 |
| 手牌入场（仅虚拟手牌候选与虚拟牌回归） | 从右侧进入，起点为可视手牌区右边缘外 **24 像素**，0.24 秒（`local_hand_gain_entry_margin`、`local_hand_gain_duration`）；真实获得牌已不再使用这条路径，参数保留给虚拟牌表现 |
| 表现牌绘制层级 | `CardUseAnimationLayer` 自身 `presentation_z_index`（默认 **30**），表现牌只用三档**固定**偏移：展示队列 +1、区域转移 +2、批次摸牌 +3，整层最高 **33**；同档内前后关系由**子节点顺序**决定。层级**禁止**写成「基准 + 队列长度 / 批内牌号」这类递增值——子节点 `z_index` 相对父节点叠加，递增值会把飞牌一路顶到“记录”面板（35）、选将遮罩（40）、统一信息框（100）与阿哈时刻过场（120）之上 |
| 阿哈时刻过场的遮挡 | 过场层级固定 **120**，必须盖住卡牌表现层全部飞牌（≤33）。过场暂停整棵场景树后飞牌与弃牌队列**不会消失**（补间被冻结），只能靠层级被视频遮住；`SKILL_ACTIVATION_Z_INDEX` 取 **34** 才能同时盖住三档表现牌并低于“记录”面板（35） |
| 拖拽落位过渡 | 松手帧被拖牌停在鼠标释放点，再以 **0.18 秒**滑向重排后的稳定槽位（`DecadeHandContainer.drag_settle_seconds`）；释放点未命中同分区手牌时沿同一条过渡回到自己的原槽位 |
| 手牌整理过渡 | 离场或插入后存活手牌滑向新槽位，0.18 秒（`DecadeHandContainer.relayout_animation_seconds`）；悬停补偿不计入槽位，故悬停不触发 |
| 弃置/被取走起点 | 接管手牌容器中的正式节点或装备槽矩形，从该牌真实位置起飞，不新建替代节点 |
| 托管遮罩 | 0.76 透明度黑色滤镜、0.45 秒省略号循环、覆盖矩形高 175 像素 |
| 聊天气泡 | 正文上限 176 像素、停留 4 秒、淡出 0.25 秒、左右内边距 7 像素、上下 4 像素 |
| 回放控制条 | 顶部居中距顶 10 像素、安全边距 4 像素 |

> 这些数值只影响客户端表现；改动后需同步 `docs/界面与交互.md`。

## 四、主题与配色

- `ui_style_registry.gd` 是**纯数据风格注册表**：稳定 ID、显示名、默认风格、语义配色与仅影响表现的主题数值。当前内置 `space_mono`、`decade_wood`、`premium_black_gold`。
- `battle_ui_style.gd` 是**统一样式工厂**：只读取当前风格的语义色，生成圆角、描边、内容边距与阴影。
- **组件不得重新保存主题专属颜色常量。**
- `OptionButton` 及其内部 `PopupMenu` 必须补齐常态、悬停、按下、焦点、禁用、弹出面板与条目悬停主题，**任何鼠标状态都不得回退引擎默认皮肤**。
- 身份语义色统一：领袖红、反贼绿、忠臣黄、内奸蓝；未知状态使用次级文字色。
- 未知身份统一用 **ASCII 半角 `?`**。

### 字体色覆盖（有专门测试把关）

`tests/font_color_audit_test.tscn` 会遍历正式主场景全部静态文本控件：

> **任何缺失统一主题字体色覆盖的 `Label`、`RichTextLabel` 或 `CheckBox` 都会使测试失败。**

该测试用于防止新增界面文字回退场景默认白字。**新增文本控件后必须跑它。**

## 五、布局与坐标

- 座次与手牌排版**不再由 `match_table.gd` 保存像素表**：桌面先把绝对座次旋转为「本地下家至本地上家」的相对顺序，再交给布局组件。布局组件不认识身份、卡牌效果、阶段或动作协议，因此**本地座次随机化不会改变环桌行动方向**。
- `decade_battle_layout.gd` 在节点身份、顺序与总人数与上次完全一致时**跳过重复位置与缩放写入**；尺寸变化信号仍强制重排。
- `decade_hand_container.gd` 以（宽度、节点身份与顺序、悬停、选中、拖动、待消费的拖拽释放点数量、布局参数）生成**结构签名**，未变化时跳过重复位置计算。**任何会改变位置写法的输入都必须进入签名**：漏掉待消费的释放点数量会让松手帧被判定为「签名未变化」而跳过布局，牌面停在鼠标松开的位置不再回落。
- 悬停不会改变其他手牌位置；悬停顶置是独立表现。
- 跨分辨率：`tests/ui_layout_test.tscn` 以 **1152×648** 客户区验证；Android 以 **1280×720** 横屏等比缩放。

## 六、性能约定

- **不注册每帧 `_process`**：对局时长用仅在进行中启动的 0.25 秒 `Timer` 检查整秒变化，终局或返回主菜单后停止。
- 组件在自身禁用/隐藏时**同步关闭帧处理**（如托管遮罩 `auto_managed=false` 时关闭 `_process`）。
- 状态广播时**只浅复制**序列化快照与静态定义的顶层字典；长机缘历史、技能与素材元数据在该只读广播周期内复用；**右键详情输出时再深复制**，外部不能修改组件缓存。
- 表现 ID 在节点创建前去重：字典与环形槽位只保存最近 **4096** 项；落后最高序号至少 4096 的远古重发直接判为过期，因此幂等记录有固定内存上限。**重新开局同时清空窗口与最高序号。**
- 同一次 `draw()` 的牌堆到手牌移动先按批次 ID 收集，完成后**一次性**提交动画层；每个收齐的批次立即启动，允许重叠播放。
- 日志面板折叠时清空 `RichTextLabel` 排版文档，展开时一次恢复全部历史；展开期间同一帧的新增记录**合并为一次**追加。

## 七、询问期间按钮态的单一维护者

操作区的「确定/取消」按钮在**内联询问**期间必须只有一个写入者：

- `_refresh_inline_choice_text()`（询问自己的渲染分支）负责询问期间的按钮文本、可用性与可见性；只要 `_inline_card_choice` 非空，**其它任何渲染路径都不得回写这些按钮**。
- `_render_local_hand()` 会按“当前是否有普通出牌动作”把确定按钮写回禁用、把取消按钮写回隐藏；它同时会被**延迟回调**（例如虚拟候选离场动画结束）触发，因此该写回必须整体受 `if _inline_card_choice.is_empty():` 保护。否则快照重渲染会覆盖刚建立的询问按钮，表现为“装备已自动选中、确定却点不动，必须先点一次取消选中再点一次选中”。
- 取消按钮的**可见性**与**可用性**是两个不同声明：`allow_cancel`（请求字段，规则层）表示“空响应是否为合法提交”，为 `false` 时沿用“可见但禁用”的灰显契约；`context.hide_cancel_button`（请求上下文，表现层）表示“本窗口不展示取消入口”，界面据此直接暗置按钮。新内容**不要**为了让按钮消失而把 `allow_cancel` 改成 `false`，也不要为某个技能在界面里写分支。

## 八、暂停令牌与「表现组件只能停自己」

表现组件（过场动画、全屏演出等）需要冻结对局时，**只能**经 `GameplayPauseService` 申请自己的令牌，**禁止**直接写 `get_tree().paused` 或自建暂停标志：

- 令牌由 `acquire_pause(原因)` 返回 ID，`release_pause(ID)` 只接受该 ID，因此组件**不可能**误释放别人的暂停，多次申请与释放的顺序也任意。
- 组件根节点必须声明 `PROCESS_MODE_ALWAYS`（场景里为 `process_mode = 3`），否则它会被自己造成的暂停一起冻结——连淡入淡出补间与「播完释放令牌」都不会推进，直接变成整局永久卡死。
- **安全网自己也要有安全网**：任何「超时兜底」计时器必须用 `get_tree().create_timer(秒数, true, false, true)`（第 2 个参数 `process_always = true`），或使用 `PROCESS_MODE_ALWAYS` 的 `Timer`。普通 `Timer` 会被这次暂停冻结，兜底回调永不触发，安全网本身反而成为卡死的成因。
- 超时回调必须带**代次校验**：申请与释放各自递增一个 generation，回调只在代数仍然一致时才收场。否则上一段演出的迟到回调会打断甚至结束之后新一段演出的暂停。
- 释放入口必须**收敛到唯一一个函数**（如 `stop_cutscene()`），并覆盖全部收场路径：正常播完、重新开局、对局终局、联机会话关闭、超时兜底。漏掉任何一条都会让令牌残留到主菜单，界面保持冻结。
- **申请暂停前必须检查本机是否仍有待办选择请求**：整棵场景树被冻结时，未声明 `PROCESS_MODE_ALWAYS` 的牌桌控件虽然可见却不可点击，而权威端会一直认为「正在等待真人输入」从而抑制停滞自修复——这是**真死锁**，不是观感问题。有此请求时只播放表现、不申请暂停。该守卫与「本机是离线端、房主还是客户端」无关，一律生效。
- 「能不能申请暂停」只保留**一个权威点**（组件内部的 `_acquire_pause()`）；牌桌只注入**只读探针**，且探针必须是 `Callable` 而不是布尔快照——联机模式与待办请求都会在组件创建之后才变化，缓存创建瞬间的结果会永远读到旧值。
- 判定被跳过时**必须打印诊断**：否则「表现播了却没暂停」会对外表现为无法解释的随机行为。


## 常见错误

| 错误 | 后果 |
|---|---|
| 为特定卡牌/技能在 UI 里写名称分支 | 内容扩展需要改界面，违反解耦 |
| 把布局参数写死在 `match_table.gd` | 破坏布局组件的通用性，本地座次随机化后方向错乱 |
| 表现 ID 去重表无上限 | 长局内存持续增长 |
| 深拷贝整个快照给每个子组件 | 高频刷新时帧率崩塌 |
| 新增 `PopupMenu` 只设常态样式 | 悬停/按下回退引擎默认皮肤，主题破坏 |
| 让手牌重渲染等通用渲染路径回写询问按钮态 | 延迟回调覆盖刚建立的询问按钮，出现“确定点不动/取消消失”，且只有特定牌（会自动选中装备的询问）与特定时机才复现 |
| 把“隐藏取消按钮”实现成 `allow_cancel=false` | 与“可见但禁用”的既有契约冲突，并误伤规则层（网络端迟到空响应、AI 动作枚举）；隐藏表现应走 `context.hide_cancel_button` |
| 跨局本地状态只靠 `_reset_presentation_for_new_match()` 或场景重建清理 | 联机客户端牌桌跨局常驻、不走该入口，上一局本地标注与身份推断会残留到新一局复用座次的武将牌上；跨局本地状态应以快照 `match_id` 变化作为清空边界（同一 `match_id` 的重复快照与断线重连必须保留） |
| 直接写 `get_tree().paused` 或自建暂停标志 | 绕过令牌模型，误释放或漏释放他人的暂停，且无法诊断谁持有 |
| 申请暂停的表现组件根节点未声明 `PROCESS_MODE_ALWAYS` | 组件被自己造成的暂停冻结，播完不释放令牌，整局永久卡死 |
| 超时兜底用普通 `Timer` | 计时器被它保护的暂停冻结，兜底永不触发，安全网本身成为卡死成因 |
| 申请暂停前不检查本机待办选择请求 | 冻结住正在等待玩家输入的响应窗口：权威端等本机、本机点不动，真死锁 |
| 把「本机是否客户端」缓存为布尔值 | 组件创建时联机尚未建立，永远读到离线态 |
| 用 `visible=false` 隐藏等待飞行的正式手牌节点 | `_layout_cards()` 只收集 `visible` 子节点，隐藏会让其余手牌误判槽位并整体错位；应改为把节点按在飞行起点（`hand_entry_offset`）由滚动区裁剪 |
| 为「获得牌飞行」新建第二套飞行/入场接口 | 同一张牌出现两段表现或两个落点，出现「飞进手里、原牌还在中央」的复制观感；统一走 `play_transfer` / `play_draw_transfer_batch` 与同一门闸 |
| 布局签名漏掉会改变位置写法的输入 | 该帧的布局被跳过，牌面停在鼠标位置或旧槽位，且只在特定交互序列下复现 |
| 门闸只依赖 `await tween.finished` 解除 | `clear_presentations()` 会终止补间，`await` 永不恢复，牌会永久停在可视手牌区之外；必须有落地回调之外的自愈路径 |
| 让进入本机手牌区的牌显示牌背 | 牌落地那一刻从牌背翻成正面，玩家看到一次突兀的翻面；`_should_show_card_back()` 必须把「目标是本机手牌」的正面判定排在 `draw_pile` 判定之前 |
| 表现牌面直接沿用 `configure()` 的默认压暗 | 飞行牌面会一直处于禁用压暗（内容0.45灰），而落地后的正式手牌可能是可用状态（明亮），玩家就会在牌进入手牌区后看到一次亮度跳变；观感必须用 `set_content_dimmed()` 单独镜像，且**不能**用 `configure(..., interactable=true)` 代替——那会让飞行中的牌变成可点击 |
| 落地后仍让飞行牌面按停留时长压在正式节点上 | 两张牌重叠会产生亮度与描边差异，且不可见的上层 `CardView` 继续拦截鼠标，刚落地的手牌点不动；`_release_local_hand_gain_flight_gates()` 必须在解闸同帧把飞行牌面置为不可见 |
| 把表现牌层级写成「基准 + 队列长度 / 批内牌号」 | 子节点 `z_index` 相对父节点叠加，层级随牌数一路爬高：批次摸牌 `90 + index` 叠在动画层 30 上就是 120+，阿哈时刻过场（120）与统一信息框（100）都会被飞牌盖住；过场暂停时飞牌不消失，玩家会在过场视频中间看到静止的牌。层级必须是固定常量，同档前后关系交给子节点顺序 |
| 只调高全屏遮罩的 `z_index` 来“压住飞牌” | 表现牌层级是递增值时没有稳定上界，遮罩的数值迟早又被超过；应先给现象层定死波段（`ACTIVE/TRANSFER/DRAW_BATCH` 三档固定偏移），再让遮罩落在波段之上，并在测试里断言这一约束 |
| 认为暂停会顺手隐藏屏幕上的飞牌 | 暂停只冻结补间：飞牌、弃牌队列与目标指示线会静止保留在画面上，遮挡关系完全由绘制层级决定，没有其他兜底 |
