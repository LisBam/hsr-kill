# UI 组件模式与视觉规格

> 权威来源：`docs/架构说明.md` 的 UI 模块职责清单、`docs/界面与交互.md`。

---

## 一、组件分工范式

### 1. 协调器 vs 子组件

`match_table.gd` 负责**协调**，子组件负责**单一表现**。子组件通过信号把意图交回协调器：

- `information_requested` / `information_dismissed` —— 统一信息框契约（`equipment_stack_view.gd`、`skill_button_view.gd`、`card_view.gd`、`player_target_view.gd` 共用）。
- `close_requested` / `cancel_requested` / 各类 `*_requested` —— 纯意图，由协调器决定如何处理。

**组件不持有第二份业务状态。** 例：`match_menu.gd` 的过关斩将"临时退出"只发出信号并关闭面板，预约状态由桌面按控制器权威查询回写。

### 2. 无状态表现组件

以下组件只接收纯值并渲染，不感知规则：

| 组件 | 只接收 |
|---|---|
| `judgment_zone_view.gd` | 牌名数组 |
| `player_state_overlay.gd` | 存活与横置两个布尔值 |
| `decade_battle_layout.gd` | 角色视图数组 + 总人数 |
| `decade_hand_container.gd` | 子节点数量、悬停索引、可视宽度 |

**新增表现先判断能否做成无状态组件**——这是本项目降低耦合的主要手段。

### 3. 静态内容与对局状态分离

`all_cards_panel.gd`、`online_settings_panel.gd`、`match_replay_panel.gd` 只读取静态定义或本机文件，**不创建** `GameState`、`PlayerState`、`CardInstance`、选择请求或网络消息。

## 二、输入处理约定

- 正式牌面以 `Node2D` 为根；**输入由透明子组件处理**（如 `card_input_area.gd`、`player_target_input_area.gd`）。
- 透明输入区域必须保持在**覆盖层之上**（如牌背覆盖层）、且 `MOUSE_FILTER` 按需设置：全屏容器自身用 `MOUSE_FILTER_IGNORE`。
- 卡牌：点击、悬停与拖放；拖放**只处理本地手牌排序**，不产生规则动作。
- 武将牌：左键、右键详情与公开装备指针坐标。
- 只有**点击选牌与点击目标**才构造 `PlayerAction` 并进入 `submit_action()`。
- 牌的禁用态用调制色（未选中非法目标为 `(0.42, 0.42, 0.42, 1.0)`），**不改变规则候选**。

## 三、视觉规格（固定像素，改动需同步文档）

| 元素 | 规格 |
|---|---|
| 实体卡牌 | **111 × 148** 像素（3:4） |
| 武将牌 | **148.35 × 197.8** 像素（3:4，竖直） |
| 装备横条读取的插画宽度 | 141.35 像素 |
| 牌名标签 | 纸张白色底、4 像素间距、对应边框 |
| 单项公开标记 `PlayerMarkerBadge` | 20 像素圆形、12 像素单字、10 像素数量字；数量在右下角并用 3 像素黑色描边；相邻间距 1 像素 |
| 其他角色标记 | 距牌面 1 像素、整体下移 8 像素 |
| 摸牌动画 | 0.24 秒飞行、0.10 秒停留、0.18 秒淡出；同批牌背按 **42 像素**横向间距整体居中 |
| 本地手牌入场 | 从右侧进入，0.24 秒 |
| 托管遮罩 | 0.76 透明度黑色滤镜、0.45 秒省略号循环、覆盖矩形高 175 像素 |
| 聊天气泡 | 正文上限 176 像素、停留 4 秒、淡出 0.25 秒、左右内边距 7 像素、上下 4 像素 |
| 回放控制条 | 顶部居中距顶 10 像素、安全边距 4 像素 |

> 这些数值只影响客户端表现；改动后需同步 `docs/界面与交互.md`。

## 四、主题与配色

- `ui_style_registry.gd` 是**纯数据风格注册表**：稳定 ID、显示名、默认风格、语义配色与仅影响表现的主题数值。当前内置 `space_mono`、`decade_wood`、`premium_black_gold`。
- `battle_ui_style.gd` 是**统一样式工厂**：只读取当前风格的语义色，生成圆角、描边、内容边距与阴影。
- **组件不得重新保存主题专属颜色常量。**
- `OptionButton` 及其内部 `PopupMenu` 必须补齐常态、悬停、按下、焦点、禁用、弹出面板与条目悬停主题，**任何鼠标状态都不得回退引擎默认皮肤**。
- 身份语义色统一：领袖红、反贼绿、忠臣黄、内奸蓝；未知状态使用次级文字色。
- 未知身份统一用 **ASCII 半角 `?`**。

### 字体色覆盖（有专门测试把关）

`tests/font_color_audit_test.tscn` 会遍历正式主场景全部静态文本控件：

> **任何缺失统一主题字体色覆盖的 `Label`、`RichTextLabel` 或 `CheckBox` 都会使测试失败。**

该测试用于防止新增界面文字回退场景默认白字。**新增文本控件后必须跑它。**

## 五、布局与坐标

- 座次与手牌排版**不再由 `match_table.gd` 保存像素表**：桌面先把绝对座次旋转为「本地下家至本地上家」的相对顺序，再交给布局组件。布局组件不认识身份、卡牌效果、阶段或动作协议，因此**本地座次随机化不会改变环桌行动方向**。
- `decade_battle_layout.gd` 在节点身份、顺序与总人数与上次完全一致时**跳过重复位置与缩放写入**；尺寸变化信号仍强制重排。
- `decade_hand_container.gd` 以（宽度、节点身份与顺序、悬停、选中、拖动、布局参数）生成**结构签名**，未变化时跳过重复位置计算。
- 悬停不会改变其他手牌位置；悬停顶置是独立表现。
- 跨分辨率：`tests/ui_layout_test.tscn` 以 **1152×648** 客户区验证；Android 以 **1280×720** 横屏等比缩放。

## 六、性能约定

- **不注册每帧 `_process`**：对局时长用仅在进行中启动的 0.25 秒 `Timer` 检查整秒变化，终局或返回主菜单后停止。
- 组件在自身禁用/隐藏时**同步关闭帧处理**（如托管遮罩 `auto_managed=false` 时关闭 `_process`）。
- 状态广播时**只浅复制**序列化快照与静态定义的顶层字典；长机缘历史、技能与素材元数据在该只读广播周期内复用；**右键详情输出时再深复制**，外部不能修改组件缓存。
- 表现 ID 在节点创建前去重：字典与环形槽位只保存最近 **4096** 项；落后最高序号至少 4096 的远古重发直接判为过期，因此幂等记录有固定内存上限。**重新开局同时清空窗口与最高序号。**
- 同一次 `draw()` 的牌堆到手牌移动先按批次 ID 收集，完成后**一次性**提交动画层；每个收齐的批次立即启动，允许重叠播放。
- 日志面板折叠时清空 `RichTextLabel` 排版文档，展开时一次恢复全部历史；展开期间同一帧的新增记录**合并为一次**追加。

## 常见错误

| 错误 | 后果 |
|---|---|
| 为特定卡牌/技能在 UI 里写名称分支 | 内容扩展需要改界面，违反解耦 |
| 把布局参数写死在 `match_table.gd` | 破坏布局组件的通用性，本地座次随机化后方向错乱 |
| 表现 ID 去重表无上限 | 长局内存持续增长 |
| 深拷贝整个快照给每个子组件 | 高频刷新时帧率崩塌 |
| 新增 `PopupMenu` 只设常态样式 | 悬停/按下回退引擎默认皮肤，主题破坏 |
