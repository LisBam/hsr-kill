# 文档同步规范

> 来源：`AGENTS.md`「文档同步规范」与 `项目专属AGENTS.md` 第 2、3 条。核心要求：**代码改动与 MD 文档必须完全对齐**。

---

## 一、同步矩阵（改代码 → 必查文档）

修改任意功能代码后，必须检索并校验对应模块的 MD 文档：

| 改动内容 | 必须校验/更新的文档 |
|---|---|
| 卡牌（新增、改效果、改数值） | `docs/卡牌系统.md`、`docs/内容制作指南.md`、`docs/游戏机制与玩法内容.md` |
| 技能（新增、改规则、改时机） | `docs/内容制作指南.md`、`docs/游戏机制与玩法内容.md` |
| 武将（新增、改体力/技能引用） | `docs/内容制作指南.md`、`docs/游戏机制与玩法内容.md` |
| 权威规则 / 结算管线 / 事件运行时 | `docs/架构说明.md`、`docs/游戏机制与玩法内容.md` |
| 状态结构（`PlayerState` / `GameState` / `CardInstance` 字段） | `docs/架构说明.md`、`docs/内容制作指南.md` 的数据结构索引 |
| AI 行为或评分数值 | `docs/AI模块.md`、`docs/游戏机制与玩法内容.md` |
| 联机 / 快照裁剪 / 重连 / 聊天 | `docs/网络通信.md` |
| 界面 / 交互 / 视觉规格 | `docs/界面与交互.md` |
| 平台适配（Android 等） | `docs/架构说明.md`（平台适配边界）、`README.md`（运行与导出） |
| 新增测试场景 | `README.md`「自动校验」章节 |

---

## 二、更新粒度要求

### 全局永久性更新

- 更新不局限于**本次修改内容**，需从项目全局与长期维护视角完善。
- 目标是保证文档与代码逻辑**完全对齐**，而非只记录增量。

### 标准化维护

同步补充文档中的：功能说明、使用规则、参数定义、注意事项。

标准：开发者可通过 MD 文档快速理解模块全貌，**无歧义、无遗漏**。

---

## 三、《游戏机制与玩法内容》的强制数值记录

项目维护一份 `docs/游戏机制与玩法内容.md`，它是游戏设计的**唯一权威快照**。

每次修改涉及**游戏机制、玩法规则、数值体系**，或新增/调整功能逻辑时，必须同步更新该文档：

1. 清晰总结本次变更的**机制内容**与**设计意图**。
2. **强制记录所有涉及的具体数值**，例如：
   - 伤害量
   - 冷却时间
   - 触发概率
   - 资源消耗量
   - 持续时间
   - 使用次数 / 距离 / 目标数 / 体力与护盾变化

目的：数值来源可追溯、可复盘。

---

## 四、内容制作指南的接口沉淀（`项目专属AGENTS.md` 第 2 条）

设计技能、卡牌时，若用到接口、变量、函数等可复用设计要素，而 `docs/内容制作指南.md` 存在缺失或描述错误，**必须同步补充修正**。

> 示例：制作「锁定技，出牌阶段限一次，你可弃置一名其他角色区域内的一张牌」时，需把锁定技创建流程、弃置角色区域卡牌函数、其他角色判定规则等配套内容写入指南。

核心目标：完善标准化制作文档，使后续所有技能、卡牌设计都能依完整规范落地。

---

## 五、临时反馈文档（`临时反馈文档.md`）

- 每次完成代码修改后，「学习反馈摘要」与「Git 提交描述」**追加**写入项目根目录 `临时反馈文档.md`。
- 追加前在内容开头加时间戳，格式 `YYYY-MM-DD HH:MM`。
- 已存在则**追加到末尾**，保留历史，不覆盖。
- 不存在则新建。
- 该文档仅供开发者临时查看，**AI 不做维护、校验或引用**。

## Quality Check

- [ ] `docs/内容制作指南.md` 中的参数总表 / 源码索引与实际代码一致。
- [ ] 玩法或数值变更已在《游戏机制与玩法内容》记录具体数值与设计意图。
- [ ] 新增测试场景已写入 `README.md` 的「自动校验」章节。
- [ ] 未把单次更新说明写进**代码注释**（代码注释保持永久性；增量记录只进 `临时反馈文档.md`）。
