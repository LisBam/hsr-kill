# 协作规范

> 来源：`AGENTS.md`（开发者记忆档案 v2.2）与 `项目专属AGENTS.md`。本页只做可执行化提炼，冲突时以原文为准。

---

## 一、原文不可变铁律（最高优先级）

需求中钦定的技能描述原文具有**最高优先级**：

- 实现过程中必须严格保持需求提供的技能描述内容不变。
- **不得改动**任何字段、数值、文字表述、标点符号及语句顺序。
- 玩家可见的技能描述面板文字，必须与原文**绝对一致**。
- 对技能逻辑的理解、适配、实现与补全，一律围绕这份不可变原文展开。

### 新机制 / 新函数处理流程

1. **代码适配判定**
   - 游戏内无对应实现 → 按需求给出的语法、参数、规则完整新增。
   - 游戏内已有对应实现 → 按本次需求定义**重构**原有代码，确保逻辑完全匹配。
2. **配套逻辑补全**
   - 对需求未明确但落地必需的逻辑（边界判定、时机校验、UI 适配等）可自行补全。
   - 补全内容必须在输出末尾**单独告知**。
3. **文档强制同步**
   - 所有新增/重构的机制规则、函数接口、参数说明、结算逻辑与 UI 规范，必须完整写入 `docs/内容制作指南.md`。

### 新武将制作流程

1. 优先查阅 `docs/内容制作指南.md` 中已有函数与机制库，**复用标准接口**实现技能逻辑。
2. 若技能涉及未收录的新机制，**先完成机制开发与文档更新，再实现武将技能**。

## 二、代码注释规范

### 永久性项目级注释

- 面向长期维护、他人阅读、未来回溯编写。
- 说明：**这段代码的作用、设计意图、使用方式、注意事项**。
- **禁止**包含单次更新相关的描述（如"本次修改…"）。
- 标准：任何人阅读都能快速理解核心逻辑。

注释风格以 `##` 文档注释为主，紧跟被说明的符号上方；与 `docs/内容制作指南.md` 中的模板保持一致：

```gdscript
## 【示例牌】卡牌源码。静态信息、目标规则与效果入口均在本文件维护。


## 写入卡牌完整静态信息；所有字段会由 GameDatabase 自动建立只读索引。
func _init() -> void:
	super({ ... })
```

### 变量注释强制

每个变量定义**必须独占一行注释**，说明：

- 该变量的作用与数据含义
- 取值范围
- 默认值的设定原因
- 修改它会造成什么影响

对 `@export` 变量，注释必须保证**在检查器中即可理解其用途**，并注明是否需要运行时动态修改。

### 尊重原版

基于现有代码修改时：

- **严禁**擅自修改变量名。
- **严禁**删除或篡改原有注释。
- 只可**新增补充注释**来完善逻辑说明。

## 三、架构原则（核心）

| 原则 | 要求 |
|---|---|
| 解耦至上 | 极致追求低耦合，严格规避硬编码与模块强依赖；生成代码必须独立可复用、无冗余关联 |
| 组件模式 | 拒绝「全能型胖脚本」；严格单一职责，通过节点挂载组件组合实现复杂逻辑 |
| 参数前置与暴露 | 所有可调整参数、魔法数字统一提取为 `@export` 变量 / 全局常量，放置在脚本最顶部，支持在检查器中直接可视化调试 |

落地判据：一个组件只做一件事；它不读取不属于自己职责的状态（例如 UI 组件不读 `GameState`），跨模块通信走信号、端口或只读快照。

## 四、AI 逻辑实现规范（`项目专属AGENTS.md` 第 3.3 条）

需求中给出的「AI 逻辑」提示**仅作针对性行为指引，不代表完整 AI 实现方案**：

- **禁止**只实现提示中明示的判断分支，必须补全全部基本通用 AI 决策逻辑，包括但不限于：主动出牌优先级、目标选择策略、手牌保留倾向、关键牌使用时机、响应技能条件、多目标选择规则。
- 实现必须基于项目**已有 AI 框架与代码结构**，保持接口统一、策略可插拔；已有通用 AI 模块应扩充完善，而非绕过或重复实现。
- 新技能引入全新博弈维度时，除技能专用评估函数外，**必须同步更新通用估值体系**（卡牌价值、血量权重、局势评估）。
- 新增/修改的 AI 行为必须与现有 AI 协同，不影响其他武将、卡牌的 AI 决策；完成后需说明补全了哪些通用逻辑及其作用域。

具体 AI 分层与数值边界见 [`../adapters/ai-pipeline.md`](../adapters/ai-pipeline.md)。

## 五、Token 优化策略（理解既有逻辑时）

- 优先查阅对应模块的 MD 文档，而非直接通读源代码。
- MD 文档是代码的标准化抽象，已含功能说明、参数定义、使用规则，可代替大部分代码解释。
- 除非文档缺失或与代码严重脱节，否则不重复展开代码细节。
- 若发现文档与代码不一致，按「文档同步规范」修正，使 MD 文档始终是唯一、高效的理解来源。

## 常见错误

| 错误 | 后果 |
|---|---|
| 按自己的理解「润色」需求提供的技能描述文字 | 违反最高优先级铁律，玩家可见文案与原文不一致 |
| 修 bug 时顺手改变量名或删掉旧注释 | 违反尊重原版，破坏历史信息 |
| 把可调数值写成函数内字面量 | 违反参数前置，检查器无法调试 |
| 只在回复里讲述改动，不写文档 | 违反文档同步，`docs/` 与代码脱节 |
| 只实现需求里明示的 AI 分支 | 违反 AI 规范，AI 行为残缺 |
