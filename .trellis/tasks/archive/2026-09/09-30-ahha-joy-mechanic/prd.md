# 阿哈时刻与欢愉技机制

## Goal

在核心层新增**阿哈时刻**触发管线与**欢愉技 / 参演编号**技能分类，使内容层只需在技能文件中声明「欢愉技 + 参演编号」，即可在阿哈时刻触发时被自动、按编号顺序依次执行。

来源：父任务 `09-30-huanyu-ahha-system`。需求原文与全局决策见父任务 `prd.md`；本文只记录本子任务范围内的要求与验收。

## Background

- 机缘选择是阿哈时刻的**参照机制**：触发点位于 `match_controller.gd:10605`（`_start_turn` 内、回合事实建立之前），概率在 `opportunity_system.gd:833` 按「存活且未离场人数倒数」计算并锁定到轮末，每轮至多一次。
- 项目现有 144 个技能，`SkillDefinition` 已有 `lock` / `leader_skill` / `out_of_game_skill` / `reincarnation` 等成熟分类参数的先例可循；`skill_instances_by_player`（`match_controller.gd:352`）是技能实例的唯一权威索引。
- 项目当前无任何欢愉 / 阿哈 / 参演编号代码（已检索确认）。

## Requirements

### R1 欢愉技静态参数与执行入口（内容基类）
- `game_data/skill_definition.gd` 新增两个**显式声明**的元数据键（不从正文推导）：`joy_skill: bool`（默认 `false`）、`performance_number: int`（默认 `0`，非负）。
- 提供只读访问器 `is_joy_skill()`、`get_performance_number()`。
- 提供无副作用前置校验 `can_perform_joy_skill()`（默认要求：是欢愉技、效果片段当前可用、持有者存活且未离场）。
- 提供执行入口 `perform_joy_skill(context)`（默认空实现）与完成回报 `finish_joy_skill_performance()`。
- 欢愉技**不生成主动发动按钮**（`ui_enabled=false`），但仍正常显示于技能栏。

### R2 阿哈时刻触发判定
- 触发时机与机缘一致：**每名角色的回合开始前**（回合事实尚未建立时）。
- 触发概率与机缘一致的算法：本轮开始时按**存活且未离场角色数倒数**计算并锁定到轮末。
- 每轮**至多触发一次**。
- 与机缘选择**各自独立**：同一轮内机缘已触发不阻止阿哈时刻按自身概率判定，反之亦然。
- **场上没有可执行欢愉技时直接跳过**：不消耗随机数、不写 `random_history`、不置本轮已触发标记、不写日志。
- 额外回合不触发（沿用机缘口径）。
- 触发随机值必须写入 `state.random_history`（`kind="ahha_moment_trigger_roll"`），保证固定种子可复现。

### R3 执行顺序
- 参与范围为**场上所有可执行的欢愉技**（不限势力），每名存活且未离场的角色所持有的每个欢愉技各为一个独立执行项。
- 排序：**参演编号升序**；编号相同时按**以当前回合位置（即将开始回合的角色）为起点、座次数组正序**排列。
- 已死亡或已离场的角色不参与；执行过程中途死亡/离场的角色，其后续欢愉技项跳过。

### R4 串行执行与续接
- 欢愉技**逐个串行**执行：前一项完全结算后才开始下一项。
- 欢愉技执行中创建的一切选择走统一选择协议；效果的嵌套结算（伤害、移牌、濒死救援）必须先于下一项完成。
- 组件内部跨帧状态只允许可序列化基础类型（不得存 `SkillDefinition` / `PlayerState` / 节点 / `Callable`）。
- 停滞自修复的软修复分支需为阿哈时刻提供兜底轻推，避免流程卡死。

### R5 回合开始前事件链
- 统一为「机缘判定 → 阿哈时刻判定 → 建立回合事实」，**机缘在前、阿哈时刻在后**。
- 三条既有路径（`_start_turn` 首次进入、`continue_after_opportunity` 机缘结算后恢复、`_start_queued_or_normal_turn` 额外回合链结束）都必须且只能获得一次阿哈时刻判定机会。
- 现有 `_begin_turn_after_opportunity` 的函数名与签名保持不变；机缘现有行为零改动。

### R6 不进入快照与存档
- 阿哈时刻**不新增 `GameState` 字段**、不进入观察者快照、不进入权威存档。
- 表现复用既有的技能发动通道（`record_skill_activation`）与对局日志。

## Acceptance Criteria

- [ ] 技能文件中声明 `joy_skill=true` 与 `performance_number=N` 后，该技能在阿哈时刻被自动执行，且**技能栏不出现可点击的主动按钮**。
- [ ] 固定种子下连续两局，阿哈时刻的触发回合与触发角色完全一致（随机值已进入 `random_history`）。
- [ ] 一轮内阿哈时刻最多触发一次；`try_trigger_before_turn_start` 在本轮已触发后返回 `false`。
- [ ] 同一轮内机缘与阿哈时刻**可以都触发**（互不阻塞）；机缘行为与改动前一致。
- [ ] 场上无任何可执行欢愉技时：不消耗随机数（`random_history` 长度不变）、不写日志、本轮额度未被占用（该轮后续回合开始仍可正常触发）。
- [ ] 两名角色分别持有编号 144 与编号 100 的欢愉技时，执行顺序恒为 100 → 144，与座次无关。
- [ ] 两名角色持有**相同编号**的欢愉技时，执行顺序以当前回合位置为起点按座次正序；把触发角色换到相邻座次后，顺序随之改变（可断言）。
- [ ] 同一角色持有两个欢愉技时，两个技能各自按各自编号排入序列。
- [ ] 欢愉技持有者在阿哈时刻中死亡或离场后，其后续欢愉技不再执行，且流程正常走到回合事实建立。
- [ ] 阿哈时刻全部执行完毕后，该角色的回合正常开始（阶段推进、摸牌、准备阶段等与改动前一致）。
- [ ] 新增 `res://tests/ahha_moment_test.tscn` 场景并 PASS。
- [ ] `event_runtime_test` / `phase_progression_test` / `skill_settlement_runtime_test` / `opportunity_system_test` 全部 PASS。

## Out of Scope

- 任何具体的欢愉技内容（武将、技能文件）——由子任务 `09-30-huohua-character` 交付。
- 阿哈时刻的专属美术、音效、全屏横幅；表现仅走既有技能提示通道与日志。
- 机缘选择机制本身的任何行为改动。
- 阿哈时刻的公开快照字段与联机定向同步（本机制无「全体同时选择」交互，不需要）。

## Key Decisions

| 决策 | 结论 | 来源 |
|---|---|---|
| 参演编号排序方向 | 小 → 大 | 用户确认 |
| 同编号座次方向 | 以当前回合位置为起点，**座次正序** | 用户确认 |
| 与机缘的次数关系 | **各自独立**，同一轮可都触发 | 用户确认 |
| 与机缘的执行先后 | **机缘在前，阿哈时刻在后** | 用户确认 |
| 无可执行欢愉技时 | **不参与判定，直接跳过** | 用户确认 |
| 落点目录 | `scripts/core/ahha_moment_system.gd`（不新增目录） | 父任务 design |
