# 新增星际和平公司势力与武将真珠

## Goal

登记新势力「星际和平公司」（铜色），新增女武将**真珠**（3 体力），其拥有欢愉技【补缀】与主动技【鉴映】。

本需求横跨三层，除内容层新增外还包含两项**核心层新机制**：

1. **真实轮末时机 `roundEnd`**：【补缀】的“本轮结束时，这些角色各失去1点护盾”需要一个真实存在的轮末时机。当前 `RuleTimingCatalog` 只有 `roundStart`，没有 `roundEnd`；不得用“下一轮开始时清理”冒充轮末时机，也不得让内容层自行补发同名事件。
2. **视为牌同时复制花色与点数**：现有手牌视为机制（【药理】【亲酿】）只替换卡牌定义（牌名与牌效），花色与点数保持实体原值。【鉴映】的“A 视为 B”要求连**花色与点数**一起视为，因此需要扩展手牌视为的牌面复制能力，并让视为横条显示“花色＋点数＋视为牌名”。

## Requirements

### R1 星际和平公司势力登记

- R1.1 `game_data/factions.json` 新增一项：`id = xingjihepinggongsi`、`display_name = 星际和平公司`、`short_name = 司`、`color = b87333`（铜色）。
- R1.2 势力只影响武将牌名称、简称、颜色与徽记，不改变身份模式阵营关系。
- R1.3 势力 ID 不得与既有势力重复；「星」已被星间寰宇占用，本势力固定使用「司」。

### R2 武将真珠

- R2.1 新增 `game_data/characters/zhenzhu.gd`：`id = zhenzhu`、`display_name = 真珠`、`gender = female`、`faction = xingjihepinggongsi`、`max_hp = 3`。
- R2.2 技能按显示顺序为【补缀】（欢愉技，排在前）与【鉴映】（主动技）。
- R2.3 武将 `description` 为定位说明，不重复写入具体数值。
- R2.4 武将插画与阵亡语音缺失属于合法状态（自动定位失败时显示统一占位图、阵亡静默），不产生校验错误，本需求不要求提供素材。

### R3 欢愉技【补缀】

- R3.1 技能正文（界面、搜索与回放共用的唯一文本）逐字为：
  `欢愉技，参演编号104，指定至多三名角色，这些角色各获得1点护盾。本轮结束时，这些角色各失去1点护盾。`
- R3.2 静态参数：`joy_skill = true`、`performance_number = 104`、`trigger = passive`；阿哈时刻按参演编号升序驱动，不生成主动发动按钮。
- R3.3 目标：至多三名**任意**存活且未离场角色（允许包含真珠自己，允许选择 0 至 3 名）。
- R3.4 结算①：每名被指定的角色各获得 1 点护盾，护盾来源为真珠。
- R3.5 结算②：**本轮结束时**，本次演出的每一名被指定角色各失去 1 点护盾。
  - 失去护盾走权威护盾扣减端口，可被 `changeHujiaBefore` 修改或取消，不属于失去体力、也不属于受到伤害。
  - 角色在轮末已经死亡或离场时不再结算（权威端口本就拒绝该类目标），不报错、不补发。
  - 角色当时护盾为 0 时失去 0 点。
- R3.6 同一轮内【补缀】可能被多次演出（例如技能请求的额外阿哈时刻）。每次演出**各自登记一条到期记录**，轮末逐条分别扣减 1 点护盾；同一次演出内同一角色只记录一次。
- R3.7 强制发动：不创建“是否发动”询问；目标选择窗口不提供取消按钮，选择 0 名目标即为合法结算。
- R3.8 配套 AI：优先指定友方（含自己）；友方数量超过上限时优先血量较少（已损失体力较多）的友方；对敌方目标记负分；当唯一可选对象都是敌方时提交 0 名目标。

### R4 主动技【鉴映】

- R4.1 技能正文逐字为：
  `出牌阶段限一次，你可以展示你的一张手牌A，然后展示一名有护盾的角色的一张手牌B，若B不为装备牌，则A视为B直到离开你的手牌区。`
- R4.2 静态参数：`trigger = active`、`enable = phaseUse`、`ui_enabled = true`；出牌阶段限一次，普通与额外出牌阶段各自拥有独立的一次发动额度。
- R4.3 发动条件：真珠存活且在场、处于自己的出牌阶段、本阶段尚未发动过、真珠有至少一张普通手牌、场上至少存在一名**有护盾且有普通手牌**的角色（可以是真珠本人）。
- R4.4 分步流程（严格顺序，不得同时展示两张）：
  1. 真珠选择自己的一张手牌 A；确认后**立即公开展示 A**（写日志并按正式展示通道飞入牌桌）。
  2. 真珠选择一名有护盾（护盾 ≥ 1）且普通手牌非空的角色；候选在步骤 1 完成后才生成。
  3. 真珠从该角色手牌中选择一张手牌 B；确认后**立即公开展示 B**。若所选角色不是真珠，候选按观察者裁剪为不可见牌面（真珠不知道具体牌面，只能按位置选择）；若所选角色是真珠自己，候选为真珠本人可见的完整牌面。
  4. 若 B 的牌类型不是装备牌，则 A 视为 B，直到 A 离开真珠的手牌区。
- R4.5 “A 视为 B”的语义：A 的**牌名、牌效、花色、点数**全部视为 B。
  - 视为花色与点数必须参与全部真实规则判定：颜色/花色筛选类技能与卡牌、判定与拼点读取、以及 A 作为材料转化其他牌时的花色点数继承，都必须读到视为后的值。
  - A 离开真珠手牌区（使用、打出、弃置、交出、进入装备区、进入判定区、进入木牛附属区等）时自动恢复原牌名与原花色点数。
  - A 离开手牌后进入公共区域的展示，恢复为原实体牌面（与既有手牌视为表现口径一致）。
- R4.6 “若 B 不为装备牌”之外的失配分支：B 是装备牌时不建立视为效果（A 保持原牌名与原花色点数），本次技能照常完成，展示与次数消费都已经发生。
- R4.7 取消与次数消费：
  - 步骤 1 取消：技能未发动，不消耗本阶段次数。
  - A 已展示后进入的步骤 2 与步骤 3 **不可取消**（界面不显示取消按钮）。
  - 次数在步骤 1 确认时消费；若步骤 2 已无合法角色或步骤 3 已无合法候选（等待期间状态变化），本次技能直接结束且不建立视为效果，次数已消费且不返还。
- R4.8 视为牌在真珠手牌中的横条必须写明**花色与点数**再写视为牌名，例如 `♥A 桃`；真珠本人、其他玩家与旁观读到的横条文本一致。
- R4.9 原实体牌面保持：A 的插画、底部牌名、角标花色点数继续显示**实体原值**，逻辑牌名与逻辑花色点数只出现在视为横条与信息框副标题中。
- R4.10 配套 AI：
  - 主动入口：`append_play_phase_actions` 在条件成立时追加 `use_skill` 动作；材料机会成本按所选 A 的价值扣减。
  - 步骤 1 选 A：优先选择手牌中**保留价值最低**的牌；真珠自身有护盾时，若手牌存在明显更高价值的牌，进一步压低低价值牌的评分以形成“低价值换高价值”的升级对。
  - 步骤 2 选角色：真珠自身有护盾时优先选自己（结果确定且可预期）；否则优先选有护盾且有手牌的敌人；敌人都没有牌或没有护盾时退化为选队友。
  - 步骤 3 选 B：所选角色是真珠自己时优先选**保留价值最高**的另一张手牌并避免选择 A 本身；所选角色是他人时候选牌面不可见，按未知牌均等处理。

### R5 真实轮末时机 `roundEnd`

- R5.1 `RuleTimingCatalog.GAME_PHASE_TIMINGS` 新增 `roundEnd`，紧邻 `roundStart`；目录总数由 235 变为 **236**，分类数量由 57 变为 **58**。
- R5.2 `roundEnd` 必须在**真实轮末边界**派发且只派发一次：普通回合结束、轮转回到轮锚点、且本回合不是额外回合。
- R5.3 派发顺序：轮末边界判定成立后，`roundEnd` 先于“直到本轮结束”的限时离场恢复，先于轮末机缘，先于下一回合的 `roundStart`。
- R5.4 `roundEnd` 必须可暂停：处理者创建选择时，轮末流程等待其结算完成后再继续离场恢复与轮末机缘，不得越过或重复派发。
- R5.5 额外回合（含机缘在回合开始前排队的额外回合）不得派发 `roundEnd`，也不得重复递增轮数。
- R5.6 `roundEnd` 事件数据固定携带结束轮的轮数（`round_number`，取值即结束的那一轮，递增发生在下一回合）与结束回合的角色 ID；内容层只依赖这两个稳定字段，不读取控制器内部状态。
- R5.7 `roundEnd` 与既有机制不冲突：既有的“直到本轮结束”离场恢复、轮末机缘保底触发、下一轮 `roundStart` 顺序与语义完全不变。

## Constraints

- 内容层文件只继承对应基类，通过 `resolver.host`、事件总线和统一选择请求修改规则状态，**不得读取或修改 UI 节点**，不得在核心脚本中新增具体牌名或武将 ID 分支。
- 【补缀】的轮末记录必须是**纯可序列化基础值**（不保存 `PlayerState`、`CardInstance`、`Callable`、节点引用）。
- 不得把“本轮结束时”实现为“下一轮开始时”；不允许内容层自行补发 `roundEnd`。
- 不得修改既有内容文件的变量名、正文原文与既有注释；新机制扩展必须保持【药理】【亲酿】等既有视为牌行为逐字不变。
- 所有魔法数字与可调阈值必须提取为带注释的常量或 `@export` 变量，放在脚本顶部。
- 技能正文（`description`）与需求原文逐字一致，界面可见文本不得添加额外提示。
- `roundEnd` 属于核心时机扩展：核心改动必须保持既有回归场景全绿，尤其 `rule_timing`、`opportunity_system`、`gameplay_regression`、`smoke`、`match_replay`。
