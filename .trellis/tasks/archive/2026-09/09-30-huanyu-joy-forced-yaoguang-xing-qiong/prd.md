# 欢愉技强制发动机制与爻光星穹三名武将

## Goal

把「欢愉技一律强制发动、不可取消、不询问是否发动」确立为欢愉技的通用口径并落到代码与文档，改写好戏正文与交互窗口，并新增爻光（仙舟联盟）、星（欢愉派系）、穹（欢愉派系）三名武将及其五个技能（凶星、鸿运、咬它、好活、当赏）。

## Background（仓库证据，已核实）

- 欢愉技体系已存在：`scripts/core/ahha_moment_system.gd`（`AhhaMomentSystem` 场景组件）、`game_data/skill_definition.gd` 的 `joy_skill` / `performance_number` 标签、加载期双向校验（`scripts/autoload/game_database.gd:307-317`）、回合开始前事件链（`scripts/core/match_controller.gd:10646` `_continue_turn_start_prelude`：机缘 → 阿哈时刻 → 回合事实）。
- 场上目前唯一的欢愉技是火花的【好戏】`game_data/skills/haoxi.gd`（参演编号 `144`）。它用 `request_target_selection(..., MIN_TARGET_COUNT=0, max, allow_cancel=true, ...)` 建立目标选择，`continue_selection()` 里 `response.confirmed == false` 时按 0 名目标结算（`haoxi.gd:57,68`）。
- 既有文档已写明「欢愉技保持 `lock=false`，其强制发动来自阿哈时刻驱动，不占用锁定技语义」（`docs/游戏机制与玩法内容.md:312`、`docs/内容制作指南.md:3969`），即「强制发动 ≠ 锁定技」在文档上已成立，本次需把「不询问是否发动、不能取消」补全到位。
- 「回合开始时」在项目内的既有落点是 `phaseBefore` 时机（`scripts/core/turn_start_service.gd:17` 派发链；订阅先例含【追歼】`zhuijian.gd:38` 等 8 处），项目**不存在**「回合事实建立之前」的技能时机——机缘与阿哈时刻是 `_continue_turn_start_prelude` 里硬编码调用的组件，不是可订阅时机。
- 阿哈时刻唯一触发入口是 `try_trigger_before_turn_start(turn_context, is_extra_turn)`（`ahha_moment_system.gd:113`），内部含概率判定与 `_triggered_this_round` 轮次额度；额外回合不参与判定（`is_extra_turn`）。
- 角标：`MatchController.set_character_corner_text_entry(player_id, entry_id, display_text, order, view_kind)`（`match_controller.gd:15416`）；【酩酊】用它写入同款条目（`game_data/skills/mingding.gd:151-171`，条目 ID 为 `"mingding:%d" % owner_player_id`，排序值 `50`）。
- 阵营 ID 既有值：仙舟联盟 = `xianzhou`（素裳、驭空、寒鸦等），欢愉派系 = `huanyu`（火花）。
- 已有欢愉技专项测试：`tests/ahha_moment_test.gd`、`tests/huohua_joy_test.gd`。

## Requirements

### R1 欢愉技强制发动口径

- R1.1 欢愉技一律**强制发动**：由阿哈时刻（或其它技能令其发动时）直接执行，不创建「是否发动」询问，不提供取消。
- R1.2 强制发动**不等于锁定技**：欢愉技保持 `lock=false`，仍可被「非锁定技失效」压制。
- R1.3 该口径需写入 `docs/游戏机制与玩法内容.md` 与 `docs/内容制作指南.md`。

### R2 好戏改写

- R2.1 玩家可见描述原文改为（逐字）：
  `欢愉技，参演编号144，你弃置0-2名其他角色各一张随机手牌，然后从牌堆中获得X张基本牌。（X为2-本次选择的目标数）`
- R2.2 目标选择窗口**没有取消按钮**；不选择任何角色直接确定即视为选择 0 名，此时 `X = 2`。
- R2.3 弃置与获得的结算规则不变（`X = 2 − 本次选择的目标数`，从摸牌堆无放回随机获得基本牌）。

### R3 爻光 yaoguang（仙舟联盟 / 女 / 体力 3）

- R3.1 【凶星】原文（逐字）：`欢愉技，参演编号116，你令一名角色下次受到的伤害+1。若该角色为你，则当你下次体力上限减少时，防止之。`
- R3.2 【凶星】AI：优先选需要集火的、嘲讽高的目标；若自己体力上限为 1 且我方欢愉技数量比敌方多 2 或以上，则选自己。
- R3.3 【凶星】角标：被选中的角色获得与【酩酊】同款角标；效果可叠加，层数 ≥2 时角标文本显示为「凶星xN」（如 `凶星x2`）。
- R3.4 【鸿运】原文（逐字）：`你的回合开始前，你可以立即触发一次额外的阿哈时刻；该阿哈时刻结束后，你减少1点体力上限。每轮限一次。`
- R3.5 【鸿运】AI：敌我欢愉技数量相等或我方只多 1 时，在自己体力值少于体力上限时发动；敌方更多时不发动；我方比敌方多 2 或以上时，只要体力上限大于 1 就发动。

### R4 星 xing_huanyv（欢愉派系 / 女 / 体力 4）

- R4.1 【咬它】原文（逐字）：`每种花色限一次，你的回合开始前，你可以弃置一张手牌，然后令一名角色发动其欢愉技。若其没有欢愉技，则令其执行一个额外的出牌阶段。`
- R4.2 【咬它】AI：目标优先级依次为「手牌数 ≥8 的队友」→「有欢愉技的队友」→「手牌数 ≥5 的队友」→「自己」；最高优先级不是自己时，只要还有可弃置花色就发动；最高优先级是自己时，只在可弃置花色的牌价值低时发动。
- R4.3 【好活】原文（逐字）：`欢愉技，参演编号120，你弃置场上的一张牌。`
- R4.4 【好活】AI：优先弃置我方角色判定区里的【乐不思蜀】与【兵粮寸断】，其次敌人装备区里的牌。
- R4.5 「场上」定义（本任务的通用概念）：**所有角色的装备区与判定区**，不含手牌区。

## Key Decisions（用户已裁决）

- D1 【鸿运】的额外阿哈时刻**不占用本轮额度**：额外演出独立完整结算，本回合开始前原本那次阿哈时刻判定照常进行（概率命中就再演出一场）。
- D2 【凶星】角标显示给**被选中的任意角色**（含自己），与效果作用对象一致。
- D3 【好活】的「场上」**包含自己**的装备区与判定区。
- D4 【咬它】「每种花色限一次」的额度为**整局每种花色各一次**（一局最多 4 次），不随回合或轮次刷新。
- D5 星与穹共用同一个【咬它】技能文件与技能 ID。
- D6 【好活】【当赏】参演编号同为 `120`（刻意设计，同编号时按座次正序排序）。
- D7 【凶星】层数存入**既有 `PlayerState.character_form_state`**（项目强制规范 `skill-authoring.md:70`：跨回合私有记忆必须写这里；随权威存档往返、不进公开快照），角标按目标身上的**总层数**显示（多名爻光打同一目标时显示如 `凶星x5`），不引入公开标记的圆形徽标。读档后层数不丢失。**不新增**任何 `PlayerState` 字段，因此不改动公开快照结构、网络同步与存档格式。
- D8 「你的回合开始前」按项目既有口径落在 `phaseBefore` 时机（项目内 8 个技能已用该时机表达「回合开始时」，如【追歼】`zhuijian.gd:38`），**不新增时机、不改动 `_continue_turn_start_prelude` 回合开始前事件链**。因此【鸿运】的额外阿哈时刻发生在本轮正常阿哈时刻判定**之后**，与 D1「不占用本轮额度」一致。

## Out of Scope

- 不修改阿哈时刻的触发概率算法（保持「每轮按在场人数倒数锁定」）。
- 不新增除本任务三名武将外的武将或技能。
- 不改动既有欢愉技【好戏】的结算数值（仅改描述与交互窗口）。
