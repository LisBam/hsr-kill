# 武将丹恒·饮月与技能【伏辰】【濯世】

> 父任务：`10-04-danheng-yinyue-and-shajin-characters`。需求原文、用户补充确认（U1–U7）与仓库事实表（F1–F28）见父任务 `prd.md`，本文件不重复抄录，只写本子任务特有的需求、约束与验收标准。

## Goal

新增武将**丹恒·饮月**（仙舟联盟 · 男 · 体力值 4）与两条技能：

- 锁定技【伏辰】：当**其他角色打出**一张【杀】后，你获得之。
- 主动技【濯世】：出牌阶段限一次的三段链——弃置一张基本牌并选择一名其他角色，弃置其一张**手牌**；然后可再弃置一张基本牌并弃置其一张**牌**；最后可再弃置一张基本牌并对其造成 **1 点雷电伤害**。

含配套基础 AI、专项测试与文档同步。**不引入任何新核心机制**。

## 本子任务的依赖与顺序

- 无前置子任务；不依赖 `10-04-batch-gain-timing-mechanism`。
- 若该机制子任务已先落地，【伏辰】的获得行为**不**受影响（单张获得自成一批，与本技能无关）。

## Requirements

### R1 武将静态资料

- `game_data/characters/danheng_yinyue.gd`，严格沿用既有 21 行模板（参照 `game_data/characters/danheng.gd`）。
- 元数据：`id` = `danheng_yinyue`、`display_name` = `丹恒·饮月`、`gender` = `male`、`faction` = `xianzhou`、`max_hp` = `4`。
- 技能安装顺序 = 技能栏顺序 = `[fuchen, zhuoshi]`（父任务验收标准要求该顺序）。
- `description` 按既有武将文件的写法填写（武将简介），不得写入技能正文。

### R2 【伏辰】

- 文案（逐字）：`锁定技，当其他角色打出一张【杀】后，你获得之。`
- 触发范围**仅**为**其他角色**的「打出」：
  - 订阅 `respond` 时机，`role="global"`（`respond` 的 `target_id` 恒为 `-1`，`role="target"` 不会命中，见 F4）。
  - 过滤 `event.player_id != owner_player_id`。
  - 过滤 `event.data["response_pattern"] == "sha"`。
  - 防御性过滤 `event.data["response_action"] == "play"`：核心在 `:5560` 已保证 `respond` 只对应「打出」，此判断只作为语义自证，不改行为。
  - 持有者本人打出的【杀】、其他角色**使用**（`useCard`）的【杀】都不得触发（U5）。
- 效果：把该实体牌从弃牌堆（核心在派发 `respond` 之前已完成 `_move_played_card_to_discard`，见 F6）移入持有者手牌，走 `gain_card_to_hand_by_uid(owner_player_id, card_uid, "fuchen")`。
- **锁定技**：必须声明锁定技元数据（`lock`），不得让玩家选择是否发动，也不需要 `continue_selection`。
- 防御：`card_uid < 0`、牌已不在牌堆/弃牌堆、持有者已死亡或离场时静默跳过，**不得**写错误日志。

### R3 【濯世】三段链

文案（逐字）：
`出牌阶段限一次，你可以弃置一张基本牌并选择一名其他角色，你弃置其一张手牌，然后你可再次弃置一张基本牌并弃置其一张牌，最后你可再次弃置一张基本牌并对其造成1点雷电伤害。`

交互必须与用户操作逻辑原文一致（父任务「来源需求原文」）：

| 步骤 | 交互 | 取消语义 |
|---|---|---|
| 1 | **一次**「选一张基本牌 + 选一名其他角色 + 确定」的合并请求 | 取消 = 整体放弃，不消耗次数、无任何效果 |
| 1a | 选并弃置目标一张**手牌**（暗选） | 前置成立后为必做；目标此时无手牌则跳过 |
| 2 | 「是否再次弃置一张基本牌」（选基本牌 + 确定 = 是） | 取消 = 放弃第二段，直接进入步骤 3 |
| 2a | 选并弃置目标一张**牌**（暗选；手牌 + 装备区） | 前置成立后为必做；目标此时无牌则跳过 |
| 3 | 「是否再次弃置一张基本牌」（选基本牌 + 确定 = 是） | 取消 = 放弃第三段，技能结束 |
| 3a | 对目标造成 **1 点雷电伤害** | — |

约束：

- **费用口径**：每一步的「一张基本牌」都来自**持有者手牌**，牌类型为 `basic`，每段各消耗 1 张、最多 3 张；同一步骤内恰好 1 张。
- **目标只选一次**：步骤 1 选定后在整条链中固定，步骤 2/3 不得重新选择目标。
- **暗选与可见性**：步骤 1a 与 2a 的候选都由**技能持有者**（而非目标）选择；步骤 1a 用「他人手牌」候选（牌面不可见），步骤 2a 用「他人手牌 + 装备区」候选。判定区的牌**不**在步骤 2a 的范围内（「一张牌」按用户 U4 的口径落为手牌+装备）。
- **步骤 1 的目标合法性**：目标必须是**存活的、非离场的其他角色且当前至少有一张手牌**——否则步骤 1a 的必做效果无从执行。该限制必须与步骤 1 的选择请求候选同源。
- **雷电伤害**：自然属性字面量 `"thunder"`（F10），伤害来源为持有者，走 `damage(...)`，因此正常经过护盾/防具/伤害时机，并计入伤害历史。
- **次数**：`出牌阶段限一次`。用实例计数器 + `phaseUseBegin` 复位（F23）；额度**只在步骤 1 的真实弃置完成时**消费，任何一步取消都不消费。
- **阶段归属**：`can_activate()` 必须校验 `host.state.current_player_id == owner_player_id` 且 `host.state.current_phase == "play"`，并拒绝已有未决选择时开新入口（F22/F23）。
- **嵌套屏障**：本技能的所有选择都由 `activate()` / `continue_selection()` 发起，**不在时机回调里建请求**；若实现中确实需要从时机回调发起，必须先查 `host.has_nested_settlement_barrier()`（F22）。

### R4 基础 AI（必须与规则同文件）

- `append_play_phase_actions(result)`：`can_activate()` 为真时追加一个 `action_type="use_skill"` 的合法动作。
- `score_ai_action(...)`：存在「持有者有基本牌 + 存在合法敌方目标」时给出严格正分，否则 `0.0`（不得只按 `can_activate()` 给分）。
- `score_ai_choice(...)`：覆盖步骤 1、1a、2、2a、3 的全部选择：
  - 步骤 1 / 2 / 3 的**确认分必须严格大于 0**（F25），否则 AI 会在「发动→取消」之间空转直到撞上动作上限。步骤 1 的确认分必须足够高（组合保底分）。
  - 步骤 1 与 2a 的**选牌分**按目标态度计价：对敌方不利为正、对友方为负（复用 `evaluator.get_attitude()`），并复用 `evaluator.score_resource_change()` 计费用（F24）。
  - 步骤 2 / 3 的「是否继续」按收益判断：步骤 3（1 点雷电伤害）对敌方应确认；步骤 2（再付一张基本牌换对方一张牌）只在净收益为正时确认。
- **不得**新增 `BasicAIPolicy` 白名单（F24）。
