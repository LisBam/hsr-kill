# 卡芙卡交付后的三项收口修正

父任务：`10-02-kafuka-new-mechanics`（其四个子任务均已归档）。本任务记录需求方在卡芙卡内容交付后提出的三项收口意见，不新增任何卡牌、技能或武将。

## 一、背景

卡芙卡内容（专属牌【言灵】、武将卡芙卡、技能【言灵】【游丝】）已于 `585c8f6` / `c069d39` / `cb39afb` 交付。需求方在试玩后提出三项修正：一项交互形态、一项规则语义、一项时机定义。

## 二、需求原文（逐字保留）

1. `修改"言灵"技能询问的方式，不是新建一个窗口，而是像"咬他"一样只是有询问按钮和手牌选择；`
2. `留白发动后，回合结束失去所有技能后，新获得的技能也是没有的。例如机缘卡给予的新技能。这不是我想要的，失去所有技能只是单次本次将所有拥有的技能失去，而以后获得的技能不受影响。`
3. `"游戏开始时"这个时机，是游戏正式开始时，是在手气卡之后的，第一轮开始前的。更正明确这个时机。因此"言灵"技能发动时，已经是在手气卡之后了，所以玩家并不能通过手气卡刷到言灵，并且"言灵"在游戏开始时也算发动技能，要有记录要有发动提示，随后才在牌堆中插入专属卡牌。`

## 三、验收标准

### 需求 1（交互形态）

- [x] `choice_type = "card_position"` 的询问不再打开 `CardSelectionPanel` 独立窗口，改为与【咬它】一致的**操作区内联询问**：手牌候选在手牌区点亮，三个选项渲染为操作行按钮。
- [x] 操作行可见按钮恰好三个：「牌堆顶第一张」「牌堆顶第二张」「取消」；不追加通用取消按钮，不产生第四个按钮。
- [x] 未选中恰好一张手牌时前两个位次按钮禁用，取消始终可点；点击取消提交 `confirmed = false` 且不移动任何牌。
- [x] 选项 ID 仍全部来自请求的 `control_options`，取消选项由上下文键 `control_cancel_option_id` 声明，界面不硬编码任何选项 ID。
- [x] `CardSelectionPanel` 中该分支的死代码（`position_submitted` 信号、位次按钮集合、提交回调）全部移除。
- [x] 权威校验口径不变：确认需恰好 `1` 张手牌 + 合法位次，取消不接受 `cancel` 作为已确认位次。

### 需求 2（永久失去的粒度）

- [x] 「失去所有技能」的清算粒度改为**技能ID名单**（`PlayerState.permanently_removed_skill_ids`），只清算发动那一刻确实拥有的技能。
- [x] 名单**之外**的技能（典型来源：机缘卡、军功、模式技能、清算之后新获得的任何技能）不受影响，照常获得、安装、显示与发动。
- [x] 名单**之内**的技能在全部装配路径上被逐项拦截：批量安装、换将重装、局内获得、存档补装、复原武将牌技能。
- [x] 名单进入公开快照与存档；旧存档只有布尔标记时按“该角色此刻本应安装的技能”补记名单完成迁移，且规则判定不再读取布尔量。
- [x] 界面按名单逐项剔除技能，不按整体标记清空技能栏，也不整体清空武将牌角标。
- [x] 清算同时清空由技能产生的记录牌名，使技能声明的“查看记录”入口随之消失。

### 需求 3（「游戏开始时」的时机）

- [x] 「游戏开始时」= **正式开局时刻**：起始手牌与手气卡全部结束之后、第一轮开始之前。
- [x] 【言灵】在该时机加入的三张专属牌不参与任何一次手气卡重发，玩家无法用手气卡刷到【言灵】。
- [x] 该时机是一次正式技能发动：写入技能发动记录与提示，并派发 `skillAfter` 时机，**随后**才逐张往牌堆插入专属牌。
- [x] 公开时机目录、文档与回归测试中的开局顺序同步更正。

## 四、范围外

- 不新增卡牌、技能、武将或界面组件；不改变专属牌定义、牌面与 AI 门槛。
- 不改变【游丝】第二段的候选范围与收益口径。
- 不为「永久失去」新增第二种标记字段之外的表达方式（旧布尔量仅作迁移兼容保留）。
