# 武将砂金与技能【筹码】【盲注】【风口】

> 父任务：`10-04-danheng-yinyue-and-shajin-characters`。需求原文、用户补充确认（U1–U7）与仓库事实表（F1–F28）见父任务 `prd.md`，本文件不重复抄录。

## Goal

新增武将**砂金**（星际和平公司 · 男 · 体力值 3）与三条技能：

- 锁定技【筹码】：游戏开始时，你摸 X 张牌，你的手牌上限 +X。（X 为你的体力上限）
- 【盲注】：摸牌阶段开始时，你可以弃置任意张颜色不同的牌；该阶段结束时按颜色比对，给 1 点护盾或摸两张牌。
- 【风口】：当你一次性获得至少两张牌时，你可以弃置这些牌；出牌阶段，你可以获得一名其他角色的随机一张手牌，按历史发动次数重复该流程，然后你失去该技能。

含配套基础 AI、专项测试与文档同步。

## 依赖与顺序（重要）

- 【风口】第一段需要**批量获得**的原子语义。本子任务**依赖** `10-04-batch-gain-timing-mechanism` 先完成并归档：该子任务提供新时机 `cardsGainedBatchAfter`（一次获得动作派发一次，载荷含 `card_uids`、`receiver_player_id`、`batch_size`）。
- 若该机制尚未落地，本子任务的【筹码】【盲注】与【风口】第二段仍可先行实现与验证，但**不得**自行在内容层近似实现第一段（用户在 U7 已明确裁定口径）。
- 本子任务**不加**任何新的核心时机；若实现中发现还缺其它核心能力，必须回到规划而不是就地打补丁。

### R2 【筹码】

- 文案（逐字）：`锁定技，游戏开始时，你摸X张牌，你的手牌上限+X。（X为你的体力上限）`
- 触发：`gameStart`，`role="global"`（该时机的 `player_id/source_id/target_id` 全为 `-1`，非 `global` 收不到 — F26）。
- X = 砂金的**体力上限**（3）。必须从持有者状态读取（不得写死字面量 3 与字段无关的常量混用；实现为「读取 `max_hp` 得到 X」，并在注释中写明当前值为 3）。
- 效果两步：`draw(owner_player_id, X)` 与 `add_hand_limit_bonus(owner_player_id, X, get_id())`（F8/F9）。
- 幂等：以实例布尔位防止同一局内重复施加（例如时机被重放或控制器重建后重复派发）。
- 锁定技：无玩家选择、无 `continue_selection`；在效果成立前调用 `announce_activation()`，使「手牌上限 +3」在日志中可见（参照 `game_data/skills/yanling.gd` 的 `gameStart` 写法）。

### R3 【盲注】

- 文案（逐字）：`摸牌阶段开始时，你可以弃置任意张颜色不同的牌。若如此做，该阶段结束时，若你以此法弃置的牌与你于此阶段内获得的牌有至少一种颜色相同，你获得1点护盾；若有至少两种颜色相同，你摸两张牌。`
- 触发窗口：
  - 开始：`phaseDrawBegin`（`role="player"`），**仅**在砂金自己的摸牌阶段、且该时机确实对应本次摸牌阶段时生效。
  - 结束：`phaseDrawEnd`（`role="player"`）。
  - 期间获得的牌：`gainAfter`（`role="player"`），只累计砂金自己获得的、落入手牌的牌。
  - 清理：`phaseDrawSkipped` / `phaseDrawCancelled` 必须清空本次记录。
- 弃置口径（U6）：
  - 候选来源 = 持有者**手牌 + 装备区**（不含判定区、不含木牛「粮」）。
  - 「颜色不同」在两色体系下等价于**两两颜色不同**，因此**最多 2 张**（1 红 + 1 黑）。
  - 实现为**两次单选**：先选第 1 张（任意颜色），再选第 2 张且候选**只含与第 1 张颜色不同的牌**，第 2 步可取消（表示只弃 1 张）。以此在构造上保证「颜色不同」，不依赖提交后校验。
  - 第 1 步取消 = 不发动，零效果、零记录。
  - 弃置走统一的「手牌或装备」弃置端口，因此正常触发「当你弃置牌时」类效果与弃置批次时机。
  - 「若如此做」：只有真实弃置了至少 1 张牌才建立本次记录；记录不存在时阶段结束**不产生任何效果**。
- 比对口径：
  - 「以此法弃置的牌」的颜色在**弃置时**解析并记录。
  - 「于此阶段内获得的牌」的颜色在**获得时**解析并记录（不在阶段结束时重新解析，避免牌已离手导致误判）。
  - 颜色集合求交集：交集中至少 1 种 → 获得 **1 点护盾**；至少 2 种 → **摸两张牌**。两种效果**可以同时生效**（原文用分号连接两个并列条件，没有「否则」）。
- 颜色只有红/黑两色（F28）；重复颜色（例如弃置 1 红、获得 3 张红）仍只算 1 种。
- 记录**不跨阶段**：每次 `phaseDrawBegin` 重置，阶段结束消费后清空。记录必须带回合号以拒绝迟到事件（参照 `game_data/skills/anke.gd` 的回合边界防御）。

### R4 【风口】

#### R4.1 展示文案（含用户显式改写）

需求原文：

```
当你一次性获得至少两张牌时，你可以弃置这些牌。出牌阶段，你可以获得一名其他角色的随机一张手牌，你每发动一次该技能便重复一次该流程，然后你失去该技能。
```

用户在同一轮对话中显式给出的**优化描述**（父任务「用户补充确认」U2 原文）：

```
当你一次性获得至少两张牌时，你可以弃置这些牌。出牌阶段，你可以获得一名其他角色的随机一张手牌，你此前每发动一次该技能便重复一次该流程，然后你失去该技能。
```

**裁定（已于规划评审确认）**：技能 `description` 采用**用户给出的优化描述**（逐字），因为它是用户在同一轮对话中对同一技能的显式改写；原始需求文本完整保留在父任务 `prd.md` 中作为不可变来源。除该句以外，标点与文字一律不得再改。

> 最终入库文本（唯一权威）：
> `当你一次性获得至少两张牌时，你可以弃置这些牌。出牌阶段，你可以获得一名其他角色的随机一张手牌，你此前每发动一次该技能便重复一次该流程，然后你失去该技能。`

#### R4.2 第一段

- 触发：`cardsGainedBatchAfter`（`role="player"`，即砂金自己是获得方），条件 `batch_size >= 2`。
- 效果：询问是否**弃置这批牌**。选择范围**恰好**是这批牌，数量固定为 `batch_size`（「弃置这些牌」= 全弃），可以取消。
- 确认后把整批牌弃置（走统一弃置端口），并把**第一段发动次数 +1**（U2：该计数决定第二段的重复次数）。
- **不产生任何额外效果**（U3）；弃置本身仍正常触发其它「当你弃置牌时」类效果。
- 计数必须**持久**：跨回合、跨技能重装、随存档往返（落在 `PlayerState.character_form_state`，键名稳定 — F21）。
- **重入**：该时机可能在同一结算内连续派发。已有未决询问时不得叠加第二个询问，必须排队并在前一个结束后顺序处理；每个队列项在处理前都要重新复核牌是否仍在手牌中。

#### R4.3 第二段

- 入口：`enable = phaseUse`、`ui_enabled = true` 的出牌阶段主动技。原文**没有**「出牌阶段限一次」，因此不限次数；但效果结束后**失去该技能**，实际上每局至多一次。
- 流程（U2 逐字口径）：
  1. 选择一名**其他角色**（必须存活、未离场、且当前至少有一张手牌）作为目标。
  2. 获得该角色**随机一张手牌**（1 张）。
  3. 然后**重复**第 2 步：重复次数 = 第一段的历史发动次数；每次重复都从**同一名目标**取 1 张随机手牌，且每次都重新取候选。
  4. 停止条件：目标没有手牌了，或已达到重复次数。
  5. 最后**失去【风口】**。
- 随机性必须走权威端口 `pick_random_candidate_index()`（F18），**禁止**在内容层自建随机源。每次取牌使用同一稳定的 `history_kind` 与可复现的 `history_data`（至少含目标 ID 与该次序号）。
- 取牌走权威端口 `take_selected_player_card(owner_player_id, target_id, card_uid)`，卡牌因此进入砂金手牌并走完整移牌时机。
- 失去技能走权威端口 `remove_skill(owner_player_id, get_id(), reason)`（F19）。
- 取消目标选择 = 不发动：不获得任何牌、**不失去技能**、不消耗任何记录。

### R5 基础 AI（必须与规则同文件）

- 【筹码】：无 AI 决策点（`gameStart` 自动生效），**不实现** AI 钩子，并在类注释中说明理由。
- 【盲注】：
  - `score_ai_action` 不适用（本技能没有主动入口）。
  - `score_ai_choice` 覆盖第 1 步与第 2 步：按「本次将弃置的牌的价值」与「已记录颜色 + 本阶段预期摸牌颜色」估算收益；收益不明显时给 `<= 0`，让 AI 取消（不发动）。
  - 第 2 步的「取消」是合法且常见的结局，因此**不得**给第 1 步/第 2 步的确认动作无条件正分——否则 AI 会为了凑 2 张而弃掉好牌。**但**第 1 步一旦进入就必须避免「发动→取消→再发动」的空转：取消路径在这里是**终结路径**（不产生后续询问），因此不存在空转风险，无需保底分。
- 【风口】：
  - 第一段：`score_ai_choice` 的确认分 = 「提高第二段重复次数的期望收益」 − 「这批牌的价值」。实现为可调常量；默认在本批牌价值较低且第二段仍可能带来正收益时确认。
  - 第二段：`append_play_phase_actions` + `score_ai_action`，在存在有手牌的敌方可选目标时给严格正分；目标选择按态度（F24）。因为技能用完即失，AI 只要存在合法目标就应当发动。
  - 所有「确认」分支的分数**必须严格大于 0 才确认**（F25）；对应当取消的分支必须给**负分**而不是 0 分，避免通用 `+0.1` 兜底把取消翻成确认（`game_data/skills/linggan.gd:76-80` 的同类注释）。
- 不得新增 `BasicAIPolicy` 白名单（F24）。
