# 技术设计：按新原文改写升变

## 1. 新原文（唯一权威，逐字写入 `description`）

> 回合开始时，你可选择一名角色，若其没有“军功”标记，你移除场上所有的“军功”标记。然后令其获得2枚“军功”标记（至多获得至8枚）。拥有“军功”标记的角色视为拥有技能“奇袭”。

## 2. 规则模型

| 步骤 | 规则 | 说明 |
| --- | --- | --- |
| 时机 | 回合开始时（`phaseBefore`，`role="player"`，持有者为当前回合角色） | 与旧实现一致；每回合重新询问，可取消 |
| 选择 | 选择一名角色（含自己） | 沿用现有 `request_target_selection` 入口 |
| 条件分支 A | 目标**没有**军功 → 移除场上所有角色的军功 | 含自己与他人；需同步撤销军功来源动态授予的【奇袭】 |
| 条件分支 B | 目标**已有**军功 → 不清场 | 只做后面的给予 |
| 给予 | `gain = clamp(8 − 目标当前军功数, 0, 2)` | 目标总数封顶8；已有8枚时获得0枚，但仍算合法发动并写日志 |
| 派生 | 目标获得军功后动态获得【奇袭】 | 沿用军功来源的派生授予机制 |
| 标签 | 不再是轮回技 | `reincarnation` 及轮回节/轮回数元数据全部移除 |

## 3. 代码改动设计

### 3.1 `game_data/skills/shengbian.gd`

- 顶部常量（`const`，带用途/取值范围/修改影响注释）：
  - `MILITARY_MERIT_MARK_ID = "jungong"`（若已有则复用）；
  - `MILITARY_MERIT_GAIN_PER_ACTIVATION: int = 2`；
  - `MILITARY_MERIT_TOTAL_CAP: int = 8`。
- `_init` 元数据：
  - `description` 替换为新原文；
  - 删除轮回技声明字段（`reincarnation`、`reincarnation_section_count` 等），确认与 `scripts/core/reincarnation_skill_service.gd` 的加载期校验兼容；
  - 保留 `trigger/timing/role` 与“可取消”语义。
- 结算：
  - 目标确认后：读取目标当前军功数；
  - 若为0 → 调用“移除全场军功”的既有辅助（当前在文件第119行附近），它必须同时清空所有角色的军功并撤销对应动态【奇袭】；
  - 计算 `gain` 并写入目标军功，写入量以实现“总数封顶8”为准；
  - 目标有军功后确保动态【奇袭】已授予；
  - 追加中文日志，覆盖三种数值结果（获得2 / 获得部分 / 获得0）。
- AI（`score_ai_action` / `score_ai_choice`）：
  - 目标收益 = 基础收益 + 给予量收益 − 清场副作用；
  - **清场副作用**：当目标无军功时，本次会清空全场军功，需评估“我方其他角色当前军功损失”；
  - **已满8枚**的目标本次实际收益为0（只保留“再次确认发动”的极小收益或直接判为不值得），必须显式处理，避免 AI 反复发动无收益的升变；
  - 取消分支：当所有候选目标收益均 ≤ 0 时取消。
- 移除轮回数相关逻辑后，检查是否残留未使用的成员并一并清理。

### 3.2 `game_data/skills/qixi.gd`

- 触发来源识别中“是否轮回技”的判断不再命中【升变】（因为它不再是轮回技）；确认 `reset_play_phase_usage` / `advance_reincarnation_section` 两个分支对升变都为 false，且不产生任何登记。
- 军功持有者视为拥有【奇袭】的派生授予/撤销路径需覆盖“军功被清空到0”的情形（清场分支会同时影响多名角色）。

### 3.3 元数据与加载期校验

- 若存在“所有轮回技必须显式声明轮回技标签”或“轮回技必须声明节数”的双向校验，需确认去掉标签后不报错。
- 【征服】等引用“翁法罗斯势力角色的轮回技推进轮回节”的内容不再把【升变】计入；确认这类聚合逻辑以标签为准而不是硬编码技能 ID。

## 4. 测试设计

改写 `tests/omphalos_transform_test.gd` 的 `_test_shengbian_qixi_and_kansha`：

1. 正文逐字断言（新原文）。
2. 不再断言轮回技标签 / 轮回节推进 / 按X增长 / 2→4→10 的旧语义。
3. 新增：目标无军功 → 全场旧军功清空 + 目标获得2枚。
4. 新增：目标已有 3 枚 → 5 枚；7 枚 → 8 枚；8 枚 → 8 枚（获得0枚）。
5. 新增：军功归零者失去动态【奇袭】，仍有军功者保留。
6. 新增：取消分支不改变任何标记。
7. 新增：【奇袭】不再被【升变】触发。
8. 把原先由【升变】覆盖的“轮回技标签校验”改用其他确实声明了轮回技的技能覆盖。

## 5. 风险

- 【升变】去掉轮回技标签会改变【征服】等聚合技能的覆盖面，属于需求带来的预期变化，必须在文档中显式写明。
- 8枚封顶若与既有 `change_player_mark_count` 的截断语义冲突，应以技能内计算 `gain` 后再写入的方式实现，避免改动通用标记接口的行为。
