# 留白改为一次性失去当前技能并新增通用失去技能端口

父任务：`10-04-kafuka-followup-fixes`（已归档）。本任务记录需求方对该批次需求 2 的**再次修正**：把「按技能ID名单永久失去」整体替换为「只失去当前持有的技能、一次性生效、不做后期维护」。

## 一、背景

`10-04` 已把【留白】第二段从「整体布尔开关」改为「技能ID名单」，解决了“清算后新获得的技能被误拦”。需求方复审后认为该实现仍然过重：名单是一种需要长期维护、且必须让五条装配路径都记得查的持久状态，而原意只是“把这些技能现在拿掉”。

## 二、需求原文（逐字保留）

1. `【留白】也不要按技能 ID 的永久失去名单，只需要失去当前持有的技能就可以了，一次性失去，不做后期维护。`
2. `如果没有这个接口，则定义一个"失去某个技能"的函数接口，这样以后设计失去技能的效果时就可以直接调用这个接口了。`
3. `失去技能只需要是直接失去现有技能，而不是持久的名单失去。`
4. `失去后鼠标悬停武将牌以及右键武将牌查看的技能信息里都不能包含这个技能。`

## 三、验收标准

- [x] `PlayerState` 中的 `permanently_removed_skill_ids` 与旧布尔量 `skills_permanently_removed` 及两个读写端口**全部删除**，不留任何兼容字段。
- [x] 新增通用端口 `remove_skill(player_id, skill_id, reason)`：卸载实例 → 清空该技能的获得/临时记录 → 清理轮回公开状态 → 写日志 → 广播；技能本不属于该角色时返回 `false` 且无任何副作用。
- [x] 新增批量端口 `remove_all_skills(player_id, reason)`：先快照当前技能ID再逐个调用通用端口，最后清空轮回公开状态与记录牌名；无技能可失去时返回 `false`。
- [x] 【留白】第二段改为调用 `remove_all_skills()`；不再写任何名单，也不影响任何后续装配路径。
- [x] 五条装配路径（批量安装、换将重装、局内获得、存档补装、复原武将牌技能）**取消全部按技能ID的拦截**，失去后的同一技能可由任何来源重新获得并照常安装与发动。
- [x] 公开快照改为下发**实际安装集合** `installed_skill_ids`（由技能实例表派生，不做任何持久化）；技能栏、悬停武将资料与右键武将详情都按它裁剪。
- [x] 失去技能后该技能立即从技能栏、悬停资料与右键详情三处消失；重新获得后立即在同一份列表中出现。
- [x] 快照缺少 `installed_skill_ids` 时（旧回放、手动构造的预览快照）不做裁剪，与改动前行为逐字节一致。
- [x] 过关斩将存档记录实际安装集合，读档只装配集合内的技能；缺该字段的旧存档按武将完整装配。
- [x] 玩法内容、架构说明、界面交互、内容制作指南、AI 模块与 README 六篇文档同步，两篇规范同步。
- [x] 那刻夏专项回归重写为一次性失去、重新获得、四条装配路径、存档集合与界面收敛六组断言。

## 四、范围外

- 不新增卡牌、技能、武将或界面组件；不改动技能描述原文与 AI 计价数值（`SKILL_LOSS_COST = 1.0` 保持不变）。
- 不保留任何旧存档的“名单迁移”逻辑：旧存档中该字段被忽略，按完整装配处理。
- 不改动 `remove_acquired_skill()` 的既有语义（只清除获得记录、有其他来源时保留实例），两者职责不同。
