# 新武将阮梅与梅绽灵赋阮弦

> 子任务，父任务 `10-18-ruanmei-and-skill-ownership-query`。
> **依赖**：本任务的兄弟任务 `10-18-skill-ownership-query-port` 必须先完成——本任务三个技能的规则段与 AI 段都调用它交付的技能拥有查询入口。
> 技术设计见本目录 `design.md`；执行顺序见 `implement.md`。

## Goal

制作新武将**阮梅**（银河学者 · 女 · 体力值3）及其三个技能**【梅绽】【灵赋】【阮弦】**，包含完整配套 AI、回归用例与全部关联文档同步。

## Source Requirements（用户原文，逐字不可变）

```
阮梅ruanmei 银河学者 女 体力值3
梅绽meizhan
锁定技，当你受到伤害后，所有拥有技能”梅绽”的角色各摸一张牌。

灵赋lingfu
出牌阶段限一次，你可以重铸一张手牌（每种类别限一次），然后令一名角色获得技能“梅绽”。若其已拥有技能“梅绽”，则改为令其增加1点体力上限并回复1点体力，然后你失去此技能。
（注意：是全局每种类别限一次。）
（AI逻辑参考：优先对没有“梅绽”的队友发动，若都有，则再考虑优先对有卖血技能的队友发动；若没有有卖血技能的队友，或有多个有卖血技能的队友，则对血量少的使用。）
（操作方式要求：发动技能时选择一张牌再同时选择一个目标，按下确定后先重铸牌，然后触发后续效果。）

阮弦ruanxian
结束阶段，你可以重铸一张锦囊牌（每种花色限一次），然后令所有拥有技能“梅绽”的其他角色各摸一张牌。
（注意：也是全局每种花色限一次。）
```

**原文不可变铁律**：三条技能正文必须逐字进入对应技能文件的玩家可见 `description`。特别注意【梅绽】原文中两个引号都是右引号 `”`，**不得**擅自改成 `“”` 配对写法。

三行 `（注意：…）` / `（AI逻辑参考：…）` / `（操作方式要求：…）` 是**设计约束说明**，不是玩家可见技能正文；它们不进入 `description`，但作为**强制验收条款**写入下方 R4 / R6 与 `design.md`。

## Requirements

### R1 武将

- R1.1 `game_data/characters/ruanmei.gd`，`extends CharacterDefinition`，静态参数：`id=ruanmei`、`display_name=阮梅`、`gender=female`、`faction=yinhexvezhe`（银河学者）、`max_hp=3`。
- R1.2 技能数组顺序固定为【梅绽】→【灵赋】→【阮弦】；三个技能脚本以 `const X_SKILL: Script = preload(...)` 前置声明后传入 `super()`。
- R1.3 技能文件 `game_data/skills/meizhan.gd`、`lingfu.gd`、`ruanxian.gd`，稳定 ID 分别为 `meizhan`、`lingfu`、`ruanxian`。
- R1.4 内容目录自动扫描注册，不得新增任何集中式 ID 白名单。

### R2 【梅绽】（meizhan）

- R2.1 锁定技（`lock: true`），无主动入口，不创建任何发动选择。
- R2.2 订阅持有者**受到伤害后**（`damageAfter`，`role="target"`）。
- R2.3 触发时**所有拥有技能“梅绽”的角色各摸一张牌**——包含受伤者本人、阮梅自己，以及任何被【灵赋】授予过“梅绽”的角色。
- R2.4 按**伤害事件**结算一次，不随伤害点数翻倍。
- R2.5 只令**存活且未离场**的持有者摸牌；伤害量为 0 的“零伤害”事件不触发。
- R2.6 技能拥有判定必须走统一入口，不得读武将固有技能列表、不得按技能 ID 白名单。

### R3 【阮弦】（ruanxian）

- R3.1 非锁定技，订阅持有者**结束阶段**（`phaseEnd`）。
- R3.2 每个结束阶段至多发动一次；发动前必须请求确认（“你可以”）。
- R3.3 费用：重铸**一张锦囊牌**（`type == "trick"` 的手牌）；**全局（整局游戏）每种花色限一次**——♠/♥/♣/♦ 各自整局至多被【阮弦】重铸一次。
- R3.4 后续效果：令**所有拥有技能“梅绽”的其他角色**各摸一张牌——**不含阮梅自己**（原文“其他角色”）。
- R3.5 无可用锦囊牌、或四种花色额度已用尽、或无其他梅绽持有者时**不创建**选择请求。

### R4 【灵赋】（lingfu）

- R4.1 主动技，入口 `phaseUse`；**每个出牌阶段至多发动一次**。
- R4.2 费用：重铸**一张手牌**；**全局（整局游戏）每种牌类别限一次**——`basic` / `trick` / `equipment` 各自整局至多被【灵赋】重铸一次。
- R4.3 操作流（用户“操作方式要求”）：发动时**同时选择一张牌与一名目标**（`request_card_target_selection`），点击确定后**先完成重铸**，再结算后续效果。
- R4.4 分支一：目标**没有**“梅绽” → 令其**获得技能“梅绽”**（经 `grant_acquired_skill`）。
- R4.5 分支二：目标**已拥有**“梅绽” → 令其**增加1点体力上限**并**回复1点体力**，然后**阮梅失去【灵赋】自身**（经 `remove_skill`）。
- R4.6 目标范围：原文“一名角色”，按项目既有口径**包含阮梅自己**（先例：【升变】“你可选择一名角色”显式允许选择自己）。阮梅自己永远命中分支二。
- R4.7 取消、或重铸未真实发生（牌已离手 / 非普通手牌）时，**不消耗**出牌阶段次数、**不写入**全局额度、**不产生**后续效果。
- R4.8 全局限次记录必须**跨「失去技能」存活**：分支二使阮梅失去【灵赋】后，若通过复原武将牌 / 机缘卡 / 换将等来源重新获得【灵赋】，已用类别不得复活。
- R4.9 无可用手牌、或三种类别额度已用尽、或无合法目标时**不创建**选择请求。

### R5 全局限次的存储契约

- R5.1 【灵赋】用 `PlayerState.character_form_state["lingfu_used_card_categories"]`（`Array[String]`，取值 `basic`/`trick`/`equipment`）。
- R5.2 【阮弦】用 `PlayerState.character_form_state["ruanxian_used_suits"]`（`Array[String]`，取值 `spade`/`heart`/`club`/`diamond`）。
- R5.3 只在重铸真实发生后写入，以 `host.recast_hand_card(...)` 的布尔返回值为准；写入即去重追加。
- R5.4 读取时做类型收敛（非 `Array` 按空集合处理），不因旧存档或异常写入崩溃。
- R5.5 候选枚举与额度判定各自只有一个实现，规则段与 AI 段共用，禁止 AI 段另建一套。

### R6 AI 配套

- R6.1 【灵赋】必须实现用户给出的三级优先（“AI逻辑参考”）：
  1. 优先对**没有“梅绽”的队友**发动（分支一，授予技能）；
  2. 若队友都已拥有“梅绽”，则优先对**有卖血技能的队友**发动（分支二）；
  3. 若没有卖血技能队友、**或有多个**卖血技能队友，则对**体力值最低的**使用。
- R6.2 按 `项目专属AGENTS.md` 2.3，必须**补全提示未覆盖的通用 AI 逻辑**，不得只实现提示分支：
  - 发动时机与收益门槛（重铸本身有换牌价值，但授予技能 / 加体力上限才是主收益）；
  - 重铸材料按**保留价值从低到高**选取（复用 `NonameAIEvaluator.CARD_RESOURCE_VALUE` 与既有保留价值口径）；
  - 取消动作的零分基线，取消必须始终可选；
  - 对敌方目标发动分支二的**负收益惩罚**（给敌人加体力上限是资敌）；
  - 目标合法性裁剪必须复用规则段的同一份候选定义。
- R6.3 【阮弦】必须评估「重铸材料的保留价值 vs 未知牌质价值」与「受益队友数量与态度」，严格正分才发动。
- R6.4 【梅绽】动态卖血估值（用户明确要求，参照系为**出手方 / AI 自己**）：
  - 元数据声明 `sell_blood_value = 1.0`（持有者本人因受伤摸到的 1 张牌）；
  - 覆盖 `modify_ai_incoming_card_effect()` 追加**其余**梅绽持有者的净价值：对出手方态度为正者 `+1` 张牌、为负者 `−1` 张牌，态度为 0 不计数；自己永远计入“我方”；
  - 只统计存活且未离场角色；只对伤害类来牌（`ai_profile.damage == true`）生效；
  - 数值尺度统一用 `NonameAIEvaluator.CARD_RESOURCE_VALUE`，不写字面量。
- R6.5 “卖血技能”判定必须复用既有 `sell_blood_value` 元数据（`get_snapshot_sell_blood_value()`），**禁止**技能 ID 白名单、禁止硬编码技能名。
- R6.6 新增 / 修改的 AI 行为不得影响其他武将、卡牌的 AI 决策；`sell_blood_value` 的既有消费者（对友方【杀】是否放弃【闪】）必须保持一致口径。
- R6.7 必须扩展既有 AI 框架（`NonameAIEvaluator` / `BasicAIPolicy` / `IdentityStrategyEvaluator` 的公开只读接口），不得绕过框架自行实现目标收益评估。

## Notes

- 原文【灵赋】的“出牌阶段限一次”与“（每种类别限一次）”**同时成立**：每个出牌阶段至多发动一次，且每个牌类别整局至多被重铸一次（故整局最多发动 3 次，分布在最多 3 个出牌阶段）。这一读法是唯一能同时满足两个限制条件的解释，已写入 `design.md`。
- 【梅绽】的卖血价值是**动态**的（随场上持有者的敌我构成变化），因此不能只写静态元数据；实现落点为既有 `modify_ai_incoming_card_effect()` 钩子，见父任务 `design.md` 第 3 节。
