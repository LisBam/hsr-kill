# 阮梅武将与技能拥有查询机制

## Goal

一次交付两个互相衔接的成果：

1. **封装「检查某角色是否拥有指定技能」的统一函数**，让后续所有「检查是否拥有指定技能」的技能代码直接调用，不再各自拼装技能列表。
2. **制作新武将阮梅（银河学者·女·体力值3）与三个技能【梅绽】【灵赋】【阮弦】**，含完整配套 AI 与全部关联文档同步。

## Source Requirements（用户原文，逐字不可变）

```
阮梅ruanmei 银河学者 女 体力值3
梅绽meizhan
锁定技，当你受到伤害后，所有拥有技能”梅绽”的角色各摸一张牌。

灵赋lingfu

（注意：是全局每种类别限一次。）
（AI逻辑参考：优先对没有“梅绽”的队友发动，若都有，则再考虑优先对有卖血技能的队友发动；若没有有卖血技能的队友，或有多个有卖血技能的队友，则对血量少的使用。）
```

**原文不可变铁律**：以上主句（技能正文）必须逐字进入对应技能文件的玩家可见 `description`，包含【梅绽】原文中两个引号均为右引号 `”` 的写法，不得擅自“纠正”标点。

`（注意：…）` / `（AI逻辑参考：…）` / `（操作方式要求：…）` 三行是**设计约束说明**，不是玩家可见技能正文；它们不进入 `description`，但作为**强制验收条款**写入本 PRD 与 `design.md`。

## 需求条目

### R1 技能拥有查询函数

- R1.1 提供**规则侧权威端口**：技能规则代码可通过 `host` 一次性查询「指定角色此刻是否拥有指定技能」，返回 `bool`。
- R1.2 提供**快照侧共享纯函数**：技能 AI 段与 AI 适配层可在只有权威快照的情况下完成同一查询，且口径与 R1.1 一致（固有 + 模式 + 临时 + 局内获得，去重）。
- R1.3 两个入口必须覆盖「视为拥有技能」类效果：由 `grant_acquired_skill` / 临时技能授予的技能必须被判为拥有。
- R1.4 收敛既有重复实现：把项目内各自实现的技能枚举收敛到同一来源，并修正只读武将固有技能、漏判局内获得技能的既有缺陷。
- R1.5 查询必须是**只读**的：不得创建技能实例、不得安装时机、不得改写任何对局状态。

### R2 新武将阮梅

- R2.1 武将：`id=ruanmei`、`display_name=阮梅`、`gender=female`、`faction=yinhexvezhe`（银河学者）、`max_hp=3`，按【梅绽】→【灵赋】→【阮弦】顺序配置技能。
- R2.2 文件名与 `id` 使用完整小写拼音；技能文件 `meizhan.gd` / `lingfu.gd` / `ruanxian.gd`，武将文件 `ruanmei.gd`。

### R3 技能【梅绽】（meizhan）

- R3.1 锁定技，订阅持有者**受到伤害后**。
- R3.2 触发时**所有拥有技能“梅绽”的角色各摸一张牌**（包含受伤者本人与阮梅自己）。
- R3.3 无主动入口，不得创建任何发动选择。
- R3.4 声明 `sell_blood_value = 1.0`（持有者本人因受伤摸到的1张牌），并在来牌估值钩子中按场面追加其余持有者的净价值。

### R4 技能【灵赋】（lingfu）

- R4.1 主动技，入口 `phaseUse`；**每个出牌阶段至多发动一次**。
- R4.2 费用：重铸**一张手牌**；**全局（整局游戏）每种牌类别限一次**——基本牌 / 锦囊牌 / 装备牌各自整局至多被【灵赋】重铸一次。
- R4.3 操作流：发动时**同时选择一张牌与一名目标**，点击确定后**先完成重铸**，再结算后续效果。
- R4.4 后续效果分支一：目标**没有**“梅绽” → 令其**获得技能“梅绽”**。
- R4.5 后续效果分支二：目标**已拥有**“梅绽” → 令其**增加1点体力上限并回复1点体力**，然后**阮梅失去【灵赋】自身**。
- R4.6 目标范围：`一名角色`，按项目既有口径**包含阮梅自己**（先例：【升变】“你可选择一名角色”显式允许选择自己）。
- R4.7 取消或重铸未真实发生时，不得消耗任何额度、不得产生后续效果。
- R4.8 全局限次记录必须**跨「失去技能」存活**：分支二使阮梅失去【灵赋】后，若通过复原武将牌 / 机缘卡 / 换将等来源重新获得【灵赋】，已用类别不得复活。

### R5 技能【阮弦】（ruanxian）

- R5.1 被动询问技，订阅持有者**结束阶段**；每个结束阶段至多发动一次。
- R5.2 费用：重铸**一张锦囊牌**；**全局（整局游戏）每种花色限一次**——♠/♥/♣/♦ 各自整局至多被【阮弦】重铸一次。
- R5.3 后续效果：令**所有拥有技能“梅绽”的其他角色**各摸一张牌（**不含阮梅自己**）。
- R5.4 全局限次记录同样必须跨技能实例重建存活。

### R6 AI 配套

- R6.1 【灵赋】AI 必须实现用户给出的三级优先：① 优先对**没有“梅绽”的队友**发动；② 若队友都已拥有，则优先对**有卖血技能的队友**发动；③ 若没有卖血技能队友、或有多个卖血技能队友，则对**体力值最低的**使用。
- R6.2 按 `项目专属AGENTS.md` 2.3，必须补全提示未覆盖的通用 AI 逻辑：发动时机与收益门槛、目标合法性裁剪、费用（重铸牌）机会成本、取消动作的零分基线、敌方目标的负收益惩罚、重铸材料按保留价值从低到高选取。
- R6.3 【阮弦】AI 必须评估「重铸材料保留价值 vs 未知牌质价值」与「受益队友数量与态度」，严格正分才发动。
- R6.4 【梅绽】的动态卖血估值：以**出手方（AI 自己）**为参照系，修正分 =（对出手方态度为正的梅绽持有者数 − 态度为负的梅绽持有者数）× 1张牌，自己永远计入“我方”；只统计存活且在场角色；只对伤害类来牌生效。
- R6.5 新增/修改的 AI 行为不得影响其他武将、卡牌的 AI 决策；`sell_blood_value` 的既有消费者（对友方【杀】是否放弃【闪】）必须保持一致口径。

### R7 文档同步

- R7.1 `docs/内容制作指南.md`：补入技能拥有查询两个入口的接口说明与使用示例、全局限次存储约定、`modify_ai_incoming_card_effect` 的动态卖血用法。
- R7.2 `docs/游戏机制与玩法内容.md`：记录阮梅与三技能的全部机制与具体数值（摸牌数、体力上限增量、回复量、全局限次维度与次数、AI 评分数值）。
- R7.3 `docs/AI模块.md`：同步技能拥有查询入口与梅绽动态卖血估值口径。
- R7.4 `docs/卡牌系统.md` 仅在重铸语义需要澄清时更新；`README.md` 若含武将/技能计数则同步。

## 非目标（Out of Scope）

- 不新增「重铸」机制本身（`recast_hand_card` 已存在且语义满足需求）。
- 不为「全局每种类别/花色限一次」新增通用框架；按项目既有惯例存入持有者私有形态状态。
- 不修改 `sell_blood_value` 的既有静态语义与既有消费者行为（只做增量）。
- 不复制、不改写 `无名杀参考代码/`、`三国杀规则集/`、`设计自用文档（AI禁改禁读）.md`。

## 关键决策记录

| 决策 | 结论 | 依据 |
|---|---|---|
| 查询函数封装范围 | 双层封装（权威端口 + 快照纯函数）并收敛既有重复实现 | 用户选择 A |
| 「一名角色」是否含自己 | 包含 | 项目既有口径（【升变】注释“升变允许选择自己”） |
| 全局限次存储位置 | 持有者私有形态状态（整局存活、不进公开快照、随存档往返） | 原文“全局”；且【灵赋】会失去自身 |
| 梅绽是否算卖血技能 | 是，且价值随场面动态变化 | 用户明确要求 |
| 梅绽卖血参照系 | 相对出手方（AI 自己），自己计入“我方” | 用户选择 A |
| 梅绽基础卖血值 | `sell_blood_value = 1.0`（本人摸到的1张），其余持有者由动态钩子追加 | 避免与既有静态口径重复计算 |
