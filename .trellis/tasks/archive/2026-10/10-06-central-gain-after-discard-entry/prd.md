# 中央区展示牌被获得时先入弃牌堆再飞向获得者

## Goal

把「一张正在中央区展示的牌被某个角色获得」的表现改成**两段连续飞行**，并让第一视角与旁观视角表现一致：

1. 这张牌先按**原有出牌动画**从它的来源飞到中央区，并在**中央弃牌展示队列中落位**（即规则上「已进入弃牌堆」）；
2. 落位之后，**同一张牌面**再从中央区飞向获得者：本机视角飞向该牌在手牌区的最终槽位，其他角色视角飞向获得者武将牌锚点。

同时**回退** `5e07e96`（2026-10-04「优化获得牌飞行落点与拖拽落位过渡」）中「伏辰」相关的那部分实现：它在本机获得时**当场把中央展示牌面从队列里拽走**并直接飞进手牌，导致（a）牌永远没有真正落到中央弃牌区、（b）其他角色获得时会在中央**复制出第二张牌面**、而原牌面仍留在队列里。

## Background

### 触发场景（用户给出的原始描述）

> 如「伏辰」获得其他角色打出的【杀】时，表现效果为其他角色打出【杀】在弃牌堆中移动到发动角色的武将牌上并被其获得，第一视角是该牌从弃牌堆中移动到手牌区。

### 当前代码事实（已核对）

| 事实 | 位置 |
|---|---|
| 打出的实体响应牌经处理区进入弃牌堆，并在此之前请求一次中央展示（`owns_discard_transfer=true`） | `scripts/core/match_controller.gd` `_move_played_card_to_discard()` L5737-L5751 |
| 【伏辰】在 `respond` 时机回调里立刻 `gain_card_to_hand_by_uid()`；此时实体已在弃牌堆 | `game_data/skills/fuchen.gd` L38-L63 |
| 本机获得路径**立即**调用 `take_over_active_card()`，把牌面从队列中摘走并从「它当前所在位置」起飞 | `scripts/ui/match_table.gd` `_play_local_hand_gain_flight()` L5014-L5048 |
| 非本机获得路径**新建一张牌面**放在中央弃牌锚点，同时原展示牌面仍在队列里 | `scripts/ui/match_table.gd` `_on_card_transfer_requested()` L4873-L4905 |
| 中央展示队列以弃牌区面板中心为轴心，成员按 `discard_queue_spacing` 水平铺开 | `scripts/ui/card_use_animation_layer.gd` `play_card()` / `_queue_card_position()` |

因为 `_move_played_card_to_discard()` 与 `respond` 派发在同一帧序列内，获得信号到达时展示牌面**通常还在从出牌者武将牌飞向中央区的途中**：本机路径会把这张刚起飞的牌直接拐进手牌（永远到不了中央弃牌区），旁观路径则会让原牌继续飞向中央、同时另造一张牌从中央飞向获得者，观感就是「复制了一张牌」。

## Requirements

### R1 先进入弃牌堆

中央区展示牌被获得时，**不得**在它飞抵中央队列之前把它从队列里取走。该牌必须走完原有的出牌飞行动画、在中央弃牌展示队列中落位，之后才允许开始第二段飞行。

### R2 第二段从中央区飞向获得者

落位后由**同一个牌面节点**继续飞行（不新建替代牌面、不允许画面上同时存在两张同 UID 牌面）：

- 获得者是本机玩家：飞向该牌在**手牌区的最终槽位中心**，落地那一帧正式手牌节点出现在同一槽位，不产生第二段滑动；
- 获得者是其他角色：飞向**获得者武将牌锚点**（沿用既有 `_try_get_player_indicator_position()` 口径）。

### R3 两个视角统一

无论获得者是本机玩家还是其他角色，第一段（飞入中央队列）与第二段（飞向获得者）的先后关系、起点取值口径必须完全一致；不得只修好其中一条路径。

### R4 接口唯一性与解耦

- 复用既有动画接口：中央展示/弃牌队列继续用 `CardUseAnimationLayer.play_card()`，区域转移继续用 `play_transfer()`，队列取牌继续用既有的取走接口；**不得新增第二套飞行动画函数**。
- 「什么时候可以取走」这一判定必须收敛到 `CardUseAnimationLayer` 内部的**唯一**「中央牌面落位通知」入口，桌面（`match_table.gd`）只消费通知，不自行轮询计时或猜测队列坐标。
- 新增的可调参数必须是 `@export` 或全局常量，并带用途/取值范围/默认值理由的中文注释。

### R5 时序安全

- 获得信号早于权威快照；等待落位期间正式手牌节点**不得**提前出现在手牌槽位（否则会与中央区那张牌同时可见）。
- 等待落位期间若该牌已离开手牌区、或本次表现被取消/重开清场，必须能安全撤销这次「等待取走」，不允许留下永不触发的回调或停在屏幕上的孤立牌面。

### R6 回归与文档

- 扩展 `tests/ui_layout_test.gd` 覆盖 R1/R2/R3 与 R5 的取消路径，并**改写**原来锁定「立即取走」的旧断言。
- 6 套基线回归（`ui_layout_test`、`virtual_hand_choice_test`、`draw_sequence_test`、`match_replay_test`、`gameplay_regression_test`、`smoke_test`）与相关专项测试全部 PASS。
- 同步 `docs/界面与交互.md`、`docs/卡牌系统.md`、`docs/游戏机制与玩法内容.md`、`docs/内容制作指南.md`、`README.md`、`.trellis/spec/ui/component-patterns.md`。

## Out of Scope

- 规则层结算顺序、`card_transfer_requested` 的发出时机、快照内容、`PlayerAction` 协议、AI 行为：本次是**纯表现层**改动。
- 装备牌飞入装备槽、延时锦囊飞入判定区、虚拟手牌候选的右侧入场路径：不动。
- 落位后是否需要额外停留时长（例如强制在弃牌堆停留固定秒数）：不新增停留；「落位」以飞行补间结束为准，落位当帧即可起飞。
- 为「获得中央展示牌」新增任何规则侧延迟或等待窗口（例如让【伏辰】延后 0.3 秒再获得）：本次不改内容层与核心时序。

## Acceptance Criteria

- [x] AC1（R1）中央队列中存在同 UID 牌面、且该牌面仍在飞向队列途中时收到本机获得信号：飞行牌面**不得**在这一帧离开 `_active_cards`；该 UID 必须被登记为「等待落位后取走」。
- [x] AC2（R1/R2）该牌面飞行补间结束后：`_active_cards` 中不再有该 UID、返回/接管的牌面实例 ID 与队列中那张完全一致（不是新建牌面）、队列其余成员按 `queue_reflow_duration` 重新铺开，第二段飞行的起点等于该牌落位后的中心。
- [x] AC3（R2）获得者是本机玩家时：第二段飞行终点等于该牌正式手牌节点的槽位中心；落地帧正式节点位于同一槽位、`hand_entry_offset` 归零、飞行牌面当帧不可见。
- [x] AC4（R3）获得者是其他角色时：第二段飞行起点等于该牌落位后的中心（而不是中央弃牌锚点）、终点等于获得者武将牌锚点，且全程只存在一张该 UID 的牌面（不出现复制牌面）。
- [x] AC5（R1）在等待落位期间先到达的权威快照里，该牌正式手牌节点必须被按在飞行起点（位于手牌滚动区之外、被裁剪），不得出现在最终槽位。
- [x] AC6（R5）等待落位期间调用取消/清场路径（`_cancel_local_hand_gain_animation()` / 重新开局清场）后：等待登记被撤销、该牌仍留在中央队列并按原有节奏淡出、正式手牌节点落回槽位，不残留回调与孤立牌面。
- [x] AC7 中央队列中没有该 UID 牌面时（例如展示已淡出或来源本来就不是中央展示）：保持原有「按统一来源解析取起点、必要时新建一张表现牌面」的行为不变。
- [x] AC8 6 套基线回归与相关专项测试全部 PASS 且退出码为 0，日志无 `ERROR` / `SCRIPT ERROR` / `FAIL`。
- [x] AC9 文档与界面规范已同步，且旧口径（「获得正在中央展示的牌时立刻取走那张牌面」）已被改写为新的两段口径。

## Notes

- 本任务为复杂任务：实现前必须有 `design.md` 与 `implement.md`。
- 被回退的旧实现是 `5e07e96` 引入的 `CardUseAnimationLayer.take_over_active_card()` 的**即时调用**；该接口本身（「取走队列中同 UID 的牌面本身」）是新方案仍然要用的能力，因此**保留接口、改变调用时机**，不删除接口。
- 上一轮任务 `10-04-card-gain-flight-target-and-drag-settle` 的 R4 目标（「不要在中央复制一张牌」）在本轮继续成立，只是「什么时候取走」从「收到获得信号的当帧」改为「该牌在中央队列落位之后」。
- 相关既有约束不得破坏：本机获得牌门闸按快照代次撤销、飞行牌面与正式手牌节点的明暗镜像、表现牌固定三档层级、手牌节点只能用位置（不能用 `visible=false`）隐藏。
