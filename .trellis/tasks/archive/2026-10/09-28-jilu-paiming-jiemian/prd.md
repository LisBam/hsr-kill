# 重构记录牌名的表现形式

## Goal

把「记录牌名」（当前仅由大黑塔【解构】写入、由【灵感】读取）从隐含在技能多步选择流程中的文字选项，重构为武将牌上的**可点击按钮**与**卡片式界面**：按钮挂在武将牌左上角角标区，点击后所有角色都能查看该武将记录了哪些牌名；技能需要选择记录牌名时，复用同一形式的界面完成选择。

本需求**不改变任何技能描述原文、不改变记录与移除牌名的规则时机、不改变记录容器的数据结构（`recorded_card_names`）**，只改变其**表现形式与交互入口**。

## Requirements

### R1 武将牌角标按钮

- R1.1 武将牌左上角新增可点击按钮，按钮文本默认为**写入该条目的技能名**（当前为「解构」）。
- R1.2 按钮位置与既有的武将牌左上角文本角标（如「酩酊」「永劫」「追歼」「安可」「逐风」）**同处一个共享槽位区域**，视觉规格（背景色、圆角、内边距、字号、描边）与文本角标保持一致。
- R1.3 该槽位区域**同时容纳多个文本角标与按钮**，按既有排序值（`order`）竖排显示，互不遮挡、互不挤占；同一武将牌上出现多个角标与多个按钮时必须全部可见。
- R1.4 记录容器为空时，**不显示**该按钮；记录出现后立即出现，记录被全部移除后立即消失。
- R1.5 按钮的可见性、文本与排序必须参与武将牌的**视觉差异检测**，记录变化后当帧刷新，不需要额外操作触发。

### R2 记录牌名的查看界面

- R2.1 点击按钮打开查看界面，展示该武将当前记录的全部牌名。
- R2.2 界面形式**参照【五谷丰登】的公共展示窗口**：居中模态、全屏遮罩、按行排列的牌面、统一信息框悬停说明。
- R2.3 由于记录的是**牌名**而非实体牌，每张牌面必须**隐藏花色与点数信息**，只显示该牌名的其余内容（牌名文本、类别、规则说明等）。
- R2.4 查看界面为**纯只读**：任何角色（含旁观者、非持有者）都能点击任意角色的该按钮打开查看，界面内不出现确定/取消按钮，牌面不可选中。
- R2.5 查看界面不产生任何规则动作、不写入手牌或任何牌区、不进入事件调度器的请求命名空间。

### R3 技能选牌的卡片式界面

- R3.1 技能需要玩家选择「记录牌名」时（当前为【灵感】的第一段“选择本牌视为哪张牌”与第三段“选择按另一记录的牌名结算目标”），展开**与 R2 同一形式**的卡片式界面，玩家点击牌面完成选择。
- R3.2 该选择界面保留**确定与取消**操作，语义与现有实现一致：未确定前不产生任何规则效果，取消等价于放弃当前步骤。
- R3.3 **取消语义不得回退**：任一步取消都不消耗【灵感】的出牌阶段次数、不移除记录牌名，之后仍可重新发动。
- R3.4 选中的对象是**牌名**，提交值必须是稳定的卡牌定义 ID，不得提交或伪造实体牌 UID。

### R4 兼容与不回退

- R4.1 既有文本角标的全部行为不得改变：`character_corner_text` 合成字符串继续按原规则生成并被现有消费者（AI 评估、既有测试）读取。
- R4.2 未声明为按钮的既有角标条目（`【酩酊】【永劫】【追歼】【安可】【逐风】` 等）继续按原样以文本形式渲染。
- R4.3 【灵感】既有的全部规则行为不得改变：可重铸/可记录范围、全体与自指目标模式的自动展开、单牌名时跳过重定向询问、无懈可击的排除、次数消费时机。

## Constraints

- 表现层**只读权威端下发的观察者裁剪快照**，不得读取 `GameState` / `MatchController` / 技能运行时实例，不得自行推算规则结论。
- 必须**复用既有组件**：牌面渲染复用 `CardView`，选择窗口复用 `CardSelectionPanel`，不得为同一数据写第二套渲染逻辑。
- 颜色、圆角、描边、边距一律经 `BattleUIStyle` / `UIStyleRegistry` 读取，不得新增主题专属颜色常量。
- 新增文本控件必须纳入统一主题字体色覆盖（`font_color_audit_test` 必须通过）；未知内容占位文本使用 ASCII 半角字符。
- 技能描述原文**逐字不可变**；本需求不触碰任何 `description` 字段。
- 记录容器 `recorded_card_names` 已存在于公开快照，不得为其新增私密字段或改变观察者裁剪规则。
- 不引入对特定技能 ID 或卡牌 ID 的硬编码白名单；按钮机制必须由**内容层技能自行声明**，核心层保持中立传递。

## Acceptance Criteria

- [ ] AC1 【解构】记录非空时，持有者武将牌左上角出现文本为「解构」的可点击按钮；记录为空时不出现。
- [ ] AC2 同一武将牌上同时存在文本角标与按钮时（例如目标身上有「酩酊」且其持有者记录了牌名），两者按 `order` 竖排同时可见，互不遮挡。
- [ ] AC3 点击按钮打开查看界面，界面按行展示全部已记录牌名，每张牌面**不显示花色与点数**。
- [ ] AC4 查看界面为只读：不出现确定/取消按钮，牌面无法选中；由任意玩家（包括非持有者）打开的结果一致。
- [ ] AC5 查看界面不改变任何权威状态（打开与关闭前后 `recorded_card_names`、手牌、牌区、事件记录均不变）。
- [ ] AC6 【灵感】第一段与第三段的选牌名步骤展开卡片式界面，点击牌面选中后由确定按钮提交，提交值为卡牌定义 ID。
- [ ] AC7 【灵感】在卡片式界面上取消任一步骤后，出牌阶段次数未消耗、记录未被移除，且仍可重新发动。
- [ ] AC8 全体目标模式（`all_others` / `all_players`）与自指模式（`self` / `self_wounded`）在卡片式界面下仍正确展开：前者不包含使用者自身，后者自动锁定使用者。
- [ ] AC9 既有文本角标行为不回退：`omphalos_transform_test`、`new_character_mechanics_test`、`reincarnation_mechanics_test` 中全部角标断言继续通过。
- [ ] AC10 `daheita_mechanics_test` 全部子测试通过，且通过行新增记录按钮相关的通过标记。
- [ ] AC11 `font_color_audit_test` 与 `ui_layout_test` 通过；全量回归维持 `TOTAL=65 OK=64 FAILED=1`（唯一失败为既有 `android_adaptation_test`）。
- [ ] AC12 文档同步：`docs/界面与交互.md`、`docs/游戏机制与玩法内容.md`、`docs/架构说明.md`、`docs/AI模块.md` 中相关描述与实际实现一致。

## Decisions Confirmed By User

- 按钮与既有文本角标**共用同一槽位区域**，但必须保证**多个角标与按钮同时全部可见**（竖排堆叠，不互相抢位）。
- 记录为空时**不显示**按钮（而非置灰或显示空界面）。
- 本需求按**复杂任务**处理，先写 `prd.md` + `design.md` + `implement.md` 再进入实现。

## Notes

- 记录牌名当前只有【解构】写入、【灵感】读取；【看破】只做移除与目标排除，不参与选择。设计仍需保证机制**通用**，不得为「解构」写死。
- `character_corner_text_entries`（`entry_id → {text, order}`）**已经在公开快照中**，因此 UI 可以直接读取有序条目，无需新增快照字段；但「按钮」语义需要在条目结构上做向后兼容的扩展。
- 本条目不改变 `character_corner_text` 的生成规则——它被 AI 评估与多个既有测试依赖。
